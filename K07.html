How the board works:

Y2-T20 · DSA-1: arrays, strings, hashing + dedup/top-k on CityPulse data

Session 20 · phase DSA · 5 points

The ticket in plain words

CityPulse is the city-data platform your squad is building. Its sensor feed sometimes sends the same reading twice, and ops wants every duplicate flagged across 10 million rows.

The obvious way to find a duplicate is to compare each row with every row before it. For 10 million rows that is about 50 trillion comparisons, which will not finish in any sensible time. A set fixes this. A set remembers what it has already seen and answers "have I seen this?" almost at once. One pass over the file is then enough, and the work grows in step with the number of rows.

This ticket is a practice interview. You work alone. You solve six small problems, state the speed and memory cost of each, run a script on real sensor data, and may explain one solution on a whiteboard. The point is to show that you choose the right data structure under pressure, and can say why.

Y2-T20.3 Solve the six problems

Goal. Six solutions, each with a complexity header and at least three tests, all green under pytest -q.

The sheet gives each problem a signature. Copy the name, parameters and order exactly. The trainer's hidden runner calls the function by that signature, so def count_pairs(nums, target) and def count_pairs(target, nums) are different functions as far as the runner is concerned.

Two techniques cover most of these problems. Learn them on small examples first.

Technique 1: a set remembers what you have seen. The example below is a teaching twin, not one of your six. It returns the first word that appears twice.

def first_repeat(words):
    seen = set()
    for word in words:
        if word in seen:
            return word
        seen.add(word)
    return None

assert first_repeat(["a", "b", "a", "c"]) == "a"
assert first_repeat(["a", "b", "c"]) is None
assert first_repeat([]) is None
assert first_repeat(["x", "x"]) == "x"

Line by line:

  • seen = set() creates an empty set. This is the memory of the loop.
  • for word in words: visits each word once, in order.
  • if word in seen: checks membership. On a set this is O(1) on average. On a list it would scan every item.
  • return word stops at the first repeat, so the function does not read the rest of the list.
  • seen.add(word) remembers the word for later checks.
  • return None runs only when no repeat exists.

The four assert lines test a normal case, a case with no repeat, an empty list and two equal words in a row. If all four pass, Python prints nothing. A failed assert stops with AssertionError.

Technique 2: a Counter counts how often each item appears. Counter(items) adds one to a count for each item in one pass, and most_common(k) ranks the top k. Use it when a problem asks "how many of each?".

import sys

Run it:

Your column names may differ. Use the names you see here in the next stages.

Stage 2. Count duplicates with a set. Replace the last two lines with a function that tracks keys. Add this below the import lines:

def count_dups(path, key_cols):
    seen = set()
    dups = 0
    with open(path, newline="") as f:
        for row in csv.DictReader(f):
            key = tuple(row[c] for c in key_cols)
            if key in seen:
                dups += 1
            else:
                seen.add(key)
    return dups

key_cols is a list of column names. tuple(...) builds the key from them, because a list is not hashable and cannot go in a set. The if checks the set, and the else adds new keys. The function returns the count of repeats. Its cost is O(n) time and O(d) space, where d is the number of distinct keys.

Watch the trace below. It shows the same logic on three rows.

Stage 3. Top five stations. Count rows per station with Counter, then rank them:

from collections import Counter

def top_stations(path, k=5):
    counts = Counter()
    with open(path, newline="") as f:
        for row in csv.DictReader(f):
            counts[row["station_id"]] += 1
    return counts.most_common(k)

counts[row["station_id"]] += 1 adds one to the station's count. most_common(5) returns the five highest pairs. Test this on a four-row CSV you write by hand before you run it on the real data.

Stage 4. Time the methods. timeit.repeat(func, number=1, repeat=3) returns three timings in seconds. Take min(...) for the best of three, and time only the function call, not the print. timeit.repeat needs a function with no arguments, so wrap your call, for example lambda: count_dups(path, key_cols).

Stage 5. Add pandas. The pandas version uses library code that hashes internally:

import pandas as pd

def dups_pandas(path, key_cols):
    df = pd.read_csv(path)
    return int(df.duplicated(subset=key_cols).sum())

pd.read_csv loads the whole file into a DataFrame. duplicated(subset=...) marks each row that repeats an earlier key. .sum() counts the marks. int(...) converts the result to a plain number. Decide whether your timing includes the file read, and say so in the README.

Y2-T20.6 Whiteboard defence (if drawn)

Goal. Explain one of your problems in five minutes, using a fixed order of steps.

Use this order every time:

  1. Clarify. Repeat the problem in your own words. Ask about input size, empty input and duplicates.
  2. Brute force. Describe the simplest correct method and its cost, even if it is slow.
  3. Optimise. Name the structure that removes the slow part, such as a set, a dict or a deque, and state the new cost.
  4. Test edges. Name three cases: empty, one item and a repeat or a tie.
  5. State complexity. Say the time and the space in one sentence each.

Practise with a fictional bakery that wants the first day it sells over 100 loaves. Brute force recomputes each total. Optimised, it keeps a running total in one pass. Do the same reasoning for your own problems.

Practise aloud, with a timer, five times. Rubric points are clarify, approach, complexity, edge cases and communication. You need at least three out of five.

Defend it in the viva

Q1. Why does a set make the duplicate check O(n), where a list makes it O(n²)?

Model answer

A set uses a hash to jump straight to the slot for a key, so each membership check takes O(1) on average. Over n rows the total is O(n). A list membership test scans every earlier item, so the total is about n times n divided by two, which is O(n²). The change from list to set is one line of code, but it changes the whole cost. Say "on average", because a bad set of hash collisions can be slower.

Q2. What is the memory cost of your set, and when would you not use it?

Model answer

The set stores one entry for each distinct key, so the extra memory is O(n) in the worst case. With 10 million distinct tuples that can be gigabytes, so memory is a real limit. I would not use a set when memory is tight. Sorting the rows costs O(n log n) time, and sorting in place needs little extra space, although the rows must still be loaded first. A sliding window that keeps only recent keys is another choice when duplicates are close together in time. The right answer depends on which resource the system cannot spare.

Q3. Which of the six problems did you choose to do first, and why?

Model answer

Explain your reasoning honestly: which problem you chose first, and why, such as building a green test run with easier ones. Your commit history shows the order, so your answer should match it.

Q4. How did you check edge cases?

Model answer

I wrote at least three tests per problem: a normal case, an empty case and a tricky case such as a repeat or a tie. Hidden tests check cases I did not write, so I also considered negative numbers and large inputs. Finally I ran the tests on a fresh clone.

Q5. Why do the pure-Python and pandas timings differ, and which would you use in production?

Model answer

Pandas loads the whole file into a table and runs its duplicate check in optimised code, so it is often faster but needs more memory. Pure Python streams the file row by row, using little memory but running slower. Timings also depend on what each includes, such as the file read. I would choose by the limit that matters, and say so in the README.

The ticket in plain words

Health officers want an alert when air stays poor for a while, not just in one hour. The measure is PM2.5, which means fine particles in the air that can reach the lungs. The alert looks at a rolling window of six hours. A rolling window is the group of the latest six readings. Each new hour adds a reading and pushes out the oldest one. For every window you need two numbers: the average and the maximum.

The slow way adds up all six readings again every hour. Most of those readings were already added an hour earlier, so the work repeats itself. The faster way keeps a running sum, a total that goes up by the new reading and down by the reading that left. For the maximum you use a deque (a double-ended queue, a list that is quick to add and remove at both ends). The deque keeps only the readings that could still be the maximum. Every reading enters and leaves once, so the work grows in a straight line with the number of readings. That is the O(n) in the ticket.

Stage 3: the running sum for the average (Y2-T21.4)

Goal. An average for each row that matches the SQL avg6.

The technique. Start with the first values. Each later step adds the new value and takes away the value that just left. The window never has to be rebuilt, so each value is handled twice in total. The divisor is the number of values in the window now, which is min(i + 1, k).

Step 3a. Write the loop with blanks. Put this in rolling_window.py below the reader, and fill in each blank:

total = 0.0
averages = []
for i, v in enumerate(values):
    total += v
    if i >= k:
        total -= ____          # hint: the value k positions back, at index i - k
    averages.append(total / ____)   # hint: min(i + 1, k)
  • enumerate(values) gives the position i and the value v at each step.
  • total += v adds the entering value.
  • if i >= k: is true once the window is full, so there is a value to remove.
  • The blank in the subtraction is the value that just left the window.
  • The blank in the division is the number of values in the window now.

Defend it in the viva

Q1. Why is the running-sum average O(n) when the naive method is O(n·k)?

Model answer

The naive method adds all k values again for every window, so the work is about n times k. The running sum adds the entering value and subtracts the leaving value, so each value is handled a fixed number of times in total. The work grows with n, not with n times k. The reasoning is that the window overlaps almost entirely with the one before it, so reusing the total avoids repeating the work.

Q2. What is the trade-off between the monotonic deque and a heap for the rolling maximum?

Model answer

A heap can also find a window maximum, at O(n log n) in the worst case with lazy deletion (old entries stay in the heap until they reach the top), and it is often easier to write. The deque is O(n) overall and needs O(k) extra space, but you must store indexes and handle expiry correctly. The trade-off is speed and a tighter bound against code that is easier to get wrong. For a stream that must run quickly on many values, the deque is the better fit. For a quick prototype, a heap can be fine.

Q3. Which function did you write, and how did you show it matched the SQL export?

Model answer

Name the function and the file you wrote, the test file you added, and the commit where you added each one. Then state the exact command you ran, the summary line it printed and the exit code. Say which bug you fixed first, if any, and what caused it. Only claim work that the commit history shows. The reviewer will check the commits, so your answer should match them.

Q4. Why does each index enter and leave the deque at most once, and why is that O(n) overall?

Model answer

Each index is pushed to the back once, and it is removed at most once, either from the back when a bigger value arrives or from the front when it leaves the window. So the total number of pops cannot exceed the number of pushes, which is n. One step can pop many items, so that step is expensive. But the total over all steps is at most about 2n, so the cost per step is constant on average. That is the amortised O(n) bound.

Q5. Your six rows span more than six hours. Why does that happen, and what should you write in the note?

Model answer

The window is defined by rows, not by time. If an hour is missing from the feed, six rows cover more than six hours. The note should state that the window is six rows, give the gap rule the squad uses, and say that the SQL view and the Python both use rows, so they agree. Naming the gap is better than hiding it, because the health officers rely on the alert time.

Y2-T22.1 Gate: trace binary search and state the invariant

Goal. Be able to explain, on a board, what each line of a binary search does and what stays true during the loop. This is the invariant: a fact that holds before and after every loop step.

Technique. The function below finds the first index where a value is at least target in a sorted list. The range from lo to hi is half-open: hi is one past the last index. The invariant is "the answer lies between lo and hi, and hi itself may be the answer". Follow the walk-through below to see the range shrink.

def first_at_least(xs, target):
    lo, hi = 0, len(xs)
    while lo < hi:
        mid = (lo + hi) // 2
        if xs[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

Walk through it with xs=[1, 3, 3, 6, 9] and target=3. The range starts as lo=0, hi=5. The middle is index 2, where xs[2] is 3. That is not less than 3, so hi moves to 2. The next middle is 1, where xs[1] is also 3, so hi moves to 1. The middle is 0, where xs[0] is 1, so lo moves to 1. Now lo equals hi, the loop stops, and the function returns 1.

Line by line: while lo < hi: repeats while the range is not empty. mid = (lo + hi) // 2 picks the middle, and // drops any fraction. The if decides which side keeps the answer.

Test it. Trace on paper with xs=[2, 4, 4, 7] and target=4. You should get 1. Then try target=8. You should get 4, which means "past the end".

State the invariant out loud. Say it in one sentence: "Every index before lo holds a value less than the target, and the answer is never before lo."

Y2-T22.4 Benchmark with timeit on 1M rows

Goal. Measured numbers, not estimates, for the build time, the scan time per query and the bisect time per query, on 1M rows.

Technique 1, timeit. timeit.repeat(fn, repeat=5, number=100) runs fn 100 times, five times over, and returns five totals in seconds. Take the minimum, because the lowest total is the least disturbed by other programs, and divide by number:

def double(x):
    return x * 2

totals = timeit.repeat(lambda: double(21), repeat=5, number=100)
per_call = min(totals) / 100
print(per_call)

Line by line: lambda: double(21) wraps the call so timeit can run it. min(totals) / 100 gives the time for one call in seconds, printed as a small number such as 1.2e-07.
