Lists

A list is an ordered collection of values kept under one name. A value is any piece of data, such as a number or a piece of text. Ordered means each item has a position, and the position never changes unless you change the list.

Lists are how CityPulse keeps a run of air-quality readings together. Here is a small one, using the Python programming language. Type it into a file called example.py and run it with python example.py in a terminal.

stations = ["MG Road", "Koramangala", "Jayanagar"]
print(stations[0])
print(stations[-1])
print(stations[0:2])
print(len(stations))
print("Jayanagar" in stations)

Line by line:

  • stations = [...] creates a list of three text values and stores it under the name stations. The square brackets [ and ] mark a list, and the commas separate its items.
  • stations[0] is an index. An index is a position inside a list, and positions start at 0, not 1. So stations[0] is the first item.
  • stations[-1] uses a negative index. -1 counts from the end, so this is the last item.
  • stations[0:2] is a slice. A slice takes a range of positions written as start:stop. The start is included and the stop is not, so this gives items 0 and 1.
  • len(stations) returns the length, which is the number of items. len is a built-in function, meaning a function that Python provides without you writing it.
  • "Jayanagar" in stations asks whether the text is one of the items. The answer is True or False. These two words are called booleans, a value that can only be true or false.

Expected output:

MG Road
Jayanagar
['MG Road', 'Koramangala']
3
True

Notice that the slice prints with square brackets and quotes. That is how Python shows a list when you print it directly.

Changing a list with methods

A method is a function that belongs to a value. You call it with a dot after the name, such as readings.append(52). The dot means "use this action on this list".

readings = [40, 65]
readings.append(52)
readings.extend([33, 70])
last = readings.pop()
print(readings)
print(last)

Line by line:

  • readings = [40, 65] starts with two numbers.
  • readings.append(52) adds one item to the end of the list. Now it holds 40, 65, 52.
  • readings.extend([33, 70]) adds every item from the list you give it to the end. Now it holds 40, 65, 52, 33, 70.
  • readings.pop() removes the last item and returns it, so the removed value is stored in last.
  • The two print lines show what is left and what was removed.

Expected output:

[40, 65, 52, 33]
70
Trap: append adds one item, even if that item is a list

readings.append([1, 2]) adds a single item that is itself a list, so the list gets one longer. If you want each number added separately, use extend.

To go through every item, use a for loop. A loop is a block of code that repeats once for each item.

for pm in readings:
    print(pm)

The first line says "for each value, call it pm, and run the indented lines". The indented print runs once per item, so this prints each reading on its own line. Indentation, the spaces at the start of a line, is how Python knows which lines belong to the loop. Use four spaces per level.

Sorting a list

sorted and sort both put a list in order, but they behave differently.

nums = [30, 10, 20]
print(sorted(nums))
print(nums)
nums.sort()
print(nums)

Line by line:

  • sorted(nums) returns a new list in ascending order. It does not change nums.
  • The second print shows that nums is still in its original order.
  • nums.sort() changes the list itself, in place. It returns nothing.
  • The last print shows the changed list.

Expected output:

[10, 20, 30]
[30, 10, 20]
[10, 20, 30]
Trap: sort returns None

nums = nums.sort() sets nums to None, because sort returns nothing. Call nums.sort() on its own line, or write nums = sorted(nums).

Copying versus aliasing

When you write b = a, Python does not copy the list. It gives the list a second name. Both names now point at the same list. This is called aliasing. An alias is another name for the same object.

a = [1, 2]
b = a
c = a.copy()
b.append(3)
print(a)
print(c)

Line by line:

  • b = a makes b an alias for the list that a names.
  • c = a.copy() makes a real copy. c is a separate list with the same items.
  • b.append(3) changes the one shared list, so a changes too.
  • c was copied earlier, so it is unchanged.

Expected output:

[1, 2, 3]
[1, 2]

A copy can also be made with a[:], which is a slice from start to end. Both forms work. The copy method is easier to read.

Tuples and unpacking

A tuple is like a list that cannot be changed after it is made. You write it with round brackets, and the commas make it a tuple. A tuple is useful for a fixed group of values, such as a latitude and longitude.

point = (12.97, 77.59)
lat, lon = point
print(lat)
print(lon)
point[0] = 5

Line by line:

  • point = (12.97, 77.59) creates a tuple of two numbers. These are roughly the latitude and longitude of Bengaluru.
  • lat, lon = point is called unpacking. Python takes the first value and stores it in lat, and the second value goes to lon. The number of names must match the number of values.
  • The two print lines show the values.
  • point[0] = 5 tries to change the first value. This is not allowed for a tuple, so Python stops with an error.

Expected output:

12.97
77.59
Traceback (most recent call last):
  File "example.py", line 5, in <module>
    point[0] = 5
TypeError: 'tuple' object does not support item assignment

A traceback is the error report Python prints. The last line names the kind of error (TypeError) and explains it. The line 5 part tells you where to look.

Unpacking also gives a neat way to swap two values: a, b = b, a. A single item in brackets needs a comma too. (5) is just the number 5, but (5,) is a tuple.

Key fact: Tuples are for fixed groups

Use a tuple when the number of items is fixed and the meaning of each position is clear, such as (name, score). Use a list when the number of items grows or changes.

Dictionaries

A dictionary stores pairs of a key and a value. The key is the name you look up with, and the value is the data you want back. You write a dictionary with curly braces, { and }, and each pair is written key: value.

Keys must be values that do not change, such as text or numbers. Within one dictionary each key appears only once.

pm = {"MG Road": 40, "Jayanagar": 65}
print(pm["MG Road"])
print(pm.get("Whitefield"))
print(pm.get("Whitefield", 0))
pm["Whitefield"] = 52
print("Whitefield" in pm)
print(len(pm))

Line by line:

  • pm = {...} creates a dictionary with two keys, "MG Road" and "Jayanagar".
  • pm["MG Road"] looks up the value for that key. The result is 40.
  • pm.get("Whitefield") looks up a key that does not exist. get returns None in that case. None is Python's word for "no value".
  • pm.get("Whitefield", 0) does the same lookup, but if the key is missing it returns the second argument, 0, instead.
  • pm["Whitefield"] = 52 adds a new key and value, because the key was not there. Assigning to an existing key replaces its value in the same way.
  • "Whitefield" in pm checks whether the key exists. Dictionaries check keys, not values, when you use in.
  • len(pm) returns the number of pairs, which is now 3.

Expected output:

40
None
0
True
3
Trap: Reading with [] stops the program when the key is missing

pm["Hebbal"] raises a KeyError if Hebbal is not a key. Use pm.get("Hebbal") or pm.get("Hebbal", 0) when a missing key is normal.

To go through every pair, use items(). It gives you each key and value together.

for station, value in pm.items():
    print(station, value)

Expected output:

MG Road 40
Jayanagar 65
Whitefield 52

Python keeps dictionary items in the order you added them. This has been guaranteed since Python 3.7, so the output order above is reliable.

The counting pattern

Counting is one of the most common jobs with a dictionary. You want to know how many times each station appears in a list of readings. The method is: for each item, read the current count (or 0 if there is none), add one, and store the result. The next trace shows it happening one line at a time.

stations = ["S1", "S2", "S1"]
counts = {}
for sid in stations:
    counts[sid] = counts.get(sid, 0) + 1
print(counts)

Line by line:

  • stations = [...] is the list of station ids you are counting.
  • counts = {} starts an empty dictionary. Empty braces make an empty dictionary, not an empty set.
  • for sid in stations: runs the indented line once for each id, and sid holds the current id.
  • counts.get(sid, 0) returns the count so far, or 0 for a new station. + 1 adds one.
  • counts[sid] = ... stores the new count under that station.

Expected output:

{'S1': 2, 'S2': 1}

Python shows text inside a dictionary with single quotes. That is only how Python displays it. The text itself is S1.

The grouping pattern

Grouping is the same idea, except each key holds a list instead of a number. You want all the readings for each station, collected together.

readings = [("MG Road", 40), ("Jayanagar", 65), ("MG Road", 44)]
by_station = {}
for station, value in readings:
    if station not in by_station:
        by_station[station] = []
    by_station[station].append(value)
print(by_station)

Line by line:

  • readings is a list of tuples. Each tuple holds a station name and a value.
  • for station, value in readings: unpacks each tuple into two names.
  • if station not in by_station: runs only the first time a station appears. It creates an empty list for that station.
  • by_station[station].append(value) adds the value to the list for that station. This line runs every time.

Expected output:

{'MG Road': [40, 44], 'Jayanagar': [65]}

Python also has a shorter form, by_station.setdefault(station, []).append(value), which does the same job in one line. Learn the longer form first, because it shows what happens.

Sets

A set is an unordered collection in which each value appears only once. Adding a value that is already there does nothing. Sets are useful for questions such as "which distinct stations are in this file?"

cities = {"Pune", "Delhi", "Pune"}
print(len(cities))
print("Delhi" in cities)
print(sorted(cities))
print({1, 2, 3} & {2, 3, 4})

Line by line:

  • cities = {...} creates a set. The second "Pune" is ignored because it is a duplicate.
  • len(cities) counts the distinct values, which is 2.
  • "Delhi" in cities checks membership. Membership checks are fast, even for large sets.
  • sorted(cities) returns the values as a sorted list. A set has no order of its own, so you sort it when you need order.
  • & means intersection. It returns the values that appear in both sets, which are 2 and 3.

Expected output:

2
True
['Delhi', 'Pune']
{2, 3}
Trap: {} is a dictionary, not a set

An empty set must be written set(). The text {} creates an empty dictionary.

Functions

A function is a named block of code that you can run whenever you need it. You define one with the word def, followed by a name and brackets. The names in the brackets are the parameters, which are the inputs the function expects. When you call the function, the values you pass in are the arguments.

def pm_category(value, limit=60):
    """Return 'high' if value is above limit, otherwise 'ok'."""
    if value > limit:
        return "high"
    return "ok"

print(pm_category(40))
print(pm_category(90))
print(pm_category(90, limit=100))

Line by line:

  • def pm_category(value, limit=60): defines the function. value is required. limit=60 is a default value, which is used when the caller does not pass a limit.
  • The text in triple quotes is a docstring. It is a description of the function, and tools and people read it to learn what the function does.
  • if value > limit: compares the two numbers.
  • return "high" ends the function and hands "high" back to whoever called it. The indented lines after if run only when the test is true.
  • pm_category(40) calls the function with 40 and uses the default limit of 60, so the answer is "ok".
  • pm_category(90, limit=100) passes the limit by name, so the answer is "ok" again.

Expected output:

ok
high
ok

Return versus print

print and return look similar, but they do different jobs. print shows text on the screen and then forgets it. return gives a value back to the code that called the function, so you can store it and use it later.

def double_print(n):
    print(n * 2)

x = double_print(4)
print(x)

Expected output:

8
None

The function printed 8, but it did not return anything, so x holds None. If you want to use the result later, use return.

Returning several values

A function can return more than one value at once. Python packs them into a tuple, and you unpack them at the other end.

def min_max(values):
    return min(values), max(values)

low, high = min_max([40, 65, 33])
print(low, high)

min and max are built-in functions that return the smallest and largest value. The return line sends back a tuple (33, 65), and low, high = ... unpacks it. The output is 33 65.

Default values and the mutable default trap

A default value is used when the caller leaves that argument out. Defaults make functions easier to use, as in pm_category(40).

There is one default value that causes a well-known problem. A default is created once, when Python reads the def line. If the default is a list or a dictionary, every call that uses the default shares the same object.

def add_item(item, bag=[]):
    bag.append(item)
    return bag

print(add_item("a"))
print(add_item("b"))

Expected output:

['a']
['a', 'b']

The second call did not start with an empty bag. It reused the list that the first call had already changed. The fix is to use None as the default and create the list inside the function:

def add_item(item, bag=None):
    if bag is None:
        bag = []
    bag.append(item)
    return bag

Now each call without a bag gets a new empty list, and the output is ['a'] followed by ['b'].

Trap: Never use a list or dictionary as a default

Write bag=None, then create the list inside the function when it is None. Numbers, text and tuples are safe as defaults because they cannot be changed in place.

Sorting properly

Sorting a list of numbers is easy. Sorting a list of records, such as station readings, needs a rule for what to compare. You tell sorted the rule with a key function. A key function receives one item and returns the value that should be compared.

A lambda is a short function written in one line, without a name. lambda r: r[1] means "a function that takes r and returns r[1]". It is the same as writing a def with one return line.

readings = [("MG Road", 40), ("Jayanagar", 65), ("Hebbal", 40)]
by_value = sorted(readings, key=lambda r: r[1])
print(by_value)

r[1] is the second item of each tuple, the reading. The output is [('MG Road', 40), ('Hebbal', 40), ('Jayanagar', 65)]. The two 40s keep their original order, because Python's sort is stable.

Several fields with a tuple key

To sort by more than one field, return a tuple from the key. Python compares tuples one item at a time: it compares the first items, and only if they are equal does it look at the second items.

readings = [("MG Road", 40), ("Jayanagar", 65), ("Hebbal", 40)]
ranked = sorted(readings, key=lambda r: (-r[1], r[0]))
print(ranked)

The key is (-r[1], r[0]). The minus sign turns the reading into a negative number, so the largest reading becomes the smallest key and sorts first. The second item, r[0], is the name, which breaks ties in alphabetical order.

Expected output:

[('Jayanagar', 65), ('Hebbal', 40), ('MG Road', 40)]

The next trace shows the keys being compared.

Descending numbers, ascending names

A common request is "highest score first, and for equal scores, names in alphabetical order". The minus sign handles the numbers. Do not use reverse=True for this, because it reverses the names too.

readings = [("MG Road", 40), ("Jayanagar", 65), ("Hebbal", 40)]
wrong = sorted(readings, key=lambda r: (r[1], r[0]), reverse=True)
print(wrong)

Expected output:

[('Jayanagar', 65), ('MG Road', 40), ('Hebbal', 40)]

With reverse=True, the names sort from Z to A, so MG Road comes before Hebbal. The correct version is the one with -r[1] and no reverse.

Trap: reverse=True flips every field in the key

reverse=True applies to the whole key tuple. If you need one field reversed and another not, negate the numeric field instead.

Comprehensions

A comprehension is a short way to build a list, set or dictionary from a loop. Read it from left to right: what goes in, where it comes from, and any condition for keeping it.

squares = [n * n for n in range(5)]
evens = [n for n in range(10) if n % 2 == 0]
lengths = {name: len(name) for name in ["Pune", "Delhi"]}
print(squares)
print(evens)
print(lengths)

Line by line:

  • [n * n for n in range(5)] loops over 0, 1, 2, 3 and 4 and stores each square in a new list. range(5) produces 0 to 4, and it stops before 5.
  • [n for n in range(10) if n % 2 == 0] keeps only the values where the remainder after division by 2 is 0. % is the remainder operator, so this keeps the even numbers.
  • {name: len(name) for name in [...]} builds a dictionary. Each name is the key and its length is the value. Curly braces with a : make it a dictionary.

Expected output:

[0, 1, 4, 9, 16]
[0, 2, 4, 6, 8]
{'Pune': 4, 'Delhi': 5}
Trap: Do not build a comprehension with side effects

A comprehension is for making a new collection. If you only want to print each item or change other variables, a normal for loop is clearer.

enumerate and zip

enumerate gives you each item together with its position. Without it, you would have to keep a counter yourself.

names = ["MG Road", "Jayanagar"]
for i, name in enumerate(names, start=1):
    print(i, name)

enumerate(names, start=1) counts from 1 instead of 0. The unpacking i, name takes each pair in turn. The output is:

1 MG Road
2 Jayanagar

zip walks through two or more lists at the same time and pairs their items.

pairs = list(zip(names, [40, 65]))
print(pairs)

zip returns pairs, not a list, so list(...) turns the result into a list you can print. The output is [('MG Road', 40), ('Jayanagar', 65)]. If the lists have different lengths, zip stops at the shorter one, so an extra item in the longer list is dropped without any error. Keep that in mind when you check your data.

None and truthiness

None means "there is no value". A function that does not return anything gives back None, and so does get when a key is missing. To test for it, use is None.

def find_station(stations, wanted):
    for s in stations:
        if s == wanted:
            return s
    return None

result = find_station(["MG Road"], "Hebbal")
if result is None:
    print("not found")
if not []:
    print("empty list is false")

Line by line:

  • The function returns the station name if it finds it, and falls through to return None if the loop ends without a match.
  • result = find_station(...) searches for Hebbal, which is not in the list, so result is None.
  • if result is None: is true, so the first message prints.
  • not [] checks truthiness. Python treats some values as true and others as false when you use them in an if. An empty list is false, so not [] is true, and the second message prints.

Expected output:

not found
empty list is false

The values that Python treats as false are None, False, 0, 0.0, the empty text "", and any empty collection such as [], {} and set(). Everything else is true.

Trap: Use is None, not a truthiness test, when 0 is valid

if not count: is also true when count is 0, which may be a real answer. Write if count is None: when you need to know whether a value is missing.

Errors you can catch

An error that stops a program is called an exception. Python reports it with a traceback and stops, unless your code catches it. You catch an exception with try and except. The code inside try runs first. If it raises an error, Python jumps to the except block instead of stopping.

def parse_reading(text):
    try:
        return int(text)
    except ValueError:
        print("not a number:", text)
        return None

print(parse_reading("42"))
print(parse_reading("forty"))

Line by line:

  • int(text) converts text such as "42" into the number 42. If the text is not a whole number, it raises ValueError.
  • except ValueError: names the error this block handles. Other errors are not caught here.
  • The print inside except tells the user what went wrong, and return None gives the caller a clear missing value.

Expected output:

42
not a number: forty
None

You can also raise an error yourself with raise. This is useful when a value breaks a rule your program depends on.

def check_pm25(value):
    if value < 0:
        raise ValueError("PM2.5 cannot be negative")
    return value

check_pm25(-5)

Running this stops the program with a traceback. The last line is ValueError: PM2.5 cannot be negative. The text in brackets is the message you chose, and it is what a reader sees first when something goes wrong.

Two other errors you will meet often are KeyError, from reading a missing dictionary key with [], and IndexError, from asking for a list position that does not exist, such as nums[10] on a three-item list.

Key fact: Catch the specific error

Write except ValueError, not a bare except:. A bare except also hides errors you did not expect, such as a typing mistake in your own code.

Practise

Each problem below has a task, an example and a tested solution. Try it yourself first. Save your attempt in a file, and run the test block against it. The solution boxes are hidden until you open them.

Problem 1: largest value

Write largest(numbers). It returns the largest number in the list. If the list is empty, it returns None.

Example: largest([3, 9, 2]) returns 9.

Show the solution
def largest(numbers):
    if not numbers:
        return None
    best = numbers[0]
    for n in numbers:
        if n > best:
            best = n
    return best

assert largest([]) is None
assert largest([5]) == 5
assert largest([3, 9, 2]) == 9
assert largest([-4, -1, -7]) == -1
assert largest([2, 2, 2]) == 2

The function first handles the empty list, because numbers[0] would fail on an empty list. It starts with the first item as best, then compares every item against it. The assert lines are checks: each one stops the program with an error if the statement after it is false, so a passing run prints nothing.

Problem 2: running total

Write running_total(numbers). It returns a new list where each item is the sum of all the numbers up to that position.

Example: running_total([1, 2, 3]) returns [1, 3, 6].

Show the solution
def running_total(numbers):
    totals = []
    total = 0
    for n in numbers:
        total = total + n
        totals.append(total)
    return totals

assert running_total([]) == []
assert running_total([5]) == [5]
assert running_total([1, 2, 3]) == [1, 3, 6]
assert running_total([4, -1, 0]) == [4, 3, 3]

total carries the sum from one loop pass to the next, and each new sum is added to the list. An empty input gives an empty list without any special case, because the loop never runs.

Problem 3: word counts

Write word_counts(words). It returns a dictionary that maps each word to the number of times it appears. The match is case-sensitive, so "Pune" and "pune" are different words.

Example: word_counts(["a", "b", "a"]) returns {"a": 2, "b": 1}.

Show the solution
def word_counts(words):
    counts = {}
    for w in words:
        counts[w] = counts.get(w, 0) + 1
    return counts

assert word_counts([]) == {}
assert word_counts(["a", "b", "a"]) == {"a": 2, "b": 1}
assert word_counts(["Pune", "pune"]) == {"Pune": 1, "pune": 1}

This is the counting pattern from earlier. get with a default of 0 handles the first time each word appears, and the dictionary keeps the words exactly as they were written.

Problem 4: group by length

Write group_by_length(words). It returns a dictionary where each key is a word length and each value is a list of the words with that length, in their original order.

Example: group_by_length(["aa", "b", "cc"]) returns {2: ["aa", "cc"], 1: ["b"]}.

Show the solution
def group_by_length(words):
    groups = {}
    for w in words:
        n = len(w)
        if n not in groups:
            groups[n] = []
        groups[n].append(w)
    return groups

assert group_by_length([]) == {}
assert group_by_length(["aa", "b", "cc"]) == {2: ["aa", "cc"], 1: ["b"]}
assert group_by_length(["x", "y"]) == {1: ["x", "y"]}

The grouping pattern from earlier, with the key being a number instead of text. Dictionary equality in assert does not depend on key order, but the list order inside each group does matter, and the loop keeps it.

Problem 5: top scorer

Write top_scorer(scores). The argument is a dictionary that maps a name to a score. Return the name with the highest score. If two names tie on the score, return the one that comes first alphabetically. If the dictionary is empty, return None.

Example: top_scorer({"Bina": 90, "Asha": 90, "Zed": 10}) returns "Asha".

Show the solution
def top_scorer(scores):
    if not scores:
        return None
    ranked = sorted(scores.items(), key=lambda item: (-item[1], item[0]))
    return ranked[0][0]

assert top_scorer({}) is None
assert top_scorer({"Asha": 70, "Ravi": 90}) == "Ravi"
assert top_scorer({"Bina": 90, "Asha": 90, "Zed": 10}) == "Asha"

scores.items() gives pairs of name and score. The key function is the same tuple key from the sorting section, so the first item in the sorted list is the highest score with the alphabetically first name. ranked[0][0] reads the name from the first pair.

Problem 6: sort readings

Write sort_readings(readings). Each reading is a dictionary with a "station" and a "pm25" value. Return a new list sorted by pm25 from highest to lowest. For equal values, sort the station names from A to Z.

Example: sorting a reading of 40 at MG Road and a reading of 65 at Koramangala puts Koramangala first.

Show the solution
def sort_readings(readings):
    return sorted(readings, key=lambda r: (-r["pm25"], r["station"]))

assert sort_readings([]) == []

data = [
    {"station": "MG Road", "pm25": 40},
    {"station": "Koramangala", "pm25": 65},
    {"station": "Jayanagar", "pm25": 40},
]
result = sort_readings(data)
assert [r["station"] for r in result] == ["Koramangala", "Jayanagar", "MG Road"]
assert data[0]["station"] == "MG Road"

The key uses the same negative-number trick as before. r["pm25"] reads a value from a dictionary, which is the way you read a field of a record. The last assert checks that sorted did not change the original list.

Problem 7: average

Write average(numbers). It returns the mean, which is the sum divided by the count. If the list is empty, return None, because there is no average to give.

Example: average([1, 2]) returns 1.5.

Show the solution
def average(numbers):
    if not numbers:
        return None
    return sum(numbers) / len(numbers)

assert average([]) is None
assert average([2, 2, 2]) == 2
assert average([1, 2]) == 1.5
assert average([10]) == 10

/ always gives a decimal result in Python 3, even when the answer is whole, so 6 / 3 is 2.0. That still equals 2 in an assert. The empty-list check comes first, because dividing by len of an empty list would divide by zero.

Problem 8: pairs from two lists

Write make_pairs(keys, values). It returns a dictionary that pairs each key with the value in the same position. If the lists have different lengths, stop at the shorter one.

Example: make_pairs(["a", "b", "c"], [1, 2]) returns {"a": 1, "b": 2}.

Show the solution
def make_pairs(keys, values):
    return dict(zip(keys, values))

assert make_pairs([], []) == {}
assert make_pairs(["a", "b", "c"], [1, 2]) == {"a": 1, "b": 2}
assert make_pairs(["x"], [9]) == {"x": 9}

zip pairs the items and stops at the shorter list. dict turns a sequence of two-item pairs into a dictionary. This is the behaviour the example relies on, so the third line of the example is a check of the edge case, not a surprise.

Problem 9: squares of every number

Write squares_of_all(rows). The argument is a list of lists of numbers. Return one flat list with the square of every number, in the same order.

Example: squares_of_all([[1, 2], [3]]) returns [1, 4, 9].

Show the solution
def squares_of_all(rows):
    return [n * n for row in rows for n in row]

assert squares_of_all([]) == []
assert squares_of_all([[1, 2], [3]]) == [1, 4, 9]
assert squares_of_all([[], [-2]]) == [4]

A comprehension with two for parts reads as two nested loops, outer first. The first for picks each inner list, and the second picks each number in it. An empty inner list adds nothing to the result, and a negative number squares to a positive one.

Problem 10: parse a PM2.5 reading

Write parse_pm25(text). It takes text typed by a user. Return the reading as an integer. Spaces around the number are allowed. Return None if the text is not a number, is empty, or is negative.

Example: parse_pm25(" 7 ") returns 7, and parse_pm25("abc") returns None.

Show the solution
def parse_pm25(text):
    try:
        value = int(text)
    except ValueError:
        return None
    if value < 0:
        return None
    return value

assert parse_pm25("42") == 42
assert parse_pm25(" 7 ") == 7
assert parse_pm25("abc") is None
assert parse_pm25("") is None
assert parse_pm25("-3") is None

int ignores spaces at both ends, which is why " 7 " works. An empty string raises ValueError too, so it is caught by the same except. The negative check is separate, because a negative number is a valid integer but not a valid reading.
