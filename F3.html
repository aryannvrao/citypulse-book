Parsing lines

Most graded labs start with text. A station sends a line such as S1,42, a log file has hundreds of such lines, and your job is to turn them into something you can count and compare. In Python, text is stored in a string, which is a sequence of characters written inside quotes, for example "S1,42". A method is a function that belongs to a value. You call it with a dot after the value, so "S1,42".split(",") calls the split method of the string "S1,42". A function is a named block of code that takes inputs (its arguments) and returns a result.

The first tool is splitlines(). It breaks a block of text into a list (an ordered collection of items written in square brackets) with one item per line. The line-break characters are removed.

text = "station,pm25\nS1,42\nS2,17\n"
lines = text.splitlines()
print(lines)

Running this prints ['station,pm25', 'S1,42', 'S2,17']. The \n inside the string is a newline character, and splitlines treats it as the end of a line. The trailing newline at the end does not create an empty fourth item.

split(",") breaks one line at every comma. It takes the separator as its first argument. A second, optional argument called maxsplit limits how many cuts are made. "k=v=w".split("=", 1) makes at most one cut and returns ['k', 'v=w']. This matters when the value itself may contain the separator, such as a free-text note.

strip() removes spaces, tabs and newlines from both ends of a string. It does not touch the middle. Labs often receive values such as " 42" with a leading space, and strip makes the comparison reliable.

partition(":") splits at the first occurrence of the separator and always returns a tuple of exactly three items: the text before, the separator, and the text after. A tuple is like a list, but its items are fixed once created and it is written with round brackets. If the separator is missing, the first item is the whole string and the other two are empty strings.

Putting these together gives the most common lab move: turning a CSV line into a dictionary. CSV stands for comma-separated values, a plain-text table where each line is one row and commas separate the columns. A dictionary is a collection of key-value pairs written in curly brackets, such as {"station": "S1", "pm25": "42"}. The first line of a CSV file is usually the header, which gives the name of each column.

def parse_csv_text(text):
    lines = text.strip().splitlines()
    header = [h.strip() for h in lines[0].split(",")]
    rows = []
    for line in lines[1:]:
        if not line.strip():
            continue
        values = [v.strip() for v in line.split(",")]
        rows.append(dict(zip(header, values)))
    return rows

assert "a,b\n".strip().splitlines() == ["a,b"]
assert "x,y,z".split(",") == ["x", "y", "z"]
assert "k=v=w".split("=", 1) == ["k", "v=w"]
assert "  hi  ".strip() == "hi"
assert "name:Asha".partition(":") == ("name", ":", "Asha")
assert "novalue".partition(":") == ("novalue", "", "")
rows = parse_csv_text("station,pm25\nS1, 42\n\nS2,17\n")
assert rows == [{"station": "S1", "pm25": "42"}, {"station": "S2", "pm25": "17"}]

Explanation, line by line:

  • def parse_csv_text(text): defines a function called parse_csv_text. The word def means "define a function", and text is the argument that the caller passes in.
  • lines = text.strip().splitlines() removes leading and trailing whitespace from the whole text, then splits it into a list of lines. The two calls are chained: the result of strip() is the thing splitlines() is called on.
  • header = [h.strip() for h in lines[0].split(",")] takes the first line, splits it at commas and strips each name. The square brackets around the for make a list comprehension, which builds a new list in one line. lines[0] means "the item at position 0", and counting in Python starts at 0, not 1.
  • rows = [] creates an empty list that will collect the results.
  • for line in lines[1:]: loops over every line after the header. The slice lines[1:] means "from position 1 to the end".
  • if not line.strip(): is true for a blank line. not reverses a true-or-false value, so the condition is true when the stripped line is empty.
  • continue skips the rest of the loop body and moves to the next line.
  • values = [...] builds the list of stripped values for this row.
  • rows.append(dict(zip(header, values))) pairs each header name with the value in the same position. zip walks two lists side by side, and dict turns those pairs into a dictionary. append adds the new dictionary to the end of rows.
  • return rows gives the list of dictionaries back to the caller.

The assert lines are checks. assert followed by a condition does nothing if the condition is true, and stops the program with an error if it is false. A file made only of functions and asserts is a test file. You save it as, for example, test.py and run it with python test.py. On Windows the command is sometimes py test.py. If the run prints nothing, every assert passed. If it prints an AssertionError, one check failed and the message points to the line.

Key fact: Every test file in this chapter works the same way

The block defines the functions, then checks them with assert. Nothing needs a file, a network or typed input, so the same block can be pasted into any lab and run.

Trap: split keeps empty pieces

"a,,b".split(",") returns ['a', '', 'b'], not ['a', 'b']. Two commas in a row mean an empty field. If a lab says a value may be missing, check for '' after you split.

Converting safely

Everything read from text is a string, even when it looks like a number. "42" and 42 are different values in Python. You cannot add a string to an integer, and "42" == 42 is False. You must convert the text first, using int() for whole numbers and float() for numbers with a decimal point.

A conversion that fails raises an exception. An exception is Python's way of signalling an error that stops the normal flow. For example, int("4.2") raises ValueError because 4.2 is not a whole number. int(None) raises TypeError because None is not text or a number at all. In a lab, a bad value should not crash the whole program. You wrap the conversion in try and except. The code under try runs first. If it raises one of the named exceptions, the code under except runs instead.

Here is the pattern:

def to_int(text):
    try:
        return int(text)
    except (TypeError, ValueError):
        return None

When you call to_int("42"), int succeeds and the function returns 42. When you call to_int("4.2"), int raises ValueError, the except line catches it, and the function returns None. None is Python's word for "no value". The round brackets around TypeError and ValueError mean "catch either of these".

float() has its own traps. It accepts "nan", which means "not a number", and "inf", which means infinity. Both are valid floats, and both can silently break an average. nan has one strange property: it is not equal to itself. So value != value is True only when value is nan. The test block below uses that property to reject it.

Another trap is that bool is a subclass of int. A subclass is a more specific kind of a class (a class is a template for a kind of value). In Python, True and False are booleans, and isinstance(True, int) returns True. True even behaves as 1 in arithmetic. A lab that asks you to validate counts must therefore reject True explicitly, because a boolean is not a count. isinstance(x, int) checks whether x is an integer. isinstance(x, bool) checks whether x is a boolean, and and not removes booleans from the accepted set.

def to_int(text):
    try:
        return int(text)
    except (TypeError, ValueError):
        return None

def to_float(text):
    try:
        value = float(text)
    except (TypeError, ValueError):
        return None
    if value != value:
        return None
    return value

def is_count(x):
    return isinstance(x, int) and not isinstance(x, bool)

assert to_int("42") == 42
assert to_int(" 7 ") == 7
assert to_int("4.2") is None
assert to_int("") is None
assert to_int(None) is None
assert to_float("4.5") == 4.5
assert to_float("abc") is None
assert to_float("nan") is None
assert is_count(3) is True
assert is_count(True) is False
assert is_count(3.0) is False

Explanation, line by line:

  • try: opens the block that might fail.
  • return int(text) attempts the conversion and returns the result if it works. A return ends the function at once.
  • except (TypeError, ValueError): lists the two exceptions to catch. Catching only the exceptions you expect is safer than writing a bare except:, which would hide unrelated bugs.
  • return None is the fallback for bad input.
  • In to_float, value != value is the nan check described above. The # symbol is not used here, so no comment is needed.
  • is_count combines two checks with and. Both must be true. isinstance(3.0, int) is False, so a float is rejected as well.
  • The assert to_int(" 7 ") == 7 shows that int ignores surrounding spaces. to_int("4.2") is None shows the failure path. We use is None rather than == None because None is a single shared object and the identity check is the idiomatic test.
Trap: A bool passes an int check

If a validator uses only isinstance(x, int), then True counts as a valid reading of 1. Add and not isinstance(x, bool).

Tip: Say the failure path in the viva

Examiners often ask what your code does with bad input. Answer with the exact fallback, for example "it returns None and the caller skips the row", rather than "it handles errors".

Counting and grouping

Counting is the most common task in a graded lab: how many readings per station, how many errors per day, how many stations exceed a limit. The plain-Python tool for this is a dictionary with a counter for each key.

dict.get(key, default) reads a value from a dictionary and returns default if the key is missing. It does not add the key. So counts.get("S1", 0) returns 0 for an unseen station and leaves counts unchanged. The common pattern is to read, add one, and store back:

counts = {}
counts["S1"] = counts.get("S1", 0) + 1

collections is a standard-library module. A module is a file of ready-made code that you load with import. collections offers two tools that remove most of the boilerplate.

Counter takes any iterable (anything you can loop over) and counts how many times each item appears. Counter(["S1", "S2", "S1"]) gives a dictionary-like object with S1 set to 2 and S2 set to 1. Asking for a missing key returns 0 and does not store anything. most_common(n) returns the n most frequent items as a list of pairs.

defaultdict is a dictionary that creates a default value the first time you touch a missing key. You give it a factory function, such as list or int. defaultdict(list) creates an empty list for each new key, so you can call .append without checking whether the key exists. Note that d[key] on a defaultdict creates the key, but d.get(key) does not.

Grouping means collecting all values that share a key. The next trace follows one loop step by step. Watch groups change as each pair is read.

The trace is the same loop you would write in a lab. Line 2 creates the data, line 3 creates the empty grouping, and lines 4 and 5 repeat for each pair. The line numbers in the trace count the lines of the code block above, starting at 1 for the from collections line.

from collections import Counter, defaultdict

def group_by_station(readings):
    groups = defaultdict(list)
    for station, pm25 in readings:
        groups[station].append(pm25)
    return dict(groups)

def count_stations(readings):
    return Counter(station for station, _ in readings)

readings = [("S1", 42), ("S2", 17), ("S1", 55)]
assert group_by_station(readings) == {"S1": [42, 55], "S2": [17]}
assert group_by_station([]) == {}
assert count_stations(readings) == Counter({"S1": 2, "S2": 1})
assert count_stations(readings)["S9"] == 0

d = {}
assert d.get("S1", 0) == 0
assert d == {}
d["S1"] = d.get("S1", 0) + 1
assert d == {"S1": 1}
assert Counter("aab").most_common(1) == [("a", 2)]

Explanation, line by line:

  • from collections import Counter, defaultdict loads two named tools from the module. Without this line the names would not exist.
  • groups = defaultdict(list) creates the grouping dictionary with empty lists as the default.
  • for station, pm25 in readings: unpacks each pair into two names. Python allows this because a pair is a tuple of two items.
  • groups[station].append(pm25) finds or creates the list for the station and adds the value.
  • return dict(groups) converts the defaultdict to an ordinary dictionary. This is a tidy habit, because a plain dictionary raises KeyError on a missing key instead of silently creating one.
  • Counter(station for station, _ in readings) is a generator expression. It produces each station name in turn and passes them to Counter. The underscore _ is a conventional name for a value you do not need.
  • count_stations(readings)["S9"] == 0 shows that a missing key in a Counter returns 0.
  • The d.get lines show that reading with get does not change the dictionary.
  • most_common(1) returns a list with one pair, the most frequent item and its count.
Trap: get does not store

d.get("S1", 0) returns 0 and leaves d empty. Only the assignment d["S1"] = ... adds a key. Forgetting this makes a count stay at zero.

Key fact: Grouping is two steps

Create the container once, then loop and add to it. Keep the two steps separate in your head and the code will be short and correct.

Best, worst and ties

Ranking is common in labs: the station with the highest reading, the lowest, the top three. Python's max and min take an iterable and return the largest or smallest item. For records (dictionaries or pairs) you must tell Python what to compare. You do that with the key argument, which is a function that returns the value to compare. lambda is a short way to write such a function inside a single expression. lambda r: r["pm25"] means "a function that takes r and returns r["pm25"]".

A tie happens when two items have the same key. max and min return the first matching item in the list order. This is deterministic, but it can be wrong for a report that should break ties by name. sorted is more useful. It returns a new sorted list and leaves the original alone. Python's sort is stable, which means items with equal keys keep their original order. To make the order fully predictable, use a tuple key: a tuple of two or more values compared one after another. The first element decides the order. If it is equal, the second element decides.

For "highest reading first, ties by station name", you negate the number so that a larger value sorts earlier, then add the name:

rows = [{"station": "S3", "pm25": 42}, {"station": "S1", "pm25": 42}]
ranked = sorted(rows, key=lambda r: (-r["pm25"], r["station"]))

-r["pm25"] makes 42 sort before 9, because the sort is ascending. Among the two rows with 42, the names decide. S1 comes before S3.

def ranked(rows):
    return sorted(rows, key=lambda r: (-r["pm25"], r["station"]))

def worst_station(rows):
    if not rows:
        return None
    return ranked(rows)[0]["station"]

def best_station(rows):
    if not rows:
        return None
    return min(rows, key=lambda r: (r["pm25"], r["station"]))["station"]

rows = [
    {"station": "S2", "pm25": 17},
    {"station": "S1", "pm25": 42},
    {"station": "S3", "pm25": 42},
    {"station": "S4", "pm25": 9},
]
assert [r["station"] for r in ranked(rows)] == ["S1", "S3", "S2", "S4"]
assert worst_station(rows) == "S1"
assert best_station(rows) == "S4"
assert worst_station([]) is None
assert best_station([]) is None
assert max([3, 9, 9], key=lambda x: x) == 9

Explanation, line by line:

  • def ranked(rows): defines the ranking function, which returns a new sorted list. The original rows is not changed.
  • key=lambda r: (-r["pm25"], r["station"]) builds a tuple for each row. The minus sign makes higher readings come first. The name breaks ties alphabetically.
  • ranked(rows)[0]["station"] calls ranked, takes the first row (position 0), and reads its station name.
  • min(rows, key=lambda r: (r["pm25"], r["station"])) finds the smallest tuple. Lowest reading wins, and among equal readings, the alphabetically earliest name wins.
  • The if not rows: return None guard handles an empty list. max and min raise ValueError on an empty list if no default is given, so the guard prevents a crash.
  • The last assert shows that max returns the first item with the largest key when two are equal, here 9 (the values are numbers, so there is no visible difference).
Trap: Ties are decided by your key, not by the file

A stable sort keeps file order for equal keys. But if the key includes the name, the name decides and the file order is irrelevant. Write the key you want, rather than hoping the file is in the right order.

Statistics by hand

Labs ask for averages, medians and spreads. The statistics module in the standard library has these, and you may use it to check your work. In a graded lab, however, you often write them yourself, because the problem asks for a specific rule, such as which values count as the middle of an even-length list.

The mean is the sum divided by the count. sum(values) adds the numbers and len(values) counts them. Dividing by zero raises ZeroDivisionError, so an empty list must be handled first.

The median is the middle value after sorting. For an odd count, there is one middle value at index n // 2. The // operator is integer division, which drops the remainder. For 5 items, 5 // 2 is 2, which is the third item because counting starts at 0. For an even count, there are two middle values. The median is their average. For 4 items, the middle values are at indexes 1 and 2, and the median is the average of the second and third sorted items.

The nearest-rank percentile picks an actual value from the data. For percentile p and n values, the rank is ceil(p * n / 100), where ceil rounds up to the next whole number. The rank is counted from 1, so the value is at index rank - 1. For p = 0 the rank is 0, which is not a valid position, so the rank must be raised to 1.

The population standard deviation measures how spread out the values are. For each value, subtract the mean and square the result. Average these squares, then take the square root. The word "population" means you divide by n. A sample standard deviation divides by n - 1 instead, and the statistics module names these pstdev (population) and stdev (sample) respectively. Read the lab's wording and use the one it asks for.

import math
import statistics

def mean(values):
    if not values:
        raise ValueError("mean of empty list")
    return sum(values) / len(values)

def median(values):
    if not values:
        raise ValueError("median of empty list")
    s = sorted(values)
    n = len(s)
    mid = n // 2
    if n % 2 == 1:
        return s[mid]
    return (s[mid - 1] + s[mid]) / 2

def percentile_nearest_rank(values, p):
    s = sorted(values)
    n = len(s)
    rank = math.ceil(p * n / 100)
    rank = max(1, min(n, rank))
    return s[rank - 1]

def pstdev(values):
    m = mean(values)
    return math.sqrt(sum((x - m) ** 2 for x in values) / len(values))

assert median([5, 1, 3]) == 3
assert median([4, 1, 3, 2]) == 2.5
assert median([7]) == 7
assert median([10, 20]) == 15.0
assert median([4, 1, 3, 2]) == statistics.median([4, 1, 3, 2])
assert percentile_nearest_rank([15, 20, 35, 40, 50], 40) == 20
assert percentile_nearest_rank([15, 20, 35, 40, 50], 50) == 35
assert percentile_nearest_rank([15, 20, 35, 40, 50], 100) == 50
assert percentile_nearest_rank([15, 20, 35, 40, 50], 0) == 15
assert mean([1, 2, 3, 4]) == 2.5
assert pstdev([2, 4, 4, 4, 5, 5, 7, 9]) == 2.0

raised = False
try:
    median([])
except ValueError:
    raised = True
assert raised

Explanation, line by line:

  • import math loads the maths module, which gives ceil and sqrt. import statistics loads the module used only for a cross-check.
  • if not values: raise ValueError(...) stops the function with a clear error on empty input. raise is the keyword that starts an exception on purpose.
  • s = sorted(values) makes a sorted copy. The original list is unchanged.
  • mid = n // 2 gives the index of the upper middle value.
  • if n % 2 == 1: tests for an odd count. The % operator gives the remainder after division, so n % 2 is 1 when n is odd.
  • return (s[mid - 1] + s[mid]) / 2 averages the two middle values for an even count.
  • In percentile_nearest_rank, p * n / 100 is the exact position. max(1, min(n, rank)) keeps the rank between 1 and n, which handles both p = 0 and p = 100 safely.
  • In pstdev, (x - m) ** 2 squares each difference. ** is the power operator. The generator expression inside sum adds the squares.
  • The try block at the end shows how to check that a function raises an error. The raised flag is set only if the except branch runs.

The next trace follows the even-length median. Each step changes one name, so you can see why the answer is 2.5 and not 3.

Trap: Taking the middle index for an even count

s[n // 2] is 3 for [1, 2, 3, 4], which is the upper middle only. The median of an even-length list is the average of both middle values.

Key fact: Sort before you pick the middle

Median and percentile both depend on sorted order. Forgetting sorted gives a plausible number that is wrong.

Rounding and float traps

Computers store decimal numbers in binary, and many decimals cannot be written exactly in binary. The result is that 0.1 + 0.2 gives 0.30000000000000004, not 0.3. This is not a Python bug. It is how floating-point numbers work, and it affects every language that uses them.

Two consequences matter in labs. First, do not compare floats with == when a calculation is involved. Use math.isclose(a, b), which returns True when the two numbers differ by only a tiny relative amount, or check abs(a - b) < 1e-9, where 1e-9 is the scientific notation for 0.000000001. Second, when a lab asks for money or exact decimals, use decimal.Decimal with values written as text, such as Decimal("0.1"). Decimals store the digits you wrote.

round(x, n) rounds to n decimal places. Python uses banker's rounding, also called round-half-to-even. When a number is exactly halfway, Python rounds to the nearest even digit. So round(2.5) is 2 and round(3.5) is 4. This surprises people who expect school rounding, where 2.5 becomes 3. For the number 2.675, the binary value is slightly below the halfway point, so round(2.675, 2) gives 2.67. Read the lab's rounding rule and check it against an example before you write the code.

Rounding is for display and final answers. Do not round in the middle of a calculation, because the error grows with each step.

import math
from decimal import Decimal

def average_pm25(values, places=1):
    if not values:
        return None
    return round(sum(values) / len(values), places)

assert round(2.5) == 2
assert round(3.5) == 4
assert round(0.125, 2) == 0.12
assert round(2.675, 2) == 2.67
assert 0.1 + 0.2 != 0.3
assert math.isclose(0.1 + 0.2, 0.3)
assert abs((0.1 + 0.2) - 0.3) < 1e-9
assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
assert average_pm25([42, 17, 55]) == 38.0
assert average_pm25([1, 2]) == 1.5
assert average_pm25([]) is None

Explanation, line by line:

  • from decimal import Decimal loads the exact decimal type. Only the name Decimal is imported.
  • round(sum(values) / len(values), places) computes the mean, then rounds it to places decimal places. places=1 is a default argument, which means the caller can leave it out.
  • round(2.5) == 2 shows round-half-to-even on an exact halfway value.
  • round(0.125, 2) == 0.12 is another halfway case. 0.125 is stored exactly in binary, so the rule is clear.
  • round(2.675, 2) == 2.67 is the surprise case. The stored value is just below 2.675, so it rounds down.
  • 0.1 + 0.2 != 0.3 is True, which proves the trap. The next line shows the safe comparison.
  • math.isclose(0.1 + 0.2, 0.3) returns True because the two values are equal to within a tiny relative tolerance.
  • Decimal("0.1") + Decimal("0.2") == Decimal("0.3") is True, because the arithmetic is done in decimal digits. Notice that the numbers are written as strings. Decimal(0.1) would copy the binary error.
Trap: Rounding before you average

If you round each reading to one place and then average, the answer can differ from averaging first and rounding once. Follow the order the lab states.

Dates and times

Timestamps arrive in labs as text, usually in ISO 8601 format. ISO 8601 is an international standard for dates, written from the largest unit to the smallest: 2026-11-11T08:30:00 means 11 November 2026 at 08:30:00. The T separates the date from the time. Because the text sorts correctly as a string, ISO format is the preferred choice in data files.

datetime is a standard-library module with a class of the same name. A class is a template for a kind of value that carries its own functions. datetime.fromisoformat(text) turns the ISO text into a datetime object. That object has attributes such as .year, .month, .day, .hour and .minute. An attribute is a value that belongs to an object, read with a dot and no brackets. .date() is a method that returns just the date part as a date object, without the time. .isoformat() turns a date back into text.

Grouping by day is the common lab task. Convert each timestamp, take its .date(), and use the date text as the dictionary key. The same defaultdict pattern from the counting section applies.

Two traps appear often. Versions of Python before 3.11 cannot read a trailing Z, which means "UTC" (the standard time zone at zero hours offset). Replace Z with +00:00 first. The second trap is comparing a datetime with a date. They are different types, and comparing them raises a TypeError. Convert both sides to the same type.

from collections import defaultdict
from datetime import datetime

def daily_counts(timestamps):
    counts = defaultdict(int)
    for text in timestamps:
        when = datetime.fromisoformat(text)
        counts[when.date().isoformat()] += 1
    return dict(counts)

stamps = ["2026-11-11T08:30:00", "2026-11-11T23:59:59", "2026-11-12T00:00:00"]
assert daily_counts(stamps) == {"2026-11-11": 2, "2026-11-12": 1}
assert daily_counts([]) == {}
assert datetime.fromisoformat("2026-11-11T08:30:00").hour == 8
assert datetime.fromisoformat("2026-11-11T08:30:00").date().isoformat() == "2026-11-11"
assert datetime.fromisoformat("2026-11-11T23:59:59") < datetime.fromisoformat("2026-11-12T00:00:00")

Explanation, line by line:

  • counts = defaultdict(int) creates a dictionary whose missing values start at 0, because int() returns 0. This is ideal for counting.
  • for text in timestamps: handles one string at a time.
  • when = datetime.fromisoformat(text) converts the text. If the text is invalid, this raises ValueError.
  • counts[when.date().isoformat()] += 1 builds the day key, such as "2026-11-11", and adds one to its count. The += operator means "add to the existing value".
  • The first assert shows that 23:59:59 belongs to the 11th and 00:00:00 on the 12th.
  • The final assert shows that datetime objects can be compared with < because they are ordered by time.
Trap: A trailing Z in older Python

In Python before 3.11, datetime.fromisoformat("2026-11-11T08:30:00Z") raises ValueError. Replace the Z with +00:00 before you parse.

Regular expressions

A regular expression (often shortened to regex) is a pattern that describes text. Labs use them to pull station ids out of a sentence, to check that a value looks like a number, or to clean up stray spaces. Python's re module runs them. In a pattern, most characters match themselves, so S matches the letter S. Special symbols have jobs:

  • \d matches one digit from 0 to 9. \s matches one whitespace character. \w matches a letter, digit or underscore.
  • [0-9] is a character class: it matches one character from the set written inside the square brackets. [jf] matches j or f.
  • ^ matches the start of the string, and $ matches the end.
  • * means zero or more of the previous item, + means one or more, and ? means zero or one. {1,3} means between one and three.
  • (...) is a group. It captures the matched text so you can read it back with .group(1), where group 1 is the first pair of brackets.

Write patterns as raw strings, with a letter r before the opening quote, such as r"\d+". Without the r, Python reads \d as an escape sequence and may fail or change the text. Raw strings keep the backslash as typed.

Four functions do most of the work. re.search(pattern, text) finds the first match anywhere in the text and returns a match object, or None. re.fullmatch(pattern, text) succeeds only if the pattern matches the whole string. re.findall(pattern, text) returns a list of every match. re.sub(pattern, replacement, text) replaces every match with the replacement text.

The most common error is using search when the lab wants a whole-string check. search("\d+", "42a") succeeds because it finds 42 inside the string. fullmatch returns None because a is left over.

import re

def station_ids(text):
    return re.findall(r"S\d+", text)

def valid_pm25(text):
    return re.fullmatch(r"\d{1,3}(\.\d+)?", text) is not None

def parse_reading(line):
    m = re.fullmatch(r"(S\d+)\s*:\s*(\d+(?:\.\d+)?)", line.strip())
    if m is None:
        return None
    return m.group(1), float(m.group(2))

def clean_spaces(text):
    return re.sub(r"\s+", " ", text).strip()

assert station_ids("S1 read 42, S12 read 7") == ["S1", "S12"]
assert valid_pm25("42") is True
assert valid_pm25("42.5") is True
assert valid_pm25("42a") is False
assert valid_pm25("") is False
assert parse_reading("S1: 42.5") == ("S1", 42.5)
assert parse_reading("  S7:3 ") == ("S7", 3.0)
assert parse_reading("S1 42") is None
assert clean_spaces("  a   b\tc \n") == "a b c"
assert re.search(r"^S\d", "S1 ok") is not None
assert re.search(r"^S\d", "xS1") is None
assert re.findall(r"(S)(\d)", "S1S2") == [("S", "1"), ("S", "2")]
assert re.sub(r"\d", "#", "a1b22") == "a#b##"

Explanation, line by line:

  • re.findall(r"S\d+", text) finds every S followed by one or more digits. The \d+ takes as many digits as it can, so S12 is one match, not S1 and 2.
  • re.fullmatch(r"\d{1,3}(\.\d+)?", text) requires the whole string to be one to three digits, with an optional decimal part. The (\.\d+)? group is optional because of the trailing ?. The \. is a literal full stop, because a bare . matches any character.
  • is not None turns the match object into True or False. A match object is always true in an if, but the test returns a clean boolean.
  • In parse_reading, the pattern has two groups. Group 1 is the station id, and group 2 is the number. \s* allows zero or more spaces around the colon.
  • (?:\.\d+)? is a group that does not capture. The ?: prefix tells Python not to store it, which is why m.group(2) is the whole number.
  • float(m.group(2)) converts the captured text to a number.
  • clean_spaces replaces any run of whitespace with one space, then removes ends with strip.
  • re.findall(r"(S)(\d)", "S1S2") returns tuples, because the pattern has groups. Without groups, findall returns plain strings.
  • re.sub(r"\d", "#", "a1b22") replaces each digit separately, so 22 becomes ##.
Trap: search is not fullmatch

If the lab says "the whole value must be a number", use fullmatch. search would accept "x42y" and call it valid.

Tip: Test with your own examples

Before you trust a pattern, run it on one good input and one bad input. Name both in your viva answer.

JSON

JSON stands for JavaScript Object Notation. It is a text format for nested data: objects in curly brackets with string keys, arrays in square brackets, and values that are strings, numbers, true, false or null. Many APIs and data exports send JSON. Python's json module converts between JSON text and Python values.

json.loads(text) reads a JSON string and returns Python values. The s in the name stands for "string". json.dumps(value) does the reverse and returns a string. Two options help you produce predictable output. sort_keys=True writes the keys in alphabetical order, so the output is the same every run. indent=2 puts each item on its own line, indented by two spaces, which is easier to read.

JSON true, false and null become Python True, False and None. JSON objects become dictionaries, and arrays become lists.

Nested data means dictionaries inside dictionaries. To read payload["station"]["name"], Python looks up "station" first, then "name" inside it. If either key is missing, the square-bracket form raises KeyError. The get method returns None instead. You can chain get calls, but only if each step returns a dictionary. If a value is null in the JSON, it is None, and calling .get on None raises AttributeError. The or {} pattern handles that case.

import json

def station_name(payload):
    station = payload.get("station") or {}
    return station.get("name")

def pm25_from_json(text):
    data = json.loads(text)
    reading = data.get("reading") or {}
    return reading.get("pm25")

doc = '{"station": {"name": "Jayanagar", "id": "S1"}, "reading": {"pm25": 42}}'
assert station_name(json.loads(doc)) == "Jayanagar"
assert station_name({}) is None
assert station_name({"station": None}) is None
assert pm25_from_json(doc) == 42
assert pm25_from_json('{"reading": null}') is None
assert json.loads('{"ok": true, "x": null}') == {"ok": True, "x": None}
out = json.dumps({"b": 1, "a": [1, 2]}, sort_keys=True)
assert out == '{"a": [1, 2], "b": 1}'
assert json.loads(out)["a"] == [1, 2]

Explanation, line by line:

  • station = payload.get("station") or {} gets the station value. If it is missing or None, the or falls through to an empty dictionary. or returns its first true-like value, and an empty dictionary is false.
  • return station.get("name") returns the name or None.
  • data = json.loads(text) turns the JSON text into a dictionary.
  • The doc string is single-quoted so that the double quotes inside the JSON do not end the string early.
  • The assert with {"station": None} shows that the guard covers null as well as a missing key.
  • json.loads('{"ok": true, "x": null}') shows the conversion of true to True and null to None.
  • json.dumps(..., sort_keys=True) puts a before b. The output uses ", " between items and ": " between key and value, which is the default spacing.
Trap: KeyError versus None

payload["reading"]["pm25"] crashes when either key is missing. Use get with an or {} guard when the lab says some fields may be absent.

Wildcards

A wildcard is a pattern with special characters that stand for unknown parts of a name. The fnmatch module checks names against shell-style patterns, the same style you may later use on the command line. In these patterns * means any number of characters, including none. ? means exactly one character. [abc] means one character from the set. Wildcards are simpler than regular expressions and are the right tool for matching file names.

The trap is case. fnmatch.fnmatch compares names in a way that depends on the operating system. On Windows it ignores case, and on Linux it does not. A lab's hidden tests may expect a specific result, so use fnmatch.fnmatchcase, which always compares case exactly. Your code then behaves the same on every machine.

import fnmatch

def pick_files(names, pattern):
    return [n for n in names if fnmatch.fnmatchcase(n, pattern)]

names = ["jan.csv", "feb.csv", "notes.txt", "data1.csv", "data12.csv"]
assert pick_files(names, "*.csv") == ["jan.csv", "feb.csv", "data1.csv", "data12.csv"]
assert pick_files(names, "data?.csv") == ["data1.csv"]
assert pick_files(names, "[jf]*") == ["jan.csv", "feb.csv"]
assert pick_files(names, "*.CSV") == []
assert pick_files([], "*") == []

Explanation, line by line:

  • import fnmatch loads the module.
  • [n for n in names if fnmatch.fnmatchcase(n, pattern)] is a list comprehension. It keeps each name n for which the test is true, and keeps the original order.
  • "*.csv" matches any name ending in .csv. The * takes any text before the dot.
  • "data?.csv" matches data1.csv but not data12.csv, because ? is exactly one character.
  • "[jf]*" matches names that start with j or f.
  • "*.CSV" matches nothing, because the comparison is case-sensitive.
  • An empty list in gives an empty list out, which the last assert checks.
Trap: fnmatch on Windows ignores case

fnmatch.fnmatch("DATA.csv", "*.csv") is True on Windows and False on Linux. Use fnmatchcase when the lab expects one exact answer.

Queues, stacks and heaps

A stack is a collection where you add and remove from the same end. The last item in is the first out, which is called LIFO (last in, first out). A Python list works as a stack: append adds to the end and pop() removes from the end. Stacks appear in lab problems about nested brackets, undo steps and depth-first searches.

A queue is first in, first out (FIFO), like a checkout line. A list can act as a queue, but pop(0) is slow on long lists, because every item must shift one place. collections.deque (pronounced "deck") is a double-ended queue built for this job. append adds to the right end, appendleft adds to the left, popleft removes from the left, and all these operations are fast.

A heap is a structure that always gives you the smallest item quickly. Python's heapq module keeps a list in heap order. heapq.heappush adds an item and heapq.heappop removes the smallest. heapq.nsmallest(k, items) and heapq.nlargest(k, items) return the k smallest or largest items in order, which is the usual way labs ask for the top few stations.

Heaps compare items with <. Tuples compare element by element, so (9, "S4") sorts before (17, "S2"). If two tuples have the same first element, Python compares the second. This gives a clean tie-break, as long as the second elements can be compared with each other. Mixing a number and a string in the same position raises TypeError.

from collections import deque
import heapq

def balanced(brackets):
    stack = []
    pairs = {")": "(", "]": "["}
    for ch in brackets:
        if ch in "([":
            stack.append(ch)
        elif ch in ")]":
            if not stack or stack[-1] != pairs[ch]:
                return False
            stack.pop()
    return not stack

def process_order(items):
    q = deque(items)
    out = []
    while q:
        out.append(q.popleft())
    return out

def lowest_readings(pairs, k):
    return heapq.nsmallest(k, pairs)

assert balanced("([])") is True
assert balanced("(]") is False
assert balanced("(()") is False
assert balanced("") is True
assert balanced(")(") is False
assert process_order([1, 2, 3]) == [1, 2, 3]
assert process_order([]) == []
assert lowest_readings([(42, "S1"), (9, "S4"), (42, "S3"), (17, "S2")], 2) == [(9, "S4"), (17, "S2")]
assert lowest_readings([(5, "S1")], 3) == [(5, "S1")]

s = []
s.append(1)
s.append(2)
assert s.pop() == 2
d = deque([1])
d.appendleft(0)
assert list(d) == [0, 1]

Explanation, line by line:

  • stack = [] creates an empty list to use as a stack.
  • pairs = {")": "(", "]": "["} maps each closing bracket to the opening bracket it must match.
  • for ch in brackets: reads one character at a time. A character is a string of length one.
  • if ch in "([": checks whether the character is an opener. in on a string asks whether the character is one of the characters in it.
  • stack.append(ch) pushes the opener.
  • if not stack or stack[-1] != pairs[ch]: fails when there is nothing to match, or when the most recent opener is the wrong kind. stack[-1] means "the last item".
  • stack.pop() removes the matched opener.
  • return not stack is true only if no openers are left over.
  • In process_order, deque(items) builds a queue from the list. q.popleft() removes items in the order they arrived.
  • heapq.nsmallest(k, pairs) returns the k smallest tuples. The first elements are readings, so the lowest readings come first. For the equal readings of 42, the names are compared, but the k=2 result does not need them.
  • The s and d lines show the operations used in the explanations above.
Trap: A stack that never empties

balanced("(()") must return False. A common mistake is to check only that every closer matches, and forget the openers left over at the end.

SQL from Python

SQL (Structured Query Language) is the standard language for asking questions of a database. A database stores data in tables, which are grids of rows and columns. The sqlite3 module in Python's standard library runs SQLite, a small database that needs no server. sqlite3.connect(":memory:") creates a database that lives only in RAM and disappears when the connection closes. This is ideal for labs and tests.

A connection is the link to the database. conn.execute(sql) runs one SQL statement and returns a cursor, which is an object that gives you the results. fetchall() reads all the result rows at once as a list of tuples. For one row with two columns, you get something like [("S1", 42.0)].

For inserting many rows, executemany runs the same statement once per item in a list. The statement uses ? placeholders. Each ? is replaced by the next value in the tuple. Always use placeholders rather than building the SQL with string formatting. Placeholders stop quotation marks in the data from changing the statement, a problem called SQL injection. The apostrophe in a name such as O'Brien is an example.

conn.commit() saves pending changes. For an in-memory database, the data is lost anyway when the connection closes, but a lab may use a file database, so get into the habit of committing. conn.close() releases the connection.

import sqlite3

def average_by_station(rows):
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE readings (station TEXT, pm25 REAL)")
    conn.executemany("INSERT INTO readings (station, pm25) VALUES (?, ?)", rows)
    conn.commit()
    result = conn.execute(
        "SELECT station, AVG(pm25) FROM readings GROUP BY station ORDER BY station"
    ).fetchall()
    conn.close()
    return result

rows = [("S1", 40), ("S2", 17), ("S1", 44)]
assert average_by_station(rows) == [("S1", 42.0), ("S2", 17.0)]
assert average_by_station([]) == []

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE t (name TEXT)")
conn.execute("INSERT INTO t VALUES (?)", ("O'Brien",))
assert conn.execute("SELECT name FROM t").fetchall() == [("O'Brien",)]
conn.close()

Explanation, line by line:

  • conn = sqlite3.connect(":memory:") opens a new in-memory database.
  • CREATE TABLE readings (station TEXT, pm25 REAL) creates a table with a text column called station and a real-number column called pm25. SQL keywords such as CREATE are conventionally written in capitals, but SQL does not require it.
  • executemany(..., rows) inserts every tuple in rows. Each tuple fills the two ? placeholders in order.
  • SELECT station, AVG(pm25) FROM readings GROUP BY station ORDER BY station asks for each station and the average of its readings. GROUP BY collects the rows by station, AVG is the average function, and ORDER BY sorts the output.
  • .fetchall() returns a list of tuples, one per station. The averages are 42.0 and 17.0 because the column type is real.
  • if no rows are inserted, GROUP BY produces no groups, so the result is an empty list. The second assert checks this.
  • The O'Brien example shows that the placeholder keeps the apostrophe as data. It does not end the SQL statement early.
Trap: fetchall returns tuples

fetchall() returns [("S1",)], not ["S1"], even when you select only one column. Use rows[0][0] to reach the value.

Key fact: Placeholders, always

Write ? in the SQL and pass the values as a second argument. Never paste user or file text into the SQL string.
