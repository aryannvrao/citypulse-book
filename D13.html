The idea in one minute

Today you learn to store files in the cloud and reach them from Python. Amazon Web Services (AWS) rents out computers and storage over the internet. Its file store is called Amazon S3 (Simple Storage Service). S3 keeps files as objects inside buckets, which are named containers. Every object has a key, which is its full name inside the bucket.

You will do three things. You will lock a bucket so that nobody outside can read it, encrypt it, and keep old copies of changed files. You will upload CityPulse air-quality data under date-based keys. You will write a short Python script that does the upload and reports failures correctly.

Think of a bucket as a warehouse and the key as the shelf label printed on each box. A tidy label scheme means you can find the box for one day without opening every box in the building.

Starting from zero

Terminal. The terminal is a text window where you type commands and the computer prints text back. A command is one line you type, such as ls, which lists the files in a folder. Use Git Bash, a terminal that understands the Bash language of commands. Git Bash is installed with Git for Windows. Use it instead of PowerShell for every command in this chapter, because the examples use single quotes and $ variables, which PowerShell reads differently.

File, folder and path. A file holds data such as text, numbers or an image. A folder holds files and other folders. A path is the address of a file, for example data/clean/aq_clean.parquet. Parquet is a compressed table format. It stores each column together, so a reader can skip the columns it does not need.

Variable and function. A variable is a name that holds a value, such as bucket = "citypulse-x7k2q9". A function is a named block of code that takes inputs and returns a result. In len("abc"), len is the function and "abc" is the input it works on.

Script and module. A script is a text file of Python code that you run with python filename.py. A module is a Python file that another program loads with import, as in import boto3.

Server and cloud. A server is a computer that answers requests from other programs. The cloud means that the servers belong to a provider such as AWS, and you rent parts of them over the internet.

Bucket, object, key and prefix. A bucket is a container with a name that is unique across the whole of AWS. An object is one stored file together with its metadata, which are extra facts such as size and content type. The key is the object's full name, for example clean/aqi/date=2026-12-17/aq_clean.parquet. A prefix is the start of a key, such as clean/aqi/. S3 has no real folders. The slashes only look like folders in the AWS web console.

API and SDK. An API (Application Programming Interface) is a list of named operations that a program can call, such as "store this file under this key". An SDK (Software Development Kit) is a library that gives you those operations in one language. boto3 is the SDK for Python. You install it with pip install boto3, where pip is the Python package installer.

HTTP and status codes. HTTP (Hypertext Transfer Protocol) is the message format that browsers and tools use to talk to web servers. Every reply carries a three-digit status code. 200 means success, 403 means the request is refused, and 404 means the thing was not found.

Credentials, profile and environment variable. Credentials are secret values that prove who you are to AWS. A profile is a named set of credentials stored in a file on your computer, such as citypulse-pipeline. An environment variable is a named setting that the shell passes to every program it starts. You set one with export NAME=value.

Region. A region is one AWS data-centre area. This course uses ap-south-1, which is the Mumbai region.

Exception and exit code. An exception is an error that Python raises while a program runs. A ClientError is the exception that boto3 raises when AWS refuses a request. The exit code is the number a program hands back to the shell when it stops. Zero means success and any other number means failure. In Bash, echo $? prints the exit code of the last command.

The tools

Amazon S3 buckets and partitioning

What it is. S3 stores objects in buckets. An object can be any size up to 5 TB, and you pay for the bytes you keep and the requests you make. CityPulse uses S3 for clean data because the virtual machine you build on Day 14 (ticket T19) and the Lambda function (a small program that AWS runs when an event happens) in a later day must write to it, and analysts must read it from anywhere.

Why not the alternatives. An EBS volume is a virtual disk attached to one virtual machine. Only that machine can use it, and you pay for the size you provision whether you use it or not. Amazon EFS is a shared file system with folder paths. It costs more and is unnecessary for files that are written once and then read. Storing files as database BLOBs (large binary values inside SQL tables) bloats the database and costs far more per gigabyte.

How it works. The CityPulse key layout is clean/<dataset>/date=YYYY-MM-DD/<filename>. The date= part is a naming convention that query tools understand. Because the date is in the key, a reader that asks for the prefix clean/aqi/date=2026-12-17/ gets only that day. This is called partitioning: the data is split into parts by a value that readers filter on.

The date= names are ISO dates. That means year first, then month, then day, all with leading zeros. Text sorted in this order is also in date order, which is why the layout works for listing.

Here is the picture of one reading moving through the system. The upload script sends the object, S3 stores it, and a dashboard asks only for one day.

Commands that prove the bucket is set up. Every setting in this chapter can be read back with a get command. The term block below shows how to check versioning. The output shown is the shape you should expect.

aws is the AWS command-line tool. s3api is the group of commands that map one-to-one onto the S3 API. get-bucket-versioning asks for the current versioning setting. --bucket is a flag, which is an option written after the command name. The flag names the bucket, and the value after it is the bucket name. Status is Enabled only after you turn versioning on. The bucket name citypulse-x7k2q9 is an example, and you use your own.

Trap: Listing the whole bucket

Running aws s3 ls s3://bucket with no prefix is denied for the scoped pipeline identity. List s3://bucket/clean/aqi/ instead. Narrow prefixes are also cheaper and faster, because S3 does less work.

Trap: Dates in the wrong order

A key such as date=17-12-2026 does not sort by date, because text sorts by its first characters. Use date=YYYY-MM-DD every time.

Trap: Choosing a bucket name

Bucket names are global and permanent. Add a random suffix, and never put personal data in the name. Once a name exists anywhere in AWS, nobody else can take it.

Encryption and the public-access block

What it is. Three settings keep the bucket safe. Block Public Access is a set of four switches that override any ACL (access control list, a permission list attached to a bucket or object) or bucket policy that would make data public. Default encryption with SSE-S3 (server-side encryption with S3-managed keys) encrypts every new object at rest, meaning while it is stored on disk, using the AES-256 algorithm. Since 2023 AWS applies SSE-S3 to new objects by default, but the course still sets it explicitly so the evidence shows it. Versioning keeps the old copy of an object when it is overwritten or deleted.

Why not the alternatives. SSE-KMS uses a key from AWS Key Management Service, which gives you a log of each use of the key. It adds cost and permissions work, so it is worth it only for sensitive data. Client-side encryption means your code encrypts the file before upload. It is the strongest option, but then you manage the keys, and S3 cannot read the data. A bucket policy that denies public access also works, but Block Public Access is simpler and overrides mistakes made elsewhere.

How it works. The three settings are bucket settings, so the admin profile sets them once. The pipeline profile never does this. The commands use the flags --bucket and --versioning-configuration, and the values are written as Name=Value pairs.

B=citypulse-x7k2q9
export AWS_PROFILE=<admin-profile> AWS_REGION=ap-south-1
aws s3api put-public-access-block --bucket "$B" --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api put-bucket-encryption --bucket "$B" --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
aws s3api put-bucket-versioning --bucket "$B" --versioning-configuration Status=Enabled

Line 1 stores the bucket name in the variable B. The shell replaces $B with the value everywhere it appears, and the quotes around "$B" stop a name with odd characters from splitting into two words. Line 2 sets two environment variables. AWS_PROFILE picks the credentials, and AWS_REGION picks the region. Replace <admin-profile> with the name of the admin profile from your setup. Line 3 turns on all four Block Public Access switches. Each value is true, and the list is separated by commas with no spaces. Line 4 sets default encryption. The argument is a JSON text in single quotes. JSON is a text format for nested data made of braces, brackets and quoted keys. The rule says that every new object gets AES256. Line 5 turns versioning on. Nothing is printed when a put command works, so you check the result with the get commands in the evidence step.

{ aws s3api get-public-access-block --bucket "$B"
  aws s3api get-bucket-encryption --bucket "$B"
  aws s3api get-bucket-versioning --bucket "$B"; } > docs/evidence/T18-bucket-settings.txt
curl -s -o /dev/null -w '%{http_code}\n' "https://$B.s3.ap-south-1.amazonaws.com/clean/aqi/date=2026-12-17/aq_clean.parquet"

The braces group three commands so their output goes into one file with >. The > symbol writes the output to a file and replaces any earlier content. curl is a tool that sends an HTTP request from the terminal. -s hides the progress meter. -o /dev/null throws the body away. -w '%{http_code}\n' prints only the status code, followed by a new line. The URL is the object's address on the internet. You are not signed in, so the expected output is 403. That is the proof that the bucket refuses the public.

Trap: Trusting a 404 as proof

A 404 means the object was not found, which proves nothing about privacy. Test an object that exists. For a private bucket, the answer must be 403.

Trap: Pipeline profile with bucket settings

Running the put- commands with the pipeline profile gives AccessDenied. Bucket configuration is an admin task, and the pipeline is deliberately not allowed to change it.

Trap: Versioning without a cleanup rule

Versioning keeps every old copy, so storage grows forever unless you expire old copies. Apply the seven-day expiry of noncurrent versions in the lifecycle file, covered in the worked example.

The boto3 SDK

What it is. boto3 is the official AWS SDK for Python. It finds credentials for you, signs each request so AWS can check it, and exposes every AWS operation as a Python method. When AWS refuses a call, boto3 raises botocore.exceptions.ClientError. botocore is the library underneath boto3 that does the low-level work.

Why not the alternatives. The AWS CLI from Bash is excellent for one-off commands and evidence, but it is harder to test from Python and harder to turn into a clean exit code. s3fs and fsspec make S3 look like a file system for pandas. They are convenient, but they hide errors and add dependencies. Raw HTTPS requests are possible, but you would have to rebuild SigV4, which is the AWS request-signing method, yourself. boto3 avoids all three problems.

How it works. When you call boto3.client("s3"), boto3 looks for credentials in a fixed order. It checks environment variables first, then the profile named by AWS_PROFILE in the shared config files, and then the role of the machine (an instance role on EC2). This is the credential chain. The same code therefore runs on your laptop with a profile and on a cloud machine with a role, and no key appears in the code.

The slide code is src/citypulse/upload.py. Every line is explained below.

import argparse, datetime, os, pathlib, sys
import boto3
from botocore.exceptions import ClientError


def object_key(dataset: str, day: datetime.date, filename: str) -> str:
    return f"clean/{dataset}/date={day.isoformat()}/{filename}"


def main() -> int:
    p = argparse.ArgumentParser()
    for flag in ("--src", "--dataset", "--date"):
        p.add_argument(flag, required=True)
    a = p.parse_args()
    src, bucket = pathlib.Path(a.src), os.environ["CITYPULSE_BUCKET"]
    key = object_key(a.dataset, datetime.date.fromisoformat(a.date), src.name)
    try:
        boto3.client("s3").put_object(Bucket=bucket, Key=key, Body=src.read_bytes())
    except ClientError as e:
        print(f"upload failed: {e}", file=sys.stderr)
        return 1
    print(f"uploaded s3://{bucket}/{key}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
  • import argparse, datetime, os, pathlib, sys loads five standard-library modules. argparse reads command-line flags, datetime handles dates, os reads environment variables, pathlib handles file paths, and sys gives access to the exit mechanism and the error output.
  • import boto3 and from botocore.exceptions import ClientError load the SDK and the one exception class this script handles.
  • def object_key(...) defines a function. Its inputs are a dataset name, a date and a file name. The type hints such as : str and -> str are notes for readers and tools. Python does not enforce them.
  • The return line builds the f-string. An f-string is a string with {...} slots filled in at run time. day.isoformat() turns a date into text such as 2026-12-17.
  • def main() -> int: defines the main function, which returns the exit code.
  • p = argparse.ArgumentParser() creates a parser that will read the command-line flags.
  • The for loop registers --src, --dataset and --date as required flags. Without a required flag, the script stops with a usage message.
  • a = p.parse_args() reads the flags and stores them in a, so a.src is the path you typed after --src.
  • The next line finds the file path with pathlib.Path, reads the bucket name from the CITYPULSE_BUCKET environment variable, and then builds the key. src.name is the file name with the folders removed.
  • try: opens a block that might raise an error. The only error caught is ClientError.
  • put_object(Bucket=..., Key=..., Body=...) sends the bytes of the file to S3 under that key. read_bytes() loads the whole file into memory, which is fine for these small files.
  • except ClientError as e: runs only when AWS refuses the call. It prints the message to sys.stderr, the error channel, and returns 1.
  • The last two lines print the success message and return 0.
  • if __name__ == "__main__": runs main() only when the file is run directly, not when another file imports it. sys.exit(main()) passes the return value to the shell as the exit code.
Trap: Hard-coding the profile

Writing boto3.Session(profile_name="citypulse-pipeline") into the code breaks the EC2 run, where there is no such profile. Let the credential chain read AWS_PROFILE or the instance role.

Trap: The wrong error class

upload_file wraps its errors in S3UploadFailedError, which comes from boto3.exceptions, not from botocore. Catch that class too, or use put_object as the script does.

Trap: Testing by uploading

Calling AWS to test object_key is slow and needs a network. Put the logic in a pure function, which means a function that depends only on its inputs, and unit-test it in tests/test_upload.py with no AWS at all.

Now watch the SDK work through a small Python program. It counts readings per station.

This trace uses a dictionary, which you will need again in the graded lab. The get method returns a default value when the key is missing, instead of raising an error.

The worked example

Goal. Upload the same clean file under two dates and then list both dates with the scoped pipeline profile. This is the workbook's example for the day. It proves that the layout, the credentials and the listing all work together.

Code.

B=citypulse-x7k2q9
export AWS_PROFILE=citypulse-pipeline AWS_REGION=ap-south-1 CITYPULSE_BUCKET="$B"
for d in 2026-12-17 2026-12-18; do
  python -m citypulse.upload --src data/clean/aq_clean.parquet --dataset aqi --date "$d"
done
aws s3 ls "s3://$B/clean/aqi/" --recursive > docs/evidence/T18-ls.txt

Explanation. The first two lines set the bucket name, the credentials and the CITYPULSE_BUCKET variable that upload.py reads. citypulse-pipeline is the scoped profile, which means a profile limited to the clean/ and raw/ prefixes. The for ... in ...; do line starts a loop over the two dates. Each pass sets the variable d to one date. python -m citypulse.upload runs the upload module as a script. --src gives the file to upload, --dataset gives the dataset name, and --date gives the date. The "$d" in quotes passes the current date. done ends the loop. The last line lists everything under clean/aqi/. --recursive lists the objects inside the nested prefixes too, not just the first level. The > symbol saves the listing as evidence.

Output. Each upload prints one line, and the listing prints one line per object. The numbers below are illustrative, because your sizes and times will differ.

The listing shows the two date= prefixes, which is the result you need. The admin then adds a lifecycle rule. The lifecycle file moves old raw data to a cheaper storage class and expires old versions. This is an admin task:

export AWS_PROFILE=<admin-profile>
aws s3api put-bucket-lifecycle-configuration --bucket "$B" --lifecycle-configuration file://infra/storage/lifecycle.json
aws s3api get-bucket-lifecycle-configuration --bucket "$B"

file:// tells the CLI to read the value from a file. The second command prints the rule back so you can save it as evidence. The course's own lifecycle.json is the authority. A rule of the same shape looks like this:

{
  "Rules": [
    {
      "ID": "raw-cheaper-and-expire-old-versions",
      "Status": "Enabled",
      "Filter": {"Prefix": "raw/"},
      "Transitions": [{"Days": 30, "StorageClass": "STANDARD_IA"}],
      "NoncurrentVersionExpiration": {"NoncurrentDays": 7}
    }
  ]
}

Filter limits the rule to keys that start with raw/. Transitions moves the current objects to the STANDARD_IA class after 30 days. NoncurrentVersionExpiration deletes an old version seven days after it stopped being the latest one.

The hands-on lab, step by step

Before you start, make sure src/citypulse/upload.py matches the listing in The tools section. Use Git Bash for every command. Keep the bucket name in a file called docs/evidence/bucket.txt, so you can reuse it.

Step 1 — Create a private, versioned bucket

What you do. Use the admin profile to create the bucket and set its three settings: Block Public Access, default encryption and versioning.

What you type.

export AWS_PROFILE=<admin-profile> AWS_REGION=ap-south-1
B=citypulse-<your-random-suffix>
aws s3api create-bucket --bucket "$B" --create-bucket-configuration LocationConstraint=ap-south-1
aws s3api put-public-access-block --bucket "$B" --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api put-bucket-encryption --bucket "$B" --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
aws s3api put-bucket-versioning --bucket "$B" --versioning-configuration Status=Enabled

The create-bucket line needs LocationConstraint for a region outside us-east-1, which is why it is there. Replace <your-random-suffix> with random letters and digits.

What you should see. create-bucket prints a small JSON block with the bucket's Location, and the other three commands print nothing when they succeed. A failure prints an error with a code such as BucketAlreadyExists. If you see that, pick a different suffix.

How you know it worked. Run aws s3api get-public-access-block --bucket "$B", get-bucket-encryption and get-bucket-versioning. The first shows four true values, the second shows AES256, and the third shows "Status": "Enabled".

Step 2 — Design a date-partitioned key layout

What you do. Write the layout on paper before you upload. The layout is clean/<dataset>/date=YYYY-MM-DD/<filename>, where the dataset for this lab is aqi.

What you type.

python -c "import datetime; print(f'clean/aqi/date={datetime.date(2026,12,17).isoformat()}/aq_clean.parquet')"

python -c runs a line of Python given on the command line instead of a file. The f-string inserts the date, and isoformat() writes it as 2026-12-17.

What you should see. clean/aqi/date=2026-12-17/aq_clean.parquet

How you know it worked. The printed key has exactly one date= part, the date is in year-month-day order, and the file name is the one you intend to upload.

Step 3 — Generate a sample readings file

What you do. Create a small CSV file with three columns. CSV means comma-separated values, a plain text table. The ts column is a time stamp, pollutant names the substance, and value is the reading.

What you type. Create make_sample.py with this content and run it.

import pathlib

rows = [
    "ts,pollutant,value",
    "2026-12-17T06:00:00Z,pm25,41.2",
    "2026-12-17T07:00:00Z,pm25,44.8",
]
pathlib.Path("readings.csv").write_text("\n".join(rows) + "\n")
print("wrote", len(rows) - 1, "rows")

rows is a list of text lines. "\n".join(rows) glues the lines together with a new line between them. write_text writes the result to a file, and the + "\n" adds a final new line. len(rows) - 1 counts the data rows by leaving out the header.

Run it with python make_sample.py.

What you should see. wrote 2 rows

How you know it worked. head readings.csv prints the header and the two data rows. head shows the first lines of a file.

Step 4 — Upload with boto3

What you do. Switch to the scoped pipeline profile and upload the file for two dates.

What you type.

unset AWS_PROFILE
export AWS_PROFILE=citypulse-pipeline AWS_REGION=ap-south-1 CITYPULSE_BUCKET="$B"
python -m citypulse.upload --src readings.csv --dataset aqi --date 2026-12-17
python -m citypulse.upload --src readings.csv --dataset aqi --date 2026-12-18

unset removes a variable from the shell, so the old profile cannot leak through. CITYPULSE_BUCKET is the variable that upload.py reads, and it must be exported for Python to see it. If you forget it, os.environ raises a KeyError.

What you should see. Two lines, uploaded s3://citypulse-<your-suffix>/clean/aqi/date=2026-12-17/readings.csv and the same for 2026-12-18.

How you know it worked. Both lines start with uploaded, and the exit code is 0. Run echo $? straight after the second command and expect 0.

Step 5 — List and read back

What you do. List the objects with the pipeline profile, then read one back from Python.

What you type.

aws s3 ls "s3://$B/clean/aqi/" --recursive

Then create read_back.py:

import os
import boto3

s3 = boto3.client("s3")
obj = s3.get_object(
    Bucket=os.environ["CITYPULSE_BUCKET"],
    Key="clean/aqi/date=2026-12-17/readings.csv",
)
text = obj["Body"].read().decode()
lines = text.splitlines()
print("header:", lines[0])
print("rows:", len(lines) - 1)

get_object fetches the object. obj["Body"] is a stream of bytes, and .read() collects all of them. .decode() turns the bytes into text, and splitlines() splits the text into a list of lines. Line 0 is the header.

What you should see. Two listing lines, each with a date, a time, a size and a key that contains date=. Then header: ts,pollutant,value and rows: 2.

How you know it worked. The listing shows both dates, and the rows count matches the file you generated in Step 3.

Step 6 — Prove versioning works

What you do. Change one value in the sample file, upload it to the same key again, and list the versions with the admin profile.

What you type.

sed -i 's/44.8/45.0/' readings.csv
python -m citypulse.upload --src readings.csv --dataset aqi --date 2026-12-17
export AWS_PROFILE=<admin-profile>
aws s3api list-object-versions --bucket "$B" --prefix clean/aqi/date=2026-12-17/ --query 'Versions[].{Key:Key,VersionId:VersionId,IsLatest:IsLatest}' --output table

sed -i edits a file in place. The expression s/44.8/45.0/ replaces the first 44.8 with 45.0 on each line. --prefix limits the listing to one day. --query uses JMESPath, a small language for picking fields from JSON output, and --output table prints the result as a table.

What you should see. Two rows with the same Key, two different VersionId strings, and IsLatest as True on exactly one row.

How you know it worked. The key appears twice with different version IDs. The old copy was kept, and the new copy is marked as the latest.

Step 7 — Clean up

What you do. Empty the bucket and then delete it. Do this only after you have saved your evidence files, and after your instructor confirms that you no longer need the bucket.

What you type. In a versioned bucket, aws s3 rm --recursive only adds a delete marker, which hides the object but keeps every version. To remove the versions as well, use the AWS web console: open the bucket, choose Empty, type the confirmation text, and then delete the bucket. Then check it from the terminal.

What you should see. aws s3api head-bucket --bucket "$B" prints an error with a code such as 404 or NoSuchBucket.

How you know it worked. The bucket no longer exists, so the error is correct. If you see a success message instead, the bucket still exists and you must empty it again.

Uploading with boto3

What it is. boto3 is the official AWS SDK (Software Development Kit) for Python. An SDK is a library that gives you ready-made functions for one service, so you do not write the web requests yourself. You create a client with boto3.client("s3"). The client finds your credentials on its own through the credential chain, so the code holds no secret. An upload is one call to put_object with three named arguments. Bucket is the bucket name, Key is the object's full name, and Body is the content. Body is normally bytes, so the safe habit is to turn a Python string into bytes with .encode("utf-8") first. The example below needs AWS to run, so read it for its shape only.

import boto3

s3 = boto3.client("s3")
body = "ts,value\n2026-12-17T06:00:00Z,41.2\n".encode("utf-8")
s3.put_object(Bucket="citypulse-x7k2q9", Key="clean/aqi/date=2026-12-17/sample.csv", Body=body)

encode("utf-8") turns the text into bytes, and \n is a new line inside the string. When the upload works, nothing is printed. When AWS refuses it, the call raises ClientError.

How it shows up in a case study. The ingest job runs at 06:00 and uploads the day's readings to clean/aqi/. The team finds that the job reports success, yet no file appears in the bucket. Their script wraps the upload in except Exception: pass, so every failure is hidden and the exit code is 0. The right reasoning is to narrow the handler to the one error the script expects, ClientError, print the message to standard error and return 1. Then the scheduler marks the run as failed, and someone sees it.

Trap: Trusting a quiet success

A broad except that prints nothing makes a refused upload look like a good one. Catch the expected error, report it and return a non-zero code.

The S3 object model

What it is. S3 (Simple Storage Service) keeps three kinds of thing. A bucket is a named container. Its name is unique across the whole of AWS and cannot be changed later. An object is one stored file, which means its bytes plus metadata such as size and content type. A key is the object's full name inside the bucket, and it is one single string. In clean/aqi/date=2026-12-17/aq_clean.parquet the slashes are part of the text. S3 has no real folders. The console shows folder-like views by grouping keys that share a prefix. Because of this, you cannot rename a folder in one step. You must copy each object to its new key and then delete the old one.

How it shows up in a case study. A data engineer wants to rename raw/aqi-old/ to raw/aqi-2026/ for the whole team. In a file system this is one command. The bucket holds about 40,000 keys under the old prefix. The team therefore plans a copy job that lists every key, copies each one to its new name, checks the copies and only then deletes the originals. The reasoning starts from the fact that the key is the whole name, so changing a prefix means changing every key under it.

Trap: Expecting a folder to be an object

The console shows a folder icon, but S3 holds no folder to rename. A single rename call does not exist.

Partitioning keys by date

What it is. Partitioning means splitting data into parts by a value that readers filter on, and writing that value into the key. CityPulse uses date=YYYY-MM-DD. A listing with the prefix clean/aqi/date=2026-12-17/ then returns only the objects for that day, because S3 matches the start of each key. The format matters. ISO dates, which put the year first, then the month, then the day, with leading zeros, sort correctly as plain text.

dates = ["2026-12-10", "2026-12-09", "2027-01-02"]
print(sorted(dates))

The output is ['2026-12-09', '2026-12-10', '2027-01-02'], which is calendar order. The day-first form does not behave this way. The text 01-01-2027 sorts before 17-12-2026, because 0 comes before 1, even though 1 January 2027 is the later date.

How it shows up in a case study. The dashboard team notices that its weekly report lists dates in the wrong order. The first pipeline wrote keys such as clean/aqi/17-12-2026/, and the report sorts those names as text. The fix is to write new uploads with date=YYYY-MM-DD.

Trap: A date that looks right

17-12-2026 looks like a date to a person, but as text it sorts wrongly across years. Use the ISO form every time.

Paginating long listings

What it is. A listing call returns one page of keys, not all of them. list_objects_v2 returns at most 1,000 keys per call. When more keys exist, the response has IsTruncated set to True, and a NextContinuationToken, which is a bookmark for the next call. A paginator hides this loop. s3.get_paginator("list_objects_v2") gives you an object whose paginate method yields one response per page. Each page has KeyCount, the number of keys in that page. Also, when no key matches the prefix, the response has no Contents entry at all, so resp["Contents"] raises KeyError. The safe form is resp.get("Contents", []). The loop below uses plain Python to show the idea. Each dictionary stands for one page.

pages = [{"KeyCount": 2}, {"KeyCount": 1}]
total = 0
for page in pages:
    total += page["KeyCount"]
print(total)

The output is 3. Each pass adds one page's count to the running total.

How it shows up in a case study. The audit job counts the objects under raw/ and reports 1,000 every month, even though the number grows. The job calls list_objects_v2 once and reads the first response. The reasoning is that IsTruncated tells the reader that more pages exist. A paginator, and a total that adds each page's KeyCount, fixes the report.

Trap: Reading only the first page

One call looks correct on a small test bucket and stops at 1,000 keys in production, without an error. Use the paginator.

Presigned URLs

What it is. A presigned URL is a web address that already carries a signature made with the signer's credentials. Anyone who holds the link can open it, even without an AWS account, until the link expires. You create one with generate_presigned_url. The first argument is the operation name, such as "get_object". Params names the bucket and key. ExpiresIn is the lifetime in seconds, so 3600 means one hour. The link carries the rights of the account that signed it, and the signing identity must stay valid.

import boto3

s3 = boto3.client("s3")
url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "citypulse-x7k2q9", "Key": "clean/aqi/date=2026-12-17/aq_clean.parquet"},
    ExpiresIn=3600,
)

The value of url is a long https address, and its query text includes an expiry such as X-Amz-Expires=3600.

How it shows up in a case study. A partner needs one clean file for a week of review, and the admin suggests making the bucket public for a day. The better answer is a presigned link to that one object. It covers one key, and its lifetime is set in seconds, so it stops working by itself. A public bucket exposes every object while it is open, and someone must remember to close it.

Trap: Confusing seconds with minutes

ExpiresIn=60 gives one minute, not one hour. Work out the value in seconds before you run the code.

Lifecycle rules

What it is. A lifecycle configuration is a set of rules that S3 applies in the background, without any code running. A rule has a Filter that limits it to a prefix, such as raw/. A Transitions entry moves current objects to a cheaper storage class after a number of days, such as STANDARD_IA. The object stays in the bucket and can still be read, though reads from the cheaper class cost extra. A NoncurrentVersionExpiration entry deletes old versions a number of days after they stopped being the latest, and it applies only in a versioned bucket. An Expiration entry deletes current objects, so it removes data. S3 applies rules in the background, so an object may move or disappear some time after its day limit.

{"Rules": [{"ID": "raw-cheaper", "Status": "Enabled", "Filter": {"Prefix": "raw/"}, "Transitions": [{"Days": 30, "StorageClass": "STANDARD_IA"}]}]}

How it shows up in a case study. Storage cost has grown since the bucket turned on versioning. Finance asks for the cheapest fix that still keeps every raw file. The reasoning is to move raw/ objects to STANDARD_IA after 30 days, which keeps the data, and to expire noncurrent versions after 7 days, which removes only the old copies. The team does not add an expiration rule for current raw data, because that would delete the files they must keep.

Trap: Expiration is not transition

An expiration rule for current objects deletes them. A transition only changes the storage class, and the data stays.

Handling boto3 errors

What it is. When AWS refuses a call, boto3 raises botocore.exceptions.ClientError. An exception is an error that Python raises while the program runs, and try and except catch it. The error details are in the response dictionary of the exception object. The error code is at e.response["Error"]["Code"], for example AccessDenied, NoSuchKey or NoSuchBucket. The message is at e.response["Error"]["Message"]. The example below builds a ClientError by hand, so it runs without AWS.

from botocore.exceptions import ClientError

try:
    raise ClientError({"Error": {"Code": "AccessDenied", "Message": "Access Denied"}}, "PutObject")
except ClientError as e:
    print("code:", e.response["Error"]["Code"])

The output is code: AccessDenied. A good handler catches only the error type it expects, prints the message to standard error, and returns a non-zero exit code.

How it shows up in a case study. A nightly job logs "upload failed" for every run, but the team cannot see why. The job prints only a short message and returns 0 at the end, so the scheduler marks every run as successful. The reasoning is that the error code tells you the cause. AccessDenied points to permissions, and NoSuchBucket points to the bucket name in the configuration. The fix is to catch ClientError only, print the error and return 1.

Trap: Catching everything

A broad except that returns success hides every failure, including bugs in your own code. Catch the error you expect.

Encryption at rest

What it is. Encryption at rest means the data is encrypted while it is stored. Default encryption with SSE-S3 (server-side encryption with S3-managed keys) makes S3 encrypt every new object with AES-256, using keys that AWS manages. You set it once on the bucket, and your code needs no change. When a reader asks for an object, S3 decrypts it for any identity that is allowed to read it. Encryption at rest is therefore not access control. Access is controlled by bucket permissions and by Block Public Access. SSE-KMS uses a key from AWS Key Management Service, and each use of the key can be logged, but each reader also needs permission to use that key. Client-side encryption means your code encrypts the file before upload. Then S3 holds data that it cannot read.

How it shows up in a case study. The client's policy says that all stored data must be encrypted at rest by default, and the team does not want to manage keys. An auditor asks who can read the data when the bucket is encrypted. The reasoning is that SSE-S3 meets the policy, because AWS manages the keys with no work for the team. Who can read the data is decided by the permissions and by Block Public Access. The pipeline profile is scoped, so only that identity and the admin identities can read it.

Trap: Treating encryption as access control

An encrypted object is still readable by any identity that has read permission. Encryption protects the stored disks, not the people inside the account.

Versioning

What it is. Versioning keeps every version of an object. With versioning on, an overwrite creates a new version and keeps the old one. A delete adds a delete marker on top, so the older versions still exist. Each version has a version ID. You read an older version by passing VersionId to get_object. You restore it by copying that version back to the same key, which makes the copy the newest version. Old versions take storage and cost money, so a lifecycle rule should expire noncurrent versions after a set number of days. Versioning protects against overwrites and deletes inside one bucket. It is not a full backup, because it does not protect you from losing the whole bucket.

How it shows up in a case study. A bad pipeline run overwrites yesterday's good Parquet file with an empty file. The team needs the good file back under the same key. The reasoning is to list the versions, find the version ID of the good file and copy it back. The team should not rely on re-running the pipeline, because a rebuild may not reproduce the same bytes. The team should also check the expiry window, because a version that has expired cannot be copied back.

Trap: Versioning as a backup

Versioning protects objects inside the same bucket. It does not replace a copy stored somewhere else.

Multipart uploads

What it is. A single upload request, PUT, can carry at most 5 GB. A larger object must be uploaded in parts. A multipart upload starts, sends each part with a part number, and then completes by naming all of the parts. Each part except the last must be at least 5 MiB, and an upload can have up to 10,000 parts. The boto3 method upload_file does the splitting for you. It switches to multipart once the file passes its threshold, which defaults to 8 MB. An upload that never completes keeps its stored parts, and those parts cost money. A lifecycle rule can abort incomplete uploads after a set number of days.

import boto3

s3 = boto3.client("s3")
s3.upload_file("big.parquet", "citypulse-x7k2q9", "clean/aqi/date=2026-12-17/big.parquet")

It chooses a single request or a multipart upload by itself.

How it shows up in a case study. A 12 GB hourly export fails with a size error from a script that was written around put_object. The reasoning is that a single request is limited to 5 GB, so the script must use upload_file, which splits large files. The team must also add a rule that aborts incomplete multipart uploads, because the failed runs left parts behind that still cost money.

Trap: Assuming put_object has no size limit

put_object takes one object up to 5 GB. Use upload_file or the multipart calls for anything larger.

What each function needs

Each function uses a few Python ideas. Learn each idea with the small example given. The examples use fruit, shop and school data, so you can see the idea without the lab's details. Try each example in a shell or a file before you rely on it.

Strings and slicing (for s3_uri). A string can be sliced with text[start:end]. Leaving out start begins at the first character, and text[1:] removes one character from the front.

name = "#ticket-9"
print(name[1:])                        # ticket-9
print("ORDER-17".startswith("ORDER"))  # True
print(f"{'Pune'}-{3}")                 # Pune-3

startswith checks the beginning of a string and returns True or False. An f-string puts values into the text where the braces are, and the output is Pune-3.

Copying a dictionary (for put_object). dict(d) makes a new dictionary with the same pairs. Changing the copy does not change the original.

prices = {"mango": 40}
copy = dict(prices)
copy["kiwi"] = 55
print(prices)  # {'mango': 40}
print(copy)    # {'mango': 40, 'kiwi': 55}

The copy is a shallow copy. The new dictionary holds the same list objects as the old one, so changing a list inside the copy changes it in the original too. Keep this in mind when a value is a list.

Looking up a key that may be missing (for get_object). d[key] raises KeyError when the key is missing. d.get(key) returns None instead, and d.get(key, default) returns the default you give.

stock = {"tea": 3}
print(stock.get("tea"))     # 3
print(stock.get("coffee"))  # None
print(stock.get("coffee", 0))  # 0
print("coffee" in stock)    # False

in checks whether a key exists and returns True or False. Use get when a missing key is a normal answer, and use in when you need to know the difference between a stored value and a missing one.

Filtering and sorting (for list_prefix). A list comprehension builds a new list from a loop in one line. sorted returns a new sorted list and leaves the original alone. Text is compared character by character, using the character codes, so capital letters come before lower-case ones.

words = ["pear", "fig", "banana"]
print([w for w in words if w.startswith("b")])  # ['banana']
print(sorted(words))                            # ['banana', 'fig', 'pear']
print(sorted(words, key=len))                   # ['fig', 'pear', 'banana']
print(sorted(["b", "a", "B"]))                  # ['B', 'a', 'b']

The key argument changes what is compared, so key=len sorts by length. Without a key, the order is the normal text order, and B comes before a. The statement asks for sorted keys, so you must not add a key that changes the order.

Worked twin problem

The twin problem below is about a college coding club and its scores. It uses dictionaries, copies, None, sorting with a key and a boundary check, so you practise the same skills in a different domain.

The task. A college coding club keeps its scores in a dictionary. Each key is a student's name, and each value is a list of scores from 0 to 100. Write three module-level functions.

  • add_score(book, name, score) returns a new dictionary, a copy of book, with score added to the end of the list for name. The name must be a non-empty string after spaces are removed from both ends. The score must be an int or a float, not a bool, and it must be from 0 to 100 inclusive. Any other input raises ValueError.
  • average(book, name) returns the average of the student's scores, rounded to one decimal place. It returns None when the student is missing or has no scores.
  • ranking(book) returns a list of names that have at least one score. The list is ordered by average, highest first. Names with equal averages are ordered from A to Z.

For example, ranking({"B": [50], "A": [50]}) returns ["A", "B"], and ranking({}) returns [].

def add_score(book, name, score):
    if not isinstance(name, str) or name.strip() == "":
        raise ValueError("name must be a non-empty string")
    if isinstance(score, bool) or not isinstance(score, (int, float)):
        raise ValueError("score must be a number")
    if score < 0 or score > 100:
        raise ValueError("score must be from 0 to 100")
    new_book = dict(book)
    new_book[name] = list(book.get(name, [])) + [score]
    return new_book


def average(book, name):
    scores = book.get(name)
    if not scores:
        return None
    return round(sum(scores) / len(scores), 1)


def ranking(book):
    rated = []
    for name in book:
        avg = average(book, name)
        if avg is not None:
            rated.append((name, avg))
    rated.sort(key=lambda pair: (-pair[1], pair[0]))
    return [name for name, _ in rated]


def raises_value_error(fn):
    try:
        fn()
    except ValueError:
        return True
    return False


book = {}
one = add_score(book, "Asha", 80)
two = add_score(one, "Asha", 90)
assert book == {}
assert one == {"Asha": [80]}
assert two == {"Asha": [80, 90]}
assert average(two, "Asha") == 85.0
assert average(two, "Ravi") is None
assert average({"Ravi": []}, "Ravi") is None

meera = add_score({}, "Meera", 70)
meera = add_score(meera, "Meera", 71)
meera = add_score(meera, "Meera", 71)
assert average(meera, "Meera") == 70.7

assert ranking(club) == ["Asha", "Kiran", "Ravi", "Meera"]

assert ranking({"B": [50], "A": [50]}) == ["A", "B"]

Line-by-line explanation.

  • add_score checks the name first. isinstance(name, str) confirms the type, and name.strip() == "" catches a name that is empty or only spaces. Either case raises ValueError, which stops the function before anything is stored.
  • The score check comes next. isinstance(score, bool) is checked before the number test, because bool is a subclass of int. Without that check, True would pass as the score 1. The test not isinstance(score, (int, float)) rejects strings such as "80".
  • The range check uses score < 0 or score > 100, so the values 0 and 100 are allowed and anything outside the range is refused.
  • new_book = dict(book) makes a copy, so the caller's dictionary is not changed. list(book.get(name, [])) copies the old list too, so the new list is separate. Then + [score] adds the new score at the end.
  • average returns None when book.get(name) gives None for a missing student, or an empty list. The test not scores is true for both.
  • round(sum(scores) / len(scores), 1) divides the total by the count, and then rounds once at the end. Rounding at the end gives 70.7 for the scores 70, 71 and 71, where the exact average is 70.666...
  • ranking builds a list of (name, average) pairs and skips students whose average is None.
  • The sort call uses a key of (-pair[1], pair[0]). The minus sign makes higher averages sort first, and the name breaks any tie in A-to-Z order. The statement's tie rule is carried by the second part of the key.
  • The last line returns only the names. for name, _ in rated unpacks each pair and throws away the average with _.

The club dictionary in the tests has a student called Dev with an empty list, so the ranking must leave Dev out. The three students with an average of 85.0 come first, in name order: Asha, Kiran, then Ravi.

def raises_value_error(fn):
    try:
        fn()
    except ValueError:
        return True
    return False


def reserve(plan, seat, passenger):
    if seat not in plan:
        raise ValueError("unknown seat")
    if not isinstance(passenger, str) or passenger.strip() == "":
        raise ValueError("passenger name required")
    if plan[seat] is not None:
        raise ValueError("seat already taken")
    new_plan = dict(plan)
    new_plan[seat] = passenger
    return new_plan


def free_seats(plan):
    return sorted(seat for seat, who in plan.items() if who is None)


def occupancy(plan):
    if not plan:
        return 0.0
    taken = sum(1 for who in plan.values() if who is not None)
    return round(100 * taken / len(plan), 1)


plan = {"1A": None, "1B": "Ana", "2A": None, "2B": None}
assert free_seats(plan) == ["1A", "2A", "2B"]
booked = reserve(plan, "2A", "Ravi")
assert booked["2A"] == "Ravi" and plan["2A"] is None
assert free_seats(booked) == ["1A", "2B"]
assert occupancy(plan) == 25.0
assert occupancy(booked) == 50.0
assert raises_value_error(lambda: reserve(plan, "1B", "Mina"))
assert raises_value_error(lambda: reserve(plan, "9Z", "Mina"))

The reserve function checks three things in order: the seat exists, the passenger is a real name, and the seat is free. Only then does it copy the dictionary and set the seat. The free_seats function uses a generator expression to pick the seats whose value is None, and sorted puts them in text order. The occupancy function counts the taken seats with sum over a generator, then turns the count into a percentage and rounds once at the end. The empty-plan check comes first, so the function never divides by zero.

Say it out loud

Why do the keys use date= and ISO dates?

The key holds the dataset and the day, so a prefix listing such as clean/aqi/date=2026-12-17/ returns one day without reading the others. The ISO form, year then month then day, sorts in calendar order as plain text. The date= name is a convention that query tools understand. Together these make the layout cheap to read and easy to scale.

How do you prove that a bucket is private?

I check the bucket's Block Public Access settings with get-public-access-block and confirm all four flags are true. Then I request an object that exists with a plain curl request that has no credentials. A private bucket must return 403, and I save that output as evidence. A 404 would prove nothing, because it only says the object is missing.

Why does upload.py use the credential chain instead of keys in the code?

The credential chain lets boto3 find credentials from environment variables, a named profile or the instance role, in that order. The same code therefore runs on a laptop with a profile and on an EC2 machine with a role, with no change. Hard-coded keys would leak through version control and would break on any other machine. Keeping secrets out of the code is also part of the course's security rules.

What does versioning protect against, and what does it cost?

Versioning protects against overwrites and deletes. When a pipeline replaces a good file with a bad one, the old version stays, so you can restore it by its version ID. The cost is storage for every old version, which grows without limit unless a lifecycle rule expires noncurrent versions. Versioning is not a full backup, because it protects only inside the same bucket.

Why should a listing use a paginator?

S3 returns at most 1,000 keys per call, and a longer listing is split across several responses. A paginator sends the continuation token for you and gives you one page at a time, so the same loop works for three objects or three million. Without it, a listing silently stops at 1,000 keys. The paginator is also the safe way to count objects.
