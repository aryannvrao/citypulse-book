## The idea in one minute

Field sensors send the same reading twice when the network drops, and sometimes they send a reading with no value at all. Nobody can average or chart those readings until they are tidied. Think of a hospital triage desk: every arrival is logged, a written rule decides what happens to each one, and every removal is counted, so nobody disappears without a record. Today you use pandas, a Python library for tables, to apply those rules, and Parquet, a compact file format, to store the result. By the end you can clean a messy CSV file with a short script, report how many rows each rule removed, and show that the stored file reads back unchanged.

## Starting from zero

This section explains the words the rest of the chapter uses. Read it once, then come back to it whenever a term is unfamiliar.

**File and folder.** A file is a named piece of stored data, such as `readings.csv`. A folder (also called a directory) is a container for files. The folder your terminal is working in is the current folder.

**Terminal and command.** The terminal is a text window where you type instructions for the computer. Each instruction is a command, and pressing Enter runs it. In this book, a line starting with `$` is a command. The `$` is the prompt that the terminal shows; you do not type it.

**Program and script.** A program is a set of instructions for a computer. A script is a program kept in one file and run from top to bottom. Python is the programming language used in this course. The command `python3 load.py` runs the script in the file `load.py`. On Windows the command may be `python`; use whichever one works on your machine.

**Variable.** A variable is a name that stores a value. After `rows = 1440`, the name `rows` refers to the number 1440. The `=` sign means "store this value under this name", not "is equal to".

**Function, argument and flag.** A function is a named block of code that you run by writing its name followed by brackets, such as `len(rows)`. The values inside the brackets are its arguments. An argument written as `name=value`, such as `index=False`, changes how the function behaves; this is called a named argument. Command-line tools use a similar switch called a flag, such as `-h` in `du -h`.

**Library and import.** A library is code that someone else wrote and published so you can reuse it. pandas and pyarrow are libraries. You install them once with `pip install pandas pyarrow`, where `pip` is the installer that comes with Python. Inside a script, `import pandas as pd` loads pandas and gives it the short name `pd`, so later lines can say `pd.read_csv`.

**List, dictionary and set.** A list is an ordered sequence written in square brackets, such as `["ST-02", "ST-03"]`. A dictionary stores pairs of a key and a value in curly braces, such as `{"ST-02": 4}`, where the key `"ST-02"` gives the value `4`. A set is an unordered collection in which each item appears once.

**CSV.** CSV stands for Comma-Separated Values. It is a plain-text table: each line is one row, and commas separate the columns. The first line is usually the header, which holds the column names. CSV stores no types, so a number and a word look the same in the file.

**Row, column and DataFrame.** A table has rows (records) and columns (fields). A pandas DataFrame is a table held in memory, which means in the computer's working memory. It disappears when the program stops, so you must save it to a file if you want to keep it.

**Dtype.** The dtype is the type that pandas gives a column. Common dtypes are `string` for text, `int64` for whole numbers, `float64` for decimal numbers, `datetime64` for dates with times, and `category` for a fixed set of labels. Older pandas versions show text as `object`.

**Missing values.** A blank cell in a CSV becomes a missing value. For numbers pandas writes `NaN`, which stands for "not a number". For dates it writes `NaT`, "not a time". A missing value is not zero, and a comparison with a missing value is never true. Python's own word for "no value" is `None`.

**Timestamp, ISO 8601 and UTC.** A timestamp is a date with a time, such as `2026-03-01 07:00:00`. That layout is the ISO 8601 standard: year, month and day, then hour, minute and second. UTC (Coordinated Universal Time) is a reference clock that does not move for daylight saving. IST (India Standard Time) is UTC plus five hours and thirty minutes.

**Duplicate and key.** Two rows are duplicates when they repeat the same values in the columns that identify a reading. Those identifying columns form the key. Today the key is the station, the timestamp and the pollutant.

**Pipeline and schema.** A pipeline is a chain of steps in which each step's output is the next step's input. A schema is the written list of column names and their types. A file with a schema can tell a reader what each column is without guessing.

**Compression and columnar storage.** Compression shrinks data so that it takes less disk space. Columnar storage keeps all the values of one column together, rather than keeping all the values of one row together. Columnar storage makes it cheap to read one column without reading the rest.

## The tools

### pandas DataFrames

pandas is the standard Python library for tabular data. A DataFrame is a table with named, typed columns. Its operations work on whole columns at once, which is why one line such as `df["value"].mean()` can replace a loop over every row. CityPulse data is a few hundred thousand hourly rows spread over several CSV files. That fits comfortably in memory, so pandas is a good fit.

The alternatives each have a cost. Polars is faster and stricter about types, and it is worth considering for tens of millions of rows; the course stays with pandas because the later tools expect it. The plain `csv` module needs no installation, but every type conversion, de-duplication and group-by becomes a hand-written loop that is slow and easy to get wrong. Excel and Google Sheets are fine for a first look, but manual edits cannot be repeated or checked by a reviewer, so a data-quality report cannot be generated from them.

The slides show the loader that every later step depends on. Read it as one repeatable function:

```python
import glob
import pandas as pd

KEY = ["ts_utc", "location", "source"]
METRICS = ["pm2_5", "pm10", "temperature_2m", "relative_humidity_2m"]


def load_raw(pattern: str = "data/raw/*.csv") -> pd.DataFrame:
    frames = [pd.read_csv(f).assign(src_file=f) for f in sorted(glob.glob(pattern))]
    df = pd.concat(frames, ignore_index=True)
    df["ts_utc"] = pd.to_datetime(df["ts_utc"], utc=True, errors="coerce")
    df[METRICS] = df[METRICS].apply(pd.to_numeric, errors="coerce")
    return df.astype({"location": "category", "source": "category"})


df = load_raw()
print(len(df), df.duplicated(subset=KEY).sum(), df.isna().mean().round(3).to_dict())
```

Line by line:

1. `import glob` loads the standard-library module that finds files whose names match a pattern.
2. `import pandas as pd` loads pandas under the short name `pd`.
3. `KEY` is a list of the column names that identify one reading. It is a named constant, so the rule is written once.
4. `METRICS` lists the numeric columns that must be converted.
5. `def load_raw(...)` defines a function. The text after the colon, `pattern: str`, says the input is text. The `-> pd.DataFrame` says the function returns a DataFrame. The default value `"data/raw/*.csv"` means the function works with no argument at all. The `*` is a wildcard that matches any text in a file name.
6. The list comprehension reads each matching file with `pd.read_csv` and adds a column `src_file` that records the file name. `sorted` makes the file order predictable, so a later rule can rely on it.
7. `pd.concat(frames, ignore_index=True)` stacks the tables one under another and renumbers the rows from 0.
8. `pd.to_datetime(..., utc=True, errors="coerce")` turns the text into UTC timestamps. A value that cannot be read becomes `NaT` instead of stopping the program.
9. `df[METRICS].apply(pd.to_numeric, errors="coerce")` runs the number converter on each metric column, so bad text becomes `NaN`.
10. `.astype({...})` converts the two label columns to `category`, which saves memory for repeated text.
11. The last line runs the function, then prints the row count, the number of repeated keys, and the share of missing values in each column.

When you run this, the first printed number is the total row count across all files. The exact numbers depend on your files, so do not expect any particular figure.

The flow below shows where pandas sits in the chapter. Every later step starts from the table this loader makes.

```flow
TITLE: From messy CSV to trusted Parquet
NODES: Raw CSV files | pandas DataFrame | Parquet file | Analysis notebook
STEPS:
1>2 :: read_csv :: pandas reads each file and converts each column to a dtype.
2>3 :: to_parquet :: The cleaned table is written with its types saved in the file.
3>4 :: read_parquet :: The notebook reads back the same types, and only the columns it needs.
```

:::trap Forgetting utc=True
Without `utc=True`, pandas can produce timestamps with no timezone. Later, converting to IST then shifts every hour by a wrong amount without any error. Always parse timestamps with `utc=True`.
:::

:::trap Chained assignment
Writing `df[df.x > 0]["y"] = 1` may change a temporary copy, so `df` stays the same. Use one indexing step with `df.loc[mask, "y"] = 1`.
:::

:::trap Concatenating an empty list of files
If the pattern matches no files, `pd.concat` raises a `ValueError` with a message that does not say why. Check that the file list is not empty first, and stop with a clear message.
:::

### Data cleaning and quality rules

A data-quality rule is a written instruction that says which rows to remove or which values to set aside. Cleaning means applying such rules to raw data until you can trust what remains. The slides name four rules for CityPulse: drop rows with no timestamp, remove duplicates on the natural key, set impossible values aside, and handle missing values by a written rule. A rule is only useful if three things hold. It is documented, it is applied in a fixed order, and its effect is counted.

Order matters. Deduplicating before the range rule means each out-of-range value is counted once. The alternative to a written rule is to drop every row with any null, which is simple but can throw away a large share of good data because one humidity value is missing. The slides also reject manual cleaning in a notebook, because the course gate requires one command and counts generated by code.

The slides show the ordered rules in code. The indentation has been restored here:

```python
RANGES = {"pm2_5": (0, 1000), "pm10": (0, 1000),
          "temperature_2m": (5, 45), "relative_humidity_2m": (0, 100)}
removed = {}
n = len(df); df = df.dropna(subset=["ts_utc"])
removed["missing_ts"] = n - len(df)
n = len(df)
df = df.sort_values("src_file").drop_duplicates(subset=KEY, keep="last")
removed["duplicates"] = n - len(df)
bad = pd.DataFrame({c: df[c].notna() & ~df[c].between(lo, hi) for c, (lo, hi) in RANGES.items()})
df[bad.any(axis=1)].to_csv("data/clean/quarantine.csv", index=False)
for c in RANGES:
    df.loc[bad[c], c] = float("nan")
removed["out_of_range_values"] = int(bad.to_numpy().sum())
assert df.duplicated(subset=KEY).sum() == 0
print(removed, df.dtypes.to_dict())
```

Line by line:

1. `RANGES` is a dictionary. Each key is a column name, and each value is a pair of the lowest and highest allowed numbers.
2. `removed = {}` creates an empty dictionary. Each rule will add one count to it.
3. `n = len(df); df = df.dropna(subset=["ts_utc"])` stores the row count, then removes rows whose timestamp is missing. The semicolon lets two statements share one line. `subset=` limits the check to one column.
4. `removed["missing_ts"] = n - len(df)` records how many rows the rule removed, by subtracting the new count from the old one.
5. `n = len(df)` stores the count before the next rule.
6. `sort_values("src_file")` puts the rows in file order. `drop_duplicates(subset=KEY, keep="last")` keeps one row for each key, the last in that order, so the newest file wins.
7. The next line records how many duplicates were removed.
8. `bad` is a table of true or false values, one column per metric. A value is bad when it is present (`notna()`) and outside its range (`~` means "not", and `between` is the range test).
9. `to_csv(..., index=False)` saves the rows that contain at least one bad value to `quarantine.csv`, before anything is changed. `index=False` stops pandas writing the row numbers as an extra column.
10. The loop sets each bad value to `NaN`. The row stays, but the impossible number is gone.
11. `int(bad.to_numpy().sum())` counts the bad values across the whole table. `int` converts the result to an ordinary Python whole number.
12. `assert` stops the program with an error if the key is still repeated. An assertion is a check that must be true; if it is not, the run must fail.
13. The final line prints the three counts and the column types.

When the run succeeds, the printed dictionary has three counts, for example `missing_ts`, `duplicates` and `out_of_range_values`. Those numbers must come from the code, not from typing.

The next box shows what `drop_duplicates` does when you give it a small list. It keeps the first copy of each key.

```trace
TITLE: Keeping the first copy of each key
CODE:
keys = ["A", "A", "B"]
seen = set()
kept = []
for k in keys:
    if k not in seen:
        seen.add(k)
        kept.append(k)
STEPS:
1 :: keys=["A", "A", "B"] :: The list of keys is created. Two of the three are the same.
2 :: keys=["A", "A", "B"]; seen=set() :: An empty set records the keys already kept.
3 :: keys=["A", "A", "B"]; seen=set(); kept=[] :: An empty list will hold the kept keys.
4 :: k="A"; seen=set(); kept=[] :: The loop takes the first key.
5 :: k="A"; seen=set(); kept=[] :: "A" is not in seen, so the test is true.
6 :: k="A"; seen={"A"}; kept=[] :: The key is recorded as seen.
7 :: k="A"; seen={"A"}; kept=["A"] :: The first copy of "A" is kept.
4 :: k="A"; seen={"A"}; kept=["A"] :: The loop takes the second "A".
5 :: k="A"; seen={"A"}; kept=["A"] :: "A" is already in seen, so the test is false and lines 6 and 7 are skipped.
4 :: k="B"; seen={"A"}; kept=["A"] :: The loop takes the third key.
5 :: k="B"; seen={"A"}; kept=["A"] :: "B" is new, so the test is true.
6 :: k="B"; seen={"A","B"}; kept=["A"] :: "B" is recorded as seen.
7 :: k="B"; seen={"A","B"}; kept=["A","B"] :: The loop ends with one copy of each key.
```

pandas does this in one call, `drop_duplicates`, but the logic is the same. The first occurrence in the current row order is the one that survives. That is why the slides say to sort by fetch order first.

:::trap Deduplicating on unsorted data
`keep="first"` keeps whichever copy comes first in the current row order, which may not be the newest reading. Sort by fetch order first, then use `keep="last"`, as the slide code does.
:::

:::trap Dropping blanks after deduplicating
Suppose a blank reading and a valid reading share the same key, and the blank comes first. Deduplicating with `keep="first"` keeps the blank and discards the valid reading. Then the missing-value rule removes the blank, and the valid reading is lost. The fix is to drop the missing values first, so that the valid reading is the only copy left for its key. Whatever order you choose, write it down and count each rule.
:::

:::trap Hand-typed counts
Typing the removed counts into a report by hand drifts away from what the code did. Generate the report from the `removed` dictionary on every run.
:::

### Parquet columnar storage

Parquet is an open file format that stores a table column by column. Each column is compressed, and the file includes a schema and summary statistics for each column. CSV loses types: after a CSV round trip, a timestamp comes back as plain text. Parquet keeps the UTC datetimes, floats and categories exactly as they were written.

The slides compare the formats with a picture. CSV is a stack of printed forms that you must read in order. Parquet is a filing cabinet with one labelled drawer for each field, so you open only the drawers you need. The alternatives have different strengths. CSV is readable by anyone, but it is larger, slower and untyped. Feather (Arrow IPC) is very fast for passing data between programs, but it is less common for long-term storage. SQLite is queryable, which is why the course loads it next, but Parquet stays the file that one stage hands to the next.

Inside a Parquet file, the data is split into row groups, which are blocks of rows. Each block holds one chunk per column, and the file ends with a footer that stores the schema. A reader uses the footer to decide which chunks to read. pandas does not write Parquet itself; it hands the table to pyarrow, which does the work.

The slides finish with this example. The indentation has been restored:

```python
import pandas as pd
import pyarrow.parquet as pq

PATH = "data/clean/readings.parquet"
df.to_parquet(PATH, engine="pyarrow", index=False)
meta = pq.ParquetFile(PATH).metadata
print(meta.num_rows, meta.num_columns, meta.num_row_groups)
eda = pd.read_parquet(PATH, columns=["ts_utc", "location", "pm2_5"])
print(eda.dtypes)  # ts_utc: datetime64[ns, UTC], location: category
eda["hour_ist"] = eda["ts_utc"].dt.tz_convert("Asia/Kolkata").dt.hour
by_hour = eda.groupby(["location", "hour_ist"], observed=True)["pm2_5"].agg(["mean", "count"])
print(by_hour.sort_values("mean", ascending=False).head())
```

Line by line:

1. `import pyarrow.parquet as pq` loads the part of pyarrow that opens Parquet files. `as pq` gives it a short name.
2. `PATH` holds the file location as text. Keeping it in one place means the write and the read cannot disagree.
3. `df.to_parquet(PATH, engine="pyarrow", index=False)` writes the DataFrame. `engine="pyarrow"` names the library that does the writing. `index=False` leaves out the row numbers.
4. `pq.ParquetFile(PATH).metadata` reads only the footer, not the data. It is a fast way to check the file.
5. The `print` line shows the number of rows, the number of columns and the number of row groups.
6. `pd.read_parquet(PATH, columns=[...])` reads only the three named columns. The rest are skipped on disk.
7. The comment after `print(eda.dtypes)` is the expected result. The `#` starts a comment, which Python ignores.
8. `.dt.tz_convert("Asia/Kolkata")` changes the displayed clock to IST. The instant is the same. `.dt` is the accessor that gives date and time tools for a column.
9. `groupby([...], observed=True)` groups by location and hour, and `observed=True` stops pandas creating empty groups for unused categories.
10. `.agg(["mean", "count"])` returns the average and the number of non-missing values for each group.
11. `sort_values(..., ascending=False).head()` shows the five highest averages.

The next box shows the file sizes from the Technology in Action example. The same 1,392 rows were saved as a CSV and as Parquet.

```term
$ du -h readings.csv readings.parquet
52K readings.csv
12K readings.parquet
```

The command `du -h` reports the disk space each file uses. `du` stands for disk usage, and `-h` asks for sizes in human-readable units such as K for kilobytes. Your numbers will differ, but Parquet is usually much smaller for repeated text and numbers.

:::trap Reading everything and then selecting
`df = pd.read_parquet(path)` followed by `df = df[["ts_utc", "pm2_5"]]` loads every column first. The benefit of columnar storage is lost. Pass `columns=` to `read_parquet` instead.
:::

:::trap Expecting CSV to keep types
A CSV reloaded with `read_csv` gives `ts_utc` the dtype `object`. Nothing is wrong with the file; CSV just has no types. Parquet keeps the datetime type, which is why the rest of the course reads Parquet.
:::

:::trap Committing data files to git
Committing `data/clean/*.parquet` bloats the repository. Git-ignore `data/clean/` except for a `.gitkeep` file, which holds the empty folder in place. Pin the pandas and pyarrow versions in your requirements file, because a different pyarrow can write a slightly different file.
:::

### Partitioned Parquet

A partitioned Parquet dataset is a folder with one subfolder for each value of a chosen column. pandas creates the subfolders when you pass `partition_cols`. The subfolders have names such as `station_id=ST-02`, and the rows for that station are stored inside. The partition column is removed from the files, because its value is already in the folder name. A reader that filters on that column can skip the other folders completely. The slides mention the trade-off indirectly, in their talk about many small files. Choose a column with few distinct values, such as station or date. A column with one value per reading creates a folder for each reading, which is slow to scan.

:::key Partitioning saves reads, not storage
Partitioning helps when queries filter on the partition column. It does not make the data smaller, and it can make it larger if you create many small files.
:::

## The worked example

The Technology in Action example follows one batch of sensor readings through seven steps. The batch has 1,440 raw rows. The goal is to end with 1,392 clean rows in a Parquet file, and to see how each step changes the count. The example uses a file called `readings.csv` in one folder, so every file is easy to find.

**Step 1: load the raw file.** The goal is to read the CSV and look at its shape before changing anything. The code uses `parse_dates=["ts"]`, which tells pandas to read the `ts` column as dates and times.

```python
import pandas as pd
df = pd.read_csv("readings.csv", parse_dates=["ts"])
print("rows:", len(df), " cols:", list(df.columns))
print(df.head(3).to_string(index=False))
```

Line by line, the first line loads pandas and the second reads the file. The third line prints the row count and a list of the column names. `df.head(3)` takes the first three rows, and `to_string(index=False)` prints them without row numbers. The output is:

```term
$ python3 load.py
rows: 1440  cols: ['station_id', 'ts', 'pollutant', 'value']
station_id                  ts pollutant  value
     ST-03 2026-03-01 18:00:00     PM2.5   49.3
     ST-02 2026-03-01 07:00:00     PM2.5   36.4
     ST-06 2026-03-02 03:00:00        O3   52.3
```

The spacing of the columns may differ on your screen. The important part is the 1,440 rows and the four column names. That is the baseline that every later step is measured against.

**Step 2: check the dtypes.** The goal is to confirm that `ts` is a real datetime, because a timestamp stored as text cannot be grouped by day.

```python
import pandas as pd
df = pd.read_csv("readings.csv", parse_dates=["ts"])
print(df.dtypes.to_string())
print("span:", df.ts.min().date(), "->", df.ts.max().date())
```

`df.dtypes` lists each column's type. `df.ts.min()` finds the earliest timestamp, and `.date()` keeps only the calendar date. The output shows `ts` as `datetime64[ns]`, `value` as `float64`, and `station_id` and `pollutant` as text. The span line shows the batch covers 2026-03-01 to 2026-03-04. The dtype of text columns can read `string` or `object`, depending on your pandas version.

**Step 3: remove duplicate readings.** The goal is to remove rows that repeat the same key. The key is station, timestamp and pollutant. The value is not part of the key, because a repeated transmission has the same key and the same value.

```python
import pandas as pd
df = pd.read_csv("readings.csv", parse_dates=["ts"])
print("raw:", len(df))
key = ["station_id", "ts", "pollutant"]
df = df.drop_duplicates(key)
print("after dedup:", len(df))
```

`key` is a list of the column names that together identify one reading. `drop_duplicates(key)` keeps the first copy of each key and drops the rest. The output is `raw: 1440` and `after dedup: 1410`. That means 30 repeated transmissions were collapsed to one row each.

**Step 4: remove blank values.** The goal is to remove readings with no value, because a blank cannot be averaged. The code removes duplicates first and then counts the blanks separately, so each rule is counted on its own.

```python
import pandas as pd
df = pd.read_csv("readings.csv", parse_dates=["ts"])
df = df.drop_duplicates(["station_id", "ts", "pollutant"])
before = len(df)
df = df.dropna(subset=["value"])
print("blanks removed:", before - len(df))
print("clean:", len(df))
```

`dropna(subset=["value"])` removes a row only when `value` is missing. The other columns are not checked. The output is `blanks removed: 18` and `clean: 1392`. Together with step 3, 48 rows were removed in all.

**Step 5: write Parquet and compare sizes.** The goal is to save the clean data in Parquet and compare it with the CSV.

```python
import pandas as pd
df = pd.read_csv("readings.csv", parse_dates=["ts"])
df = df.drop_duplicates(["station_id", "ts", "pollutant"])
df = df.dropna(subset=["value"])
df.to_parquet("readings.parquet", index=False)
print("wrote", len(df), "rows")
```

The output is `wrote 1392 rows`, followed by the size comparison from the earlier term block: the CSV is 52K and the Parquet file is 12K. The Parquet file is about four times smaller, with the same data.

**Step 6: read one column.** The goal is to show that Parquet can load one column without loading the others.

```python
import pandas as pd, pyarrow.parquet as pq
v = pd.read_parquet("readings.parquet", columns=["value"])
print("columns read:", list(v.columns), "rows:", len(v))
print("mean value:", round(v.value.mean(), 2))
print(pq.read_schema("readings.parquet"))
```

The `columns=["value"]` argument loads one of the four columns. `v.value.mean()` computes the average, and `round(..., 2)` keeps two decimal places. `pq.read_schema` prints the types stored in the file. The output lists `station_id: string`, `ts: timestamp[ns]`, `pollutant: string` and `value: double`. The mean value in the example is 51.01.

**Step 7: run the whole pipeline.** The goal is to put steps 3 to 5 into one script that you can run again on each new batch. In the example, this is a shell script called `run_all.sh`, which runs `python3 to_parquet.py` and then prints the file sizes with `du -h`. The output is `wrote 1392 rows`, then the two sizes, 52K and 12K. A shell script is a text file of commands that the terminal runs in order.

The steps show the same discipline as the slides. Each step prints a count. Each count is the evidence that a rule did what it should, and the next rule starts from the number that the last one left.

The quotes around `EOF` stop the terminal from changing the text.

### pandas dtypes

A dtype decides how pandas stores and treats each column. Numbers stored as text cannot be averaged, and dates stored as text cannot be grouped by day. The examiner's trap is a column that looks numeric but contains one bad cell, such as `NA*`. pandas then keeps the whole column as text.

### pandas groupby

A group-by splits the rows into groups by one or more columns, then runs an aggregation such as `mean`, `sum` or `count` on each group. The result has one row per group. You pass a list to group by several columns at once. When the group column is a category, use `observed=True` so that unused categories do not create empty rows. The examiner's trap is confusing `size()` with `count()`. `size()` counts every row, including rows with a missing value, whereas `count()` counts only the values that are present.

### pandas dedup

`drop_duplicates(subset=..., keep=...)` removes rows that repeat a key. `keep="first"` keeps the first occurrence in the current row order, `keep="last"` keeps the last, and `keep=False` removes every copy. Deduplication works on the key you name, not on the whole row, so you must choose the key on purpose. The row order decides which copy survives, which is why the slides sort by fetch order first. The examiner's trap is the order of rules: dropping blanks and deduplicating in the wrong order can remove the one valid reading.

### parquet format

Parquet stores a table column by column, with a schema, compression and summary statistics for each column. It keeps the types of the columns, so a timestamp comes back as a timestamp. CSV keeps no types, so a timestamp comes back as text, and the file is usually larger. The examiner's trap is to say that Parquet is compressed because it is columnar. Columnar layout helps compression, but the reason for the format is the typed, separated columns. Parquet is also not something you can read in Notepad, so treat it as a binary file.

### parquet partitioning

Partitioning writes one folder for each value of a chosen column, named in the form `column=value`. A reader that filters on the partition column skips every folder that does not match. The partition column is not repeated inside the files. Partitioning is useful only for columns with a small number of values, because each value creates its own folder and its own small files. The examiner's trap is to partition by a column with one value per reading, such as a full timestamp, which creates huge numbers of tiny files and slows every read.

### pandas reshape

Reshaping changes the layout of a table without changing the data. `pivot_table` turns long data, where one column holds the labels, into wide data, where each label has its own column, and it aggregates duplicate combinations with the mean by default. `melt` does the reverse, turning columns into rows. `pivot` also reshapes, but it raises an error when the same index and column pair appears twice. The examiner's trap is the difference between `pivot` and `pivot_table` when the data has duplicates. The first fails loudly, and the second averages the values silently.

### pandas merge

`pd.merge` joins two tables on one or more key columns. A `how="left"` join keeps every row of the left table, a `how="inner"` join keeps only matches, and a `how="outer"` join keeps the rows of both. If the right table has a key more than once, each matching left row is copied once for each match, so the row count can grow without any error. The `validate=` argument checks the relationship, for example `validate="many_to_one"`, and raises an error when the right table has duplicate keys. The examiner's trap is the silently larger table after a merge.

### pandas timeseries

A timestamp with a timezone is a single instant. The clock shown for it depends on the timezone. `tz_convert` changes the displayed timezone without changing the instant, while `tz_localize` attaches a timezone to a time that has none. The `.dt` accessor gives the date and time parts of a column, and `resample("D")` groups time-stamped rows by calendar day. A reading that is on one date in UTC can be on the next date in IST. The examiner's trap is the date boundary: a reading at 20:00 UTC is already the next day in IST.

### parquet column pruning

Column pruning means reading only the columns you name. Parquet stores each column in its own chunks, so the reader can skip the chunks it does not need. You request the columns with the `columns=` argument of `read_parquet`. The benefit is largest for wide tables, where analytics touch only a few columns. The examiner's trap is selecting columns after reading the whole file. That still loads every column first, so the benefit is lost.

### pandas indexing

`loc` selects by label, while `iloc` selects by integer position. A boolean mask, such as `df[df["value"] > 40]`, keeps the rows where the test is true. To change values, write through `loc`, as in `df.loc[mask, "value"] = 0`. With `loc`, a slice such as `0:4` includes both ends and uses labels, so it can return fewer rows than expected if labels are missing. With `iloc`, the end is excluded, so `0:4` returns four rows. The examiner's trap is confusing the two, especially after rows have been filtered out.

## The graded lab skill

The graded lab asks you to write a few Python functions in one file. Hidden tests then run those functions on inputs you have not seen. Hidden tests punish missed edge cases, such as an empty list, a city with no valid readings, or a number stored as text. This section teaches the techniques you need, from scratch, and then sets a practice problem with a full solution.

**Functions.** A function is defined with `def`, followed by a name, its parameters in brackets and a colon. The indented lines below it are the body. `return` sends a value back to the caller, and the function stops at that line. A function that does not return anything gives back `None`.

**Loops and conditions.** `for row in rows:` runs the indented block once for each item. `if` runs its block only when the test is true. `continue` skips straight to the next item of the loop, which is useful for skipping missing values.

**Dictionaries.** `totals = {}` creates an empty dictionary. `totals.get(city, 0.0)` returns the value stored for `city`, or `0.0` if the key is not there yet. `totals[city] = ...` stores or changes a value. A common pattern is to keep one dictionary of totals and one of counts, then divide.

**Tuples and unpacking.** A tuple is a fixed group of values in round brackets, such as `("Pune", "2026-03-01T06:00:00", 21.0)`. In `for city, ts, raw in rows:`, Python splits each tuple into three names, which is called unpacking.

**Missing and text values.** A value is missing when it is `None`, when it is a string that holds only spaces, or when it is `NaN`. `float(raw)` converts a number or numeric text to a decimal number. `math.isnan(x)` is the standard test for `NaN`, because `NaN == NaN` is false.

**Sorting and median.** `sorted(...)` returns a new sorted list, and `list.sort()` sorts the list in place. The median is the middle value of the sorted list. With an odd count, it is the middle item. With an even count, it is the average of the two middle items. `//` is integer division, which gives the position of the middle item.

**Dates from ISO text.** `datetime.fromisoformat(text)` reads an ISO 8601 timestamp. `.date()` keeps only the calendar date, and `.isoformat()` turns it back into text in the form `YYYY-MM-DD`. A trailing `Z` means UTC, and older versions of Python read it only if you replace it with `+00:00` first.

**Practice problem.** Write three functions in one file. Each row is a tuple `(city, iso_timestamp, temp)`, and `temp` may be a number, a numeric string, `None`, a blank string or `NaN`.

- `mean_by_city(rows)` returns a dictionary from each city to the mean of its valid temperatures. Cities with no valid values are left out.
- `median_for_city(rows, city)` returns the median of the valid temperatures for that city, or `None` if there are none.
- `daily_means(rows, city)` returns a list of `(date, mean)` pairs, one for each calendar day that has at least one valid value for that city, sorted by date.

For example, with these rows:

```text
("Pune", "2026-03-01T06:00:00", 21.0)
("Pune", "2026-03-01T14:00:00", 33)
("Pune", "2026-03-02T06:00:00", "24.5")
("Pune", "2026-03-02T13:00:00", "")
("Delhi", "2026-03-01T12:00:00", 30.0)
("Mumbai", "2026-03-01T09:00:00", None)
```

`mean_by_city` returns `{"Pune": 26.1666..., "Delhi": 30.0}`. Pune's valid values are 21.0, 33 and 24.5, so the mean is 78.5 divided by 3. The solution below does not round, so it returns the exact mean. `median_for_city(rows, "Pune")` returns 24.5. `daily_means(rows, "Pune")` returns `[("2026-03-01", 27.0), ("2026-03-02", 24.5)]`.

**Edge-case checklist.** Test your functions against each of these before you submit.

- Empty input: an empty list should give an empty dictionary, an empty list or `None`, as the function's rule says.
- Ties: a median of equal values, or two rows with the same key, must still give one clear answer.
- Ordering: the answer must not depend on the order of the input rows, and the daily list must be sorted by date.
- Types: integers, decimal numbers, numeric text, `None`, blank text and `NaN` must all be handled.
- Rounding: do not round unless the problem asks. Compare results with the exact values you expect.
- Missing fields: decide what a city with no valid values returns, state it in your code, and test it.

import math
from datetime import datetime


def _value(raw):
    """Return raw as a float, or None when the value is missing."""
    if raw is None:
        return None
    if isinstance(raw, str):
        raw = raw.strip()
        if raw == "":
            return None
    value = float(raw)
    if math.isnan(value):
        return None
    return value


def _day(ts):
    """Return the calendar date of an ISO timestamp as 'YYYY-MM-DD'."""
    return datetime.fromisoformat(ts.replace("Z", "+00:00")).date().isoformat()


def mean_by_city(rows):
    totals = {}
    counts = {}
    for city, _ts, raw in rows:
        value = _value(raw)
        if value is None:
            continue
        totals[city] = totals.get(city, 0.0) + value
        counts[city] = counts.get(city, 0) + 1
    return {city: totals[city] / counts[city] for city in totals}

        return None
    values.sort()
    middle = len(values) // 2
    if len(values) % 2 == 1:
        return values[middle]
    return (values[middle - 1] + values[middle]) / 2


def daily_means(rows, city):
    totals = {}
    counts = {}
    for row_city, ts, raw in rows:
        value = _value(raw)
        if row_city != city or value is None:
            continue
        day = _day(ts)
        totals[day] = totals.get(day, 0.0) + value
        counts[day] = counts.get(day, 0) + 1
    return [(day, totals[day] / counts[day]) for day in sorted(totals)]


rows = [
    ("Pune", "2026-03-01T06:00:00", 21.0),
    ("Pune", "2026-03-01T14:00:00", 33),
    ("Pune", "2026-03-02T06:00:00", "24.5"),
    ("Pune", "2026-03-02T13:00:00", ""),
    ("Pune", "2026-03-02T18:00:00", None),
    ("Pune", "2026-03-03T00:00:00Z", 19.0),
    ("Delhi", "2026-03-01T12:00:00", 30.0),
    ("Delhi", "2026-03-01T15:00:00", float("nan")),
    ("Mumbai", "2026-03-01T09:00:00", "   "),
]

# Mean per city: Pune 21, 33, 24.5, 19 gives 97.5 / 4. Delhi has 30.0. Mumbai has no values.
assert mean_by_city(rows) == {"Pune": 24.375, "Delhi": 30.0}
assert "Mumbai" not in mean_by_city(rows)
assert mean_by_city([]) == {}

# Median: sorted Pune values are 19, 21, 24.5, 33, an even count, so (21 + 24.5) / 2.
assert median_for_city(rows, "Pune") == 22.75
assert median_for_city(rows, "Delhi") == 30.0
assert median_for_city(rows, "Mumbai") is None
assert median_for_city(rows, "Chennai") is None
odd = [("X", "2026-01-01T00:00:00", 5), ("X", "2026-01-01T01:00:00", 1), ("X", "2026-01-01T02:00:00", 3)]
assert median_for_city(odd, "X") == 3

# Daily means: one pair per day with a valid value, sorted by date.
expected = [("2026-03-01", 27.0), ("2026-03-02", 24.5), ("2026-03-03", 19.0)]
assert daily_means(rows, "Pune") == expected
assert daily_means(rows, "Mumbai") == []
# A day where every value is missing must not appear.
extra = rows + [("Pune", "2026-03-04T06:00:00", "")]
assert daily_means(extra, "Pune") == expected
# The input order must not change the answer.
assert daily_means(list(reversed(rows)), "Pune") == expected
print("all checks passed")

Line by line, in the same order as the code:

1. `import math` loads the module with `isnan`. `from datetime import datetime` loads the class that reads ISO timestamps.
2. `_value` is a helper. The leading underscore is a convention meaning "for use inside this file".
3. `if raw is None` handles `None`. `is` checks identity, which is the correct test for `None`.
4. `raw.strip()` removes spaces at both ends, so a value of `"   "` becomes empty and counts as missing.
5. `float(raw)` converts integers, decimals and numeric text to a decimal number.
6. `math.isnan(value)` detects `NaN`, which must be tested this way because `NaN == NaN` is false.
7. `_day` reads the timestamp. `replace("Z", "+00:00")` turns a UTC marker into the form that `fromisoformat` accepts. `.date().isoformat()` returns the date as text, such as `2026-03-03`.
8. `mean_by_city` keeps two dictionaries. `totals` holds the running sums and `counts` holds how many valid values each city has.
9. `continue` skips missing values, so they affect neither the sum nor the count.
10. The dictionary comprehension divides each total by its count. A city with no valid values never appears in `totals`, so it is left out of the result.
11. `median_for_city` collects only the valid values for the named city.
12. `if not values` returns `None` when there is nothing to take a median of.
13. `values.sort()` sorts the list in place, which the median needs.
14. `len(values) // 2` is the index of the middle item. Integer division never gives a fraction.
15. An odd count returns the middle item. An even count returns the average of the two middle items.
16. `daily_means` skips rows for other cities and missing values, and groups the rest by calendar day.
17. The final line returns a list of pairs. `sorted(totals)` sorts the day strings, which works because `YYYY-MM-DD` sorts correctly as text.
18. The `rows` list holds the test data. It includes a text number, an empty string, `None`, `NaN`, a whitespace string and a `Z` timestamp, so every rule is exercised.
19. The first assertion checks the exact means. 97.5 divided by 4 is 24.375, which is exact in binary, so the comparison is safe.
20. The median assertion checks the even case, and the odd-count test checks the odd case.
21. The checks for empty results cover a city with no values and a city that is not in the data.
22. The `extra` row adds a day with only a blank value. The assertion shows that the day does not appear in the output.
23. The reversed-order check proves the answer does not depend on the order of the input.

When every assertion passes, the program prints `all checks passed`. If one fails, Python stops and shows which line failed.

## Say it out loud

Viva examiners and interviewers ask the same kind of question about your work: why, what, and how do you know. Each answer below is a model. Say it in your own words, and keep the numbers you can defend.

:::answer Why did you apply the rules in a fixed order?
Each rule changes the table, so the order decides which rows the next rule sees. In the lab, I removed duplicates before blanks, because a duplicate and a blank can share a key, and the order decides which copy survives. I wrote the order in the code and counted each rule's removals separately. That way, anyone can rerun the script and get the same numbers, and a reviewer can see exactly what was removed.
:::

:::answer Why Parquet and not CSV?
CSV keeps no types, so timestamps come back as text and the numbers must be parsed again every time. Parquet stores the schema, so the types come back exactly as they were written. It is also much smaller for repeated values, and a reader can load one column without parsing the others. The trade-off is that Parquet is binary, so you cannot open it in a text editor to check it.
:::

:::answer What does drop_duplicates decide, and what could go wrong?
It decides which rows are copies, using only the key columns you name, not the whole row. It keeps the first or last copy in the current row order, so the order of the rows decides which reading survives. The risk is choosing a key that is too wide, which keeps real duplicates, or too narrow, which deletes real readings. I checked the result with an assert, which stops the run if a key is still repeated.
:::

:::answer Why store timestamps in UTC and convert only for display?
UTC does not change for daylight saving, so one instant always has one UTC value and sorting is reliable. Local clocks can repeat an hour or skip one, which causes errors in grouping. I convert to IST only when I need an hour-of-day view, for example at the analysis step. The stored value stays in UTC, so any later analysis starts from the same facts.
:::

:::answer Why use pandas instead of the plain csv module?
The csv module reads text, so every type conversion, de-duplication and group-by becomes a loop I write and test by hand. pandas expresses each rule as one short, readable line, and the same library is used later in the course for analysis. Its operations are also well tested, which reduces the chance of a subtle bug in code I wrote. For a few hundred thousand rows, pandas is fast enough and the code stays short.
:::
