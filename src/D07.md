## The idea in one minute

Today you learn to take a raw sensor file, check it, and turn it into a few numbers you can trust, using only tools that come with Python. Think of a clerk who receives a pile of handwritten forms from air-quality sensors. Before adding anything up, the clerk checks which column is which, writes each value in the right box, and counts only the forms that answer the question being asked. A Python script does the same job. It reads each line of a CSV file (a plain text table), turns the text into numbers, filters the rows, and prints a summary.

By the end of the day you will be able to write small functions that take values in and return values out, read a CSV without crashing on bad rows, group and summarise readings, print a neat report, and prove the result with a test.

## Starting from zero

You do not need any prior programming. Each term below appears in this chapter, so read them once.

**Terminal.** A text window where you type instructions to the computer and read its replies. On Windows you can use PowerShell or Git Bash. On macOS and Linux it is called Terminal.

**Command.** One line you type in the terminal, followed by Enter. The computer runs it. For example, `python --version` asks Python to print its version number.

**File and folder.** A file holds data or instructions, such as `readings.csv`. A folder (sometimes called a directory) holds files. The terminal always works inside one folder, which is called the current folder or working directory.

**Changing folder.** `cd` means "change directory". `cd Desktop\citypulse` moves the terminal into a folder called `citypulse` on the Desktop. Use `dir` on Windows or `ls` on Git Bash, macOS and Linux to list the files in the current folder.

**Script.** A text file of Python instructions, saved with the ending `.py`. You run it with `python summarise.py`. The word "script" just means a program that is short enough to live in one file.

**Python and the interpreter.** Python is a programming language. The program that reads your `.py` file and carries out its instructions is called the interpreter. The slides ask for Python 3.11 or later. Check your version with `python --version`.

**Variable.** A name that holds a value, so you can use the value later. In `total = 5`, the name `total` now holds the number 5.

**Type.** The kind of value something is. `int` is a whole number such as 7. `float` is a number with a decimal point such as 36.6. `str` is text such as `"S1"`. `bool` is `True` or `False`. `None` means "no value".

**List.** An ordered collection written in square brackets, such as `[36.6, 52.1]`. Items are numbered from 0, so the first item is `values[0]`.

**Dictionary (dict).** A collection of key-value pairs written in curly braces, such as `{"S1": 36.6}`. The key `"S1"` finds the value `36.6`.

**Function.** A named block of code. You define it with `def`, give it inputs called parameters, and send back a result with `return`. Calling `average([1, 2, 3])` runs the block and gives you `2.0`.

**Standard library.** The collection of modules that ships with Python. A **module** is a single `.py` file that gives you ready-made code, and you load it with `import`. For example, `import csv` loads the module that reads CSV files.

**CSV.** Comma-Separated Values. A plain text table in which each line is a row and commas separate the columns. The first line is usually a header that gives the column names. The file `readings.csv` in this chapter looks like this:

```text
station_id,ts,pollutant,value
S1,2026-03-01T00:00:00,pm25,36.6
S1,2026-03-01T00:00:00,no2,22.9
```

**API.** Application Programming Interface. A defined way for one program to ask another for data. The slides use one of these to fetch weather and air-quality data.

**Server.** A computer, or a program on a computer, that answers requests from other programs over a network. The API in the slides is provided by a server run by someone else.

**Error (exception).** A problem that stops the normal flow of a program, such as a missing file. Python reports it with a name such as `FileNotFoundError`. You can catch an error and decide what to do with it.

## The tools

### The csv module and DictReader

**What it is.** `csv` is a standard library module that reads and writes CSV files. You could split each line on commas yourself with `line.split(",")`, but that breaks when a quoted field contains a comma. The `csv` module handles quotes correctly, so you should use it.

**Why CityPulse uses it.** The sensor dumps are CSV files, and the module needs no extra installation. The course's later lesson moves to pandas, but pandas is not needed to read a file this small.

**How it works.** `csv.DictReader` reads the header line once, then gives you one dictionary per data row. The keys are the header names, and the values are the text from that row. Every value is a string, even `"36.6"`.

**The slide code, explained.** The Technology in Action workbook uses this function:

```python
import csv

def load(path):
    rows = list(csv.DictReader(open(path)))
    for r in rows:
        r["value"] = float(r["value"])
    return rows

if __name__ == "__main__":
    rows = load("readings.csv")
    print(f"loaded {len(rows)} rows")
    print("first:", rows[0])
    print("value is", type(rows[0]["value"]).__name__)
```

Line by line:

- `import csv` loads the CSV module so you can write `csv.` before its functions.
- `def load(path):` defines a function called `load` that takes one parameter, `path`, the file name as text.
- `rows = list(csv.DictReader(open(path)))` opens the file, reads every row as a dictionary, and stores all of them in a list called `rows`. `list(...)` forces the reading to happen now.
- `for r in rows:` takes each dictionary in turn and calls it `r`.
- `r["value"] = float(r["value"])` replaces the text in the `value` key with a float. `float("36.6")` returns the number 36.6.
- `return rows` gives the list back to whoever called the function.
- `if __name__ == "__main__":` is true only when you run this file directly, not when another file imports it. The lines below it run only in that case.
- The three `print` lines show the row count, the first row, and the type of its `value`.

Expected output when `readings.csv` has 1,440 data rows:

```text
loaded 1440 rows
first: {'station_id': 'S1', 'ts': '2026-03-01T00:00:00', 'pollutant': 'pm25', 'value': 36.6}
value is float
```

The flow below shows how one row travels from the file to your code.

```flow
TITLE: From CSV file to a number
NODES: readings.csv | csv.DictReader | your function | print
STEPS:
1>2 :: next row :: DictReader reads one line and pairs each value with its header.
2>3 :: one dict per row :: Every value arrives as text, such as "36.6".
3>3 :: float(value) :: Your function converts the text to a float before using it.
3>4 :: summary numbers :: The function returns numbers, and print shows them.
```

The trace below shows why the conversion matters. Each step runs one line of code, and you can see the variables change.

```trace
TITLE: Turning text into numbers
CODE:
lines = ["S1,36.6", "S2,52.1"]
values = []
for line in lines:
    station, text = line.split(",")
    values.append(float(text))
STEPS:
1 :: lines=["S1,36.6", "S2,52.1"] :: A list holds two lines of text.
2 :: lines=["S1,36.6", "S2,52.1"]; values=[] :: Start with an empty list for the numbers.
3 :: line="S1,36.6"; values=[] :: The loop takes the first line.
4 :: line="S1,36.6"; station="S1"; text="36.6" :: split(",") cuts the line at the comma into two pieces of text.
5 :: line="S1,36.6"; station="S1"; text="36.6"; values=[36.6] :: float turns the text "36.6" into the number 36.6 and appends it.
3 :: line="S2,52.1"; values=[36.6] :: The loop takes the second line.
5 :: line="S2,52.1"; station="S2"; text="52.1"; values=[36.6, 52.1] :: The second number is added to the list.
```

:::trap Comparing text with numbers
A value read from CSV is text, so `row["value"] > 50` either fails or compares the wrong things. Python 3 raises `TypeError` when you compare text with a number. Always convert with `float()` once, at the point where you read the file.
:::

:::trap Forgetting newline="" on the file
The Python documentation asks you to open CSV files with `newline=""`. Without it, a quoted field that contains a line break can be read wrongly on Windows. The lab uses `open(path, newline="", encoding="utf-8")` for this reason.
:::

### Comprehensions and f-strings

**What they are.** A list comprehension builds a new list from an old one in a single line. An f-string is a piece of text that starts with `f"` and puts variables inside curly braces.

**Why CityPulse uses them.** A comprehension reads like the question you are asking, such as "the pm25 values". An f-string formats numbers for people to read, such as `38.7` rather than `38.700000000000003`.

**How it works.** `[expression for item in list if condition]` loops over the list, keeps the items where the condition is true, and applies the expression to each one. An f-string with `:.1f` formats a number with one digit after the decimal point.

**The slide code, explained.**

```python
vals = [float(r["value"]) for r in rows if r["pollutant"] == "pm25"]
print(f"pm25 avg: {mean(vals):.1f}")
```

Line by line:

- `vals =` stores the result in a variable called `vals`.
- `[float(r["value"]) ...]` is the expression. It is applied to every row that passes the filter.
- `for r in rows` loops over the rows, and `if r["pollutant"] == "pm25"` keeps only the rows whose pollutant is `pm25`. The double equals sign checks equality. A single equals sign would store a value, and Python would reject it in this position.
- In the `print` line, `mean(vals)` calls the `mean` function you import from `statistics`.
- `:.1f` inside the braces means "format as a float with one decimal place". The value 38.66 prints as `38.7`.

:::tip Use the question as the guide
When you write a comprehension, read it aloud as a sentence. "Each float value, for each row, where the pollutant is pm25." If the sentence does not match the question you were asked, the code is wrong.
:::

:::trap Rounding is only for display
`:.1f` changes how the number looks, not the number you keep. Calculate with the full value and round only in the printed text.
:::

### statistics and collections

**What they are.** `statistics` is a standard library module with functions such as `mean`, `median` and `stdev`. `collections` is a module with extra container types, such as `defaultdict`, which is a dictionary that creates a missing entry for you.

**Why CityPulse uses them.** A city-wide average hides hotspots, so the course groups readings by station. `defaultdict(list)` lets you append to a group without first checking whether the group exists.

**The slide code, explained.**

```python
from collections import defaultdict
from statistics import mean

groups = defaultdict(list)
for r in rows:
    if r["pollutant"] == "pm25":
        groups[r["station_id"]].append(r["value"])
avgs = {s: mean(v) for s, v in groups.items()}
```

Line by line:

- The two `from ... import` lines load one named item from each module, so you can write `mean(...)` rather than `statistics.mean(...)`.
- `groups = defaultdict(list)` creates a dictionary where any new key starts with an empty list.
- The loop keeps pm25 rows only.
- `groups[r["station_id"]].append(r["value"])` finds the list for that station, creating it if needed, and adds the value to it.
- `avgs = {s: mean(v) for s, v in groups.items()}` is a dictionary comprehension. For each station `s` and its list of values `v`, it stores the mean of `v`.

:::trap mean of an empty list
`statistics.mean([])` raises `StatisticsError`. Check that a list is not empty before you call `mean`, and decide what the empty case should return.
:::

### Modules and packages

**What they are.** A module is one `.py` file. A package is a folder of modules that contains a file named `__init__.py`. A package that has a `pyproject.toml` file can be installed, so that any script can import it from any folder.

**Why CityPulse uses them.** The course splits code into `config.py`, `fetch.py` and later modules, so several students can work on different files at once. Installing the package means `python -m citypulse.fetch` works from anywhere.

**How it works.** `python -m name` runs a module as a program. `pip install -e .` installs the folder you are in, in editable mode, so your code edits take effect at once.

**The slide commands, explained.**

```bash
mkdir -p src/citypulse
cat > pyproject.toml <<'EOF'
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"
[project]
name = "citypulse"
version = "0.3.0"
requires-python = ">=3.11"
dependencies = ["requests==2.32.3", "python-dotenv==1.0.1"]
EOF
echo '__version__ = "0.3.0"' > src/citypulse/__init__.py
python -m pip install -e . && python -c 'import citypulse; print(citypulse.__version__)'
```

Line by line:

- `mkdir -p src/citypulse` creates the folder `src/citypulse`. `-p` creates the parent folder `src` too, and does not complain if the folder already exists.
- `cat > pyproject.toml <<'EOF'` writes everything up to the next `EOF` line into a file called `pyproject.toml`. The quotes around `'EOF'` stop the shell changing the text.
- The lines between are the package description. `name` and `version` identify the package, and `requires-python` says which Python versions it supports. `dependencies` lists the other packages to install, with exact versions.
- `echo '...' > src/citypulse/__init__.py` writes one line into the `__init__.py` file. `echo` prints text, and `>` sends it to a file instead of the screen.
- `python -m pip install -e .` runs pip, the package installer, as a module. `-e .` means "install the package in the current folder in editable mode".
- `&&` runs the next command only if the previous one succeeded.
- The final command imports the package and prints its version, `0.3.0`.

:::trap Installing outside the virtual environment
If you run `pip install -e .` without activating your virtual environment (`.venv`), the package goes into the global Python, and the next project may not find it. Activate the environment first.
:::

:::trap Naming a file after a library
A file called `logging.py` or `statistics.py` in your folder hides the real library, because Python looks in the current folder first. Choose project names such as `readings_report.py`.
:::

### logging

**What it is.** `logging` is the standard library module for messages that have a level, a time and a destination. The levels are DEBUG, INFO, WARNING and ERROR.

**Why CityPulse uses it.** `print` has no levels and no timestamps, and it mixes messages in with your data output. A logged ERROR line tells you why a scheduled run failed. The course also has a gate that requires zero `print(` calls in `src/`.

**How it works.** Each module creates its own logger with `logging.getLogger(__name__)`. The main function sets the format and level once, and every logger uses that setup.

**The slide code, explained.**

```python
import logging
import requests

log = logging.getLogger(__name__)

class FetchError(Exception):
    """Raised when the source API cannot be read."""

def fetch_json(url: str, timeout: float = 20.0) -> dict:
    """GET url and return the decoded JSON body, or raise FetchError."""
    try:
        resp = requests.get(url, timeout=timeout)
        resp.raise_for_status()
    except requests.RequestException as exc:
        log.error("fetch failed for %s: %s", url, exc)
        raise FetchError(str(exc)) from exc
    return resp.json()
```

Line by line:

- `import requests` loads a third-party library (one you installed with pip) that makes web requests.
- `log = logging.getLogger(__name__)` creates a logger named after the module. `__name__` is the module's name, such as `citypulse.fetch`.
- `class FetchError(Exception):` defines a new kind of error. The docstring (the text in triple quotes) describes it.
- `def fetch_json(url: str, timeout: float = 20.0) -> dict:` defines the function. `timeout` has a default of 20 seconds. The `-> dict` part says what the function returns.
- `requests.get(url, timeout=timeout)` sends a GET request, which asks the server for data. If the server does not answer within 20 seconds, the request fails.
- `resp.raise_for_status()` turns an HTTP error such as 404 or 500 into an exception.
- `except requests.RequestException as exc:` catches only request problems. `exc` holds the error so you can log it.
- `log.error("fetch failed for %s: %s", url, exc)` writes an ERROR message. The values are passed as separate arguments, not joined with an f-string.
- `raise FetchError(str(exc)) from exc` raises your own error and keeps the original as its cause.
- `return resp.json()` converts the response body from JSON text to a Python dictionary.

When the URL is wrong, the log line contains `ERROR`, the words `fetch failed for`, and the URL. The exact layout depends on how `main()` configures the format.

:::trap A bare except hides bugs
`except:` or `except Exception: pass` catches everything, including typing mistakes in your own code, and then discards them. Catch the specific error you expect and log it.
:::

:::trap Calling basicConfig in every module
Configure logging once, in `main()`. If each module configures it, messages can be duplicated or formatted in different ways.
:::

### Type hints

**What they are.** Annotations that say what a function takes and returns, such as `name: str` and `-> Row`. Python does not enforce them when the code runs.

**Why CityPulse uses them.** Five students each write a different function, and the hints make the agreement between them explicit. Editors and the checker mypy use the hints to find mistakes early.

**How it works.** A `TypedDict` describes the keys and value types of a dictionary once, so every function that builds or reads a row uses the same names.

**The slide code, explained.**

```python
from typing import Any, TypedDict

class Row(TypedDict):
    timestamp: str
    location: str
    pm2_5: float | None
    pm10: float | None

def parse(payload: dict[str, Any], location: str) -> Row:
    """Pure: turn the 'current' block of an Open-Meteo response into one row."""
    cur = payload["current"]
    return Row(timestamp=to_utc_iso(cur["time"], payload.get("timezone", "UTC")),
               location=location, pm2_5=cur.get("pm2_5"), pm10=cur.get("pm10"))
```

Line by line:

- `from typing import Any, TypedDict` loads the names used for hints. `Any` means "any type".
- `class Row(TypedDict):` defines the shape of a row. Each line after it names a key and its type.
- `float | None` means "a float or None". The `|` symbol combines types. This form needs Python 3.10 or later.
- `def parse(payload: dict[str, Any], location: str) -> Row:` takes the response dictionary and a location name, and promises to return a `Row`.
- The docstring says `parse` is pure. A pure function reads only its inputs, does no file or network work, and gives the same result for the same input.
- `cur = payload["current"]` takes the `current` block of the response. A missing key here raises `KeyError`.
- `payload.get("timezone", "UTC")` reads the timezone, or uses `"UTC"` if it is missing.
- `Row(...)` builds the row from named values, and `cur.get("pm2_5")` returns `None` when the key is absent.

:::trap Hints are not checks
Python does not check hints at runtime. `parse` will happily return a row with wrong data. Check the fields and units yourself, as the `check_units` function does below.
:::

:::trap Plain dict everywhere
Annotating every value as `dict` tells the reader nothing about the keys. Use `TypedDict` for a shape you know.
:::

### UTC datetimes and data dictionaries

**What they are.** UTC (Coordinated Universal Time) is the shared clock that does not change with the seasons or with local time zones. A data dictionary is a document that lists every column, with its type, unit, source and an example.

**Why CityPulse uses them.** Open-Meteo returns local times, and the bash fetcher used Asia/Kolkata times. Parity between the two fetchers requires the same UTC strings. A data dictionary means that nobody can change the unit of a column without anyone noticing.

**How it works.** `zoneinfo` attaches a named time zone to a naive time, which is a time with no zone attached. `astimezone` converts it to UTC, and `strftime` formats it as text.

**The slide code, explained.**

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

def to_utc_iso(local_time: str, tz_name: str = "UTC") -> str:
    """'2026-12-01T18:30' in Asia/Kolkata -> '2026-12-01T13:00:00Z'."""
    aware = datetime.fromisoformat(local_time).replace(tzinfo=ZoneInfo(tz_name))
    return aware.astimezone(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")

EXPECTED_UNITS = {"pm2_5": "μg/m³", "pm10": "μg/m³"}

def check_units(units: dict[str, str]) -> None:
    """Raise ValueError if current_units differ from docs/data-dictionary.md."""
    for col, unit in EXPECTED_UNITS.items():
        if units.get(col) != unit:
            raise ValueError(f"{col}: expected {unit!r}, got {units.get(col)!r}")
```

Line by line:

- `datetime.fromisoformat(local_time)` reads text such as `2026-12-01T18:30` and returns a `datetime` object, a value that holds a date and a time.
- `.replace(tzinfo=ZoneInfo(tz_name))` attaches the zone `Asia/Kolkata` to it. Now the value is "aware", meaning it knows its zone.
- `.astimezone(timezone.utc)` converts it to UTC. 18:30 in India is 13:00 UTC, because India is five and a half hours ahead.
- `strftime("%Y-%m-%dT%H:%M:%SZ")` formats the result as text. `%Y` is the year, `%m` the month, `%d` the day, `%H:%M:%S` the time, and the final `Z` marks UTC.
- `EXPECTED_UNITS` maps each column to the unit it must have. `μ` and `³` are the Greek mu and the superscript three, which together spell µg/m³.
- `check_units` loops over the expected columns. `units.get(col)` returns the unit from the response, or `None` if it is missing.
- `raise ValueError(...)` stops the program with a clear message when a unit differs. `!r` shows the text in quotes so that invisible differences are visible.

Expected result: `to_utc_iso("2026-12-01T18:30", "Asia/Kolkata")` returns `'2026-12-01T13:00:00Z'`.

:::trap Appending Z without converting
Writing `Z` onto an IST time gives a value that is five hours and thirty minutes wrong. Convert to UTC first, then add the `Z`.
:::

:::trap datetime.utcnow
`datetime.utcnow()` returns a naive value and is deprecated. Use `datetime.now(timezone.utc)`, which returns an aware value.
:::

### Step 3: Parse the CSV safely

**What you do.** Add these functions below the class. `parse_row` converts one dictionary into a `Reading`. `load_readings` reads the whole file and skips any row that cannot be converted, counting how many it skipped.

```python
import csv

def parse_row(row: dict) -> Reading:
    return Reading(
        station_id=row["station_id"],
        ts=row["ts"],
        pollutant=row["pollutant"],
        value=float(row["value"]),
    )

def load_readings(path: str) -> tuple[list[Reading], int]:
    readings = []
    skipped = 0
    with open(path, newline="", encoding="utf-8") as f:
        for row in csv.DictReader(f):
            try:
                readings.append(parse_row(row))
            except (KeyError, TypeError, ValueError):
                skipped += 1
    return readings, skipped
```

Line by line:

- `import csv` goes at the top of the file, above the class.
- `parse_row(row: dict) -> Reading` takes one row and returns a `Reading`. `float(row["value"])` is the only conversion, and it happens in one place.
- `load_readings` returns two things at once, a list and a count, written as `tuple[...]`.
- `with open(path, newline="", encoding="utf-8") as f:` opens the file. The `with` block closes the file automatically, even if an error happens inside it. `encoding="utf-8"` says how to read the characters.
- `for row in csv.DictReader(f):` reads one row at a time from the open file.
- `try:` starts a block that may fail. If `parse_row` fails, Python jumps to the `except` line.
- `except (KeyError, TypeError, ValueError):` catches three specific problems: a missing column (`KeyError`), a missing value that becomes `None` (`TypeError`), and text that is not a number such as `"abc"` (`ValueError`).
- `skipped += 1` adds one to the count, which is short for `skipped = skipped + 1`.

## What the quiz tests

The day quiz has ten questions, one per topic below, in this order. Each question is a case study. Read the scenario carefully, because the wrong options are usually things that look right in a different language.

### type-conversion

You must know that every value read from a CSV file is a string, and that Python does not convert types for you when you compare them. `int()` turns text into a whole number, `float()` into a decimal, and `str()` back into text. Converting `"3.5"` with `int()` raises `ValueError`, while `float("3.5")` works. Convert once at the boundary where data enters your code. The examiner's trap is the option that says Python will convert text automatically, or that a comparison such as `"36.6" > 50` is true.

### collections

You must know the difference between a list (ordered, allows duplicates), a dictionary (key-value pairs), a set (unordered, no duplicates) and a tuple (ordered and unchangeable). Reading a missing key with `d[key]` raises `KeyError`, while `d.get(key, default)` returns the default. `defaultdict` and `Counter` from `collections` are shortcuts for counting and grouping. The examiner's trap is the claim that a normal dictionary creates a missing key on read.

### context-managers

A context manager is used with `with`, and it guarantees cleanup, such as closing a file, even when an error occurs. `with open(path) as f:` closes `f` at the end of the block. Using `f` after the block fails with `ValueError: I/O operation on closed file`. The examiner's trap is code that opens a file without `with` and forgets to close it. Such code may work in a short test and fail in a long-running scheduled job.

### functions

A function takes parameters, does work and sends a result back with `return`. A function with no `return` statement gives back `None`, and `print` shows a value on the screen without giving it to the caller. Parameters with default values must come after parameters without them. Functions should do one job each, so that they are easy to test. The examiner's trap is the function that prints an average but never returns it.

### exception-handling

You must know that `try` holds code that may fail, `except` names the error type to catch, `else` runs when nothing failed, and `finally` runs in every case. Catch the most specific error you expect, log it and raise a project-specific error, using `raise ... from exc` to keep the original cause. A bare `except:` also catches `KeyboardInterrupt`, so it stops the user from cancelling the program. The examiner's trap is the silent `except: pass`.

### generators

A generator is a function that uses `yield` to produce values one at a time, which saves memory on large files. A generator can be used only once, because after it has produced its values it is empty. `sum(gen)` consumes it, and `list(gen)` afterwards returns `[]`. The examiner's trap is reusing the same generator for two calculations. The fix is to build a list once, or to call the generator function again.

### dataclasses

A `@dataclass` class writes `__init__`, `__repr__` and `__eq__` for you, based on its annotated fields. Two readings with the same fields compare as equal. A field that needs a fresh empty list uses `field(default_factory=list)`. Writing `items: list = []` is rejected when the class is defined, with a `ValueError`. The examiner's trap is the claim that a dataclass default list is safe because the class prevents sharing, when the real behaviour is that the class refuses to be defined.

### mutable-defaults

A default value in a `def` line is evaluated once, when the function is defined, not each time it is called. So `def f(log=[])` shares one list across all calls, and the list keeps growing. The fix is `def f(log=None)`, followed by `if log is None: log = []` inside the function. The examiner's trap is a function that gives different results on the first call and later calls with the same input.

### modules-imports

`import name` loads a module, and `from name import thing` loads one item from it. Python searches the folder of the running script before the standard library, so a file called `statistics.py` in your folder replaces the real library and breaks imports. `if __name__ == "__main__":` runs code only when a file is started directly. The examiner's trap is a student file named after a standard library module.

### functools-caching

`functools.lru_cache` remembers the results of earlier calls, keyed by their arguments, so repeated calls return instantly. Every argument must be hashable, which means it can be used as a dictionary key. A list is not hashable, so calling a cached function with a list raises `TypeError: unhashable type: 'list'`. Convert it to a tuple first. Caching is safe only for pure functions, whose results depend only on their arguments. The examiner's trap is caching a function that reads a file or the clock.

## The graded lab skill

The graded lab asks you to write a few functions and passes them to visible and hidden tests. The hidden tests check the cases you did not think about, so this section teaches the techniques in full and then gives a practice problem with a full solution.

### Counting per key

A dictionary can count items. For each item, you read the current count with `get`, which returns a default if the key is missing, then store the count plus one.

```python
counts = {}
counts["Asha"] = counts.get("Asha", 0) + 1
```

`counts.get("Asha", 0)` returns the existing count, or 0 if `"Asha"` is not yet a key. The second argument is the default. The assignment then stores the new count.

### Averaging over a filtered subset

Filter the items first, then divide. Keep the filter in a list comprehension, and check the list before dividing, because dividing by zero raises `ZeroDivisionError`.

```python
amounts = [o["amount"] for o in orders if o["category"] == "sensor"]
average = sum(amounts) / len(amounts) if amounts else None
```

`sum` adds the numbers. `len` counts them. The conditional expression `... if amounts else None` returns `None` when the list is empty. Written in full, that is the same as an `if` and an `else` on separate lines.

### Finding the highest count with a tie-break

`min` and `max` accept a `key` function. The key is applied to each item and the item with the smallest key wins. A tuple such as `(-count, name)` compares its first item first, and then its second item only when the first is equal. Negating the count turns "highest count" into "smallest key".

```python
counts = {"Ravi": 2, "Meena": 2, "Asha": 1}
best = min(counts, key=lambda name: (-counts[name], name))
```

`lambda name: ...` is a small unnamed function. For each key `name`, it returns the tuple. `(-2, "Meena")` is smaller than `(-2, "Ravi")` because `"Meena"` comes before `"Ravi"` alphabetically, so `best` is `"Meena"`.

### Empty input

An empty list has no counts, no average and no top customer. Decide the return value before you write the loop. The graded problem asks for `None` in each case. Returning `0.0` for an empty average is a different choice, and the hidden tests will expect whichever value the task states.

### Edge-case checklist

Before you submit, check each of these:

- Empty input: the list is `[]`.
- Ties: two keys have the same count, and the answer is the alphabetically first name.
- Ordering: the answer does not depend on the order of the input list.
- Types: amounts can be whole numbers such as `1200`. Divide with `/`, which always gives a float in Python 3.
- Rounding: do not round the average unless the task asks you to. Return the exact value.
- Missing fields: decide what to do if a dictionary has no `category`. The task here assumes every dictionary has all three keys.
- Filter with no matches: the category `"cable"` has no orders, so its average is `None`.

### Practice problem

## Say it out loud

### Why do you convert the value to a float at the start?

:::answer Model answer
CSV fields are always text, so `"36.6" > 50` is either an error or a wrong comparison. I convert the value once, where the row is read, so the rest of the code works with numbers. That also means a bad value fails in one known place, where I can skip the row and count it. Every later function can then assume the type is correct.
:::

### Why use `with open(...)` instead of a plain `open`?

:::answer Model answer
The `with` statement guarantees that the file is closed when the block ends, even if an exception happens in the middle. A plain `open` depends on the code reaching a `close` call, and a crash skips it. In a scheduled job that runs unattended, an unclosed file can leave data unwritten or lock it on some systems. The `with` form costs nothing extra and removes that risk.
:::

### Why is a bare `except:` dangerous?

:::answer Model answer
A bare `except:` catches every error, including bugs in my own code, such as a misspelled variable name. If I then do nothing, the error disappears and the report shows wrong or empty results with no sign of a problem. I catch only the errors I expect, such as `ValueError` for bad numbers, and I log the reason. Unexpected errors then stop the program, and I can see and fix them.
:::

### What is a pure function, and why does it help testing?

:::answer Model answer
A pure function returns a result that depends only on its inputs, and it does no file, network or clock work. Because of that, I can test it with an `assert` on a small hand-made input, and the test will always give the same result. The fetching and saving stay in separate functions, so that the parsing can be tested without a network connection. This is why `parse` in the slides takes the JSON as an input.
:::

### What is the difference between a module and a package?

:::answer Model answer
A module is a single `.py` file that other code can import. A package is a folder of modules with an `__init__.py` file, and it can be installed with a `pyproject.toml` file. The installed package can be imported from any folder, so scripts, tests and the scheduled job all use the same code. The editable install with `pip install -e .` links the package to my source folder, so my edits take effect immediately.
:::

| `min(items, key=...)` | Item with the smallest key | `min(counts, key=lambda n: (-counts[n], n))` |

| `defaultdict(list)` | Dict that creates missing keys as empty lists | `groups[k].append(v)` |
