## The idea in one minute

A single model makes mistakes that often differ from row to row. Combine several models and some of those mistakes cancel out. Today you build ensembles (groups of models), measure the errors row by row and group by group, and write a model card, which is a short document that tells a reviewer what the model is for and where it fails. Think of a school where one teacher's mark for a pupil is unreliable: the head asks three teachers, averages their marks, and then checks which classes are marked worst. That is the whole day. CityPulse needs this because officers will act on pollution forecasts, and they need to know when to trust them.

## Starting from zero

**Terminal.** A text window where you type a command and press Enter. The computer runs it and prints the result underneath.

**Command.** A line you type at the terminal prompt, such as `python3 boost.py`. The first word is the program, the rest are its inputs.

**File and folder.** A file holds text or data. A folder (also called a directory) holds files. A path such as `reports/ml/test_predictions.parquet` names a file by its folders.

**Python and a script.** Python is a programming language. A script is a text file of Python instructions, saved with the extension `.py`. Running `python3 boost.py` reads the file and carries out its lines from top to bottom.

**Variable.** A name that holds a value. `a = 10` stores the number 10 under the name `a`. Later lines can use `a`.

**List and dictionary.** A list is an ordered collection in square brackets: `[10, 20, 30]`. Position 0 is the first item. A dictionary is a collection of key-value pairs in curly brackets: `{"A": 2}` stores the value 2 under the key `"A"`.

**Loop.** Repeats a block of lines for each item. `for x in [1, 2]:` runs the indented lines twice, with `x` set to 1, then 2. Indentation (the spaces at the start of a line) shows which lines belong to the loop.

**Function.** A named, reusable action. `abs(-3)` is a built-in function that returns 3. A function can also be defined by you with `def`.

**Library.** Code written by other people that you bring in with `import`. Install one with `pip install`. This course uses four: scikit-learn (imported as `sklearn`) for models, pandas (`pd`) for tables, joblib for saving models, and PyYAML (`yaml`) for reading and writing YAML text files.

**DataFrame.** pandas' name for a table with named columns and numbered rows.

**Model, training and prediction.** A model is a rule learned from data. Training means fitting the model to rows where the answer is known. Prediction means asking the trained model for answers on new rows.

**Train/test split.** You hold back some rows (the test set) and do not show them to the model during training. Scores on the test set are an honest estimate of how the model will do on new data.

**Error measures.** Given the actual value and the predicted value for each row:

- The **residual** is actual minus predicted. In this course, a positive residual means the model under-predicted.
- The **MAE** (mean absolute error) is the average of the absolute residuals. It is the average size of the miss, in the same units as the target.
- The **bias** here means the mean of the signed errors. Near zero means the errors cancel out. Note that the word "bias" also has a second meaning in statistics; in this chapter it always means the mean signed error.

**Decision tree.** A model that answers a question by following a sequence of yes/no splits, such as "is the hour above 17?", until it reaches a leaf that gives the answer.

**Overfitting.** A model that memorises the training rows and does badly on new rows.

**Ensemble.** A combination of several models whose outputs are merged into one answer.

**Random seed.** A number, written as `random_state=42`, that fixes the random choices a model makes. Using the same seed gives the same result each run, so your numbers can be checked against the course.

**IST.** Indian Standard Time, which is UTC plus 5 hours 30 minutes. In code it is written `Asia/Kolkata`.

## The tools

### Random forests and gradient boosting

A **random forest** trains many decision trees, each on a bootstrap sample. A bootstrap sample is drawn with replacement from the training rows, so each tree sees a slightly different set. The trees are independent of each other, and the forest averages their predictions. Averaging reduces variance: a single tree's answer swings when the data changes, and the average swings less. CityPulse uses it because trees capture effects such as the evening rush peak that a straight-line model needs hand-made features to capture.

**Gradient boosting** works the other way. It adds shallow trees one after another. Each new tree is fitted to the errors left by the trees so far, so the team gets better at the cases it still gets wrong. This reduces bias. `HistGradientBoostingRegressor` groups (bins) each numeric feature into a fixed number of buckets before fitting, which makes it fast on large tables.

```trace
TITLE: Averaging two forecast lists position by position
CODE:
a = [10, 20]
b = [12, 18]
avg = []
for x, y in zip(a, b):
    avg.append((x + y) / 2)
STEPS:
1 :: a=[10, 20] :: Create the first list.
2 :: a=[10, 20]; b=[12, 18] :: Create the second list.
3 :: a=[10, 20]; b=[12, 18]; avg=[] :: Start with an empty list for the averages.
4 :: x=10; y=12; avg=[] :: zip pairs up position 0 of each list.
5 :: x=10; y=12; avg=[11.0] :: (10 + 12) / 2 is 11.0, and it is added to avg.
4 :: x=20; y=18; avg=[11.0] :: zip moves on to position 1.
5 :: x=20; y=18; avg=[11.0, 19.0] :: (20 + 18) / 2 is 19.0.
```

The animation above shows the averaging step that the graded lab uses. Press play and watch `x` and `y` change as the loop moves along the two lists.

The slide code for the comparison is below. It assumes `cfg`, `train` and `cv` were built by an earlier script, `tune.py`, so you cannot run it on its own yet.

```python
from sklearn.ensemble import HistGradientBoostingRegressor, RandomForestRegressor
from sklearn.model_selection import cross_validate
from src.pipeline import build_pipeline
# cfg, train and cv are built exactly as in tune.py (same rows, same folds)
models = {
    "rf": RandomForestRegressor(n_estimators=300, min_samples_leaf=5, n_jobs=-1, random_state=42),
    "histgb": HistGradientBoostingRegressor(max_iter=300, learning_rate=0.05, random_state=42),
}
for name, est in models.items():
    pipe = build_pipeline(cfg).set_params(model=est)
    r = cross_validate(pipe, train, train[cfg["target"]], cv=cv, scoring="neg_mean_absolute_error")
    mae = -r["test_score"]
    print(f"{name}: CV MAE {mae.mean():.2f} ± {mae.std():.2f}  fit {r['fit_time'].mean():.1f}s/fold")
```

Line by line:

- The first two `from ... import` lines bring in the two ensemble models and the cross-validation function. `from` names the library, `import` names the parts you want.
- `from src.pipeline import build_pipeline` brings in a function from the project's own `src` folder. It builds the preprocessing steps and the model in one object.
- The comment line is for you, not the computer. Python ignores anything after `#`.
- `models = { ... }` is a dictionary. The keys `"rf"` and `"histgb"` are short labels for printing.
- `n_estimators=300` means 300 trees. `min_samples_leaf=5` stops a tree splitting until a leaf holds at least 5 rows, which curbs overfitting and file size. `n_jobs=-1` uses all your processor cores. `random_state=42` fixes the seed.
- `max_iter=300` means 300 boosting stages and `learning_rate=0.05` sets how much each stage changes the answer.
- The `for` loop runs once per model. `set_params(model=est)` swaps the model in the pipeline for `est` and keeps every other step the same. This is what makes the comparison fair.
- `cross_validate` trains and tests on each fold (each split of the data) and returns the scores in `r`. `cv=cv` reuses the same folds for each model.
- `scoring="neg_mean_absolute_error"` makes scikit-learn return the MAE as a negative number, because its convention is that a higher score is better. The next line flips the sign back.
- The `print` line shows the mean and standard deviation of the fold MAEs, and the average fit time per fold.

When the course runs this on its data, it prints one line for each model. The exact numbers depend on the data, so compare your numbers with the course output, not with anybody else's.

### Slice-based error analysis

An overall MAE can hide a group that is badly served. Slice-based error analysis splits the test rows into groups (slices), such as each station or each hour of the day, and reports the count, MAE and bias for each. A small slice can look bad by chance, so the count matters too.

```python
import pandas as pd
pred = pd.read_parquet("reports/ml/test_predictions.parquet")    # station, ts, y_true, y_pred
pred["err"] = pred["y_pred"] - pred["y_true"]                      # bias > 0: over-predicts
pred["hour_ist"] = pd.to_datetime(pred["ts"]).dt.tz_convert("Asia/Kolkata").dt.hour
overall = pred["err"].abs().mean()
for by in ("station", "hour_ist"):
    t = pred.groupby(by)["err"].agg(n="size", mae=lambda e: e.abs().mean(), bias="mean").round(2)
    t["note"] = (t["n"] < 100).map({True: "insufficient", False: ""})
    t = t.sort_values("mae", ascending=False)
    print(t.head(5).to_string())
    print(f"worst {by}: {t.index[0]} MAE {t['mae'].iloc[0]} vs overall {overall:.2f}\n")
```

Line by line:

- `import pandas as pd` loads pandas and gives it the short name `pd`.
- `pd.read_parquet(...)` reads a Parquet file, a compact table format, into a DataFrame called `pred`. The file holds the test predictions saved by an earlier step.
- `pred["err"] = pred["y_pred"] - pred["y_true"]` creates a new column. Square brackets pick a column by name. This line uses prediction minus actual, which is the opposite sign to the residual used in the next section. The comment says so: a positive bias means over-prediction.
- `pd.to_datetime(pred["ts"])` turns the text timestamps into date-time values. `.dt.tz_convert("Asia/Kolkata")` converts them to IST, and `.dt.hour` keeps only the hour. Without the conversion, the hours would be in UTC and would not match officers' clocks.
- `overall` is the MAE across all test rows, for comparison with each slice.
- `for by in ("station", "hour_ist"):` runs the block twice, once grouping by station and once by hour.
- `groupby(by)` splits the rows into groups. `agg(...)` computes three numbers per group: `n` is the row count (`"size"`), `mae` is a small function that averages the absolute errors, and `bias` is the mean signed error.
- `.round(2)` rounds the table to two decimal places.
- `t["note"]` marks each group with fewer than 100 rows as `insufficient`. `map` looks up each True or False value in the dictionary given.
- `sort_values("mae", ascending=False)` puts the worst group first.
- The first `print` shows the top five rows. The second prints the worst group and compares its MAE with the overall figure. `\n` adds a blank line.

The output has one table per grouping, with the worst groups at the top. You know it worked when the station table shows one row per station and an `n` column that adds up to the number of test rows.

The Technology in Action workbook uses the same idea with a shorter script. It groups absolute errors by station and sorts them. Its result was station ST-04 with a MAE of 6.13, against an overall MAE of 5.18.

```trace
TITLE: Summing absolute errors for each group
CODE:
groups = ["A", "B", "A"]
actual = [10, 10, 20]
predicted = [12, 7, 17]
totals = {}
for g, a, p in zip(groups, actual, predicted):
    totals[g] = totals.get(g, 0) + abs(a - p)
STEPS:
1 :: groups=["A", "B", "A"] :: Three parallel lists, one row per position.
2 :: groups=["A", "B", "A"]; actual=[10, 10, 20] :: The actual values.
3 :: groups=["A", "B", "A"]; actual=[10, 10, 20]; predicted=[12, 7, 17] :: The predictions for the same rows.
4 :: totals={} :: The running totals start empty.
5 :: g="A"; a=10; p=12; totals={} :: Row 1 belongs to group A.
6 :: g="A"; a=10; p=12; totals={"A": 2} :: get returns 0 for a new key, so abs(10 - 12) = 2 is stored.
5 :: g="B"; a=10; p=7; totals={"A": 2} :: Row 2 belongs to group B.
6 :: g="B"; a=10; p=7; totals={"A": 2, "B": 3} :: abs(10 - 7) = 3 is stored under B.
5 :: g="A"; a=20; p=17; totals={"A": 2, "B": 3} :: Row 3 belongs to group A again.
6 :: g="A"; a=20; p=17; totals={"A": 5, "B": 3} :: The A total grows from 2 to 5.
```

Slices must use test-window rows only. Training and cross-validation predictions are too optimistic and will hide the real weak spots.
:::

### Model cards and explainability

A **model card** is a short document, introduced by Mitchell and colleagues in 2019. It states the model's details, its intended and out-of-scope uses, the training data, metrics overall and by slice, limitations and ethical considerations. It works like the leaflet inside a medicine box.

Two tools give evidence for the "why" in the card.

**Permutation importance** shuffles one raw input column in the test inputs, keeps the others as they are, and measures how much the MAE rises. Repeating the shuffle ten times gives a mean and a standard deviation. Because it measures reliance on the test data, it is not biased toward columns with many distinct values in the way a tree's built-in importance is.

**A partial dependence plot (PDP)** varies one input across its range, averages the predictions, and draws the resulting curve. It shows the shape of the effect.

```python
import joblib, yaml
import pandas as pd
from sklearn.inspection import PartialDependenceDisplay, permutation_importance
from src.features import add_target
pipe = joblib.load("models/model_v1.joblib")
cfg = yaml.safe_load(open("config.yaml"))
df = add_target(pd.read_parquet(cfg["data"]["path"])).dropna(subset=[cfg["target"]])
test = df[df["ts"] >= pd.Timestamp(cfg["split"]["test_start"], tz="Asia/Kolkata")]
X, y = test.drop(columns=[cfg["target"]]), test[cfg["target"]]
r = permutation_importance(pipe, X, y, n_repeats=10, random_state=42, scoring="neg_mean_absolute_error")
imp = pd.DataFrame({"mean": r.importances_mean, "std": r.importances_std}, index=X.columns)
print(imp.sort_values("mean", ascending=False).head(5).round(3))   # MAE rise when shuffled
disp = PartialDependenceDisplay.from_estimator(pipe, X, ["humidity"])
disp.figure_.savefig("docs/img/pdp_humidity.png", dpi=150, bbox_inches="tight")
```

Line by line:

- `joblib.load(...)` reads the saved model file, `models/model_v1.joblib`, back into memory as the same pipeline object you trained. This is how the API will use it.
- `yaml.safe_load(open("config.yaml"))` reads the project's settings file. `open` returns a handle to the file, and `safe_load` turns the YAML text into a dictionary.
- `add_target(...)` adds the target column, and `.dropna(subset=...)` removes rows where the target is missing.
- `test = df[df["ts"] >= ...]` keeps only the rows at or after the test start date, in IST.
- `X` holds the inputs and `y` holds the answers. `drop(columns=...)` removes the target column from the inputs.
- `permutation_importance(...)` does the shuffling. `n_repeats=10` shuffles each column ten times. `random_state=42` fixes the shuffle.
- The DataFrame `imp` stores the mean and standard deviation for each column, with the column names as row labels.
- `sort_values` puts the largest reliance first. The comment reminds you what the numbers mean.
- `PartialDependenceDisplay.from_estimator(...)` builds the PDP for the column `humidity`. It must be a raw input column, because the pipeline takes raw inputs.
- `savefig(...)` writes the picture to a PNG file. `dpi=150` sets the resolution and `bbox_inches="tight"` trims the white border.

Expect a table of five rows, each with a mean and std, and a PNG file in `docs/img/`. If the folder `docs/img` does not exist, the save step fails, so create it first.

:::trap Reading importance as causation
Permutation importance shows how much this model relies on a column. It does not show how much that column changes air quality in the real world.
:::

The card must name `models/model_v1.joblib` exactly, the file the API loads. A card that points at another file documents a model nobody is serving.
:::

## What the quiz tests

### Random forests (ensemble-random-forest)

A random forest trains many trees, each on a bootstrap sample of the training rows, and averages their predictions for regression. Averaging lowers variance, which means the answer is less sensitive to the particular rows the model happened to see. Bootstrap samples are drawn with replacement, and each tree usually sees about two-thirds of the distinct rows. Expect examiners to ask which parameter controls leaf size and why. The trap is to say that a forest fits trees one after another; that describes boosting.

### Gradient boosting (ensemble-boosting)

Boosting adds shallow trees one stage at a time, and each new tree is fitted to the residuals left by the earlier stages. It mainly reduces bias. Its main settings are the number of stages, the learning rate and the depth of each tree; a smaller learning rate usually needs more stages. The trap is to think boosting averages independent trees. HistGradientBoosting bins features first, which makes it faster on large tables.

### Feature importance (ensemble-feature-importance)

A tree's built-in `feature_importances_` is computed from the training data, and it favours columns with many distinct values. Permutation importance is computed on held-out data by shuffling one column and measuring how much the error rises. Both tell you how much the model relies on a column. Neither tells you that the column causes the outcome. The trap is to read a high value as a cause.

### Residuals (error-analysis-residuals)

The residual is actual minus predicted. A mean residual near zero means no systematic skew, because positive and negative errors cancel. A negative mean means predictions are, on average, slightly above the actual values. The worst absolute residual shows the single largest miss, and the residual standard deviation shows the typical spread. The trap is to report only the mean: a small bias can coexist with a large single miss.

### Slicing (error-analysis-slicing)

Slice analysis groups test rows by a column such as station or IST hour and reports n, MAE and bias for each group. The worst group by MAE becomes a finding, and it becomes a limitation in the card. Always show n, and flag groups with fewer than 100 rows as insufficient evidence. The trap examiners set is a slice with 12 rows that looks terrible by chance, and a grouping done in UTC instead of IST.

### Ensemble diversity (ensemble-diversity)

Averaging helps when the models make different errors. If three models have almost the same errors on almost every row, their average has almost the same errors as each one. Diversity can come from different algorithms, different training samples or different inputs. Expect examiners to ask why adding a fourth copy of a good model adds nothing. The trap is to assume that more models always means a better average.

### Intended use (model-card-intended-use)

The intended-use section names who uses the model, for what decision and on what inputs. The out-of-scope section names uses the model was not built or tested for. For CityPulse, the intended use is a short-horizon pollution signal for officers. Out-of-scope uses include individual medical decisions. The trap is to write a vague intended use such as "for air quality". A reviewer cannot test that sentence.

### Disaggregated metrics (model-card-disaggregated-metrics)

A card reports the overall metric and the same metric for each important group, with the count for each group. This is how an overall figure is kept from hiding a weak group. The disaggregated numbers should match the slice tables. The trap is to report only the overall MAE and call the model "fair", which needs evidence that the card does not contain.

### Trees and the number of estimators (ensemble-n-estimators-tradeoff)

More trees in a random forest lower variance, but the gains flatten out. Each extra tree costs fit time and file size. The sensible choice is the smallest count after which the cross-validated MAE stops improving by more than the fold standard deviation. For boosting, too many stages can overfit, so the count is also tuned. The trap is to pick the largest count because it looks best on one split.

### Training data (model-card-training-data)

The card states the source, the date range, the number of rows, the features and the split used for training and testing. It must say what the training data does not cover. The CityPulse workbook gives a limit of one week of January data and no monsoon regime. The trap is to describe the data without the limits that follow from it.

## Graded lab skill

The graded lab asks you to write a few Python functions. Three techniques cover most of it.

**Lists and loops.** A list is an ordered sequence. `len(xs)` gives its length. `for x in xs:` visits each item. Both lists must be the same length when you compare them row by row, so check the lengths first.

**`zip`.** `zip(a, b)` pairs item 0 of `a` with item 0 of `b`, then item 1 with item 1, and stops at the shorter list. `for x, y in zip(a, b):` gives you the matching pairs. Use `*` before a list of lists, as in `zip(*forecasts)`, to take the lists apart and pair up the positions across all of them.

**Dictionaries as totals.** `totals.get(key, 0)` returns the stored value, or 0 if the key is new. Adding to it and storing it back builds a running total for each group. Divide the total by the count to get a mean.

The trace below shows the averaging technique in full. It was placed in the tools section too, so it is not repeated as a second animation here.

Next comes the practice problem. It is an original task, and it trains the same three skills as the graded lab.

:::tip Practice problem
Rainfall forecasts come from three models for the same list of test days. Write three functions:

1. `ensemble_forecast(*forecasts)` takes one or more forecast lists and returns one list, where each position is the average of that position across all the lists.
2. `residuals(actual, predicted)` returns actual minus predicted for each row.
3. `mae_by_group(groups, actual, predicted)` returns a dictionary from each group label, such as a city, to the MAE for that group.

Add `worst_group(mae)`, which returns the group with the highest MAE. If two groups tie, return the one that comes first alphabetically.

Example: `ensemble_forecast([10, 20, 30], [12, 18, 30], [11, 19, 27])` returns `[11.0, 19.0, 29.0]`. `residuals([10, 20], [12, 18])` returns `[-2, 2]`.
:::

Edge-case checklist for hidden tests:

- Empty input: an empty list of forecasts, or lists with no rows.
- Mismatched lengths: raise `ValueError`, do not guess.
- Ties: two groups with the same MAE.
- Ordering: the averaging must keep the day order, and the worst group must not depend on dictionary order.
- Types: integers and decimals should both work. Division with `/` always gives a float.
- Rounding: do not round inside the functions unless asked. The checks compare the exact values.
- Missing groups: a city with no rows does not appear in the result; do not invent it.

:::answer Full solution and explanation
```python test
def ensemble_forecast(*forecasts):
    """Average several forecast lists position by position."""
    if not forecasts:
        raise ValueError("need at least one forecast list")
    if len({len(f) for f in forecasts}) != 1:
        raise ValueError("forecast lists must have the same length")
    count = len(forecasts)
    return [sum(values) / count for values in zip(*forecasts)]


def residuals(actual, predicted):
    if len(actual) != len(predicted):
        raise ValueError("actual and predicted must have the same length")
    return [a - p for a, p in zip(actual, predicted)]


def mae_by_group(groups, actual, predicted):
    if not (len(groups) == len(actual) == len(predicted)):
        raise ValueError("all inputs must have the same length")
    totals = {}
    for g, a, p in zip(groups, actual, predicted):
        total, count = totals.get(g, (0.0, 0))
        totals[g] = (total + abs(a - p), count + 1)
    return {g: total / count for g, (total, count) in totals.items()}


def worst_group(mae):
    if not mae:
        raise ValueError("no groups to compare")
    return min(mae, key=lambda g: (-mae[g], g))


def raises(error, fn, *args):
    try:
        fn(*args)
    except error:
        return True
    return False


# ensemble_forecast
assert ensemble_forecast([10, 20, 30], [12, 18, 30], [11, 19, 27]) == [11.0, 19.0, 29.0]
assert ensemble_forecast([5.0]) == [5.0]
assert ensemble_forecast([]) == []
assert raises(ValueError, ensemble_forecast)
assert raises(ValueError, ensemble_forecast, [1, 2], [1])

# residuals
assert residuals([10, 20, 30], [12, 18, 30]) == [-2, 2, 0]
assert residuals([], []) == []
assert raises(ValueError, residuals, [1, 2], [1])

# mae_by_group
groups = ["Ajmer", "Pune", "Ajmer", "Pune"]
actual = [10, 10, 20, 20]
predicted = [12, 7, 17, 20]
assert mae_by_group(groups, actual, predicted) == {"Ajmer": 2.5, "Pune": 1.5}
assert mae_by_group([], [], []) == {}
assert raises(ValueError, mae_by_group, ["A"], [1, 2], [1, 2])

# worst_group
assert worst_group({"Ajmer": 2.5, "Pune": 1.5}) == "Ajmer"
assert worst_group({"Pune": 2.0, "Delhi": 2.0, "Chennai": 1.0}) == "Delhi"
assert raises(ValueError, worst_group, {})

print("all checks passed")
```

Line by line, in the order the file runs:

- `ensemble_forecast(*forecasts)` takes any number of lists. The `*` gathers them into a tuple called `forecasts`.
- `if not forecasts:` is true when no list was given. `raise ValueError` stops the function with an error, which is what the checks expect.
- `{len(f) for f in forecasts}` is a set of the lengths. A set keeps only distinct values, so the set has exactly one item when all lengths match.
- `zip(*forecasts)` takes the lists apart and yields one tuple per position, such as `(10, 12, 11)`.
- `sum(values) / count` averages that tuple. Dividing by `count` (the number of lists) keeps the division exact for these numbers.
- `residuals` uses a list comprehension, `[a - p for a, p in zip(...)]`, which builds a new list of differences.
- `mae_by_group` keeps a dictionary of `(total, count)` pairs. `totals.get(g, (0.0, 0))` returns a new pair of zeros for a city it has not seen yet.
- The last line of the loop stores the new total and count. The dictionary comprehension at the end divides each total by its count.
- `worst_group` uses `min` with a key. The key `(-mae[g], g)` sorts by the largest MAE first, because the value is negated, and then alphabetically for ties.
- `raises` runs a function and returns True only if the named error was raised. It lets the checks test error cases.
- The `assert` lines check each function against the examples and the edge cases. If any check is false, the file stops with an error, which is what the build reports.
- The `print` runs only if every check passes, so the output is `all checks passed`.
:::

## Say it out loud

**Q1. Why does a random forest use bootstrap samples?**
:::answer Model answer
Each tree sees a different random sample of the training rows, drawn with replacement. Because the trees see different data, their errors differ, and averaging them lowers the variance of the forest. Without this variation, every tree would make the same error, and the average would gain nothing.
:::

**Q2. How does gradient boosting differ from a random forest?**
:::answer Model answer
A random forest trains independent trees in parallel and averages them. Gradient boosting trains shallow trees one after another, and each new tree is fitted to the errors left by the trees before it. The forest mainly reduces variance, and boosting mainly reduces bias. For that reason the two need different tuning.
:::

**Q3. Why did you slice the errors by station and hour, when the overall MAE was already known?**
:::answer Model answer
An overall MAE averages away local failures. A model can have a reasonable average and still be badly wrong for one station or one time band. Slicing shows where it fails, and the count for each slice shows how much evidence supports the finding. Officers act per ward and hour, so that is the level at which the risk matters.
:::

**Q4. A slice has only 12 rows and a very high MAE. What do you do?**
:::answer Model answer
I report the slice with its count and flag it as insufficient evidence, because 12 rows can look terrible by chance. I do not remove it, and I do not retrain on the test rows to improve it. I would collect more data for that group before drawing a firm conclusion.
:::

**Q5. What belongs in a model card, and why does it matter?**
:::answer Model answer
A model card states what the model is for, what it is not for, what data it was trained on, the metrics overall and by slice, and its known limits. It matters because a reviewer or officer can only trust a model when they know where it is weak. A card with specific numbers and named segments lets someone check the claims, while a vague card does not.
:::
