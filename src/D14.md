TITLE: Day 14 — Virtual machines: EC2, SSH and hardening
SUB: You will be able to launch a tagged cloud server that accepts SSH only from your own IP address and your own key, harden its SSH settings, prove the result, and shut everything down cleanly.

## The idea in one minute

Today you rent a computer that sits in an Amazon data centre and control it from your laptop. Think of it as renting a flat and holding the only key. Every flat has a gate, and anyone on the street can knock on it. So you will close the gate to everyone except your own address, make sure only your key opens the door, switch off the older, weaker ways of getting in, and then check each change with a command. By the end you will be able to launch the server, connect to it, prove it is locked down, and delete what you created so that you are not billed for it.

## Starting from zero

This section defines every word the day depends on. Read it once before the tools section.

**Computer and server.** A computer is a machine that runs programs. A server is a computer that runs programs for other computers to use, and it normally stays switched on. Your laptop is a computer. A web server that answers website requests is a server.

**Cloud and virtual machine.** The cloud means renting computers, storage and other services from a company over the internet. A virtual machine (VM) is a computer that exists as software running on someone else's physical hardware. The VM behaves like a real computer: it has its own operating system, its own files and its own network address. Amazon Web Services (AWS) is the company used in this course, and its VM service is called EC2.

**Terminal.** The terminal is a window where you type text instead of clicking. Everything in today's lab happens in a terminal. On Windows, use Git Bash or WSL so that the commands in this chapter work as written.

**Command.** A command is one line of text that the computer runs. For example, `ls` lists the files in the current folder. The program that reads and runs your commands is called the shell.

**Flag.** A flag is an option added to a command. Flags usually start with a dash. In `ls -l`, the `-l` is a flag that asks for a long listing. In `aws ec2 describe-instances --instance-ids i-123`, the `--instance-ids` flag says which instance you mean, and `i-123` is its value.

**Variable.** A variable is a named box that holds a value. `NAME=asha` puts the text asha into a box called NAME. Writing `$NAME` later means "the value in that box". Variables exist only in the terminal session where you set them, so if you open a new terminal you must set them again.

**File and directory.** A file holds data. A directory is a folder that holds files. The symbol `~` means your home directory. `~/.ssh` is a directory in your home folder that holds SSH keys.

**Server, IP address and port.** Every machine on a network has an IP address, which works like a postal address. A public IP address can be reached from the internet. A port is a numbered door on that machine. A service listens on a port, and clients connect to it. SSH uses port 22.

**CIDR notation.** CIDR is a short way to write a range of IP addresses. `203.0.113.47/32` means exactly one address. `0.0.0.0/0` means every address, which is the whole internet. You will meet both in this chapter.

**Firewall and security group.** A firewall is software that allows or blocks network traffic according to rules. An AWS security group is a firewall attached to a VM. Its rules say which ports and which source addresses may connect in.

**Key pair.** A key pair is two linked files. The private key is secret and stays on your computer. The public key can be shared and is stored on the server. Only the matching private key can prove that you are the owner of the public key. This is how SSH logs you in without a password.

**SSH.** SSH stands for Secure Shell. It gives you an encrypted connection to a remote machine's shell, so you can type commands there as if you were sitting in front of it. The SSH server program is called `sshd`. The `d` stands for daemon, which means a program that runs in the background and waits for connections.

**Patching.** Patching means installing updated software that fixes known security bugs. Ubuntu provides updates through a package manager, the program that installs and upgrades software.

**Stateful.** A stateful firewall remembers the connections it has allowed. If it lets your SSH connection in, it automatically lets the replies go back out. You do not need a separate outbound rule for those replies.

## The tools

### Amazon EC2

**What it is.** EC2 rents virtual machines by the second. You choose an image, which is a saved copy of an operating system with software already installed, called an AMI (Amazon Machine Image). You choose a size, called an instance type. The instance type `t3.micro` is a small, low-cost size. You also choose network rules and a login key. Each running VM is called an instance.

**Why CityPulse uses it.** The CityPulse pipeline needs an always-on Linux host that runs `cron`. Cron is a scheduler that runs commands at fixed times, such as every 15 minutes. Your laptop cannot be relied on for that. The pipeline script `run_pipeline.sh`, its Python virtual environment and the `sqlite3` database all run unchanged on Ubuntu 24.04, so the move to the cloud needs no rewrite. A `t3.micro` in the Mumbai region `ap-south-1` is cheap, and the habit of tagging and stopping it teaches cost control.

The slides list three alternatives. AWS Lambda has no server to patch and is billed per run, but it has time limits and packaging constraints, and it arrives later in the course. Amazon Lightsail offers simpler fixed-price VMs, but it hides the security groups and roles that this course wants you to learn. ECS with Fargate runs containers, which is better for many services but needs Docker and more setup, and it is covered in Year III.

**How it works.** One command, `run-instances`, combines an image, a size, network rules, a login key and an AWS identity into one running server. Tags are labels such as `Owner=asha` that make each resource easy to find when you need to count its cost or tear it down. Stopping an instance halts compute charges, but the disk is kept. Terminating an instance deletes it, and the disk goes with it.

**The slide code.** The slide code is shown below with its line breaks restored. Each line is explained after the block.

```bash
NAME=asha; export AWS_PROFILE=$NAME-admin AWS_REGION=ap-south-1
AMI=$(aws ssm get-parameter --name /aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id --query Parameter.Value --output text)
SG_ID=$(aws ec2 describe-security-groups --group-names "citypulse-ssh-$NAME" --query 'SecurityGroups[0].GroupId' --output text)
ID=$(aws ec2 run-instances --image-id "$AMI" --instance-type t3.micro \
  --key-name "citypulse-$NAME" --security-group-ids "$SG_ID" \
  --iam-instance-profile Name=citypulse-pipeline \
  --metadata-options HttpTokens=required,HttpEndpoint=enabled \
  --tag-specifications "ResourceType=instance,Tags=[{Key=Owner,Value=$NAME},{Key=Project,Value=citypulse},{Key=Env,Value=lab}]" \
  --query 'Instances[0].InstanceId' --output text)
aws ec2 wait instance-running --instance-ids "$ID"
aws ec2 describe-instances --instance-ids "$ID" --query 'Reservations[0].Instances[0].[State.Name,PublicIpAddress]' --output text
# end of day:
aws ec2 stop-instances --instance-ids "$ID"
```

Line by line:

1. `NAME=asha` stores your name in the variable NAME. `export` makes the variables after it visible to programs started from this terminal, including the `aws` program. `AWS_PROFILE=$NAME-admin` tells the AWS tool which saved set of credentials to use. `AWS_REGION=ap-south-1` selects the Mumbai region.
2. `AMI=$(...)` runs the command inside the brackets and stores its output in AMI. The command asks AWS Systems Manager for the official Ubuntu 24.04 image ID. `--query Parameter.Value` picks out just the value from the JSON reply, and `--output text` prints it as plain text. Using the official parameter avoids a random image published by a stranger.
3. `SG_ID=$(...)` looks up the ID of the security group you created in lab step 2. `--group-names` takes a name, and `--query 'SecurityGroups[0].GroupId'` takes the first match's ID.
4. `ID=$(aws ec2 run-instances ...)` starts the VM. `--image-id` gives the image. `--instance-type t3.micro` gives the size. `--key-name` names the public key AWS installs on the VM. `--security-group-ids` attaches the firewall. The backslash `\` at the end of a line tells the shell that the command continues on the next line.
5. `--iam-instance-profile Name=citypulse-pipeline` attaches the role for the VM. The profile must already exist, which is set up in the instance roles part of the slides. If it is missing, the launch fails.
6. `--metadata-options HttpTokens=required` forces IMDSv2, which is the session-token version of the instance metadata service. You will see why in the instance roles section.
7. `--tag-specifications` attaches three tags to the instance. `Owner` tells you whose VM it is, and `Env=lab` marks it as a lab resource.
8. `--query 'Instances[0].InstanceId'` picks the new instance's ID, and the ID is stored in ID.
9. `aws ec2 wait instance-running` pauses until the instance reports the running state. Without it, the next command might run too early.
10. `describe-instances` prints the state and public IP address. You should see one line such as `running 13.200.45.67`. The address will be different for you.
11. `stop-instances` halts the instance at the end of the day. The `# end of day:` line is a comment. The shell ignores anything after `#`.

:::trap Leaving the VM running overnight
A running `t3.micro` is billed every second, even if nobody uses it. Stop it by 15:30 and check the console, filtered by the `Owner` tag, to be sure nothing else is running.
:::

:::trap Picking a random community image
Resolve the official Ubuntu image from the SSM parameter, as the slide does. Do not search for an image by name, because anyone can publish one.
:::

:::trap Hard-coding the public IP
Stopping and starting an instance changes its public IP address. Look it up again after each start with `describe-instances`. Never write the address into a script.
:::

### SSH keys and security groups

**What it is.** A key pair logs you in. AWS stores the public half and installs it on the VM. The private half stays in a `.pem` or key file on your laptop. The security group is the firewall that decides who may reach the VM at all.

**Why CityPulse uses it.** Internet-facing SSH with passwords is attacked within minutes by automated scanners that try common passwords. The lesson requires key-only login. Restricting port 22 to `<your-ip>/32` removes the server from the reach of nearly every scanner. Setting `PermitRootLogin no` and `KbdInteractiveAuthentication no` closes the remaining easy routes in.

The slides list three alternatives. AWS Systems Manager Session Manager opens no inbound port at all, but it needs an agent and extra IAM setup. EC2 Instance Connect pushes short-lived keys, but it still needs port 22 open. Opening port 22 to `0.0.0.0/0` is easy from anywhere, but it fails the course gate.

**How it works.** The private key never leaves your laptop. The security group filters traffic before it reaches the VM. The sshd drop-in file disables password and root logins. Before you reload sshd, you check the config file for errors and keep one session open, so that a mistake does not lock you out.

**The slide code.** The following block is the key, security group and sshd part of the slides, with line breaks restored.

```bash
NAME=asha; export AWS_PROFILE=$NAME-admin AWS_REGION=ap-south-1
ssh-keygen -t ed25519 -f ~/.ssh/citypulse-$NAME -C "$NAME@citypulse"
aws ec2 import-key-pair --key-name "citypulse-$NAME" --public-key-material "fileb://$HOME/.ssh/citypulse-$NAME.pub"
SG_ID=$(aws ec2 create-security-group --group-name "citypulse-ssh-$NAME" --description "SSH from operator IP only" --query GroupId --output text)
aws ec2 authorize-security-group-ingress --group-id "$SG_ID" --protocol tcp --port 22 --cidr "$(curl -s https://checkip.amazonaws.com)/32"
# on the VM, keeping this session open:
sudo tee /etc/ssh/sshd_config.d/99-citypulse.conf >/dev/null <<'EOF'
PasswordAuthentication no
PermitRootLogin no
KbdInteractiveAuthentication no
EOF
sudo sshd -t && sudo systemctl reload ssh
sudo sshd -T | grep -Ei 'passwordauthentication|permitrootlogin|kbdinteractive'
```

Line by line:

1. Sets the NAME variable and the AWS profile and region, as before.
2. `ssh-keygen` creates a key pair on your laptop. `-t ed25519` chooses the modern ed25519 algorithm. `-f ~/.ssh/citypulse-$NAME` sets the file path for the private key. The public key is saved next to it with `.pub` added. `-C` adds a comment, which is a label stored inside the public key so you can recognise it later.
3. `import-key-pair` uploads the public key to AWS under the name `citypulse-$NAME`. `--public-key-material` takes the public key content. The `fileb://` prefix means "read this file as raw bytes", and `$HOME` is your home directory.
4. `create-security-group` makes a new, empty firewall. `--description` is a note for humans. `--query GroupId --output text` prints just the ID, which is stored in SG_ID. A new security group has no inbound rules, so everything is blocked until you add one.
5. `authorize-security-group-ingress` adds one inbound rule. `--protocol tcp` and `--port 22` allow SSH. `--cidr` sets the source. `$(curl -s https://checkip.amazonaws.com)` runs `curl`, which fetches a web page, and `-s` hides its progress meter. The page returns your current public IP. `/32` makes the rule cover that single address.
6. The `# on the VM` line is a comment for you. The text after `sudo tee` is run on the VM, not on your laptop. `sudo` runs the next command with administrator rights. `tee` writes its input to a file, and `>/dev/null` hides the copy that `tee` would otherwise print to the screen.
7. `<<'EOF'` starts a "here document". Every line until the next `EOF` is sent to `tee` as file content. Quoting `'EOF'` stops the shell from changing `$` signs inside the text.
8. The three lines inside the file turn off password logins, root logins and keyboard-interactive logins, which is another way of typing a password.
9. `sudo sshd -t` checks the configuration for syntax errors and prints nothing when it is valid. The `&&` means "only if the previous command succeeded". `systemctl reload ssh` tells the running SSH service to read the new config without dropping existing connections.
10. `sudo sshd -T` prints the effective settings that sshd will really use. `grep -Ei` filters the lines. `-E` allows the `|` alternatives, and `-i` ignores upper and lower case.

:::trap A drop-in file can be overridden
sshd uses the first value it reads for each setting. Files in `sshd_config.d` are read in name order, so an earlier file such as `00-something.conf` can override your `99-citypulse.conf`. Always confirm with `sshd -T`, not by reading your own file.
:::

:::trap Reloading with a typo
If you reload sshd with a broken config and close your only session, you cannot get back in. Run `sshd -t` first, and keep one session open until a second, new session has logged in successfully.
:::

:::trap Loose key permissions
SSH refuses a private key that others can read. The key you make with `ssh-keygen` is already restricted. If you copy a key somewhere else, restore the restriction with `chmod 600` (owner can read and write) or `chmod 400` (owner can only read). Never commit a key to Git.
:::

### Instance roles

**What it is.** An instance role is an IAM role attached to an EC2 instance through an instance profile. IAM, which stands for Identity and Access Management, controls who may do what to which AWS resource. A role is a set of permissions that software can use temporarily. Software on the VM asks the instance metadata service (IMDS) for short-lived credentials. Those credentials rotate automatically, so no permanent access key is stored on disk.

**Why CityPulse uses it.** Gate T19 forbids long-lived keys on the VM. The folder `~/.aws` must not exist, and no `AWS_ACCESS_KEY_ID` variable may be set. The role reuses the policy `citypulse-pipeline-s3`, so the VM has the same scoped access as the user from the previous ticket. IMDSv2 protects against credential-theft tricks in which an attacker makes the server fetch its own credentials. The slides mention a well-known breach in which that technique was used.

The alternatives are copying the user's keys onto the VM, which works but never expires and leaks with any disk snapshot, or putting secrets in environment variables, which are still long-lived keys. IAM Roles Anywhere is for servers outside AWS and is not needed for an EC2 host.

**How it works.** A role has two policies. The trust policy says who may take the role, here the EC2 service. The permissions policy says what the role may do. The instance profile carries the role onto the VM. Once there, the AWS CLI and the Python library boto3 ask IMDSv2 for credentials automatically.

**The slide code.** The following block creates the role and attaches it to the instance, then checks the VM. Line breaks are restored.

```bash
ACCT=$(aws sts get-caller-identity --query Account --output text)
aws iam create-role --role-name citypulse-pipeline \
  --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ec2.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
aws iam attach-role-policy --role-name citypulse-pipeline --policy-arn "arn:aws:iam::$ACCT:policy/citypulse-pipeline-s3"
aws iam create-instance-profile --instance-profile-name citypulse-pipeline
aws iam add-role-to-instance-profile --instance-profile-name citypulse-pipeline --role-name citypulse-pipeline
aws ec2 associate-iam-instance-profile --instance-id "$ID" --iam-instance-profile Name=citypulse-pipeline
aws ec2 modify-instance-metadata-options --instance-id "$ID" --http-tokens required --http-endpoint enabled
# on the VM: no stored keys, yet AWS calls work
ls -la ~/.aws 2>/dev/null || echo "no ~/.aws"
env | grep AWS_ACCESS_KEY_ID || echo "no key variable"
aws sts get-caller-identity --query Arn --output text
```

Line by line:

1. `aws sts get-caller-identity` asks AWS who you are. `--query Account` picks the 12-digit account number, and it is stored in ACCT.
2. `create-role` makes the role. `--role-name` is its name. The JSON after `--assume-role-policy-document` is the trust policy. `"Service":"ec2.amazonaws.com"` means the EC2 service may take this role. The single quotes keep the JSON together for the shell, and the backslash continues the line.
3. `attach-role-policy` adds the permissions policy to the role. `--policy-arn` is the full name of the policy. An ARN (Amazon Resource Name) is a unique address for an AWS object.
4. `create-instance-profile` makes the container that carries a role onto a VM.
5. `add-role-to-instance-profile` puts the role inside that profile.
6. `associate-iam-instance-profile` attaches the profile to your running instance, using `$ID`.
7. `modify-instance-metadata-options` changes an existing instance to require IMDSv2 (`--http-tokens required`) and keeps the metadata endpoint on.
8. On the VM, `ls -la ~/.aws` lists the hidden folder with details. `2>/dev/null` hides the error if the folder does not exist, and `||` runs the `echo` only when `ls` failed. A success message means no stored keys.
9. `env` prints the environment variables, and `grep AWS_ACCESS_KEY_ID` shows only the one you care about. `||` again runs the message if nothing matched.
10. `get-caller-identity --query Arn` prints who the VM is now. The answer should contain `assumed-role/citypulse-pipeline`, not `user/`.

Expected output from the last command looks like this:

```term
$ aws sts get-caller-identity --query Arn --output text
arn:aws:sts::123456789012:assumed-role/citypulse-pipeline/i-0a1b2c3d4e5f6a7b8
```

Here the `123456789012` is a placeholder for your 12-digit account number, and the `i-...` part is your instance ID.

The next diagram shows where the temporary credentials come from.

```flow
TITLE: How the VM gets temporary credentials
NODES: EC2 instance and CLI | Instance metadata service | AWS services
STEPS:
1>2 :: ask for a session token :: The CLI on the VM first asks the metadata service for a token. This is the IMDSv2 step.
2>1 :: session token :: The service answers only requests that carry the token, which blocks many theft tricks.
1>2 :: ask for role credentials :: The CLI presents the token and asks which role this VM holds.
2>1 :: short-lived keys :: The service returns keys that expire after a short time and are replaced automatically.
1>3 :: signed request :: The CLI calls AWS with those keys, and AWS checks the role's permissions.
```

:::trap Attaching the policy to the user, not the role
The policy `citypulse-pipeline-s3` must be attached to the role with `attach-role-policy`. Attaching it to the user `citypulse-pipeline` does nothing for the VM.
:::

:::trap Leftover credentials override the role
If `~/.aws/credentials` exists on the VM, the CLI uses it instead of the role. Delete the file. The gate checks that it does not exist.
:::

:::trap Launching too early
A new instance profile may not be visible for a few seconds. If the launch fails with a message about the profile, wait and retry.
:::

### Runbooks

**What it is.** A runbook is a written document of step-by-step procedures that you can copy and paste, for example how to launch, connect, deploy, stop and recover a system. A good runbook is tested by someone other than its author and is stored in the same repository as the code, so that it is reviewed like code.

**Why CityPulse uses it.** When an intern's IP address changes or sshd breaks, the fix must be found in minutes, not rediscovered. The slides also cite the October 2021 outage at Facebook, in which engineers were locked out of their own systems because the recovery path was not ready. Gate T19 requires `docs/cloud-runbook.md` with five sections, and each section must be dry-run and initialled by a squad member.

The alternatives are tribal knowledge, which fails when the expert is absent; full automation with Terraform or SSM documents, which is best long term but still needs recovery steps that a human can run; and wiki pages far from the code, which drift out of date and are not reviewed in pull requests.

**How it works.** Each section starts from a symptom, gives a quick diagnosis, and then gives exact commands to fix and verify. The recovery section for a changed public IP looks like this, with line breaks restored.

```bash
# Symptom: ssh to the VM times out after moving networks
NAME=asha; export AWS_PROFILE=$NAME-admin AWS_REGION=ap-south-1
SG_ID=$(aws ec2 describe-security-groups --group-names "citypulse-ssh-$NAME" --query 'SecurityGroups[0].GroupId' --output text)
OLD=$(aws ec2 describe-security-groups --group-ids "$SG_ID" --query 'SecurityGroups[0].IpPermissions[?FromPort==`22`].IpRanges[0].CidrIp' --output text)
NEW="$(curl -s https://checkip.amazonaws.com)/32"
echo "rule allows $OLD, you are $NEW"
aws ec2 revoke-security-group-ingress --group-id "$SG_ID" --protocol tcp --port 22 --cidr "$OLD"
aws ec2 authorize-security-group-ingress --group-id "$SG_ID" --protocol tcp --port 22 --cidr "$NEW"
IP=$(aws ec2 describe-instances --filters "Name=tag:Owner,Values=$NAME" "Name=instance-state-name,Values=running" --query 'Reservations[0].Instances[0].PublicIpAddress' --output text)
ssh -i ~/.ssh/citypulse-$NAME ubuntu@"$IP" 'aws sts get-caller-identity --query Arn --output text'
```

Line by line:

1. The first line starting with `#` is a heading for the reader. It is not run.
2. The first two commands set the variables again, because a new terminal starts empty.
3. `OLD=$(...)` reads the address currently allowed on port 22. The `--query` expression filters the rules to those whose `FromPort` is 22. The backticks inside the quotes are part of the JMESPath query language that `--query` uses, and they mark a literal number.
4. `NEW=` builds your new address in the same `/32` form.
5. `echo` prints both addresses so that you can read them before anything changes.
6. `revoke-security-group-ingress` removes the old rule. This is the only removal in the block.
7. `authorize-security-group-ingress` adds the rule for the new address.
8. `describe-instances --filters` finds the running instance tagged with your name. `Name=tag:Owner,Values=...` matches the tag set at launch.
9. `ssh -i` connects with your key. The text in quotes is run on the VM, and it proves the role is still working.

:::trap Steps that cannot be run
A step such as "fix the security group" is not a runbook step. Write the exact command with its variables, as the block above does.
:::

:::trap A runbook never tested
A runbook that has never been run is a guess. Have a teammate dry-run each section and initial it before you rely on it.
:::

:::trap Opening 0.0.0.0/0 temporarily
It is tempting to open port 22 to everyone "just for now" to recover. Do not do it. Replace the `/32` rule instead, because temporary rules are the ones that get forgotten.
:::

## The worked example

This example uses the names from the Technology in Action workbook: an instance called `citypulse-worker`, a `t3.small` size, the Amazon Linux user `ec2-user`, and a security group `sg-0cp42`. The lab later in this chapter uses the names from the course slides, which are `citypulse-$NAME`, `t3.micro` and `ubuntu`. The commands have the same shape, so the example shows you the method.

**Goal.** Connect to a VM that is reachable only from your own IP, using a key that has been locked down.

**Step 1: lock the private key.** Run the following command on your laptop.

```bash
chmod 400 citypulse-worker.pem
```

`chmod` changes the permissions of a file. The number `400` means the owner can read the file and nobody can write or execute it. The workbook's `400` and the slides' `600` both pass, because SSH only refuses keys that group members or other users can read.

**Step 2: open port 22 to your IP.**

```bash
aws ec2 authorize-security-group-ingress \
  --group-id sg-0cp42 --protocol tcp --port 22 \
  --cidr "$(curl -s ifconfig.me)/32"
```

This adds a single inbound rule. `ifconfig.me` is a website that returns your public IP address, the same job that `checkip.amazonaws.com` does in the lab. The rule allows SSH from that address and no other.

**Step 3: connect.**

```bash
ssh -i citypulse-worker.pem ec2-user@54.12.9.108
```

`ssh` opens the connection. `-i citypulse-worker.pem` tells it which private key to use. `ec2-user@54.12.9.108` means "log in as the user `ec2-user` at this address". The first time you connect, ssh asks whether you trust the host, and you type `yes`. The output then ends with a prompt that looks like this:

```term
$ ssh -i citypulse-worker.pem ec2-user@54.12.9.108
Are you sure you want to continue connecting (yes/no)? yes
[ec2-user@citypulse-worker ~]$ uptime
 09:14:02 up 3 min,  1 user,  load average: 0.08, 0.03, 0.01
```

The `uptime` command shows how long the machine has been running. A small uptime shows that you are on a freshly booted machine. The `~` in the prompt means you are in your home directory.

**Step 4: check the result.** The rules should now show only SSH from your address. The slide example also keeps port 443 open for the API, but that port is not part of the lab.

:::key Why the worked example matters
Every later step depends on three facts: the key file is private, the security group allows only one address, and the server accepts only key-based logins. You check each one with a command, not by trusting that it worked.
:::

## The hands-on lab, step by step

Work through these seven steps in order. Step 2 must come before step 3, because the launch needs the security group ID. Use the names from the course slides, since the checks below rely on them.

Before you start, open a terminal and check that you have the AWS command-line tool, which is the program called `aws`. Run `aws --version`. You should see a line beginning with `aws-cli/`. Your course set-up gave you an AWS profile named after you, such as `asha-admin`. If the profile is missing, stop and ask your instructor. Do not create new credentials yourself.

Every new terminal needs the variables set again. Run `NAME=asha; export AWS_PROFILE=$NAME-admin AWS_REGION=ap-south-1` each time, and use your own name in place of `asha`.

:::trap Mixing up the two versions
Some reference material describes a `t3.small` instance with the user `ec2-user` and an RSA key. That is the workbook version. The lab uses the names and commands in this chapter. If a name in your terminal does not match, check which version you copied from.

### Step 1: Create a key pair

**What you do.** Make a new ed25519 key pair on your laptop, then upload the public half to AWS.

**What you type.**

```bash
ssh-keygen -t ed25519 -f ~/.ssh/citypulse-$NAME -C "$NAME@citypulse"
aws ec2 import-key-pair --key-name "citypulse-$NAME" --public-key-material "fileb://$HOME/.ssh/citypulse-$NAME.pub"
```

**What you should see.** `ssh-keygen` prints two lines starting with `Your identification has been saved` and `Your public key has been saved`. `import-key-pair` prints JSON with your key name and a fingerprint, which is a short code that identifies the key.

**How you know it worked.** Run `aws ec2 describe-key-pairs --key-names "citypulse-$NAME"`. It should list one key pair with the same name. The file `~/.ssh/citypulse-asha` (with your name) exists on your laptop, and the `.pub` file beside it holds the public key.

### Step 2: Create a tight security group

**What you do.** Create an empty firewall for your VM and add one rule that allows SSH from your current IP address only.

**What you type.**

```bash
SG_ID=$(aws ec2 create-security-group --group-name "citypulse-ssh-$NAME" --description "SSH from operator IP only" --query GroupId --output text)
aws ec2 authorize-security-group-ingress --group-id "$SG_ID" --protocol tcp --port 22 --cidr "$(curl -s https://checkip.amazonaws.com)/32"
```

**What you should see.** The first command prints nothing, because its output went into `SG_ID`. The second prints JSON that contains your rule. Its CIDR ends in `/32`.

**How you know it worked.** Run this:

```bash
aws ec2 describe-security-groups --group-ids "$SG_ID" --query 'SecurityGroups[0].IpPermissions[*].[FromPort,IpRanges[0].CidrIp]' --output text
```

The output should be one line: `22` followed by your address and `/32`. If you see `0.0.0.0/0`, delete the rule and fix the command before you go on.

### Step 3: Launch a t3.micro

**What you do.** Start a small VM with your key, your firewall, the instance profile and IMDSv2.

**What you type.** Use the launch block from the EC2 section above, exactly as written. Its first lines set `NAME`, look up the Ubuntu image, and look up `$SG_ID`. The launch line then creates the instance.

**What you should see.** The launch returns an instance ID that starts with `i-`. The wait command returns without output when the instance is running. The describe line prints `running` and an IP address.

**How you know it worked.** The describe line shows `running` as the state. If the launch fails with a message about `citypulse-pipeline`, the instance profile does not exist yet. Create it using the instance roles block, then retry. Stop the lab there if you cannot get the profile to appear, and ask for help rather than removing the profile line silently.

### Step 4: Connect over SSH

**What you do.** Find the VM's current IP address and open a shell on it.

**What you type.**

```bash

```

**What you should see.** On the first connection, ssh shows a fingerprint and asks whether you want to continue. Type `yes`. Then the prompt changes to something like `ubuntu@ip-10-0-1-23:~$`. The user name before the `@` is `ubuntu`, which is the default user on Ubuntu images.

**How you know it worked.** Run `hostname` and `whoami`. The output should show a host name that starts with `ip-` and the user `ubuntu`. Type `exit` to return to your laptop's prompt.

:::trap Key permissions warning
If ssh says that the key is unprotected and refuses it, run `chmod 600 ~/.ssh/citypulse-$NAME` and try again. `ssh-keygen` normally sets this for you.

### Step 5: Patch and harden sshd

**What you do.** Install pending updates on the VM, then apply the sshd drop-in from the SSH section. Keep your first session open while you do it.

**What you type.** On the VM, in your open session:

```bash

```

`apt-get update` refreshes the list of available packages. `apt-get upgrade -y` installs the newer versions, and `-y` answers yes to the question it would otherwise ask. The upgrade can take a few minutes.

**How you know it worked.** `sshd -t` printing nothing is the test. If it prints an error with a line number, fix that line before reloading. Do not close your first session until step 6 is complete.

### Step 6: Verify the hardening

**What you do.** Check the effective sshd settings on the VM, then prove from your laptop that a password login is refused.

**What you type.** On the VM:

```bash

```

On your laptop, in a second terminal, with `$IP` set as in step 4:

```bash

```

**What you should see.** On the VM, the three lines show `no` for each setting. On the laptop, the password test fails with a message that ends in `Permission denied (publickey).`. The `-o` options switch off key login and ask only for a password, so the test really checks password logins.

**How you know it worked.** Your key login in the first session still works, and the password attempt is refused. Finally, check the rules once more with the step 2 command and confirm that only your `/32` rule exists. ## What the quiz tests

Each topic below has a short explanation and the trap that examiners set. The quiz block after the ten topics contains one original question for each, in the same order.

### SSH keys

You must know that SSH logs you in with a key pair, not a password. The public half is stored on the server and the private half stays on your laptop. AWS keeps only the public half, so a lost `.pem` file cannot be downloaded again from AWS. The command `create-key-pair` returns the private key once, while `import-key-pair` uploads a public key that you already made. Examiners set the trap by suggesting that AWS keeps a copy of the private key.

### Key file permissions

SSH refuses a private key that other users on the machine can read. The fix is `chmod 600` or `chmod 400`, which restricts the file to its owner. Examiners often offer `chmod 777` or `chmod 644` as tempting answers, because they look like valid commands. A permission number is read in three groups, for owner, group and everyone else, and only the owner group may hold read access to a key. Renaming the file or moving it does not change its permissions.

### Security groups

A security group is a stateful firewall. It allows the inbound traffic you list and blocks everything else, and it remembers allowed connections so the replies flow back. The rule `TCP 22 from your /32` is the only one that meets the lesson's requirement. The trap is a rule that looks narrow but is not, such as `22 from the VPC CIDR`, which opens SSH to every machine inside the network. Remember that `0.0.0.0/0` means everyone.

### sshd hardening

The three settings that matter are `PasswordAuthentication no`, `PermitRootLogin no` and `KbdInteractiveAuthentication no`. You apply them in a drop-in file, check the syntax with `sshd -t`, reload the service, and confirm the effective values with `sshd -T`. The trap is to reload before checking, or to trust your file when an earlier drop-in wins. Another trap is closing your only session before proving the new login works.

### EC2 pricing

EC2 bills an instance by the second while it is running, plus the storage its disk uses. A stopped instance does not incur compute charges, but its disk still incurs storage charges. Cheaper commitments exist for steady workloads, but a lab that you forget to stop is billed at the full on-demand rate. The examiner's trap is the claim that a stopped instance is free. Check the current AWS pricing pages when you need exact amounts.

### Instance hardening

Hardening means removing what you do not need. Each open port, each login method and each unpatched package is attack surface. For CityPulse, that means only SSH from your address, nothing else open to the world, passwords and root login switched off, and updates installed. The trap is opening everything for convenience and calling it temporary. Another trap is to treat a hardened host as finished, when patching is an ongoing task.

### User data bootstrap

User data is a script that you hand to AWS at launch. The instance runs it once during its first boot, as an administrator user, which is the standard behaviour of the cloud-init tool that most Linux images use. Because user data can be read by anyone with permission to describe the instance, it must never hold secrets. In CityPulse the bootstrap is run by hand, as `infra/vm/bootstrap.sh`, which makes each step visible and repeatable. Examiners set the trap by asking you to put a password in user data.

### Private subnet egress

A private subnet has no route from the internet to its machines, and the machines have no public IP address. They can still reach the internet for updates through a NAT gateway, which sits in a public subnet and forwards outbound traffic only. Inbound connections are blocked, and that is the point. The trap is to give the private machine a public IP and open the port, which removes the protection that the subnet provides. Session Manager is the alternative when you need a shell without any inbound port at all.

### Access management

The right way for a VM to call AWS is an instance role. It gives temporary credentials that rotate, and the VM holds no permanent keys. Access should always be least privilege, meaning the minimum that the job needs. The trap is to copy a user's access keys onto the VM, because those keys never expire, and they leak through disk snapshots. Attaching a policy to the user when the role needs it is the second trap.

### Config drift

Config drift happens when the live state of a server stops matching what the documentation or the code says it should be. A person edits a file on the server, forgets to record it, and the next rebuild loses the change. The prevention is to record every change in the runbook or in code, to check the effective settings with `sshd -T`, and to dry-run the runbook. The trap is to assume that a change made in the console is documented, because it is not until it is written down.

## The graded lab skill

The graded lab is a Python problem. You write a few functions, and the platform runs them against visible tests and then hidden tests. The hidden tests look for the edge cases you did not think about, so this section teaches each technique from the beginning.

### Python from scratch

**Variables and values.** A variable stores a value. Python does the same thing as the terminal's `NAME=asha`, but without the `$` sign when you read it back. `port = 22` stores the whole number 22 in `port`.

**Dictionaries.** A dictionary holds named values in pairs, written inside curly braces. `rule = {"from_port": 22, "to_port": 22, "source": "203.0.113.47/32"}` stores three named values. You read one by its key in square brackets: `rule["from_port"]` gives 22. Keys are text in quotes, and each pair is separated by a comma.

**Lists and tuples.** A list is an ordered collection in square brackets, such as `rules = [rule_a, rule_b]`. You can loop over it. A tuple is a fixed group in round brackets, such as `(22, "any")`.

**Functions.** A function is a named block of code that takes inputs and gives back a result. `def port_in_range(port, rule):` starts the function and names its inputs. Everything indented under it is the body. `return` gives the result back to the caller. A function with no `return` gives back `None`, which is Python's word for nothing, and a test that expects True will fail.

**Loops and conditions.** `for rule in rules:` runs the indented body once for each item in the list. `if` runs its body only when a condition is true. `continue` skips the rest of the current loop run and moves to the next item.

**Comparisons and membership.** `==` asks whether two values are equal. `<=` means less than or equal to. Python lets you write `rule["from_port"] <= port <= rule["to_port"]` as a single check. The `in` operator asks whether a value is inside a list, a tuple or a set, and returns True or False.

**Ranges include the start and exclude the end.** `range(80, 82)` produces 80 and 81, but not 82. To include the last port of a range, add 1: `range(from_port, to_port + 1)`. This is the most common bug in port problems.

**Sets and sorted.** A set holds each value once, so adding 80 twice keeps one 80. `sorted(some_set)` returns a list in ascending order. Sets do not keep an order, so always sort when the task asks for ordered output.

**The ipaddress module.** Python's standard library includes `ipaddress`, which understands CIDR. `ipaddress.ip_network("10.0.0.0/8")` describes the range, and the test `address in network` returns True when the address is inside it. You need `import ipaddress` at the top of the file. No installation is needed.

**Assertions.** `assert condition` does nothing when the condition is true, and stops the program with an error when it is false. The tests at the end of a tested solution are a list of assertions, so one wrong answer fails the whole block.

### The practice problem: a home-router audit

Your task is a small audit of a home router. The router's forwarding rules are a list of dictionaries. Each has a `from_port`, a `to_port`, and a `source`. The source is either the text `any`, the text `0.0.0.0/0`, or a CIDR range such as `10.0.0.0/8` or a single address such as `203.0.113.47/32`.

Write these five functions:

1. `port_in_range(port, rule)` returns True when `port` falls inside the rule's range, both ends included.
2. `is_open_to_any(rule)` returns True when the rule's source is `any` or `0.0.0.0/0`.
3. `reachable(rules, port, source_ip)` returns True when at least one rule opens `port` to the address `source_ip`, given as text such as `"10.1.2.3"`.
4. `open_ports_to_any(rules)` returns a sorted list of every port open to anyone, with no duplicates.
5. `risky_exposure(rules)` returns a dictionary `{3389: ..., 23: ...}` where each value is True when that port is open to anyone.

Example: with the rules `{"from_port": 80, "to_port": 80, "source": "any"}` and `{"from_port": 3389, "to_port": 3389, "source": "0.0.0.0/0"}`, `open_ports_to_any` returns `[80, 3389]`, and `risky_exposure` returns `{3389: True, 23: False}`.

:::key Edge-case checklist
Before you submit, check each of these:

- **Empty input.** An empty list of rules gives `False`, `[]` and no exposure.
- **Ties and overlaps.** Two rules can open the same port. The output must list it once.
- **Ordering.** The open ports must be sorted, even if the rules are not.
- **Types.** Ports are whole numbers. `"22"` as text is not the same as `22`.
- **Rounding.** Ports are whole numbers, so no rounding is involved. Do not convert with `float`.
- **Missing fields.** The examples always have all three fields. Decide whether a missing field should crash. The solution assumes all fields are present, and it says so.
- **Range ends.** Test the first and last port of a range, and the port one above the last.
- **Address boundaries.** Test an address just inside and just outside a CIDR range.
:::

:::answer Show the full solution and its explanation
The solution is below. It uses only the standard library, so it runs on any Python 3.

```python test
import ipaddress


def port_in_range(port, rule):
    """True when port is between from_port and to_port, both included."""
    return rule["from_port"] <= port <= rule["to_port"]


def is_open_to_any(rule):
    """True when the source is 'any' or the whole internet."""
    return rule["source"] in ("any", "0.0.0.0/0")


def reachable(rules, port, source_ip):
    """True when at least one rule opens port to source_ip."""
    address = ipaddress.ip_address(source_ip)
    for rule in rules:
        if not port_in_range(port, rule):
            continue
        if is_open_to_any(rule):
            return True
        if address in ipaddress.ip_network(rule["source"], strict=False):
            return True
    return False


def open_ports_to_any(rules):
    """Sorted list of every port open to anyone, without duplicates."""
    ports = set()
    for rule in rules:
        if is_open_to_any(rule):
            ports.update(range(rule["from_port"], rule["to_port"] + 1))
    return sorted(ports)


def risky_exposure(rules):
    """Report whether remote desktop (3389) or telnet (23) is open to anyone."""
    open_ports = set(open_ports_to_any(rules))
    return {3389: 3389 in open_ports, 23: 23 in open_ports}


rules = [
    {"from_port": 22, "to_port": 22, "source": "203.0.113.47/32"},
    {"from_port": 80, "to_port": 80, "source": "any"},
    {"from_port": 8000, "to_port": 8010, "source": "10.0.0.0/8"},
    {"from_port": 3389, "to_port": 3389, "source": "0.0.0.0/0"},
]

assert port_in_range(22, rules[0]) is True
assert port_in_range(21, rules[0]) is False
assert port_in_range(8010, rules[2]) is True
assert port_in_range(8011, rules[2]) is False
assert is_open_to_any(rules[1]) is True
assert is_open_to_any(rules[0]) is False

assert reachable(rules, 22, "203.0.113.47") is True
assert reachable(rules, 22, "203.0.113.48") is False
assert reachable(rules, 80, "198.51.100.9") is True
assert reachable(rules, 8005, "10.1.2.3") is True
assert reachable(rules, 8005, "192.168.1.1") is False
assert reachable(rules, 9999, "10.1.2.3") is False
assert reachable([], 22, "1.2.3.4") is False

assert open_ports_to_any(rules) == [80, 3389]
assert open_ports_to_any([]) == []
overlap = [
    {"from_port": 80, "to_port": 81, "source": "any"},
    {"from_port": 81, "to_port": 82, "source": "0.0.0.0/0"},
]
assert open_ports_to_any(overlap) == [80, 81, 82]

assert risky_exposure(rules) == {3389: True, 23: False}
assert risky_exposure([]) == {3389: False, 23: False}
```

**Explanation, line by line.**

- `import ipaddress` loads the standard module that understands IP addresses and CIDR ranges.
- `port_in_range` compares with a chained check. Both ends are included, because `<=` is used on each side.
- `is_open_to_any` uses `in` with a tuple of the two spellings that mean everyone. Using a tuple keeps the check on one line.
- `reachable` converts the text address into an address object first, so a malformed address fails early with a clear error.
- The loop in `reachable` uses `continue` to skip rules whose port range does not match. That keeps the rest of the body flat.
- `is_open_to_any(rule)` returns True straight away, because an open-to-anyone rule accepts every address.
- `ipaddress.ip_network(rule["source"], strict=False)` builds the range. `strict=False` lets a host address with bits set, such as `10.1.2.3/8`, be read without error.
- `address in network` gives True when the address lies inside the range.
- `open_ports_to_any` puts ports into a set, so duplicates disappear. `range(from, to + 1)` includes the last port, which the `+ 1` fixes.
- `sorted(ports)` returns an ordered list, which is what the task asks for.
- `risky_exposure` converts the list back to a set for fast `in` checks, then builds the dictionary with the two keys the task names.
- The assertions use `is True` and `is False` for the Boolean results, so a function that returns a truthy value such as 1 would fail.
- The test `overlap` checks that ports 81 and 82 from two rules are each listed once, in order.

Expected result when you run the file: no output, and no error. Any failed assertion prints a traceback that names the line that failed.
:::

## Say it out loud

:::answer Why is port 22 limited to your /32 and not left open to the internet?
Port 22 is the door to the VM's shell, so an open door can be found and attacked by automated scanners within minutes. Limiting the rule to `/32` means only your single address can even see the port, and the scanners see nothing. Key-only login and disabled root login then protect the door if someone does reach it. I would say that the firewall and the sshd settings are two separate layers, and that each one covers the other's failure.
:::

:::answer Why does the VM use an instance role instead of stored access keys?
An instance role gives the VM temporary credentials that AWS rotates automatically, so there is no permanent key on disk to steal. A key copied to the VM never expires, and it leaks with any disk snapshot or backup. The role uses the same scoped policy as the user, so the access is no broader than before. IMDSv2 also protects the credentials from theft by a request forgery trick.
:::

:::answer What do sshd -t and sshd -T do, and why keep a session open?
The command `sshd -t` checks the configuration file for syntax errors and prints nothing when it is valid. The command `sshd -T` prints the effective settings that sshd will actually use, which matters because the first value read wins. I keep one session open so that if the new config locks me out, the open session is my way back in to fix it. Reloading only after both checks passes reduces the chance of a lockout to nearly zero.
:::

:::answer Why does a stopped instance still cost money?
Stopping halts the compute charges, because the instance is no longer running on a host. The disk stays attached and keeps its data, and storage is billed separately, so the cost does not drop to zero. Some public address charges may also apply, depending on current pricing. For that reason I stop instances at the end of the day, and terminate them when the lab is finished and the disk is no longer needed.
:::

:::answer What makes a runbook useful during an incident?
A useful runbook starts from a symptom, gives a quick diagnosis, and then gives exact commands with their variables filled in. Each section has been dry-run by someone other than the author, so it is known to work under pressure. It is stored in the repository next to the code, so it is reviewed in pull requests and stays current. An incident is the wrong time to discover that a step says "fix the security group" and nothing more.
:::

## Flashcards

```cards
ssh-keygen -t ed25519 :: Creates an ed25519 key pair; the private file has no extension and the public file ends in .pub.
Private key location :: It stays on your laptop. AWS keeps only the public half.
chmod 600 :: Makes the key readable and writable by its owner only, so SSH accepts it.
Security group :: A stateful firewall attached to an instance; new groups have no inbound rules.
/32 :: A CIDR range of exactly one IP address.
0.0.0.0/0 :: Every IP address on the internet. Never allow SSH from it.
sshd -t :: Checks the sshd config syntax and prints nothing when it is valid.
sshd -T :: Prints the effective sshd settings. The first value read for a setting wins.
Instance role :: An IAM role on an EC2 VM that gives temporary, rotating credentials instead of stored keys.
IMDSv2 :: The session-token version of the instance metadata service, which blocks many credential-theft tricks.
stop-instances :: Halts compute charges and keeps the disk. Terminating deletes the instance permanently.
Runbook :: A tested, copy-pasteable document of exact commands for launch, connect, stop and recovery.
```
