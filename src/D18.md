## The idea in one minute

Exploratory data analysis (EDA) is the first careful look at a dataset, before you trust any number from it. It works like a doctor's check-up: pulse, temperature and blood pressure are measured before any diagnosis is made. Today you open a file of air-quality sensor readings, count what is there, find the gaps and the strange values, summarise the month in a few numbers, and draw charts that show the pattern. By the end you will be able to write one finding that gives a number, the number of readings behind it, the date range, and what someone should do next.

## Starting from zero

**Terminal.** A text window where you type instructions to the computer. Each instruction is a **command**: you type it, press Enter, and read the reply underneath.

**File and folder.** A file is a named piece of stored data, such as `readings.csv`. A **folder** (also called a directory) holds files. The part of the name after the last dot, such as `.csv` or `.py`, is the **extension**, which hints at the format.

**CSV.** Comma-separated values. A CSV file is plain text in which each line is one row and commas separate the columns. The first line usually holds the column names, and any text editor can open it.

**Python and scripts.** Python is a programming language: you write its instructions as text. A **script** is a Python file that runs from top to bottom when you type `python script.py` in the terminal. Use `python` in place of `python3` if your terminal says `python3` is not recognised.

**Variable.** A name attached to a value. `x = 5` stores the number 5 under the name `x`, so later lines can use it. The `=` sign means "store this", not "is equal to".

**Function and method.** A function is a named, reusable set of instructions, called with brackets. `len(rows)` calls the function `len`, which returns how many items `rows` holds. A **method** is a function attached to a value and called with a dot, such as `text.upper()`. The brackets may hold **arguments**, which are options passed in.

**Library and import.** A library is a package of ready-made code. `import pandas as pd` loads the pandas library and gives it the short name `pd`, so you write `pd.read_csv` rather than the full name.

**List, tuple and dictionary.** A **list** is an ordered collection in square brackets, such as `[2, 5, 10]`. A **tuple** is a fixed group in round brackets, such as `("S1", 40.0)`. A **dictionary** stores pairs of key and value in curly brackets: `{"S1": 40.0}` means the key `S1` holds the value 40.0.

**DataFrame and Series.** pandas stores a table as a **DataFrame**: rows with named columns. One column of a DataFrame is a **Series**. The row labels are called the **index**.

**Timestamp, UTC and IST.** A **timestamp** is a date plus a time. **UTC** (Coordinated Universal Time) is the reference clock with no offset. **IST** (Indian Standard Time) is UTC plus five hours thirty minutes. Converting a timestamp to another **time zone** changes how the clock reads, not the moment it describes. The pandas name for IST is `Asia/Kolkata`.

**Mean, median and percentiles.** The **mean** is the sum divided by the count. The **median** is the middle value once the numbers are sorted; with an even count it is the average of the two middle values. A **percentile** is the value below which a given share of the data falls. The **quartiles** are the 25th, 50th and 75th percentiles, written Q1, Q2 and Q3. The **standard deviation** (std) measures how far values typically sit from the mean.

**Outlier and IQR.** An **outlier** is a value far from the rest. The **interquartile range** (IQR) is Q3 minus Q1, the width of the middle half of the data.

**Histogram and bin.** A **histogram** counts values in ranges of equal width. Each range is a **bin**.

**Correlation.** A number from -1 to 1 showing how strongly two columns move together in a straight-line way. The default method is **Pearson**.

**Missing value and NaN.** An empty cell is a missing value. pandas stores it as **NaN** (Not a Number). NaN is not zero.

**Resample, pivot table and heatmap.** To **resample** is to regroup a time-ordered series into regular intervals, such as hours or days. A **pivot table** is a grid whose rows and columns come from two columns of the data, with an average or other summary in each cell. A **heatmap** is a grid of coloured cells where the colour shows the size of the value.

**Pollution terms.** PM2.5 is particulate matter finer than 2.5 micrometres; PM10 is particles finer than 10 micrometres; NO2 is nitrogen dioxide. Concentrations are written in micrograms per cubic metre, µg/m³. The CPCB (Central Pollution Control Board) sets India's limits. The 24-hour PM2.5 limit used in this course is 60 µg/m³.

**Chart parts.** The **axes** are the plotting area with its x and y scales. The **title** states what the chart shows, a **label** names an axis, and the **legend** maps colours to names. A **reference line** is drawn at a fixed value, such as a limit. A **spine** is one of the four border lines of the plot area. **dpi** (dots per inch) sets the resolution of a saved picture, and **PNG** is a common picture file format.

## The tools

### EDA workflow

EDA is an order of questions, not a pile of charts. Start with coverage: how many readings each station produced on each day. A day with 10 readings instead of 24 has a gap, so comparing it with a complete day is unfair. Then look at distributions and missing values, then trends over time, then patterns by hour and weekday, then relationships between columns. Each finding is written as one observation with one chart, one number and a "So what:" action.

Automated profiling tools such as ydata-profiling produce a generic report for every column. That is fast, but it does not give the decision-linked observations the course asks for. SQL views are good for counts and totals, but weak at showing distributions and patterns.

```flow
TITLE: From readings to a finding
NODES: readings.csv | pandas DataFrame | matplotlib figure | PNG file
STEPS:
1>2 :: read_csv :: pandas reads the file and builds a table in memory.
2>3 :: groupby, resample :: The table is filtered and summarised into a few rows.
3>4 :: savefig :: The figure is drawn and written to a picture file.
4>1 :: next batch :: A new batch of readings arrives and the same steps run again.
```

:::trap Pattern before coverage
A chart that shows a clean day can simply show a day with fewer readings. Check rows per day before you claim one day was cleaner than another.
:::

### pandas

pandas is the library that holds tables (DataFrames) and works on whole columns at once. The course uses it because the script can be re-run on each new batch and gives the same answer every time. Excel needs manual clicks that cannot be repeated exactly. Plain Python needs you to write the grouping loops yourself. The course also uses SQL views for aggregates in earlier lessons.

Each column is a Series, and an operation such as `value.mean()` runs over all the rows. `groupby` splits the rows into groups by one or more columns, then applies an aggregate, such as `mean`, `sum`, `count` or `size`, to each group.

The slide code below is the coverage check from the lesson notebook. The line breaks have been joined back together.

```python
import pandas as pd
df = pd.read_parquet("data/clean/aq_clean.parquet")
df["ts_ist"] = pd.to_datetime(df["ts_utc"], utc=True).dt.tz_convert("Asia/Kolkata")
coverage = (df.groupby(["location_id", df["ts_ist"].dt.date])
              .size().unstack(fill_value=0))
print(coverage.iloc[:, -7:])
print("incomplete location-days:", int((coverage < 24).sum().sum()))
```

- `import pandas as pd` loads pandas under the short name `pd`.
- `pd.read_parquet(...)` reads the cleaned file into a DataFrame called `df`. Parquet is a compact column-based binary format, so you cannot open it in a text editor.
- `pd.to_datetime(df["ts_utc"], utc=True)` turns the text in `ts_utc` into timestamps and labels them UTC. `.dt.tz_convert("Asia/Kolkata")` changes the display to IST. The moments do not change.
- The `groupby` line groups rows by location and by the calendar date in IST. `.size()` counts the rows in each group.
- `.unstack(fill_value=0)` turns the date level of the index into columns, so each row is a location and each column a date. Any missing combination becomes 0.
- `print(coverage.iloc[:, -7:])` prints the last seven date columns. `iloc` selects by position, and `:, -7:` means all rows and the last seven columns.
- `(coverage < 24).sum().sum()` marks each cell that is below 24, then adds up the marks across rows and then columns. `int(...)` converts the total to a whole number.

Running this prints a table of counts and then a line such as `incomplete location-days: 12`. The count is the number of location-days with fewer than 24 readings. Your count depends on your data.

Running a script from the terminal looks like this:

```term
$ python3 describe.py
count     30.00
mean      50.22
std       13.33
min       19.52
25%       43.55
50%       51.22
75%       57.74
max       92.19
Name: value, dtype: float64
```

The lines starting with `$ ` are the command you type. The lines below are what the script prints.

Grouping by the hour of a UTC timestamp puts an evening peak in the wrong place. Convert to `Asia/Kolkata` first, then take `.dt.hour`, and label the axis IST.
:::

### matplotlib and seaborn

matplotlib is Python's core plotting library. You create a figure and axes, then draw lines, bars and labels on those axes. seaborn sits on top of matplotlib and draws statistical charts, such as heatmaps, from a DataFrame in one call. The course uses matplotlib for the static PNG charts in the report, because it gives full control over reference lines, labels and borders.

The alternatives are Plotly, which is interactive and used for the dashboard, and `pandas .plot()`, which is quick but is matplotlib underneath with less control over styling.

The slide code below draws the hour-of-day by weekday heatmap for ticket Y2-T24.

```python
import matplotlib.pyplot as plt
import pandas as pd
import seaborn as sns
df = pd.read_parquet("data/clean/aq_clean.parquet")
ts = pd.to_datetime(df["ts_utc"], utc=True).dt.tz_convert("Asia/Kolkata")
days = ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"]
grid = (df.assign(hour=ts.dt.hour, weekday=ts.dt.day_name())
          .pivot_table(index="weekday", columns="hour", values="pm2_5", aggfunc="mean")
          .reindex(days))
fig, ax = plt.subplots(figsize=(11, 4))
sns.heatmap(grid, cmap="viridis", cbar_kws={"label": "Mean PM2.5 (µg/m³)"}, ax=ax)
ax.set(xlabel="Hour of day (IST)", ylabel="", title="Mean PM2.5 by weekday and hour (IST)")
fig.savefig("reports/eda/heatmap_hour_weekday.png", dpi=150, bbox_inches="tight")
```

- The first two imports load the drawing module as `plt`, and pandas as `pd`. `import seaborn as sns` loads the statistical drawing library.
- `ts` is the timestamp column converted to IST, as in the previous section.
- `days` is a list of weekday names in Monday-to-Sunday order.
- `df.assign(hour=..., weekday=...)` adds two new columns: the IST hour and the weekday name. `day_name()` returns English names such as "Monday".
- `pivot_table(... aggfunc="mean")` makes the grid: weekdays as rows, hours as columns, and the mean PM2.5 in each cell.
- `.reindex(days)` puts the rows in the order of the `days` list. Without it, pandas sorts the names alphabetically, so Friday comes before Monday.
- `plt.subplots(figsize=(11, 4))` creates one figure and one axes. The size is in inches, width then height.
- `sns.heatmap(grid, cmap="viridis", ...)` draws the grid as coloured cells. `cmap` picks the colour scale, and viridis is readable by colour-blind viewers. `cbar_kws` passes options to the colour bar, here its label. `ax=ax` tells seaborn to draw on the axes you created.
- `ax.set(...)` sets the axis labels and title. An empty `ylabel=""` removes the label, because the weekday names already explain the rows.
- `fig.savefig(..., dpi=150, bbox_inches="tight")` writes the PNG at 150 dots per inch. `bbox_inches="tight"` trims the margins so no label is cut off.

Running it creates `heatmap_hour_weekday.png`. Open it to check that the rows run Monday to Sunday and the title reads as a sentence.

:::trap Global state in matplotlib
`plt.plot(...)` draws on whatever figure is current, so functions that use it can leak into each other. Create `fig, ax = plt.subplots()` inside the function and return the figure.
:::

### Plotly

Plotly draws interactive charts that run in the browser, with hover, zoom and legend toggling. `plotly.express` creates common charts from a DataFrame in one call, and the returned figure can be changed with `add_hline` and `update_layout`. The course uses Plotly for the dashboard, because a ward officer on a phone can tap a point to see the station, date and value. The alternatives are Altair, which is concise but less familiar to the team, and Bokeh, which needs more setup than two charts require.

The slide code below is the dashboard's chart function, from `src/citypulse/charts.py`.

```python
import pandas as pd
import plotly.express as px
OKABE_ITO = ["#0072B2", "#E69F00", "#009E73", "#CC79A7", "#56B4E9"]
def daily_trend_fig(daily: pd.DataFrame, limit: float):
    """daily: columns date, station, pm25_mean (daily_station.parquet)."""
    fig = px.line(daily, x="date", y="pm25_mean", color="station", color_discrete_sequence=OKABE_ITO,
                  labels={"pm25_mean": "PM2.5 (µg/m³)", "date": "", "station": ""})
    fig.add_hline(y=limit, line_dash="dash", line_color="#D55E00",
                  annotation_text=f"CPCB NAAQS 24h limit {limit:g} µg/m³")
    over = int((daily.groupby("date")["pm25_mean"].mean() > limit).sum())
    fig.update_layout(title=f"City mean PM2.5 exceeded the limit on {over} days", template="simple_white")
    return fig
```

- `OKABE_ITO` is a list of five hex colour codes that stay distinct for colour-blind readers. The name is written in capitals because it is a constant that is not meant to change.
- `def daily_trend_fig(daily: pd.DataFrame, limit: float):` defines a function. The two parameters are a DataFrame and a number. The `: pd.DataFrame` and `: float` notes say what type is expected; Python does not enforce them.
- The docstring (the text in triple quotes) lists the columns the function expects.
- `px.line(...)` draws one line per station, with `date` on x and `pm25_mean` on y. `color_discrete_sequence` sets the colours from the list.
- `fig.add_hline(...)` draws a dashed horizontal line at the limit and writes its label. The number 60 comes from `config/limits.yaml`, passed in as `limit`.
- `over = ...` takes the city mean for each date, marks the dates above the limit as True, and adds up the Trues. `int` makes it a whole number.
- `fig.update_layout(title=...)` sets the title with `over` inserted, so the title is computed from the data. `template="simple_white"` gives a plain style.
- `return fig` hands the figure back. The function takes no file path, so the dashboard and the saved report use the same logic.

:::trap Plotting every hourly point
Months of hourly points make the dashboard slow on a phone. Aggregate to daily first, as the function expects, and limit how many stations you show.
:::

### Chart choice and storytelling

Choose the chart type from the question. A line chart shows change over time, a bar chart compares categories, and a scatter plot shows the relationship between two numbers. Storytelling means leading with the answer: a title that states the takeaway with a number, one reference line for context, and at most two annotations. In the report, every claim links to a chart file.

The slide code below sets a computed title and the limit line for one report chart.

```python
import matplotlib.pyplot as plt
import pandas as pd
import yaml
limit = yaml.safe_load(open("config/limits.yaml"))["pm25_24h_limit"]   # 60, CPCB NAAQS 2009
df = pd.read_parquet("data/clean/aq_clean.parquet")
ts = pd.to_datetime(df["ts_utc"], utc=True).dt.tz_convert("Asia/Kolkata")
daily = df.set_index(ts)["pm2_5"].resample("D").mean().dropna()
over = int((daily > limit).sum())
fig, ax = plt.subplots(figsize=(8, 4))
ax.plot(daily.index, daily.values, color="#0072B2")
ax.axhline(limit, color="#D55E00", ls="--", label=f"CPCB NAAQS 24h limit ({limit} µg/m³)")
ax.set(title=f"Daily PM2.5 exceeded the limit on {over} of {len(daily)} days", ylabel="PM2.5 (µg/m³)")
ax.spines[["top", "right"]].set_visible(False); ax.legend(frameon=False)
fig.savefig("reports/charts/01_days_over_limit.png", dpi=200, bbox_inches="tight")
```

- `yaml.safe_load(open(...))` reads the config file. YAML is a plain-text format for settings, and `["pm25_24h_limit"]` picks one key from it. The limit is 60.
- `df.set_index(ts)` replaces the row labels with the IST timestamps. `resample("D").mean()` then averages the readings into calendar days in IST. `dropna()` removes days with no readings.
- `over` counts the days above the limit, and `len(daily)` gives the number of days, so the title reads, for example, "on 9 of 30 days".
- `ax.plot(daily.index, daily.values, ...)` draws the line. `ax.axhline(limit, ...)` draws the horizontal limit line, and `label=` gives it a legend entry.
- `ax.set(title=...)` puts the computed title on the chart, so it stays correct when the data refreshes.
- `ax.spines[["top", "right"]].set_visible(False)` hides two of the border lines, which removes clutter.
- `fig.savefig(..., dpi=200, ...)` writes the PNG the report links to.

A pie chart cannot show change over time. Use a line for time and a sorted bar for comparisons.

## The worked example

**Goal.** Find the daily mean PM2.5 for April 2026, describe the spread, and name the three worst days. The file `readings.csv` has four columns (`station_id`, `ts`, `pollutant`, `value`) and 10,800 rows: five stations, three pollutants, 720 hours.

**Code.** This combines steps 1 to 5 of the workbook example.

```python
import pandas as pd

df = pd.read_csv("readings.csv", parse_dates=["ts"])
pm = df[df.pollutant == "PM2.5"]
daily = pm.groupby(pm.ts.dt.date).value.mean()
print(daily.describe().round(2).to_string())
top = daily.sort_values(ascending=False).head(3)
print("top 3 days by mean PM2.5:")
print(top.round(1).to_string())
print("mean of all days:", round(daily.mean(), 1))
```

**Explanation.**

- `pd.read_csv("readings.csv", parse_dates=["ts"])` reads the file into `df`. `parse_dates` converts the text in `ts` into timestamps while loading.
- `df[df.pollutant == "PM2.5"]` compares every row's pollutant with "PM2.5", giving True or False per row. The square brackets keep only the True rows, so `pm` holds 3,600 rows.
- `pm.groupby(pm.ts.dt.date).value.mean()` takes the calendar date of each row, groups the rows by date, selects the `value` column, and averages each group. The result is a Series with one number per date. Its index is named `ts` because the grouping came from that column.
- `daily.describe()` gives the count, mean, standard deviation, minimum, quartiles and maximum. `.round(2)` keeps two decimal places, and `.to_string()` prints every row.
- `daily.sort_values(ascending=False)` sorts the days from largest to smallest. `.head(3)` keeps the first three.
- `round(daily.mean(), 1)` gives the mean of all days to one decimal place.

**Output.**

```text

std       13.33
min       19.52
25%       43.55
50%       51.22
75%       57.74
max       92.19
top 3 days by mean PM2.5:
ts
2026-04-18    92.2
```

**Reading the output.** The maximum (92.19) is far above the 75th percentile (57.74), which points to an outlier. The worst day, 18 April at 92.2, is about 1.8 times the month mean of 50.2. Before calling it a real event, you would check that day's rows by station and hour.

## The hands-on lab, step by step

Create a folder called `eda-lab`, open the terminal inside it, and keep every file in that folder. Each step ends with something you can check.

### Step 1: Generate a realistic readings file

**What you do.** Create `make_readings.py` with the code below, then run it. The script writes `readings.csv` with 30 days of hourly readings for five stations and three pollutants, and puts a spike on 18 April in the PM2.5 values.

```python
import csv
import random
from datetime import datetime, timedelta, timezone

random.seed(18)
start = datetime(2026, 4, 1, tzinfo=timezone.utc)
stations = ["ST01", "ST02", "ST03", "ST04", "ST05"]
base = {"PM2.5": 50, "PM10": 80, "NO2": 30}

with open("readings.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["station_id", "ts", "pollutant", "value"])
    for hour in range(30 * 24):
        ts = start + timedelta(hours=hour)
        for station in stations:
            for pollutant, mu in base.items():
                value = round(max(0.0, random.gauss(mu, mu * 0.2)), 1)
                if pollutant == "PM2.5" and ts.month == 4 and ts.day == 18:
                    value = round(value + 40, 1)
                if random.random() < 0.02:
                    value = ""
                writer.writerow([station, ts.isoformat(), pollutant, value])
```

- `import csv`, `random` and `datetime` load the library parts for writing CSV, making random numbers and handling dates.
- `random.seed(18)` fixes the random sequence, so the same script gives the same file on each run.
- `start` is 1 April 2026 at 00:00 UTC. `base` holds an average level for each pollutant.
- `open("readings.csv", "w", newline="")` opens the file for writing. `newline=""` stops Windows adding blank lines between rows. The `with` block closes the file automatically.
- `writer.writerow(...)` writes one row. The first row is the header.
- The nested loops produce 720 hours times 5 stations times 3 pollutants, which is 10,800 rows.
- `random.gauss(mu, mu * 0.2)` draws a random value around the average. `max(0.0, ...)` prevents negative concentrations, and `round(..., 1)` keeps one decimal.
- The `if` on 18 April adds 40 to PM2.5. The date is the UTC date.
- `random.random() < 0.02` leaves about 2 per cent of the readings blank, which gives you data to clean.
- `ts.isoformat()` writes the time as text such as `2026-04-01T00:00:00+00:00`.

**You should see.** Running `python make_readings.py` prints nothing. A new file named `readings.csv` appears in the folder.

**How you know it worked.** In PowerShell, run `(Get-Content readings.csv | Measure-Object -Line).Lines`. It should print 10801: one header and 10,800 rows.

### Step 3: Quantify data quality

**What you do.** Create `quality.py`. It counts missing values, the share missing for `value`, and any duplicate readings.

```python
import pandas as pd

df = pd.read_csv("readings.csv", parse_dates=["ts"])
print(df.isna().sum())

print("duplicates:", df.duplicated(["station_id", "ts", "pollutant"]).sum())
```

- `df.isna()` returns True for each missing cell. `.sum()` counts the Trues in each column.
- `.isna().mean()` gives the share of missing cells, and `* 100` turns it into a percentage.
- `df.duplicated([...])` marks rows whose station, time and pollutant repeat an earlier row.

**You should see.** `value` has about 216 missing cells, roughly 2 per cent. The exact number depends on the random draw. The other columns show 0 and the duplicate count is 0.

**How you know it worked.** The missing count for `value` is close to 2 per cent of 10,800, and the duplicate count is 0.

### Step 4: Clean deliberately

**What you do.** Create `clean.py`. It removes only the blank rows, reports how many it removed, and describes what is left.

```python
import pandas as pd

df = pd.read_csv("readings.csv", parse_dates=["ts"])
clean = df.dropna(subset=["value"])
print("removed:", len(df) - len(clean), "of", len(df))
print(clean.value.describe().round(1).to_string())
```

- `dropna(subset=["value"])` drops rows where `value` is missing. `subset` limits the check to that column.
- The `removed:` line is the difference in row counts. Recording it is part of cleaning: a reader needs to know how many readings were excluded.
- `describe()` on the cleaned values shows whether the minimum is still non-negative.

**You should see.** The number removed equals the blank count from step 3. The minimum is 0.0 or higher, because step 1 never writes a negative value.

**Why you keep the spike.** Only blanks are removed. The 18 April values are high but valid readings, and a spike can be a real event. Removing it needs evidence of a fault, not a feeling that it is too big.

**How you know it worked.** `len(clean)` equals 10,800 minus the removed count.

### Step 5: Resample to an hourly trend

**What you do.** Create `hourly.py`. It takes the PM2.5 readings, indexes them by time, and averages the five stations within each hour.

```python
import pandas as pd

df = pd.read_csv("readings.csv", parse_dates=["ts"])
clean = df.dropna(subset=["value"])
pm = clean[clean.pollutant == "PM2.5"].set_index("ts")
hourly = pm.value.resample("h").mean()
print(len(hourly), "hourly points")
print(hourly.head(3).round(1).to_string())
```

- `set_index("ts")` makes the timestamp the index, which `resample` needs.
- `resample("h")` groups the rows into one-hour bins, and `.mean()` averages each bin. Use `"H"` in pandas versions older than 2.2.
- `len(hourly)` counts the bins.

**You should see.** `720 hourly points`, then three lines with values near 50, since each hour averages about five stations.

**How you know it worked.** The count is 720, which is 30 days times 24 hours.

### Step 6: Chart the story

## What the quiz tests

### Grouping with groupby (pandas-groupby)

`groupby` splits a DataFrame into groups by one or more columns, then applies an aggregate such as `mean`, `sum`, `count` or `size` to each group. The result has one value per group, indexed by the group key. The standard pattern is `df.groupby("station_id")["value"].mean()`, which selects the column before the aggregate. Examiners set traps on the shape of the output: a single-column result is a Series, not a DataFrame, and the group key becomes the index, not a column. `mean` skips missing values by default, so a group with many blanks is averaged over fewer readings.

### Parsing timestamps (pandas-datetime-parsing)

Timestamps usually arrive as text, and pandas must convert them to datetime values before any time-based operation works. `pd.to_datetime` does this, and `parse_dates` in `read_csv` does it while loading. Text that carries an offset, such as `+05:30` or `+00:00`, is read as a specific moment, and `utc=True` converts everything to UTC. The `errors` argument decides what happens to a bad cell: `"raise"` stops the program, and `"coerce"` stores a missing timestamp (NaT). The usual trap is a column that looks like dates but is still text, so `.dt.hour` fails or gives wrong results.

### Histograms (matplotlib-histogram)

A histogram counts values in equal-width bins, which shows the shape of a distribution: whether it is centred, skewed or has a long tail. `plt.hist(values, bins=20)` draws one and returns the counts and bin edges. The number of bins is a choice: too few hides the shape, and too many shows noise. Use a histogram, not a line chart, when the question is about how values are spread. The trap is confusing a histogram, with values on the x-axis, with a bar chart of categories, which has gaps between the bars.

### Missing values (pandas-missing-values)

A missing value is stored as NaN, and NaN is not zero. `isna()` returns True for missing cells, so `isna().sum()` counts them per column and `isna().mean()` gives the share. `dropna` removes rows with missing values and `fillna` replaces them, and either choice must be recorded. Averages skip NaN silently, so a mean over a column with many gaps rests on fewer readings than the row count suggests. The trap is filling gaps with zero, which makes a sensor that failed look like clean air.

### Resampling time series (pandas-resample)

`resample` groups a time-indexed Series into fixed intervals, such as `"h"` for hours or `"D"` for days, and then applies an aggregate. It needs a DatetimeIndex, so set one with `set_index("ts")` first. Use `"h"` in pandas 2.2 and later; older versions use `"H"`. Resample produces a row for every interval in the range, so an hour with no readings appears as NaN. The trap is the time zone: bin edges follow the index's zone, so a UTC index gives UTC days unless you convert first.

### Time-series charts (matplotlib-timeseries)

A time-series chart puts time on the x-axis and the measured value on the y-axis, usually as a line. Pass the index as x and the values as y to `ax.plot`. A pandas Series can draw itself, but the matplotlib axes let you add reference lines, labels and titles. The trap is the zone: convert with `tz_convert` before plotting, so the points and the axis label agree, and label the axis IST.

### Pivot tables (pandas-pivot-table)

`pivot_table` builds a grid: the values of one column become rows, the values of another become columns, and each cell holds an aggregate of a third column. `aggfunc` sets the summary, and its default is `"mean"`. Use it when several readings share the same row and column pair, which is common when five stations report each hour. The trap is `pivot` versus `pivot_table`: `pivot` raises a ValueError about duplicate entries in that case, while `pivot_table` averages them.

### IQR outliers (pandas-outlier-iqr)

The IQR is Q3 minus Q1. The common rule marks a value as an outlier when it is below Q1 minus 1.5 times the IQR, or above Q3 plus 1.5 times the IQR. Get the quartiles from a Series with `quantile(0.25)` and `quantile(0.75)`. The trap is the boundary: a value exactly on a fence is not an outlier, because the rule uses strict inequalities. Also, the rule flags values for checking; it does not justify deleting them.

### Correlation (pandas-correlation)

`corr` measures how strongly two columns move together in a straight-line way, on a scale from -1 to 1. Pandas uses Pearson by default, and `method="spearman"` ranks the values first, which suits monotonic but curved links. A high correlation does not show cause, because a shared factor such as weather can drive both columns. The trap is reading 0.92 as "92 per cent of one value", which is not what the number means. Pandas skips missing values pair by pair, so the calculation still runs.

### Subplots (matplotlib-subplots)

`plt.subplots(rows, cols)` creates a figure and a grid of axes. With one row and two columns it returns two axes, and you unpack them with `fig, (ax1, ax2) = plt.subplots(1, 2)`. With more than one row and column it returns a two-dimensional array, indexed as `axes[0, 1]`. `sharex=True` makes the panels share an x-axis, so times line up. The trap is calling a method such as `plot` on the whole array instead of on one axes.

### Descriptive statistics by hand

Sort a copy of the list with `sorted(marks)`, which leaves the original list unchanged. `len(ordered)` gives the count, `ordered[0]` the minimum and `ordered[-1]` the maximum. The mean is `sum(ordered) / n`. For the median, `n // 2` (integer division, which drops the remainder) gives the middle index. An odd count uses that middle value, and an even count averages the two middle values. Put all five results in one dictionary, using descriptive keys such as `"mean"`.

### Per-group averages with a dictionary

Keep two dictionaries, one for the running total of each group and one for its count. For each record, `totals.get(name, 0)` returns the current total, or 0 if the group is new, and the code stores the new total. `dict.get(key, default)` is the safe way to read a key that may not exist yet. At the end, divide each total by its count with a dictionary comprehension.

### Histogram bins

Find the minimum and maximum, then compute the bin width as `(hi - lo) / n`. Each value's bin is `int((m - lo) / width)`. `int` drops the decimal part, so 2.9 becomes 2. The maximum value gives an index equal to `n`, which does not exist, so it is pulled back into the last bin. If every value is equal, the width is zero and the division would fail, so put all values in the first bin before computing the width.

### The practice problem

Write three functions in one file.

1. `summarise(marks)` takes a non-empty list of numbers and returns a dictionary with the keys `count`, `min`, `max`, `mean` and `median`. An empty list raises `ValueError`.
2. `average_by_class(records)` takes a list of `(class_name, mark)` tuples and returns a dictionary from each class name to its mean mark. An empty list returns `{}`.
3. `histogram_counts(marks, n)` returns a list of `n` integers: the number of marks in each of `n` equal-width bins from the minimum to the maximum. The maximum belongs in the last bin. If all marks are equal, they all go in the first bin. An empty list returns `n` zeros. If `n` is zero or negative, raise `ValueError`.

Examples:

```text
summarise([40, 10, 30, 20])          -> {'count': 4, 'min': 10, 'max': 40, 'mean': 25.0, 'median': 25.0}
average_by_class([("A", 50), ("B", 70), ("A", 60)])  -> {'A': 55.0, 'B': 70.0}
histogram_counts([2, 10], 2)         -> [1, 1]
```

### Edge-case checklist

- **Empty input.** `summarise` must raise, `average_by_class` returns `{}`, and `histogram_counts` returns `n` zeros.
- **Ties.** Two equal values in the middle still need the even-count median. All-equal marks need the zero-width rule.
- **Ordering.** Do not rely on the input order. Sort a copy, and do not change the caller's list.
- **Types.** `sum / n` always gives a float in Python 3, so `mean` of `[5, 5]` is `5.0`. Compare dictionaries with the expected types in mind.
- **Rounding.** Do not round inside the functions. Round only when you display a result.
- **Boundaries.** The maximum goes into the last bin, not a bin that does not exist.

:::answer Full solution
```python test
def summarise(marks):
    if not marks:
        raise ValueError("marks is empty")
    ordered = sorted(marks)
    n = len(ordered)
    mid = n // 2
    if n % 2 == 1:
        median = ordered[mid]
    else:
        median = (ordered[mid - 1] + ordered[mid]) / 2
    return {
        "count": n,
        "min": ordered[0],
        "max": ordered[-1],
        "mean": sum(ordered) / n,
        "median": median,
    }


def average_by_class(records):
    totals = {}
    counts = {}
    for class_name, mark in records:
        totals[class_name] = totals.get(class_name, 0) + mark
        counts[class_name] = counts.get(class_name, 0) + 1
    return {name: totals[name] / counts[name] for name in totals}


def histogram_counts(marks, n):
    if n <= 0:
        raise ValueError("n must be positive")
    counts = [0] * n
    if not marks:
        return counts
    lo = min(marks)
    hi = max(marks)
    if lo == hi:
        counts[0] = len(marks)
        return counts
    width = (hi - lo) / n
    for m in marks:
        i = int((m - lo) / width)
        if i >= n:
            i = n - 1
        counts[i] += 1
    return counts

assert summarise([5, 1, 3])["median"] == 3
assert summarise([5, 5])["mean"] == 5.0
```
