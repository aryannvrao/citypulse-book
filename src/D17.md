## The idea in one minute

Today is about avoiding work you do not need. Binary search finds a value in a sorted list by checking the middle item and throwing away the half that cannot contain it. Recursion solves a problem by calling the same function on a smaller input until a simple case returns the answer directly. Breadth-first search (BFS) walks a network one ring of neighbours at a time, so the first route it finds has the fewest hops. A heap keeps the most important few items ready without sorting everything.

The everyday analogy is a printed dictionary. You open it near the middle, see whether your word comes before or after that page, and tear out the half you no longer need. Do the same again on the remaining half and you reach the word in a handful of steps.

By the end you will write a recursive function with a base case, search a sorted list, find a shortest-hop route through a network, and keep the top k items with a heap.

## Starting from zero

**Program.** A program is a text file full of instructions for the computer. A Python program is saved with the ending `.py`, for example `lab17_step1.py`. Running it makes the computer carry out the instructions from the top of the file downwards.

**Terminal.** The terminal is a window where you type commands instead of clicking. A **command** is one line you type and press Enter on. The course uses `python3`; on Windows, if that is not recognised, use `python` instead. `cd` means "change directory", which moves the terminal into a folder, so `cd lab17` moves it into a folder called `lab17`.

**Function.** A function is a named block of code you can run many times. You create it with `def`, and you run it by writing its name with brackets, which is called a **call**. The values you put in the brackets are **arguments**. The value a function sends back is its **return value**. In `max([3, 9, 4])`, `max` is the function, the list is the argument, and `9` is the return value.

**Variable.** A variable is a name that holds a value. `score = 88` stores 88 under the name `score`, and later you can use `score` anywhere you would use 88.

**List.** A list is an ordered collection written in square brackets, such as `[88, 142, 97]`. Items are numbered from 0. This number is the **index**, so `values[0]` is 88. A slice such as `values[1:]` means "everything from index 1 to the end".

**Tuple.** A tuple is a fixed group of values in round brackets, such as `(88, "s7")`. Python compares tuples element by element, first item first, and uses the second item only when the first items are equal.

**Dictionary.** A dictionary stores pairs of a key and a value in curly braces, such as `{"S1": 60}`. `d["S1"]` returns 60. `d.get("S9", 0)` returns 0 when the key is missing, instead of raising an error.

**Loop.** A `for` loop repeats an indented block once for each item in a collection. `while` repeats the block as long as its condition is true.

**Recursion and base case.** Recursion is a function calling itself. A **base case** is the condition under which the function returns without calling itself again. Without one, the calls never stop.

**Call stack.** While a function waits for a call it made, Python keeps a record of it on the **call stack**. Each nested call adds one record. If the stack grows past Python's limit, which is about 1000 by default, Python stops with a `RecursionError`.

**Sorted and monotonic.** A list is sorted when each value is at least as big as the one before it. Mathematicians call this **monotonic** (or non-decreasing when equal values are allowed). Binary search needs this property.

**Graph, node, edge, neighbour.** A graph is a set of **nodes** joined by **edges**. In a city network, a sensor is a node and a link between two sensors is an edge. Two nodes joined by an edge are **neighbours**. An **adjacency list** is a dictionary that maps each node to the list of its neighbours. A **tree** is a graph with a single root and no loops. A **cycle** is a route that leads back to where it started.

**Queue.** A queue is first in, first out: items leave in the order they arrived, like a bus queue. In Python, `collections.deque` gives a queue with `append` (add at the back) and `popleft` (remove from the front).

**Heap.** A heap is a tree stored in a list in which every parent is no larger than its children. A **min-heap** always has its smallest item at index 0. The Python module `heapq` (a module is a file of ready-made code that you load with `import`) provides `heappush` and `heappop` for it.

**Big-O.** Big-O notation describes how the work grows as the input size n grows. O(n) grows in step with n. O(log n) grows slowly: doubling n adds only one more step. O(n log k) means n items are each handled with work proportional to log k.

## The tools

### Recursion and binary search

Binary search answers "where does this value sit in an ordered list?" by halving the search range on every step. A linear scan checks every item and costs O(n) per question. Binary search costs O(log n) per question, but only once the data is ordered, and building that order costs time too. Recursion is one way to write binary search. The other ways are a `while` loop, which is often clearer in Python, and the library function `bisect`, which is what the slides use. `numpy.searchsorted` does the same job faster on large arrays, but the course allows it only as an extra benchmark column.

CityPulse needs the question "when did PM2.5 first cross 200?" for a series of readings. Raw readings go up and down, so they are not sorted, and binary search cannot be run on them directly. The fix is a **running maximum**: the largest value seen so far at each position. The running maximum never goes down, so it is monotonic, and binary search can find the first position where it reaches the threshold.

Here is the slide code, with indentation restored:

```python
from bisect import bisect_left
from itertools import accumulate

def scan(values: list[float], ts: list[str], threshold: float) -> str | None:
    return next((t for v, t in zip(values, ts) if v >= threshold), None)  # O(n)

def build(values: list[float]) -> list[float]:
    return list(accumulate(values, max))  # O(n) once; non-decreasing

def query(run_max: list[float], ts: list[str], threshold: float) -> str | None:
    i = bisect_left(run_max, threshold)  # O(log n): first run_max >= threshold
    return ts[i] if i < len(run_max) else None

vals, ts = [120, 90, 210, 180, 240], ["00h", "01h", "02h", "03h", "04h"]
assert all(scan(vals, ts, t) == query(build(vals), ts, t) for t in (150, 200, 230, 10000))
```

Line by line:

- `from bisect import bisect_left` loads one function, `bisect_left`, from the standard library module `bisect`. The word `from` picks the module, and `import` names what you want from it.
- `from itertools import accumulate` does the same for `accumulate`, which produces a running result, one value at a time.
- `def scan(values, ts, threshold):` defines the slow version. The `: list[float]` parts are type hints. They describe the expected type and do not change what the code does. `-> str | None` says the function returns either a string or `None`. The `|` symbol means "or". This syntax needs Python 3.10 or newer.
- In `scan`, `zip(values, ts)` pairs each reading with its timestamp. The generator expression `(t for v, t in ... if v >= threshold)` yields each timestamp whose reading reaches the threshold. `next(..., None)` takes the first one, or `None` when there is none. The comment `# O(n)` is a note for you. Python ignores it.
- `build` uses `accumulate(values, max)`. The second argument, `max`, tells `accumulate` to combine each new value with the running result using `max`. So the output for `[120, 90, 210]` is `[120, 120, 210]`. `list(...)` turns the result into a list.
- `query` calls `bisect_left(run_max, threshold)`. It returns the first index `i` at which `threshold` could be inserted and keep the list in order. Because the list is non-decreasing, that is the first index where `run_max[i] >= threshold`.
- `return ts[i] if i < len(run_max) else None` is a one-line `if`. If `i` is past the end, no crossing happened, so the answer is `None`.
- The `assert` line runs `scan` and `query` for four thresholds and checks that they agree. `all(...)` is True only when every comparison is True. The line prints nothing when it passes. If any comparison fails, Python stops with an `AssertionError`.

:::key Why the running maximum is needed
Binary search only works when the values it looks at are in order. The raw readings are not, but their running maximum is. Build the running maximum once, then answer any number of threshold questions in O(log n) each.
:::

:::trap Binary-searching the raw readings
Passing the raw PM2.5 list to `bisect_left` returns an index, but the index can point to the wrong place because the list is not ordered. The code runs without error, which makes the mistake easy to miss. Always check that the sequence you search is sorted or monotonic.
:::

:::trap Off-by-one errors in the loop
Binary search bugs usually come from the boundaries: `mid + 1` versus `mid`, or `hi = mid` versus `hi = mid - 1`. State the invariant before you write the loop, for example "the answer lies in the range [lo, hi)". Or use `bisect_left`, which has already been tested.
:::

:::trap Recursion without a base case
A recursive function with no case that returns directly will call itself until Python raises `RecursionError`. Write the base case first, with a comment, then test the empty input and the single-item input, because those are where the base case is needed.
:::

### Trees and BFS/DFS

A graph is a set of nodes and the edges between them. A tree is a graph with a single root and no cycles, such as a region hierarchy of city, zone and station. CityPulse uses graphs for the sensor network, where links join physically neighbouring stations, and for the bus routes between wards.

There are two standard ways to walk a graph. **Depth-first search (DFS)** follows one branch to its end before it comes back, usually with recursion or an explicit stack. **Breadth-first search (BFS)** visits the neighbours of the start first, then their neighbours, using a queue. For shortest routes in an unweighted graph, BFS is the right choice, because it reaches every node at distance 1 before any node at distance 2. When edges have weights, such as minutes or rupees, BFS is no longer enough, and you need Dijkstra's algorithm, which appears later in this chapter. The slides also mention the `networkx` library, which contains ready-made graph algorithms, but the checkpoint does not allow it because it hides the method you are being tested on.

BFS keeps two things. The queue holds the nodes still to be visited. The **parent map** is a dictionary that records which node first reached each node. The parent map also works as the "already seen" record, so a node is never queued twice. When the goal is found, you walk the parent map backwards from the goal to the start, and reverse the result.

```flow
TITLE: How BFS finds the fewest-hop route from S1 to S9
NODES: Start station | Queue | Neighbour check | Parent map
STEPS:
1>2 :: enqueue S1 :: The start station goes into the queue first.
2>3 :: popleft gives S1 :: The oldest item leaves the front. Its neighbours S2 and S4 are checked next.
3>4 :: S2 not seen :: S2 has not been visited, so the map records that S2 was reached from S1.
3>2 :: enqueue S2 :: S2 joins the back of the queue and waits for its turn.
2>3 :: popleft gives S2 :: S2 is the next item out, and its neighbours are checked.
```

The animation shows the order of work. Each item goes through the queue once, which is why the search finishes in time proportional to the number of nodes and edges.

Here is the slide code for the route search, with indentation restored:

```python
from collections import deque

def shortest_path_bfs(graph: dict[str, list[str]], start: str, goal: str) -> list[str] | None:
    parent, q = {start: None}, deque([start])  # time O(V + E), space O(V)
    while q:
        node = q.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for nxt in graph.get(node, []):
            if nxt not in parent:
                parent[nxt] = node
                q.append(nxt)
    return None
```

Line by line:

- `from collections import deque` loads the double-ended queue class.
- `parent, q = {start: None}, deque([start])` sets up two things at once. `parent` starts with the start node mapped to `None`, meaning "no parent". `q` starts holding the start node. Assigning two names in one line is a tuple assignment.
- `while q:` repeats while the queue is not empty. An empty deque is treated as False.
- `node = q.popleft()` removes and returns the front item. Using `pop(0)` on a list would also work, but it is slow on long lists.
- `if node == goal:` checks whether the node we have just taken out is the goal. Because nodes leave the queue in order of distance, the first time we see the goal, the route to it has the fewest edges.
- The inner `while node is not None:` loop walks the parent map. It appends each node, then moves to its parent. The loop stops at the start, whose parent is `None`.
- `path[::-1]` is a slice with a step of -1. It returns the list in reverse order, so the route runs from start to goal.
- `for nxt in graph.get(node, []):` checks each neighbour. `get` returns an empty list when the node is missing, so an unknown node does not crash the search.
- `if nxt not in parent:` is the visited check. A neighbour already in the parent map has been found before, so it is skipped.
- `parent[nxt] = node` records how we reached `nxt`, and `q.append(nxt)` queues it.
- `return None` runs only when the queue empties without finding the goal. That means the goal cannot be reached.

On the nine-station network from Step 3 of the lab, the call `shortest_path_bfs(g, "S1", "S9")` returns `['S1', 'S2', 'S6', 'S7', 'S8', 'S9']`. That is five hops. The route through S4 and S5 is six edges long, because it runs through S5 to S6, which is one hop longer than the direct route to S6 through S2.

:::trap Marking nodes as seen when you dequeue them
If you check `nxt not in parent` only when a node leaves the queue, the same node can be queued many times. The parent map must record a node the moment it is queued, as the slide code does.
:::

:::trap Using a list with pop(0) as the queue
`list.pop(0)` shifts every remaining item one place, so it gets slower as the queue grows. `collections.deque` with `popleft` takes the same time whatever the queue length.
:::

:::trap Forgetting disconnected graphs
If the goal sits in a separate part of the graph, the search runs out of nodes and must return `None`. Test that case explicitly, because the code path that handles it is easy to forget.
:::

:::tip Depth-first search in one sentence
DFS goes as deep as it can along one branch before backtracking, so the first route it finds need not be the shortest. In an interview, say "BFS for fewest hops, DFS for exploring everything".
:::

### Heaps (heapq)

A heap gives you the smallest item at index 0 at all times, and adding or removing an item costs O(log n). That makes it the right tool when you need the top few items from a stream of data without sorting all of it. The live "top five most polluted stations" widget needs five items, so a heap of size 5 avoids sorting every station. The slides name two alternatives. `sorted(values)[:k]` is O(n log n) and simpler, which is fine for small data and works as a correctness check. `heapq.nlargest` is one line and uses a heap internally, but the checkpoint asks you to write the size-k heap yourself.

The method is simple. Keep a min-heap of at most k items. Push each new value. When the heap holds more than k items, pop the smallest, which is the one that does not belong in the top k. At the end, the heap holds the k largest values.

The slide code reads CSV data, keeps the latest reading for each station, and then selects the top k. Indentation is restored below:

```python
import csv, heapq, sys

def top_k_latest(path: str, k: int = 5) -> list[tuple[float, str]]:
    latest: dict[str, tuple[str, float]] = {}
    with open(path, newline="") as f:
        for row in csv.DictReader(f):  # columns: station, ts, pm25
            if row["pm25"] and (row["station"] not in latest or row["ts"] > latest[row["station"]][0]):
                latest[row["station"]] = (row["ts"], float(row["pm25"]))
    heap: list[tuple[float, str]] = []  # min-heap, size <= k: O(n log k)
    for station, (_, pm25) in latest.items():
        heapq.heappush(heap, (pm25, station))
        if len(heap) > k:
            heapq.heappop(heap)  # drop the smallest of k + 1
    return sorted(heap, reverse=True)

print(top_k_latest(sys.argv[1]))
```

Line by line:

- `import csv, heapq, sys` loads three modules in one line. `csv` reads comma-separated files, `heapq` provides the heap, and `sys` gives access to the command-line arguments.
- `def top_k_latest(path: str, k: int = 5)` declares a parameter `k` with a default value of 5. If the caller leaves `k` out, it is 5.
- `latest: dict[...] = {}` creates an empty dictionary. The annotation tells the reader what it holds, and the code does not depend on it.
- `with open(path, newline="") as f:` opens the file and guarantees it will be closed at the end of the block. `newline=""` stops the `csv` module from mishandling line endings.
- `csv.DictReader(f)` reads each row as a dictionary whose keys are the column names, so `row["pm25"]` is the PM2.5 text in that row.
- The `if` line skips rows where `pm25` is blank, so `float("")` never runs. It also keeps the row only if the station is new or the timestamp is later than the one already stored. Timestamps in ISO 8601 form, such as `2027-01-09T10:00`, compare correctly as text.
- `latest[row["station"]] = (row["ts"], float(row["pm25"]))` stores the timestamp and the number as a tuple.
- `heap: list[tuple[float, str]] = []` starts the heap as an empty list.
- `heapq.heappush(heap, (pm25, station))` adds one tuple. The pm25 value comes first, so the heap orders by reading.
- `if len(heap) > k:` checks the size. `heapq.heappop(heap)` removes the smallest tuple. The comment says what it removes.
- `sorted(heap, reverse=True)` sorts the k remaining items largest first. `reverse=True` is a flag that flips the order.
- `print(top_k_latest(sys.argv[1]))` runs the function on the file named after the script on the command line. `sys.argv` is a list of the words you typed, so `sys.argv[0]` is the script name and `sys.argv[1]` is the first argument after it.

Running `python3 topk_heap.py latest.csv` prints a list of up to five pairs of `(pm25, station)`, largest first. The exact numbers depend on your file.

:::trap Using a max-heap of every item
A max-heap of all n readings costs O(n log n) and keeps every reading in memory. The slide code keeps a min-heap of size k, which costs O(n log k) and never holds more than k+1 items. Look at `heap` in the code: it never grows beyond k.
:::

:::trap Calling float on a blank reading
`float("")` raises `ValueError`. Check that `row["pm25"]` is not empty before converting it, as the `if` line in the slide code does.
:::

:::trap Comparing timestamps in mixed formats
Text comparison works for ISO 8601 timestamps such as `2027-01-09T10:00`, but not for `09/01/2027 10:00`, which sorts by day before month or year. Parse the timestamps when the formats differ.
:::

## The worked example

The workbook example takes four readings and keeps the three worst. The goal is to see the size-3 heap change as each reading arrives.

```python
import heapq

def top_k(readings, k):
    heap = []
    for s, v in readings:
        heapq.heappush(heap, (v, s))
        if len(heap) > k:
            heapq.heappop(heap)  # drop the current lowest
    return sorted(heap, reverse=True)

for v, s in top_k([("s7", 88), ("s3", 142), ("s9", 97), ("s1", 60)], 3):
    print(s, v)
```

Line by line:

- `import heapq` loads the heap functions. Nothing else needs importing.
- `def top_k(readings, k):` takes a list of `(station, value)` pairs and the number `k`. The pairs are written station first in the input, but the heap stores them value first.
- `for s, v in readings:` unpacks each pair into two names.
- `heapq.heappush(heap, (v, s))` stores the value first, so that the heap orders by reading.
- `if len(heap) > k:` and `heapq.heappop(heap)` keep the heap at size k by removing the smallest item.
- `return sorted(heap, reverse=True)` returns the survivors, largest first.
- The last loop prints the results. `for v, s in top_k(...)` unpacks each returned pair, and `print(s, v)` prints the station and the value separated by a space.

The heap holds the following after each push, in the order `heapq` stores them:

| Reading pushed | Heap size before pop | Heap after any pop | Popped |
|---|---|---|---|
| (88, s7) | 1 | (88, s7) | nothing |
| (142, s3) | 2 | (88, s7), (142, s3) | nothing |
| (97, s9) | 3 | (88, s7), (142, s3), (97, s9) | nothing |
| (60, s1) | 4 | (88, s7), (142, s3), (97, s9) | (60, s1) |

Running the code prints:

```term
$ python worst_stations.py
s3 142
s9 97
s7 88
```

The first line is the command you typed. The three lines below it are the output. Station s1 is gone because its reading of 60 was the lowest and was popped at the fourth push.

:::tip Know the tie rule before you write code
`sorted(heap, reverse=True)` sorts tuples by value first, and then by station name in reverse. If two stations tie on 97, the one with the later name comes first. The graded lab asks for a fixed tie-break, which is different, so always read the tie rule in the task.
:::

### Step 1. Recursion with a base case

**What you do.** Write a recursive function that adds up a list of numbers.

**What you type.**

```python
def total(values):
    if not values:                        # base case: an empty list adds up to 0
        return 0
    return values[0] + total(values[1:])  # recurse on a list one item shorter

print(total([3, 5, 7]))
```

Line by line: `def total(values):` defines the function. `if not values:` is True when the list is empty, because `not` turns an empty list into True. That is the base case, and it returns 0 without calling itself. `values[0]` is the first item, and `values[1:]` is the rest of the list. The last line calls the function and prints the result.

**What you should see.**

```term
$ python3 lab17_step1.py

```

**How you know it worked.** The output is 15. The calls run like this: `total([3, 5, 7])` becomes `3 + total([5, 7])`, then `5 + total([7])`, then `7 + total([])`, and the last call returns 0. That is four calls on the call stack. To see the failure, delete the `if` block and run the file again. Python prints a `RecursionError` after about 1000 calls.

### Step 2. Binary search a time-sorted array

**What you do.** Write a recursive binary search over a list of timestamps measured in minutes.

**What you type.**

```python
def bsearch(arr, target, lo=0, hi=None):
    if hi is None:
        hi = len(arr) - 1
    if lo > hi:                  # base case: empty range, so a miss
        return -1
    mid = (lo + hi) // 2
    if arr[mid] == target:
        return mid
    if arr[mid] < target:
        return bsearch(arr, target, mid + 1, hi)
    return bsearch(arr, target, lo, mid - 1)

ts = [0, 15, 30, 45, 60, 75, 90, 105, 120, 135]
print("find 90 ->", bsearch(ts, 90))
print("find 7 ->", bsearch(ts, 7))
```

Line by line: `lo=0, hi=None` gives the two bounds default values, so the first call only needs the array and the target. `if lo > hi:` returns -1 when the range is empty, which is the base case that stops the recursion. `mid = (lo + hi) // 2` finds the middle index. `//` is integer division, which drops any fraction. The two `if` lines then decide whether the target lies to the right or the left of the middle, and each recursive call searches only that half. The `print` lines call the function twice.

**What you should see.**

```term
$ python3 lab17_step2.py
find 90 -> 6
find 7 -> -1
```

**How you know it worked.** Index 6 holds 90 in the list, and 7 is not in the list at all, so -1 is correct. Count the midpoints for 90 to check the halving: the search looks at index 4, then 7, then 5, then 6. Each step cuts the range roughly in half.

### Step 3. Model the station graph

**What you do.** Turn the list of links between sensors into an adjacency list, and count the stations and links.

**What you type.**

```python
EDGES = [("S1","S2"),("S1","S4"),("S2","S3"),("S2","S6"),
         ("S3","S5"),("S4","S5"),("S5","S6"),("S6","S7"),
         ("S7","S8"),("S8","S9")]

def build(edges):
    g = {}
    for a, b in edges:
        g.setdefault(a, []).append(b)
        g.setdefault(b, []).append(a)  # undirected: the link works both ways
    return g

g = build(EDGES)
print(f"stations: {len(g)} edges: {len(EDGES)}")
```

```python
def shortest_path_bfs(graph, start, goal):
    parent, q = {start: None}, deque([start])
    while q:
        node = q.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]

                q.append(nxt)
    return None
```

## What the quiz tests

The day quiz has ten case-study questions, and the first attempt counts. Each topic below is one of those ten, in the order the quiz uses them.

### binary-search

You must know that binary search needs a sorted or monotonic sequence, and that it halves the range each step to reach O(log n) per lookup. You must also know what `bisect_left` returns: the first index where the value could be inserted and stay in order. If every value is smaller than the target, the answer is `len(list)`, which is one past the end. The examiner's trap is a list that looks ordered in time but is not ordered by value, such as raw PM2.5 readings. The correct move is to build a running maximum first.

:::trap Searching a list that is not sorted
Binary search returns an index without an error even when the list is unsorted, so the mistake is silent. The examiner expects you to name the property that makes the search valid.
:::

### recursion-base-case

A recursive function must have a case that returns without calling itself, and every recursive call must move closer to that case. The number of calls that are waiting at once is the depth of the call stack. Python stops at about 1000 by default, so a function that recurses once per item of a 5000-item list fails with `RecursionError`. The examiner's trap is a base case that is never reached, such as when the input is shrinking in the wrong direction, or a base case that is checked after the recursive call instead of before it.

:::trap A base case that is never reached
A function whose recursive call moves away from the base case, such as `n + 1` when the base case is `n == 0`, runs forever. Every recursive call must make the input smaller in a way that reaches the base case.
:::

### bfs-shortest-path

You must know that BFS finds the path with the fewest edges in an unweighted graph, because it uses a FIFO queue and visits nodes in order of distance. The parent map gives the route when you walk it back from the goal. Mark a node as seen when it is queued, not when it is dequeued, because otherwise nodes are queued many times. The examiner's trap is a DFS-based answer for a "fewest stops" question, which returns some route, but not necessarily the shortest one.

:::trap Using DFS for the shortest route
DFS explores one branch deeply before returning, so its first route to the goal can be long. For "fewest hops", the answer is always BFS.
:::

### min-heap

Python's `heapq` is a min-heap. The smallest item is always at index 0, which you can read in O(1) with `heap[0]`. `heappush` and `heappop` each cost O(log n). The module has no max-heap, so a common method is to push negated numbers. The examiner's trap is assuming that `heappop` returns the largest item, or that `heap` is sorted as a list. It is not sorted; only index 0 is guaranteed to be the smallest.

:::trap Reading the heap as a sorted list
Only `heap[0]` is guaranteed to be the minimum. Printing `heap` shows the internal layout, which is not sorted order. Use `sorted(heap)` to see the items in order.
:::

### bst-range-query

A binary search tree keeps every key in the left subtree smaller than the node and every key in the right subtree larger. A range query for keys between `lo` and `hi` can therefore skip a whole subtree whenever the node's key rules it out. The cost is roughly O(h + m), where h is the height of the tree and m is the number of keys reported. The examiner's trap is a tree that is not balanced. A tree built from sorted input becomes a chain with height n, and then the query costs O(n).

:::trap Visiting every node in a range query
If you search the whole tree, the answer is still correct, but the point of the tree is lost. Skip any subtree that cannot overlap the range.
:::

### top-k-heap

Keep a min-heap of size k, push each value, and pop whenever the size exceeds k. This costs O(n log k) and holds at most k+1 items. The alternative of sorting costs O(n log n). The examiner's trap is a max-heap of all n items, which is correct but slower and uses more memory, and a tie-break that is not stated. When two values are equal, the answer depends on what is stored in the tuple, so state which tie-break you are using.

:::trap A max-heap of everything
A max-heap of all n values is O(n log n) and holds all n values. The min-heap of size k is O(n log k). Both give the right answer, but only the second meets the "at most k" rule.
:::

### cycle-detection

In an undirected graph, a cycle exists when DFS or BFS reaches a node that has already been visited and is not the node we came from. The edge back to the parent is normal, so it must be ignored. In a directed graph the test is different, and you need to track which nodes are currently on the search path. The examiner's trap is counting the edge to the parent as a cycle, which makes every edge look like a loop.

:::trap Counting the parent edge
In an undirected graph, the edge from a node back to its parent always leads to a visited node. Only a visited node other than the parent proves there is a loop.
:::

### memoization

Memoization stores the answer to each recursive call in a dictionary the first time the call is made, and returns the stored value for later calls with the same arguments. For Fibonacci-like recursions, this turns exponential time into linear time. Python's `functools.lru_cache` does this for you. The examiner's trap is a cache that is keyed on only part of the arguments, or one that stores mutable results that later change. A cached result must depend only on its arguments.

:::trap Forgetting that the cache key must match the arguments
If the function takes two arguments and the cache key uses only one, different calls return each other's results. The key must include every argument that changes the answer.
:::

### bfs-complexity

BFS visits each node once and checks each adjacency entry once, so the time is O(V + E). The queue and the parent map each hold at most V items, so the space is O(V). With an adjacency list, the work depends on the number of edges. With an adjacency matrix, the work is O(V squared), because every pair of nodes must be checked. The examiner's trap is stating O(V) alone, which ignores the cost of looking at every link.

:::trap Forgetting the edges
Saying "BFS is O(V)" is wrong for any graph with many links. The edges cost time too, so the total is O(V + E).
:::

### dijkstra

Dijkstra's algorithm finds the cheapest total cost from a start node when every edge weight is zero or positive. It keeps a min-heap of (total cost so far, node) pairs and always takes out the cheapest. When a node is taken out for the first time, its cost is final. With a heap, the time is O(E log V). The examiner's trap has two parts: BFS is wrong for weighted graphs, because it counts hops rather than cost, and Dijkstra gives wrong answers when a weight is negative.

:::trap Using BFS on weighted edges
BFS finds the route with the fewest edges, not the cheapest. A route with two cheap edges can cost less than a route with one expensive edge, and BFS would choose the one-edge route.
:::

## The graded lab skill

The graded lab is a Python problem marked by visible tests and by hidden tests. The hidden tests check edge cases you did not think about, so the techniques below matter as much as the main idea. Each technique is explained from first principles before the practice problem.

### Dictionaries of dictionaries as weighted graphs

A weighted graph stores its edges in a dictionary that maps each node to another dictionary of neighbours and weights. For example, `graph["BLR"]["DEL"]` is the fare from Bengaluru to Delhi. `graph.get(node, {})` returns an empty dictionary when the node has no outgoing edges, so a missing airport does not raise an error. The `.items()` method gives the pairs of neighbour and fare, which you loop over with `for nxt, fare in ...`.

Edges are one-way as written. If a flight runs both ways, the data must list both directions. The code never adds a reverse edge for you. Assume fares are zero or more, because Dijkstra's algorithm is not correct with negative fares.

### heapq with tuples

`heapq` compares tuples element by element. Storing `(total_cost, airport)` means the heap always removes the cheapest total cost. When two costs are equal, the airport name breaks the tie, which is harmless for the shortest path but matters for top-k selection. Only the `<` operator is used by `heapq`, so any object that defines `__lt__` can be stored in the heap.

### A sentinel return value

A **sentinel** is a special value that means "no answer". The task asks for `-1` when there is no route, and for `0` when the start and destination are the same. A sentinel must be a value that can never be a real answer. A fare is never negative, so `-1` is safe here. The function returns it at the very end, after the search has run out of options. Returning `None` would also work, but the task specifies `-1`, so follow the specification exactly.

### Dijkstra with lazy deletion

Dijkstra's algorithm keeps the best known cost to each node in a dictionary. When a node is pushed onto the heap with a cost, the entry may later become out of date, because a cheaper route to the same node may be found. Instead of removing the old entry from the heap, which is slow, the code skips it when it is popped. This is called **lazy deletion**. The check `if cost > best[node]: continue` identifies an out-of-date entry.

### Top-k with a deterministic tie-break

To keep the k best players by score, with ties broken by name in alphabetical order, a min-heap needs to know which of two equal-score players is weaker. The weaker one is the player whose name comes later alphabetically, because the earlier name ranks higher. A tuple `(score, name)` would keep the wrong player, because the smaller name would be treated as the weakest. The solution uses a small class with `__lt__` that defines "weaker" the right way round.

### The practice problem

Write two functions.

**`cheapest_fare(graph, src, dst)`** receives a weighted graph as a dictionary of dictionaries, where `graph[a][b]` is the fare for a flight from `a` to `b`. It returns the cheapest total fare from `src` to `dst`. It returns `0` when `src` and `dst` are the same airport, and `-1` when there is no route.

**`top_k_players(pairs, k)`** receives a list of `(name, score)` pairs. It returns a list of the `k` highest-scoring players as `(name, score)` pairs, highest score first. When scores tie, the player whose name comes first alphabetically comes first.

Example. With the graph `{"BLR": {"DEL": 5000, "BOM": 3000}, "BOM": {"DEL": 1500, "GOI": 1500}, "DEL": {"GOI": 4000}, "GOI": {}}`:

- `cheapest_fare(graph, "BLR", "DEL")` returns `4500`, because BLR to BOM to DEL costs 3000 + 1500, which is less than the direct 5000.
- `cheapest_fare(graph, "GOI", "BLR")` returns `-1`, because GOI has no outgoing flights.
- `cheapest_fare(graph, "BLR", "BLR")` returns `0`.
- `top_k_players([("Asha", 50), ("Ravi", 70), ("Bina", 70), ("Chetan", 40)], 2)` returns `[("Bina", 70), ("Ravi", 70)]`.

**Edge-case checklist**

- Empty input: an empty graph or an empty list of pairs must not raise an error.
- Missing fields: an airport that is not a key in the graph, or a destination that no route reaches.
- Same start and destination: the answer is `0`, even if the airport has no flights at all.
- Ordering: the cheapest route is not always the one with the fewest flights.
- Ties: equal scores must be ordered by name, and the heap must keep the right one at the boundary.
- Types: fares and scores may be whole numbers. Compare them as numbers, not as text.
- Rounding: fares are whole rupees, so do not round. If a fare were a decimal, keep its exact value.
- `k` values: zero, negative, and larger than the number of players.

```python test
import heapq

def cheapest_fare(graph, src, dst):
    if src == dst:
        return 0
    best = {src: 0}                  # cheapest known total to each airport
    heap = [(0, src)]                # (total so far, airport)
    while heap:
        cost, node = heapq.heappop(heap)
        if node == dst:
            return cost
        if cost > best[node]:        # stale entry: a cheaper one was already handled
            continue
        for nxt, fare in graph.get(node, {}).items():
            new_cost = cost + fare
            if new_cost < best.get(nxt, float("inf")):
                best[nxt] = new_cost
                heapq.heappush(heap, (new_cost, nxt))
    return -1


class _Rank:
    """Orders players so that the heap root is the weakest kept player."""
    __slots__ = ("score", "name")

    def __init__(self, score, name):
        self.score = score
        self.name = name

    def __lt__(self, other):
        if self.score != other.score:
            return self.score < other.score
        return self.name > other.name   # same score: the later name is weaker


def top_k_players(pairs, k):
    if k <= 0:
        return []
    heap = []
    for name, score in pairs:
        heapq.heappush(heap, _Rank(score, name))
        if len(heap) > k:
            heapq.heappop(heap)
    ordered = sorted(heap, key=lambda r: (-r.score, r.name))
    return [(r.name, r.score) for r in ordered]

    "BLR": {"DEL": 5000, "BOM": 3000},
    "BOM": {"DEL": 1500, "GOI": 1500},
```

Line by line:

- `import heapq` loads the heap functions. No other module is needed.
- `if src == dst: return 0` handles the same-airport case first, so it works even when the airport has no flights.
- `best = {src: 0}` records the cheapest known total to each airport. The start costs nothing.
- `heap = [(0, src)]` starts the heap with the start airport. The tuple puts the cost first, so the heap orders by cost.
- `while heap:` runs until there is nothing left to explore. If the loop ends, no route exists.
- `cost, node = heapq.heappop(heap)` removes the cheapest entry. The two names unpack the tuple.
- `if node == dst: return cost` is the key rule of Dijkstra's algorithm. The first time the destination leaves the heap, its cost is final, so return it.
- `if cost > best[node]: continue` skips an out-of-date entry, as explained under lazy deletion. `continue` moves to the next loop round.
- `graph.get(node, {}).items()` gives each outgoing flight. A node with no outgoing flights, such as GOI, gives an empty loop.
- `new_cost = cost + fare` is the total cost of reaching `nxt` through `node`.
- `best.get(nxt, float("inf"))` returns a value larger than any real cost when `nxt` has not been reached yet, so the first route always wins. `float("inf")` is Python's infinity.
- The last two lines inside the `if` update the best cost and push the new entry.
- `return -1` runs only when the heap is empty, which means the destination was never reached. That is the sentinel.
- `class _Rank:` defines a small class. The leading underscore is a convention meaning "for internal use". The docstring in triple quotes describes the class.
- `__slots__ = ("score", "name")` tells Python to store only these two attributes. It saves memory and is not needed for correctness.
- `__init__` runs when a new `_Rank` is created, and `self.score = score` stores the value on the object. `self` is the object itself.
- `__lt__` answers the question "is this item less than that one?". `heapq` uses only this method. A lower score is less. When scores are equal, the later name is less, because it is the weaker player. `self.name > other.name` compares the strings alphabetically.
- In `top_k_players`, `if k <= 0: return []` handles zero and negative k before any work is done.
- `heapq.heappush(heap, _Rank(score, name))` pushes the player, and `heappop` removes the weakest when the heap grows past k.
- `sorted(heap, key=lambda r: (-r.score, r.name))` sorts by negated score, so the highest score comes first, and then by name in ascending order. `lambda` creates a short unnamed function that gives the sort key. The minus sign flips the order of the numbers.
- The last line converts each `_Rank` into the `(name, score)` tuple the task asks for.
- The `assert` lines are the tests. The first group checks the route cases: a normal route, a cheaper multi-hop route, the same airport, an unreachable airport, and an airport missing from the graph. The second group checks the top-k cases: a tie at the boundary, a tie where the heap must remove the later name, a `k` larger than the list, an empty list, and `k` equal to zero. The program prints nothing when all the checks pass.
:::

## Say it out loud

The ticket Y2-T27 asks you to write a size-k heap with skipped blanks and a check against `sorted()`, and the contest Y2-T57 asks you to state the pattern and its complexity aloud. These five questions are the ones an examiner is likely to ask.

**Why does binary search need sorted data, and what do you do when the data is not sorted?**

:::answer Model answer
Binary search rejects half the range on each step, and that is only valid when the values are ordered, because then one comparison tells you which half could hold the target. When the readings are not in value order, you must first make the data monotonic. For a first-crossing question, the running maximum is monotonic, so the search runs on it and returns the first position where the threshold is reached. The cost is O(n) to build it once, then O(log n) for every query.
:::

**What is a base case, and what happens if your recursion has none?**

:::answer Model answer
A base case is the input for which the function returns an answer without calling itself. Every recursive call must move the input closer to a base case, so the recursion always ends. Without a reachable base case, the calls keep stacking until Python stops with a `RecursionError`, which is a sign that the recursion is not closing. I write the base case first, with a comment, and test the empty and single-item inputs before I trust the rest of the function.
:::

**Why does BFS give the fewest hops, and what would DFS give you instead?**

:::answer Model answer
BFS uses a first-in, first-out queue, so it visits all nodes at distance one before any node at distance two, and so on. The first time it reaches the goal, the path it walked has the fewest edges, and the parent map rebuilds that path. DFS goes deep along one branch before it backtracks, so its first route to the goal can be much longer than the shortest. DFS is still useful for exploring everything, detecting cycles and ordering tasks, but not for fewest hops.
:::

**Why does a top-k heap keep a min-heap of size k, and what does it cost?**

:::answer Model answer
The smallest item in the heap is the first candidate to leave, so keeping a min-heap of size k means the heap always holds the k largest values seen so far. Every new value costs O(log k) to push or pop, and there are n values, so the total is O(n log k). A max-heap of everything would cost O(n log n) and hold far more items, and sorting everything costs the same O(n log n). The answer is correct whatever the method, but the size-k heap is the one that scales.
:::

**How do you know your heap answer is correct?**

:::answer Model answer
I compare it with a simple method that I trust, usually a sorted list, using an `assert` line. The check covers the normal case, a value of k bigger than the number of items, and k equal to zero, because those are the edges where a heap is easiest to get wrong. If the check fails, Python stops and shows which line failed. I also state the tie rule, because two equal values can be ordered differently by two correct methods, and the test must agree with the rule in the task.
:::
