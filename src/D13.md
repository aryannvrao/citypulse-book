TITLE: Day 13 — Object storage with S3 and boto3
SUB: You will be able to create a private, encrypted and versioned S3 bucket, upload files under date-based keys with boto3, and show that anonymous access is refused.

## The idea in one minute

Today you learn to store files in the cloud and reach them from Python. Amazon Web Services (AWS) rents out computers and storage over the internet. Its file store is called Amazon S3 (Simple Storage Service). S3 keeps files as objects inside buckets, which are named containers. Every object has a key, which is its full name inside the bucket.

You will do three things. You will lock a bucket so that nobody outside can read it, encrypt it, and keep old copies of changed files. You will upload CityPulse air-quality data under date-based keys. You will write a short Python script that does the upload and reports failures correctly.

Think of a bucket as a warehouse and the key as the shelf label printed on each box. A tidy label scheme means you can find the box for one day without opening every box in the building.

## Starting from zero

**Terminal.** The terminal is a text window where you type commands and the computer prints text back. A **command** is one line you type, such as `ls`, which lists the files in a folder. Use **Git Bash**, a terminal that understands the **Bash** language of commands. Git Bash is installed with Git for Windows. Use it instead of PowerShell for every command in this chapter, because the examples use single quotes and `$` variables, which PowerShell reads differently.

**File, folder and path.** A file holds data such as text, numbers or an image. A folder holds files and other folders. A **path** is the address of a file, for example `data/clean/aq_clean.parquet`. Parquet is a compressed table format. It stores each column together, so a reader can skip the columns it does not need.

**Variable and function.** A **variable** is a name that holds a value, such as `bucket = "citypulse-x7k2q9"`. A **function** is a named block of code that takes inputs and returns a result. In `len("abc")`, `len` is the function and `"abc"` is the input it works on.

**Script and module.** A **script** is a text file of Python code that you run with `python filename.py`. A **module** is a Python file that another program loads with `import`, as in `import boto3`.

**Server and cloud.** A **server** is a computer that answers requests from other programs. The **cloud** means that the servers belong to a provider such as AWS, and you rent parts of them over the internet.

**Bucket, object, key and prefix.** A bucket is a container with a name that is unique across the whole of AWS. An **object** is one stored file together with its **metadata**, which are extra facts such as size and content type. The **key** is the object's full name, for example `clean/aqi/date=2026-12-17/aq_clean.parquet`. A **prefix** is the start of a key, such as `clean/aqi/`. S3 has no real folders. The slashes only look like folders in the AWS web console.

**API and SDK.** An **API** (Application Programming Interface) is a list of named operations that a program can call, such as "store this file under this key". An **SDK** (Software Development Kit) is a library that gives you those operations in one language. **boto3** is the SDK for Python. You install it with `pip install boto3`, where **pip** is the Python package installer.

**HTTP and status codes.** **HTTP** (Hypertext Transfer Protocol) is the message format that browsers and tools use to talk to web servers. Every reply carries a three-digit **status code**. 200 means success, 403 means the request is refused, and 404 means the thing was not found.

**Credentials, profile and environment variable.** **Credentials** are secret values that prove who you are to AWS. A **profile** is a named set of credentials stored in a file on your computer, such as `citypulse-pipeline`. An **environment variable** is a named setting that the shell passes to every program it starts. You set one with `export NAME=value`.

**Region.** A **region** is one AWS data-centre area. This course uses `ap-south-1`, which is the Mumbai region.

**Exception and exit code.** An **exception** is an error that Python raises while a program runs. A `ClientError` is the exception that boto3 raises when AWS refuses a request. The **exit code** is the number a program hands back to the shell when it stops. Zero means success and any other number means failure. In Bash, `echo $?` prints the exit code of the last command.

## The tools

### Amazon S3 buckets and partitioning

**What it is.** S3 stores objects in buckets. An object can be any size up to 5 TB, and you pay for the bytes you keep and the requests you make. CityPulse uses S3 for clean data because the virtual machine you build on Day 14 (ticket T19) and the Lambda function (a small program that AWS runs when an event happens) in a later day must write to it, and analysts must read it from anywhere.

**Why not the alternatives.** An **EBS volume** is a virtual disk attached to one virtual machine. Only that machine can use it, and you pay for the size you provision whether you use it or not. **Amazon EFS** is a shared file system with folder paths. It costs more and is unnecessary for files that are written once and then read. Storing files as **database BLOBs** (large binary values inside SQL tables) bloats the database and costs far more per gigabyte.

**How it works.** The CityPulse key layout is `clean/<dataset>/date=YYYY-MM-DD/<filename>`. The `date=` part is a naming convention that query tools understand. Because the date is in the key, a reader that asks for the prefix `clean/aqi/date=2026-12-17/` gets only that day. This is called **partitioning**: the data is split into parts by a value that readers filter on.

```trace
TITLE: Building one dated key
CODE:
import datetime
dates = ["2026-12-17", "2026-12-18"]
keys = []
for text in dates:
    day = datetime.date.fromisoformat(text)
    keys.append("clean/aqi/date=" + day.isoformat() + "/aq_clean.parquet")
print(keys)
STEPS:
1 :: (no variables yet) :: Python loads the datetime module.
3 :: dates=["2026-12-17", "2026-12-18"]; keys=[] :: The two date strings are stored, and the key list starts empty.
4 :: dates=["2026-12-17", "2026-12-18"]; keys=[]; text="2026-12-17" :: The loop takes the first date string.
5 :: dates=["2026-12-17", "2026-12-18"]; keys=[]; text="2026-12-17"; day=2026-12-17 :: fromisoformat checks the text and makes a date object. A text that is not a real date raises ValueError.
6 :: keys=["clean/aqi/date=2026-12-17/aq_clean.parquet"]; text="2026-12-17"; day=2026-12-17 :: The first key is built from the date and appended.
4 :: keys=["clean/aqi/date=2026-12-17/aq_clean.parquet"]; text="2026-12-18" :: The loop comes round again with the second date.
5 :: keys=["clean/aqi/date=2026-12-17/aq_clean.parquet"]; text="2026-12-18"; day=2026-12-18 :: The second date becomes a date object.
6 :: keys=["clean/aqi/date=2026-12-17/aq_clean.parquet", "clean/aqi/date=2026-12-18/aq_clean.parquet"] :: The second key is appended, and the loop ends.
7 :: keys=[both keys] :: print shows the list, with two keys in order.
```

The `date=` names are ISO dates. That means year first, then month, then day, all with leading zeros. Text sorted in this order is also in date order, which is why the layout works for listing.

Here is the picture of one reading moving through the system. The upload script sends the object, S3 stores it, and a dashboard asks only for one day.

```flow
TITLE: One day of AQI data, from upload to dashboard
NODES: upload.py | S3 bucket | Dashboard reader
STEPS:
1>2 :: put_object with Key :: upload.py sends the file bytes and the key clean/aqi/date=2026-12-17/aq_clean.parquet.
2>1 :: stored, success :: S3 writes the object and replies that the write succeeded.
3>2 :: list with Prefix :: The dashboard asks only for keys that start with clean/aqi/date=2026-12-17/.
2>3 :: matching keys only :: S3 returns the keys under that prefix, so the dashboard reads one day and nothing else.
2>1 :: AccessDenied :: If the caller is not allowed, S3 refuses, and the refusal travels back as an error.
```

**Commands that prove the bucket is set up.** Every setting in this chapter can be read back with a `get` command. The term block below shows how to check versioning. The output shown is the shape you should expect.

```term
$ aws s3api get-bucket-versioning --bucket citypulse-x7k2q9
{
    "Status": "Enabled"
}
```

`aws` is the AWS command-line tool. `s3api` is the group of commands that map one-to-one onto the S3 API. `get-bucket-versioning` asks for the current versioning setting. `--bucket` is a flag, which is an option written after the command name. The flag names the bucket, and the value after it is the bucket name. `Status` is `Enabled` only after you turn versioning on. The bucket name `citypulse-x7k2q9` is an example, and you use your own.

:::trap Listing the whole bucket
Running `aws s3 ls s3://bucket` with no prefix is denied for the scoped pipeline identity. List `s3://bucket/clean/aqi/` instead. Narrow prefixes are also cheaper and faster, because S3 does less work.
:::

:::trap Dates in the wrong order
A key such as `date=17-12-2026` does not sort by date, because text sorts by its first characters. Use `date=YYYY-MM-DD` every time.
:::

:::trap Choosing a bucket name
Bucket names are global and permanent. Add a random suffix, and never put personal data in the name. Once a name exists anywhere in AWS, nobody else can take it.
:::

### Encryption and the public-access block

**What it is.** Three settings keep the bucket safe. **Block Public Access** is a set of four switches that override any **ACL** (access control list, a permission list attached to a bucket or object) or bucket policy that would make data public. **Default encryption** with SSE-S3 (server-side encryption with S3-managed keys) encrypts every new object at rest, meaning while it is stored on disk, using the AES-256 algorithm. Since 2023 AWS applies SSE-S3 to new objects by default, but the course still sets it explicitly so the evidence shows it. **Versioning** keeps the old copy of an object when it is overwritten or deleted.

**Why not the alternatives.** **SSE-KMS** uses a key from AWS Key Management Service, which gives you a log of each use of the key. It adds cost and permissions work, so it is worth it only for sensitive data. **Client-side encryption** means your code encrypts the file before upload. It is the strongest option, but then you manage the keys, and S3 cannot read the data. A **bucket policy** that denies public access also works, but Block Public Access is simpler and overrides mistakes made elsewhere.

**How it works.** The three settings are bucket settings, so the admin profile sets them once. The pipeline profile never does this. The commands use the flags `--bucket` and `--versioning-configuration`, and the values are written as `Name=Value` pairs.

```bash
B=citypulse-x7k2q9
export AWS_PROFILE=<admin-profile> AWS_REGION=ap-south-1
aws s3api put-public-access-block --bucket "$B" --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api put-bucket-encryption --bucket "$B" --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
aws s3api put-bucket-versioning --bucket "$B" --versioning-configuration Status=Enabled
```

Line 1 stores the bucket name in the variable `B`. The shell replaces `$B` with the value everywhere it appears, and the quotes around `"$B"` stop a name with odd characters from splitting into two words. Line 2 sets two environment variables. `AWS_PROFILE` picks the credentials, and `AWS_REGION` picks the region. Replace `<admin-profile>` with the name of the admin profile from your setup. Line 3 turns on all four Block Public Access switches. Each value is `true`, and the list is separated by commas with no spaces. Line 4 sets default encryption. The argument is a JSON text in single quotes. JSON is a text format for nested data made of braces, brackets and quoted keys. The rule says that every new object gets `AES256`. Line 5 turns versioning on. Nothing is printed when a `put` command works, so you check the result with the `get` commands in the evidence step.

```bash
{ aws s3api get-public-access-block --bucket "$B"
  aws s3api get-bucket-encryption --bucket "$B"
  aws s3api get-bucket-versioning --bucket "$B"; } > docs/evidence/T18-bucket-settings.txt
curl -s -o /dev/null -w '%{http_code}\n' "https://$B.s3.ap-south-1.amazonaws.com/clean/aqi/date=2026-12-17/aq_clean.parquet"
```

The braces group three commands so their output goes into one file with `>`. The `>` symbol writes the output to a file and replaces any earlier content. `curl` is a tool that sends an HTTP request from the terminal. `-s` hides the progress meter. `-o /dev/null` throws the body away. `-w '%{http_code}\n'` prints only the status code, followed by a new line. The URL is the object's address on the internet. You are not signed in, so the expected output is `403`. That is the proof that the bucket refuses the public.

:::trap Trusting a 404 as proof
A 404 means the object was not found, which proves nothing about privacy. Test an object that exists. For a private bucket, the answer must be 403.
:::

:::trap Pipeline profile with bucket settings
Running the `put-` commands with the pipeline profile gives `AccessDenied`. Bucket configuration is an admin task, and the pipeline is deliberately not allowed to change it.
:::

:::trap Versioning without a cleanup rule
Versioning keeps every old copy, so storage grows forever unless you expire old copies. Apply the seven-day expiry of noncurrent versions in the lifecycle file, covered in the worked example.
:::

### The boto3 SDK

**What it is.** boto3 is the official AWS SDK for Python. It finds credentials for you, signs each request so AWS can check it, and exposes every AWS operation as a Python method. When AWS refuses a call, boto3 raises `botocore.exceptions.ClientError`. **botocore** is the library underneath boto3 that does the low-level work.

**Why not the alternatives.** The **AWS CLI** from Bash is excellent for one-off commands and evidence, but it is harder to test from Python and harder to turn into a clean exit code. **s3fs** and **fsspec** make S3 look like a file system for pandas. They are convenient, but they hide errors and add dependencies. **Raw HTTPS requests** are possible, but you would have to rebuild SigV4, which is the AWS request-signing method, yourself. boto3 avoids all three problems.

**How it works.** When you call `boto3.client("s3")`, boto3 looks for credentials in a fixed order. It checks environment variables first, then the profile named by `AWS_PROFILE` in the shared config files, and then the role of the machine (an instance role on EC2). This is the **credential chain**. The same code therefore runs on your laptop with a profile and on a cloud machine with a role, and no key appears in the code.

The slide code is `src/citypulse/upload.py`. Every line is explained below.

```python
import argparse, datetime, os, pathlib, sys
import boto3
from botocore.exceptions import ClientError


def object_key(dataset: str, day: datetime.date, filename: str) -> str:
    return f"clean/{dataset}/date={day.isoformat()}/{filename}"


def main() -> int:
    p = argparse.ArgumentParser()
    for flag in ("--src", "--dataset", "--date"):
        p.add_argument(flag, required=True)
    a = p.parse_args()
    src, bucket = pathlib.Path(a.src), os.environ["CITYPULSE_BUCKET"]
    key = object_key(a.dataset, datetime.date.fromisoformat(a.date), src.name)
    try:
        boto3.client("s3").put_object(Bucket=bucket, Key=key, Body=src.read_bytes())
    except ClientError as e:
        print(f"upload failed: {e}", file=sys.stderr)
        return 1
    print(f"uploaded s3://{bucket}/{key}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

- `import argparse, datetime, os, pathlib, sys` loads five standard-library modules. `argparse` reads command-line flags, `datetime` handles dates, `os` reads environment variables, `pathlib` handles file paths, and `sys` gives access to the exit mechanism and the error output.
- `import boto3` and `from botocore.exceptions import ClientError` load the SDK and the one exception class this script handles.
- `def object_key(...)` defines a function. Its inputs are a dataset name, a date and a file name. The type hints such as `: str` and `-> str` are notes for readers and tools. Python does not enforce them.
- The return line builds the f-string. An f-string is a string with `{...}` slots filled in at run time. `day.isoformat()` turns a date into text such as `2026-12-17`.
- `def main() -> int:` defines the main function, which returns the exit code.
- `p = argparse.ArgumentParser()` creates a parser that will read the command-line flags.
- The `for` loop registers `--src`, `--dataset` and `--date` as required flags. Without a required flag, the script stops with a usage message.
- `a = p.parse_args()` reads the flags and stores them in `a`, so `a.src` is the path you typed after `--src`.
- The next line finds the file path with `pathlib.Path`, reads the bucket name from the `CITYPULSE_BUCKET` environment variable, and then builds the key. `src.name` is the file name with the folders removed.
- `try:` opens a block that might raise an error. The only error caught is `ClientError`.
- `put_object(Bucket=..., Key=..., Body=...)` sends the bytes of the file to S3 under that key. `read_bytes()` loads the whole file into memory, which is fine for these small files.
- `except ClientError as e:` runs only when AWS refuses the call. It prints the message to `sys.stderr`, the error channel, and returns `1`.
- The last two lines print the success message and return `0`.
- `if __name__ == "__main__":` runs `main()` only when the file is run directly, not when another file imports it. `sys.exit(main())` passes the return value to the shell as the exit code.

:::trap Hard-coding the profile
Writing `boto3.Session(profile_name="citypulse-pipeline")` into the code breaks the EC2 run, where there is no such profile. Let the credential chain read `AWS_PROFILE` or the instance role.
:::

:::trap The wrong error class
`upload_file` wraps its errors in `S3UploadFailedError`, which comes from `boto3.exceptions`, not from `botocore`. Catch that class too, or use `put_object` as the script does.
:::

:::trap Testing by uploading
Calling AWS to test `object_key` is slow and needs a network. Put the logic in a pure function, which means a function that depends only on its inputs, and unit-test it in `tests/test_upload.py` with no AWS at all.
:::

Now watch the SDK work through a small Python program. It counts readings per station.

```trace
TITLE: Counting readings per station
CODE:
counts = {}
for sid in ["S1", "S2", "S1"]:
    counts[sid] = counts.get(sid, 0) + 1
STEPS:
1 :: counts={} :: Start with an empty dictionary.
2 :: sid="S1"; counts={} :: The loop takes the first station id.
3 :: sid="S1"; counts={"S1": 1} :: "S1" was not there, so get returns 0, and 0 + 1 is stored.
2 :: sid="S2"; counts={"S1": 1} :: Second time round the loop.
3 :: sid="S2"; counts={"S1": 1, "S2": 1} :: Same pattern for the new station.
2 :: sid="S1"; counts={"S1": 1, "S2": 1} :: Third time round the loop.
3 :: sid="S1"; counts={"S1": 2, "S2": 1} :: "S1" is already there, so get returns 1, and the count becomes 2.
```

This trace uses a dictionary, which you will need again in the graded lab. The `get` method returns a default value when the key is missing, instead of raising an error.

## The worked example

**Goal.** Upload the same clean file under two dates and then list both dates with the scoped pipeline profile. This is the workbook's example for the day. It proves that the layout, the credentials and the listing all work together.

**Code.**

```bash
B=citypulse-x7k2q9
export AWS_PROFILE=citypulse-pipeline AWS_REGION=ap-south-1 CITYPULSE_BUCKET="$B"
for d in 2026-12-17 2026-12-18; do
  python -m citypulse.upload --src data/clean/aq_clean.parquet --dataset aqi --date "$d"
done
aws s3 ls "s3://$B/clean/aqi/" --recursive > docs/evidence/T18-ls.txt
```

**Explanation.** The first two lines set the bucket name, the credentials and the `CITYPULSE_BUCKET` variable that `upload.py` reads. `citypulse-pipeline` is the scoped profile, which means a profile limited to the `clean/` and `raw/` prefixes. The `for ... in ...; do` line starts a loop over the two dates. Each pass sets the variable `d` to one date. `python -m citypulse.upload` runs the upload module as a script. `--src` gives the file to upload, `--dataset` gives the dataset name, and `--date` gives the date. The `"$d"` in quotes passes the current date. `done` ends the loop. The last line lists everything under `clean/aqi/`. `--recursive` lists the objects inside the nested prefixes too, not just the first level. The `>` symbol saves the listing as evidence.

**Output.** Each upload prints one line, and the listing prints one line per object. The numbers below are illustrative, because your sizes and times will differ.

```term
$ for d in 2026-12-17 2026-12-18; do python -m citypulse.upload --src data/clean/aq_clean.parquet --dataset aqi --date "$d"; done
uploaded s3://citypulse-x7k2q9/clean/aqi/date=2026-12-17/aq_clean.parquet
uploaded s3://citypulse-x7k2q9/clean/aqi/date=2026-12-18/aq_clean.parquet
$ aws s3 ls "s3://citypulse-x7k2q9/clean/aqi/" --recursive
2026-12-17 09:30:12       1834 clean/aqi/date=2026-12-17/aq_clean.parquet
2026-12-18 09:30:14       1834 clean/aqi/date=2026-12-18/aq_clean.parquet
```

The listing shows the two `date=` prefixes, which is the result you need. The admin then adds a lifecycle rule. The lifecycle file moves old raw data to a cheaper storage class and expires old versions. This is an admin task:

```bash
export AWS_PROFILE=<admin-profile>
aws s3api put-bucket-lifecycle-configuration --bucket "$B" --lifecycle-configuration file://infra/storage/lifecycle.json
aws s3api get-bucket-lifecycle-configuration --bucket "$B"
```

`file://` tells the CLI to read the value from a file. The second command prints the rule back so you can save it as evidence. The course's own `lifecycle.json` is the authority. A rule of the same shape looks like this:

```json
{
  "Rules": [
    {
      "ID": "raw-cheaper-and-expire-old-versions",
      "Status": "Enabled",
      "Filter": {"Prefix": "raw/"},
      "Transitions": [{"Days": 30, "StorageClass": "STANDARD_IA"}],
      "NoncurrentVersionExpiration": {"NoncurrentDays": 7}
    }
  ]
}
```

`Filter` limits the rule to keys that start with `raw/`. `Transitions` moves the current objects to the `STANDARD_IA` class after 30 days. `NoncurrentVersionExpiration` deletes an old version seven days after it stopped being the latest one.

## The hands-on lab, step by step

Before you start, make sure `src/citypulse/upload.py` matches the listing in The tools section. Use Git Bash for every command. Keep the bucket name in a file called `docs/evidence/bucket.txt`, so you can reuse it.

### Step 1 — Create a private, versioned bucket

**What you do.** Use the admin profile to create the bucket and set its three settings: Block Public Access, default encryption and versioning.

**What you type.**

```bash
export AWS_PROFILE=<admin-profile> AWS_REGION=ap-south-1
B=citypulse-<your-random-suffix>
aws s3api create-bucket --bucket "$B" --create-bucket-configuration LocationConstraint=ap-south-1
aws s3api put-public-access-block --bucket "$B" --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api put-bucket-encryption --bucket "$B" --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
aws s3api put-bucket-versioning --bucket "$B" --versioning-configuration Status=Enabled
```

The `create-bucket` line needs `LocationConstraint` for a region outside `us-east-1`, which is why it is there. Replace `<your-random-suffix>` with random letters and digits.

**What you should see.** `create-bucket` prints a small JSON block with the bucket's `Location`, and the other three commands print nothing when they succeed. A failure prints an error with a code such as `BucketAlreadyExists`. If you see that, pick a different suffix.

**How you know it worked.** Run `aws s3api get-public-access-block --bucket "$B"`, `get-bucket-encryption` and `get-bucket-versioning`. The first shows four `true` values, the second shows `AES256`, and the third shows `"Status": "Enabled"`.

### Step 2 — Design a date-partitioned key layout

**What you do.** Write the layout on paper before you upload. The layout is `clean/<dataset>/date=YYYY-MM-DD/<filename>`, where the dataset for this lab is `aqi`.

**What you type.**

```bash
python -c "import datetime; print(f'clean/aqi/date={datetime.date(2026,12,17).isoformat()}/aq_clean.parquet')"
```

`python -c` runs a line of Python given on the command line instead of a file. The f-string inserts the date, and `isoformat()` writes it as `2026-12-17`.

**What you should see.** `clean/aqi/date=2026-12-17/aq_clean.parquet`

**How you know it worked.** The printed key has exactly one `date=` part, the date is in year-month-day order, and the file name is the one you intend to upload.

### Step 3 — Generate a sample readings file

**What you do.** Create a small CSV file with three columns. CSV means comma-separated values, a plain text table. The `ts` column is a time stamp, `pollutant` names the substance, and `value` is the reading.

**What you type.** Create `make_sample.py` with this content and run it.

```python

rows = [
```

`rows` is a list of text lines. `"\n".join(rows)` glues the lines together with a new line between them. `write_text` writes the result to a file, and the `+ "\n"` adds a final new line. `len(rows) - 1` counts the data rows by leaving out the header.

Run it with `python make_sample.py`.

**What you should see.** `wrote 2 rows`

**How you know it worked.** `head readings.csv` prints the header and the two data rows. `head` shows the first lines of a file.

### Step 4 — Upload with boto3

**What you do.** Switch to the scoped pipeline profile and upload the file for two dates.

**What you type.**


**How you know it worked.** Both lines start with `uploaded`, and the exit code is 0. Run `echo $?` straight after the second command and expect `0`.

### Step 5 — List and read back

**What you do.** List the objects with the pipeline profile, then read one back from Python.

**What you type.**

```bash
aws s3 ls "s3://$B/clean/aqi/" --recursive
```

Then create `read_back.py`:

```python
import os
import boto3
```

`get_object` fetches the object. `obj["Body"]` is a stream of bytes, and `.read()` collects all of them. `.decode()` turns the bytes into text, and `splitlines()` splits the text into a list of lines. Line 0 is the header.

### S3 object model

S3 has buckets, objects and keys. A bucket has a globally unique name and sits in one region. An object is the bytes plus metadata, and it has a key and, when versioning is on, a version ID. The key is one full string, and the slashes in it are part of that string. S3 has no real folders, so renaming a "folder" means copying each object to the new key and deleting the old one. The trap examiners set is the belief that a folder is an object that can be renamed in one step.

### S3 partitioning

Partitioning puts a value that readers filter on into the key. In CityPulse the value is the date, written as `date=YYYY-MM-DD`. A prefix listing then returns only the keys for one day. Dates must be in ISO order so that the text sorts by date. The trap examiners set is a date format such as `17-12-2026`, which looks fine but sorts wrongly across years.

### boto3 pagination

`list_objects_v2` returns at most 1,000 keys per call. A response with more keys has `IsTruncated` set to `True` and a `NextContinuationToken` to fetch the rest. A paginator handles that loop for you. Each page has a `KeyCount`, and `PageSize` controls how many keys each request asks for. The trap examiners set is reading `resp["Contents"]` directly. When no key matches, S3 leaves `Contents` out of the response, so the lookup raises `KeyError`.

### Presigned URLs

A presigned URL is a web address that contains a signature, so the holder can use it without AWS credentials. You create it with `generate_presigned_url`, and you set how long it lasts with `ExpiresIn`, which is measured in seconds. The URL carries the permissions of the account that signed it. Sharing it is safer than making a bucket public, because it expires and it covers one object. The trap examiners set is making the bucket public to share one file, which exposes everything.

### S3 lifecycle

A lifecycle configuration is a set of rules that run on their own. A rule can change the storage class of current objects after a number of days, for example to `STANDARD_IA`. It can also expire old versions with `NoncurrentVersionExpiration`. Rules can be limited to a prefix with `Filter`. Lifecycle rules save money, but they do not delete current data unless you add an expiration rule for current objects. The trap examiners set is confusing a transition, which keeps the data, with an expiration, which deletes it.

### boto3 error handling

When AWS refuses a call, boto3 raises `ClientError`. The error code is in `e.response["Error"]["Code"]`, for example `AccessDenied` or `NoSuchKey`. A good script catches only the errors it can handle, prints the message to standard error, and returns exit code 1. A bare `except Exception: pass` hides every failure and makes the shell think the upload worked. The trap examiners set is a broad `except` that returns success.

### S3 encryption

Default encryption with SSE-S3 is AWS-managed encryption at rest, and it uses AES-256. It needs no key management from you, and reads work with no code change. SSE-KMS adds an audit log of key use, but it also adds cost and needs `kms:Decrypt` permission for each reader. Encryption at rest does not stop anyone who is allowed to read the object, because S3 decrypts the data for them. The trap examiners set is treating encryption as access control.

### S3 versioning

With versioning on, an overwrite creates a new version, and a delete adds a delete marker. The old bytes stay until a lifecycle rule expires them. You restore by reading an older version with its `VersionId` and copying it back to the key. Versioning cannot be turned off once enabled, only suspended. The trap examiners set is the idea that versioning is a backup, when it is only protection against overwrites and deletes inside the same bucket.

### Multipart upload

S3 accepts at most 5 GB in a single `PUT` request. Larger objects must be uploaded in parts. Each part must be at least 5 MiB, except the last part, and an upload can have up to 10,000 parts. `upload_file` splits large files for you once the file passes its threshold, which defaults to 8 MB. An upload that never completes leaves stored parts behind and costs money, so a lifecycle rule should abort incomplete uploads. The trap examiners set is assuming `put_object` can send any size.

### A dictionary as a key-value store

A **dictionary** in Python stores pairs of a key and a value, written `{"a": 1}`. The key is looked up by its exact value, and it must be an immutable type such as a string. Four operations cover most of the work:

- `d[key] = value` stores or replaces a pair.
- `d.get(key)` returns the value, or `None` when the key is missing. `None` is Python's word for "no value", and it is not an error. `d.get(key, default)` returns `default` instead.
- `key in d` checks whether the key exists, and returns `True` or `False`.
- `del d[key]` removes the pair. Deleting a missing key raises `KeyError`, so check with `in` first.

A **string** can be built with an f-string, such as `f"cache://{namespace}/{key}"`. The `startswith(prefix)` method returns `True` when the text begins with the prefix. `sorted(...)` returns a new list in ascending order. For text, ascending order means character by character, so `"b/1"` comes before `"z"`.

A **class** groups data and functions. `class Cache:` defines it, and `__init__` runs when you create one with `Cache()`. Inside a method, `self` is the object itself, so `self._store` is the dictionary stored in that object. A method is a function written inside a class.

To reject bad input, use `raise ValueError("message")`. This stops the function and reports a clear error to the caller. The test then checks that the error happens.

```trace

store = {}

```

### The practice problem: a namespaced cache

Write a class `Cache` with these methods. Store values in a dictionary. The address of each value is a URI (a text address) of the form `cache://namespace/key`.

- `make_uri(namespace, key)` returns the address. It raises `ValueError` if the namespace is empty or contains `/`, or if the key is empty.
- `set(namespace, key, value)` stores the value. Setting the same key again replaces the value.
- `get(namespace, key)` returns the stored value, or `None` when the key is missing.
- `delete(namespace, key)` returns `True` if the key existed and was removed, and `False` if it was not there.
- `list_keys(namespace)` returns the full URIs of all keys in that namespace, sorted in ascending order. It raises `ValueError` for a bad namespace.

For example, after `c.set("img", "a.png", b"one")` and `c.set("img", "z", 2)`, `c.list_keys("img")` returns `["cache://img/a.png", "cache://img/z"]`.

**Edge-case checklist.** Check each one before you submit.

- Empty input: an empty namespace or an empty key must raise `ValueError`.
- A namespace that contains `/` must raise `ValueError`, because `a/b` plus `c` would give the same address as `a` plus `b/c`.
- Missing key: `get` returns `None`, and `delete` returns `False`.
- Overwrite: setting a key twice keeps only the latest value.
- Ordering: `list_keys` returns sorted output, not insertion order.
- Prefix collision: namespace `img` must not return keys from `img2`. The prefix must end with the slash, `cache://img/`.
- Types: the value can be any type, including `None`. Here `get` cannot tell a stored `None` from a missing key, so do not rely on that difference.
- Rounding: not relevant to this problem, so no rounding is needed.
- Missing fields: a key that was never set returns `None`, not an error.

:::answer Model solution
The solution below is a complete program with a test block. The test block runs automatically when the book is built, so it must pass.

```python test
class Cache:
    def __init__(self):
        self._store = {}

    def _check_namespace(self, namespace):
        if not namespace or "/" in namespace:
            raise ValueError("namespace must be non-empty and contain no '/'")

    def make_uri(self, namespace, key):
        self._check_namespace(namespace)
        if not key:
            raise ValueError("key must not be empty")
        return f"cache://{namespace}/{key}"

    def set(self, namespace, key, value):
        self._store[self.make_uri(namespace, key)] = value

    def get(self, namespace, key):
        return self._store.get(self.make_uri(namespace, key))

    def delete(self, namespace, key):
        uri = self.make_uri(namespace, key)
        if uri in self._store:
            del self._store[uri]
            return True
        return False

    def list_keys(self, namespace):
        self._check_namespace(namespace)
        prefix = f"cache://{namespace}/"
        return sorted(uri for uri in self._store if uri.startswith(prefix))


def raises_value_error(fn):
    try:
        fn()
    except ValueError:
        return True
    return False


c = Cache()
assert c.make_uri("img", "a.png") == "cache://img/a.png"
assert c.make_uri("img", "2026/12/17") == "cache://img/2026/12/17"
assert c.get("img", "a.png") is None
c.set("img", "a.png", b"one")
assert c.get("img", "a.png") == b"one"
c.set("img", "a.png", b"two")
assert c.get("img", "a.png") == b"two"
c.set("img2", "x", 1)
c.set("img", "z", 2)
c.set("img", "b/1", 3)
assert c.list_keys("img") == ["cache://img/a.png", "cache://img/b/1", "cache://img/z"]
assert c.list_keys("img2") == ["cache://img2/x"]
assert c.list_keys("empty") == []
assert c.delete("img", "a.png") is True
assert c.delete("img", "a.png") is False
assert c.get("img", "a.png") is None
assert raises_value_error(lambda: c.set("", "k", 1))
assert raises_value_error(lambda: c.set("a/b", "k", 1))
assert raises_value_error(lambda: c.get("img", ""))
assert raises_value_error(lambda: c.list_keys("a/b"))
assert c.list_keys("img") == ["cache://img/b/1", "cache://img/z"]
```

**Line-by-line explanation.**

- `class Cache:` starts the class, and `__init__` runs when you write `Cache()`. It sets `self._store` to an empty dictionary. The leading underscore is a convention meaning "for internal use only".
- `_check_namespace` is a helper method. `not namespace` is true for an empty string, and `"/" in namespace` checks for a slash. Either case raises `ValueError`. The helper is used twice, so the rule lives in one place.
- `make_uri` checks the namespace, then checks that the key is not empty. It returns the f-string address.
- `set` builds the address and stores the value under it. Storing under an existing address replaces the old value.
- `get` uses the dictionary's `get` method. A missing address returns `None`, and no error is raised.
- `delete` checks with `in` before it removes anything. It returns `True` only when a pair was removed, which is what the test checks.
- `list_keys` builds the prefix with the trailing slash. The generator expression picks each address that starts with the prefix, and `sorted` puts them in ascending order.
- `raises_value_error` runs a function and returns `True` if it raised `ValueError`. Any other exception passes through and fails the test, which is what you want.
- The first assertions check the address format and the missing-key result. The `img` and `img2` assertions check the prefix collision.
- The `delete` assertions check the `True` and `False` return values in order.
- The last group checks each error rule from the edge-case list.
- The final assertion runs after the deletion and confirms that the rest of the namespace is still listed in order.

## Say it out loud

:::answer Why do the keys use date= and ISO dates?
The key holds the dataset and the day, so a prefix listing such as `clean/aqi/date=2026-12-17/` returns one day without reading the others. The ISO form, year then month then day, sorts in calendar order as plain text. The `date=` name is a convention that query tools understand. Together these make the layout cheap to read and easy to scale.
:::

:::answer How do you prove that a bucket is private?
I check the bucket's Block Public Access settings with `get-public-access-block` and confirm all four flags are true. Then I request an object that exists with a plain `curl` request that has no credentials. A private bucket must return 403, and I save that output as evidence. A 404 would prove nothing, because it only says the object is missing.
:::

:::answer Why does upload.py use the credential chain instead of keys in the code?
The credential chain lets boto3 find credentials from environment variables, a named profile or the instance role, in that order. The same code therefore runs on a laptop with a profile and on an EC2 machine with a role, with no change. Hard-coded keys would leak through version control and would break on any other machine. Keeping secrets out of the code is also part of the course's security rules.
:::

:::answer What does versioning protect against, and what does it cost?
Versioning protects against overwrites and deletes. When a pipeline replaces a good file with a bad one, the old version stays, so you can restore it by its version ID. The cost is storage for every old version, which grows without limit unless a lifecycle rule expires noncurrent versions. Versioning is not a full backup, because it protects only inside the same bucket.
:::

:::answer Why should a listing use a paginator?
S3 returns at most 1,000 keys per call, and a longer listing is split across several responses. A paginator sends the continuation token for you and gives you one page at a time, so the same loop works for three objects or three million. Without it, a listing silently stops at 1,000 keys. The paginator is also the safe way to count objects.
:::
