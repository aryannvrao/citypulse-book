What a program is

A program is a list of instructions. The computer carries them out one at a time, from the top of the file to the bottom, unless an instruction tells it to jump somewhere else. A recipe works the same way: you read step one, do it, then read step two.

Python is a language for writing those instructions. The program that reads your Python and carries it out is called the interpreter. You talk to it in two ways.

Interactive mode. You type one line, the interpreter runs it straight away and shows the result. To start it, open a terminal. A terminal is a window where you type commands and the computer answers in text. Type python and press Enter. A prompt made of three arrows, >>>, appears. Type 2 + 3 and press Enter, and the answer 5 appears underneath. Type exit() and press Enter to leave.

$ python
>>> 2 + 3
5
>>> exit()

In this block, the first line is what you type after the $ sign. The $ is the terminal's prompt and you do not type it. The >>> lines are what Python shows you while it is running.

Script mode. You save your instructions in a file and run the whole file at once. A file is a named block of data kept on disk. A file whose name ends in .py is a Python file. Create a file called hello.py in a folder of your choice, and put these two lines in it:

name = "CityPulse"
print("Hello from", name)

Line by line:

  • name = "CityPulse" stores the text CityPulse in a variable called name. A variable is a name that points at a value. The = sign means "store this in", not "is equal to". You will meet the real equality test later.
  • print("Hello from", name) calls a function. A function is a named action that you run by writing its name followed by round brackets. print shows its contents on the screen. The two things inside the brackets are separated by a comma, and print puts a space between them.

To run the file, go to the folder that holds it in the terminal and type this:

python starts the interpreter. hello.py tells it which file to read. Python runs the file from top to bottom and prints Hello from CityPulse. On Windows, if python is not recognised, try py hello.py instead. Both start the same interpreter.

Any line that starts with # is a comment. Python ignores comments. Use them to explain your own code:

## This line is ignored by Python.
print("This line runs.")
Tip: Test in the interactive mode first

When you are unsure what an expression does, type it into interactive mode. You will see the result before you commit it to a file.

Values and types

A value is a piece of data: a number, a piece of text, or a yes-or-no answer. Every value has a type, which decides what you can do with it. Python has five types that you will use in this course:

Type What it holds Examples
int whole numbers, positive, negative or zero 42, -7, 0
float numbers with a decimal point 3.5, 0.0, 2.0
str text, also called a string "PM2.5", 'air'
bool yes or no True, False
None no value at all None

Notice that 2.0 is a float even though it is a whole number. The decimal point is what makes it a float. Notice too that True and False start with capital letters. Python will not recognise true.

The function type() tells you the type of a value. Put the value inside the brackets:

print(type(42))
print(type(2.5))
print(type("PM2.5"))
print(type(True))
print(type(None))

Expected output:

<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
<class 'NoneType'>

Each print line asks Python for the type of one value and shows it. The text <class 'int'> means "the class int". In Python, a class and a type mean the same thing for this course. NoneType is the type of None.

Python can change one type into another. The function int() converts text into a whole number, float() converts into a decimal number, and str() converts into text:

print(int("42") + 1)
print(float("2.5") * 2)
print(str(42) + "!")

Expected output: 43, 5.0 and 42!. The first line turns the text "42" into the number 42 and adds 1. The second line turns the text "2.5" into 2.5 and doubles it, which gives a float. The third line turns the number 42 into text and adds an exclamation mark.

Trap: Quotes change the type

42 is a number. "42" is text. The text version looks the same on the screen, but "42" + 1 fails with an error because Python will not add text to a number. Use int("42") + 1 to convert first.

Variables

A variable is a name that you attach to a value. You create or change a variable with the assignment statement, which is a single equals sign:

readings = 3
readings = readings + 1
print(readings)

Expected output: 4.

Line by line:

  • readings = 3 creates a variable called readings and stores the number 3 in it.
  • readings = readings + 1 works out the right-hand side first. readings is 3, so readings + 1 is 4. Then it stores the 4 back into readings. The old value is replaced.
  • print(readings) shows what the variable holds now, which is 4.

Names you choose must follow four rules. They can use letters, digits and underscores. They cannot start with a digit, so 2nd_reading is not allowed. They cannot contain spaces, so use air_quality rather than air quality. They are case sensitive, so Readings and readings are two different names. Also avoid the reserved words that Python uses for itself, such as if, for and while.

Use names that describe the data. station_id is far easier to read in a viva than x.

Arithmetic

Python does arithmetic with these operators:

Operator Meaning Example Result
+ add 7 + 2 9
- subtract 7 - 2 5
* multiply 7 * 2 14
/ divide, always gives a float 7 / 2 3.5
// floor division, keeps the whole part 7 // 2 3
% remainder after division 7 % 2 1
** power 2 ** 5 32

Try this program:

print(7 / 2)
print(7 // 2)
print(7 % 2)
print(2 ** 5)
print(2 + 3 * 4)
print((2 + 3) * 4)
print(-7 // 2)
print(-7 % 3)

Expected output, one line for each print: 3.5, 3, 1, 32, 14, 20, -4 and 2.

Line by line:

  • 7 / 2 is ordinary division, so the answer is 3.5 and it is a float.
  • 7 // 2 divides and throws away the part after the point. The answer is 3.
  • 7 % 2 gives the remainder. Seven is three lots of two with one left over.
  • 2 ** 5 means 2 multiplied by itself 5 times, which is 32.
  • 2 + 3 * 4 gives 14, because multiplication is done before addition.
  • (2 + 3) * 4 gives 20, because the brackets are done first.
  • -7 // 2 gives -4. Floor division rounds down towards minus infinity, so the answer is further from zero than you might expect. This is the case that catches people out.
  • -7 % 3 gives 2. In Python the remainder always has the same sign as the divisor, which is 3 here.

The order of operations is the usual school order. Brackets come first, then **, then *, /, // and % from left to right, then + and - from left to right.

The remainder operator % is very useful. reading % 2 == 0 is a test for an even number, and you will use it in the practice problems.

Trap: Division always gives a float

6 / 2 gives 3.0, not 3. If you need a whole number, use //. Hidden tests in the graded lab may check the type of the answer as well as its value. In Python 3.0 == 3 is True, but type(3.0) is float, so a strict type check on an integer answer fails.

Text

Text is written inside quotation marks. Single quotes and double quotes both work, but the closing mark must match the opening one: "air" and 'air' are fine, "air' is an error.

Each character in a string has a position called an index. The first position is 0, not 1. Count from zero, and you will avoid most off-by-one errors. The word CityPulse has these positions:

Position 0 1 2 3 4 5 6 7 8
Character C i t y P u l s e

Square brackets with an index pick out one character:

word = "CityPulse"
print(word[0])
print(word[4])
print(word[-1])

Expected output: C, P and e.

word[-1] uses a negative index. Negative numbers count from the end, so -1 is the last character, -2 is the one before it, and so on.

A slice takes a piece of the string. It uses a colon inside the brackets, with a start and a stop: text[start:stop]. The start is included and the stop is not. Watch how the next program works:

If you leave out the start, slicing begins at the start of the text, so word[:4] also gives City. If you leave out the stop, it runs to the end, so word[5:] gives ulse. Expected output of print(len(word)) is 9. The function len() returns the length of any sequence, including text.

Text values have methods. A method is a function that belongs to a value. You call it with a dot after the value, like text.upper(). The methods you will use most are these:

raw = "  PM2.5, NO2, O3  "
clean = raw.strip()
print(clean)
parts = clean.split(",")
print(parts)
print(", ".join(["PM2.5", "NO2"]))
print("Bengaluru".lower())
print("Bengaluru".upper())
print("PM2.5".startswith("PM"))
print("PM2.5".endswith("5"))
print("air-quality".replace("-", " "))
print("CityPulse".find("Pulse"))
print("CityPulse".find("Ozone"))

Expected output:

PM2.5, NO2, O3
['PM2.5', ' NO2', ' O3']
PM2.5, NO2
bengaluru
BENGALURU
True
True
air quality
4
-1

Line by line:

  • raw.strip() removes spaces from both ends of the text. It does not touch the spaces in the middle. The result is stored in clean.
  • clean.split(",") cuts the text at each comma and gives a list, which is a numbered collection of values written in square brackets. The output shows ['PM2.5', ' NO2', ' O3']. The second and third items still begin with a space, because split only cuts. It does not clean. You would call strip on each one to remove those spaces.
  • ", ".join([...]) does the reverse. It joins the items of a list, putting ", " between them.
  • lower() returns a copy of the text in lower case, and upper() returns it in upper case.
  • startswith("PM") and endswith("5") return True or False, depending on how the text begins or ends.
  • replace("-", " ") swaps every hyphen for a space.
  • find("Pulse") returns the position where Pulse starts, which is 4. If the text is not found, find returns -1. Remember that -1 is a signal, not a position, so check for it before you use the result as an index.
Trap: Methods do not change the original

word.upper() returns a new string and leaves word alone. A line that calls word.upper() by itself does nothing useful. Write word = word.upper() to keep the result.

Finally, the f-string lets you put variables into text. Put the letter f before the opening quote, then wrap each variable name in curly brackets:

station = "S1"
count = 12
print(f"Station {station} has {count} readings")
print(f"Average: {2 / 3:.2f}")

Expected output: Station S1 has 12 readings and Average: 0.67. Inside the braces, Python replaces the name with the value it holds. In the second line, :.2f is a format instruction. It means "show this float with two digits after the point", so 0.6666 becomes 0.67.

Comparisons and logic

A comparison asks a question about two values and gives back a bool. The comparison operators are == (equal to), != (not equal to), <, >, <= (less than or equal to) and >=.

Two more keywords combine yes-or-no answers. and is true only when both sides are true. or is true when at least one side is true. not turns true into false and false into true. The word in checks whether something is inside another thing.

aqi = 72
print(aqi > 50)
print(aqi == 72)
print(50 < aqi <= 100)
print(aqi > 50 and aqi < 60)
print(not aqi > 50)
print("PM" in "PM2.5")
print("NO2" in ["PM2.5", "O3"])

Expected output: True, True, True, False, False, True and False.

Line by line:

  • aqi > 50 is true, because 72 is greater than 50.
  • aqi == 72 is true. Note the double equals sign. A single = stores a value, and == asks a question.
  • 50 < aqi <= 100 checks two things at once. Python reads it as "50 is less than aqi, and aqi is at most 100". Both are true.
  • aqi > 50 and aqi < 60 is false, because the first part is true and the second part, 72 is less than 60, is false.
  • not aqi > 50 turns the true answer into false.
  • "PM" in "PM2.5" is true, because PM appears inside the text.
  • "NO2" in ["PM2.5", "O3"] is false, because in checks the items of the list and NO2 is not one of them.
Tip: Use short circuits on purpose

In x != 0 and 10 / x > 1, Python checks the left side first. If it is false, Python does not run the right side, so there is no division by zero. Order your tests so the safe check comes first.

Trap: One equals sign is not a test

if aqi = 72: is a syntax error. Python will not guess that you meant ==. Use two equals signs for a comparison.

Decisions

An if statement runs a block of code only when a condition is true. A block is a group of lines that belong together. In Python, a block is marked by indentation, which means the spaces at the start of a line. Use four spaces for each level. Every line in the same block must have the same indentation.

aqi = 72
if aqi <= 50:
    print("good")
elif aqi <= 100:
    print("moderate")
else:
    print("poor")

Expected output: moderate.

Line by line:

  • if aqi <= 50: asks the question. The colon at the end is required. It starts the block.
  • print("good") is indented, so it belongs to the if. It runs only when the question is true.
  • elif means "otherwise, if". Python tests it only when every earlier test was false. The word is short for "else if".
  • else: has no question. It runs when none of the earlier tests were true.

Python reads the tests in order and runs the first branch that is true, then skips the rest. Here 72 is not less than or equal to 50, so the first branch is skipped. 72 is less than or equal to 100, so the elif branch runs and prints moderate. The else branch is skipped.

Trap: A missing colon or wrong indentation stops the program

Forgetting the colon after if gives a SyntaxError. A line that is indented in the wrong place gives an IndentationError, which is a kind of syntax error. Python checks the whole file before it runs anything, so a single bad line stops the whole program.

Loops

A loop repeats a block of code. A for loop goes through a sequence one item at a time. A sequence is anything ordered that you can step through, such as text or a list. The variable after for takes each item in turn.

for ch in "AQI":
    print(ch)

for i in range(3):
    print(i)

for i in range(2, 10, 3):
    print(i)

Expected output: A, Q, I, then 0, 1, 2, then 2, 5, 8.

range() makes a sequence of whole numbers. range(3) gives 0, 1 and 2. The stop value is never included, which is the same rule as slicing. range(2, 10, 3) starts at 2, adds 3 each time, and stops before 10. That gives 2, 5 and 8.

A while loop repeats as long as a condition stays true:

countdown = 3
while countdown > 0:
    print(countdown)
    countdown = countdown - 1
print("done")

Expected output: 3, 2, 1, done. The loop tests countdown > 0 before each round. When countdown reaches 0, the test is false, the loop stops, and the last line runs.

Inside a loop, two keywords change the flow. continue skips the rest of this round and moves to the next item. break leaves the loop completely.

for n in [4, 7, 10, 13]:
    if n % 2 == 0:
        continue
    if n > 10:
        break
    print(n)

Expected output: 7. The number 4 is even, so continue skips it. The number 7 is odd and not above 10, so it is printed. The number 10 is even, so it is skipped. The number 13 is odd but above 10, so break ends the loop before anything else is printed.

The accumulator pattern

Many programs collect a result over many rounds. A variable that starts with a neutral value and grows inside a loop is called an accumulator. Here it adds up the readings:

readings = [42, 65, 58]
total = 0
for value in readings:
    total = total + value
print(total)
print(total / len(readings))

Expected output: 165 and 55.0. The variable total starts at zero, so it is a safe starting point for addition. Each round adds one reading to it. After the loop, total holds the sum, and dividing by len(readings), which is 3, gives the average.

The next trace shows how the variables change in the accumulator. Watch total grow one step at a time.

Now a loop with a decision inside it. This is the pattern you will see in most graded problems: go through the data, test each item, and do something different depending on the answer.

The thresholds 50 and 100 are used here as a worked example. Use the values your lab gives you, not these, when you write your own code.

Trap: The infinite loop

A while loop that never changes the value it tests will run forever. If countdown = countdown - 1 were missing from the countdown example, the number would stay at 3 and the program would never finish. In the terminal, press Ctrl and C together to stop a running program.

Reading error messages

Every beginner sees errors. A program that fails prints a traceback, which is a report of where it failed. Read it from the bottom up:

  1. The last line gives the error type, such as NameError, and a message that explains it.
  2. The lines above it show the file name and the line number where Python stopped.
  3. The line of code is printed under the file name, so you can compare it with what you meant to write.

For example, if hello.py contains print(greting) on line 3, Python shows this:

Traceback (most recent call last):
  File "hello.py", line 3, in <module>
    print(greting)
NameError: name 'greting' is not defined

The last line says the problem is a NameError. The name greting is not defined anywhere. The line number tells you where to look. The fix is to correct the spelling to greeting, or to store a value in that name before you use it.

Five errors appear over and over in this course. Learn to recognise them:

Error Usually means Example that causes it Fix
SyntaxError The code is not valid Python. The wording of the message changes between versions. if 3 > 2 with no colon Add the missing colon, bracket or quote.
NameError You used a name that was never stored, often because of a typo. print(greting) Check the spelling, or assign the variable first.
TypeError You combined two types that do not work together. 1 + "2" gives unsupported operand type(s) for +: 'int' and 'str' Convert one value with int() or str().
IndexError You asked for a position that does not exist. "AQI"[5] gives string index out of range Remember positions run from 0 to len(text) - 1.
ValueError The right type was given, but the value makes no sense for the operation. int("abc") gives invalid literal for int() with base 10: 'abc' Check the text before you convert it.

A SyntaxError is different from the other four. Python finds it before running anything, so the program does not start at all. The other four appear while the program is running, so the lines before the error may already have done their work.

Key fact: Start with the line number

The message tells you what went wrong. The line number tells you where. Go to that line first. If it looks correct, look at the line just above it, because a missing colon or bracket on the line before often causes the error to appear one line later.

Practise

Try each problem before you read its answer. Write your function in a file, then add the test code under it and run the file. If every assert line passes, Python prints nothing and simply finishes. An assert is a check that says "this must be true". If one check fails, Python stops and prints AssertionError with the line number of the failed check.

The answers include edge cases. An edge case is an unusual input, such as an empty string, zero, a negative number or a tie. Hidden tests in the graded lab use these cases, so practise them now.

Problem 1: is_even

Write is_even(n). It returns True when the whole number n is even, and False otherwise. For example, is_even(4) returns True and is_even(-3) returns False.

Show the solution
def is_even(n):
    return n % 2 == 0

assert is_even(4) is True
assert is_even(0) is True
assert is_even(-3) is False
assert is_even(7) is False

Line by line. def is_even(n): defines a function called is_even that takes one input, which it calls n. The indented line below is the function body. return sends a result back to whoever called the function. n % 2 == 0 computes the remainder, then asks whether it is zero. The answer is already True or False, so there is no need for an if. The asserts check a positive even number, zero, a negative odd number and a positive odd number. Zero is even, and Python handles negative remainders correctly, so -3 % 2 gives 1, and the result is False.

Problem 2: word_count

Write word_count(sentence). It returns how many words the sentence contains, where words are separated by spaces. Extra spaces at the start, end or middle must not be counted as words. For example, word_count("sensor data arrived") returns 3.

Show the solution
def word_count(sentence):
    return len(sentence.split())

assert word_count("sensor data arrived") == 3
assert word_count("") == 0
assert word_count("   ") == 0
assert word_count("  one   two ") == 2

Line by line. sentence.split() with no argument splits at any run of spaces and throws away empty pieces. The empty text and the text of spaces both give an empty list, so len returns 0. The text " one two " gives the list ['one', 'two'], so the answer is 2. Passing "," to split would be wrong here, because the words are not separated by commas.

Problem 3: clean_station_id

Write clean_station_id(text). It removes spaces from both ends and changes the letters to upper case. For example, clean_station_id(" s1 ") returns "S1". An empty string returns an empty string.

Show the solution
def clean_station_id(text):
    return text.strip().upper()

assert clean_station_id("  s1 ") == "S1"
assert clean_station_id("") == ""
assert clean_station_id("Ab2") == "AB2"

Line by line. text.strip() removes the spaces at both ends. The dot then calls upper() on the result, so the methods are chained, left to right. Each method returns a new string, which is why the chain works without storing anything in between. The asserts check normal input, empty input and input that is already mixed case.

Problem 4: grade_aqi

Write grade_aqi(value). It returns "good" when the value is 50 or less, "moderate" when it is more than 50 and up to 100, and "poor" when it is more than 100. The boundary values 50 and 100 belong to the lower band. For example, grade_aqi(51) returns "moderate".

Show the solution
def grade_aqi(value):
    if value <= 50:
        return "good"
    elif value <= 100:
        return "moderate"
    else:
        return "poor"

assert grade_aqi(0) == "good"
assert grade_aqi(50) == "good"
assert grade_aqi(51) == "moderate"
assert grade_aqi(100) == "moderate"
assert grade_aqi(101) == "poor"

Line by line. The first test uses <=, so 50 itself falls into the "good" band. The elif tests 100 with <=, so 100 falls into "moderate". The else catches everything above 100. Each return ends the function straight away, so only one branch can give an answer. The five asserts test each side of both boundaries, which is where hidden tests usually look.

Problem 5: sum_positive

Write sum_positive(numbers). It adds up only the numbers in the list that are greater than zero. Zero and negative numbers are ignored. If the list is empty, or contains no positive numbers, the answer is 0.

Show the solution
def sum_positive(numbers):
    total = 0
    for n in numbers:
        if n > 0:
            total = total + n
    return total

assert sum_positive([]) == 0
assert sum_positive([-1, 2, 0, 5]) == 7
assert sum_positive([-4, -2]) == 0
assert sum_positive([0, 0]) == 0

Line by line. total is an accumulator that starts at zero. The loop visits each number in turn. The if lets only the positive numbers into the sum. Because the accumulator starts at zero, an empty list or a list with no positive numbers returns zero without any special case. The return is at the level of the for, not inside it, so the function returns only after the loop has finished. Putting it inside the loop is a common mistake, and it would return after the first item.

Problem 6: initials

Write initials(name). It returns the first letter of each word in upper case, joined together with no spaces. For example, initials("ada lovelace") returns "AL". Extra spaces must be ignored, and an empty string returns an empty string.

Show the solution
def initials(name):
    result = ""
    for word in name.split():
        result = result + word[0].upper()
    return result

assert initials("ada lovelace") == "AL"
assert initials("  grace   brewster hopper ") == "GBH"
assert initials("") == ""

Line by line. result is an accumulator for text, and it starts as the empty string. name.split() gives the words without any empty pieces, so word[0] always exists. word[0] is the first character, and upper() makes it a capital. Adding it to result grows the text one letter at a time. For empty input, split() gives an empty list, the loop never runs, and the empty string is returned.

Problem 7: digit_sum

Write digit_sum(n). It returns the sum of the digits of a whole number. For example, digit_sum(123) returns 6. A negative number uses the digits of its size, so digit_sum(-905) returns 14. digit_sum(0) returns 0.

Show the solution
def digit_sum(n):
    n = abs(n)
    total = 0
    while n > 0:
        total = total + n % 10
        n = n // 10
    return total

assert digit_sum(0) == 0
assert digit_sum(7) == 7
assert digit_sum(123) == 6
assert digit_sum(-905) == 14
assert digit_sum(1000) == 1

Line by line. abs(n) gives the size of the number without its sign, so the rest of the function only works with positive numbers. n % 10 gives the last digit, because the remainder after dividing by ten is the final digit. n // 10 removes that last digit. The while loop repeats until n is 0. For 123, the rounds add 3, then 2, then 1, so the total is 6. For 0, the loop never runs, and the total stays at 0, which is correct.

Problem 8: longest_word

Write longest_word(sentence). It returns the longest word in the sentence, where words are separated by spaces. If two words have the same length, return the first one. An empty sentence returns an empty string. For example, longest_word("air quality index") returns "quality".

Show the solution
def longest_word(sentence):
    best = ""
    for word in sentence.split():
        if len(word) > len(best):
            best = word
    return best

assert longest_word("air quality index") == "quality"
assert longest_word("cat dog") == "cat"
assert longest_word("") == ""
assert longest_word("  a bb  ") == "bb"

Line by line. best starts as the empty string, which has length 0, so the first real word always beats it. The > is strict. A word of the same length as the current best does not replace it, which is why the first of two equal words wins. The test "cat dog" checks this tie. The loop variable word is a piece of text from split(), and len(word) measures it.
