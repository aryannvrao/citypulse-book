What examiners are scoring

The viva is a spoken examination. You sit with an examiner, they ask questions, and you answer out loud. During the capstone (the final project in which you build a working piece of CityPulse), the viva is held daily. Each session scores four things from 0 to 5, giving a total out of 20. The four things are:

  1. Acceptance criteria met: does the work do what the ticket asked for?
  2. Technical depth: do you understand the tools you used?
  3. Contribution and ownership: what did you personally do?
  4. Understanding: can you explain why it works and what would break it?

The course overview gives the four dimensions and the 0 to 5 range. It does not publish the marking bands. The table below describes what a 2 and a 5 usually sound like. Treat it as a guide to how examiners judge, not as the official rubric.

Dimension What the examiner wants A 2 sounds like A 5 sounds like
Acceptance criteria met Proof that each requirement works "I think the chart loads now." "Criteria one to four pass. Criterion five fails for stations with no data, and here is the test that shows it."
Technical depth Knowledge of the tool, not just its use "I copied the command from the slides." "I used --fail so curl returns an error on HTTP failures, which lets the script stop early."
Contribution and ownership Your own decisions and work "We built the pipeline." "I wrote the fetch script and its tests, and I reviewed my partner's SQL change before it merged."
Understanding The reason behind each choice "It works, so it's fine." "The load uses an upsert (insert the row, or update it if it already exists), so rerunning the load does not create duplicates."

Two things separate the scores in practice. A 5 always includes evidence: a file name, a command, a test or a number you saw. A 5 also includes a limit: a sentence about what the work does not do yet. Examiners trust people who know the edges of their own work.

Key fact: Evidence and limits

Every strong answer in a viva has evidence (something you can point to) and a limit (something you admit the work does not do). Leave out either and the score drops.

The shape of a strong answer

A good spoken answer has three parts, in this order:

  • The claim: a direct answer in one sentence. Say what you did or what is true.
  • The evidence: something from your own work that backs the claim. Name a file, a command, a test, or a result.
  • The trade-off: what you gave up to get this result, and why that was acceptable.

A trade-off is a deliberate cost. Every engineering choice has one. If you cannot name the cost of your choice, the examiner will assume you did not consider alternatives.

Here is the same question answered twice. The question is: "Why did you store the readings in a database instead of a plain CSV file?" (CSV means comma-separated values, a plain text table with one row per line.)

Weak answer: "Because a database is better. Everyone uses databases for this kind of thing."

Why it scores low: there is no claim about your work, no evidence, and no trade-off. "Everyone uses" is an appeal to popularity, which examiners discount.

Strong answer: "I stored the readings in a database because the dashboard asks for one station over one date range, and a database can return only those rows. A CSV file would need the whole file read and filtered on every page load. The trade-off is that I now maintain a table schema (the list of columns and their types), and a wrong column breaks the load. I reduced that risk by writing the load as an idempotent step, meaning running it twice gives the same result as running it once, and I checked that with a rerun in my test."

The strong answer is longer, but every sentence does a job. The reasons above are an example of the shape. Replace them with the real reasons from your project.

Tip: Practise the three parts aloud

Pick five decisions you made in CityPulse. For each, say the claim in one sentence, then add one piece of evidence and one trade-off. Time yourself. Aim for under 45 seconds per decision.

Explaining code you wrote

An examiner may ask you to walk through a function. Use this method every time:

  1. Say the purpose in one sentence. ("This function gives the average PM2.5 reading.")
  2. Say the inputs and the output. (PM2.5 is a measure of fine particles in the air.)
  3. Walk the main path in order, from top to bottom.
  4. Name one edge case and what the function does with it.
  5. Say how you tested it.

Here is a short example in Python, the language the course uses for data work:

def average_pm25(readings):
    """Return the mean PM2.5 value, or None if there are no readings."""
    values = [r["pm25"] for r in readings if r.get("pm25") is not None]
    if not values:
        return None
    return sum(values) / len(values)

Line by line:

  • def average_pm25(readings): starts a function called average_pm25. def means define a function. The name is what you type to run it, and readings is the input the function receives.
  • The triple-quoted text under the first line is a docstring, a description of the function. Python stores it, and tools display it.
  • values = [...] builds a new list. A list is an ordered collection of items in square brackets. The part for r in readings says: take each reading, call it r, and keep it only if if r.get("pm25") is not None is true. r.get("pm25") looks up the key "pm25" in the reading (a dictionary, which stores key-value pairs in curly brackets). If the key is missing, .get returns None instead of crashing. is not None keeps only readings that have a value.
  • if not values: checks whether the list is empty. An empty list counts as false, so not makes the test true. With no values, the function returns None, which Python uses to mean "no value".
  • return sum(values) / len(values) adds up the values and divides by the count. sum and len are built-in functions. return sends the result back to whoever called the function.

Expected output: calling average_pm25([{"pm25": 40}, {"pm25": None}, {"pm25": 60}]) returns 50.0. The reading with None is skipped, so the average uses only 40 and 60. Calling average_pm25([]) returns None.

Spoken, the walkthrough sounds like this: "This function takes a list of readings and returns the average PM2.5. It first keeps only the readings that have a value, because a missing value would break the sum. If nothing is left, it returns None, so the caller knows there is no average. Otherwise it divides the total by the count. I tested it with an empty list and a list with one missing value."

Trap: Explaining the code, not the syntax

Examiners do not want to hear "this line has a for loop". They want to hear what the loop does for the data. Say "this keeps only the readings with a value" rather than "this is a list comprehension".

When you do not know

You will be asked something you cannot answer. Do not bluff. An invented answer is found out by the next question, and then your credibility drops for every other answer too.

Use this three-part response:

  1. Say what you do know, even if it is only the nearby idea.
  2. Say how you would find the answer. Name the tool, the document or the command.
  3. If you want to offer a guess, label it as a guess.

For example, suppose an interviewer asks: "How does the database decide the order of rows when you use an ORDER BY with ties?" You might say: "I know ORDER BY sorts the rows, but I am not certain how ties are broken. I would check the database documentation for the exact rule, and I would not rely on the order if my code needs a specific one. The safe approach is to add a second column to the ORDER BY so the order is fully defined."

That answer shows knowledge (ORDER BY sorts), honesty (not certain), a method (check the docs), and good practice (add a tie-breaker). It is far stronger than "I think it is random", and far stronger than silence.

Trap: Saying "I don't know" and stopping

"I don't know" ends the conversation. Always add the next step: how you would find out, or what you would check first.

Rapid-fire questions

Rapid-fire questions are short, direct and quick. Answer in two or three sentences. The answers below are model answers. Read each one, then say it in your own words. Do not memorise them word for word, because the examiner will notice and ask a follow-up.

Words that need explaining are explained the first time they appear in each answer.

Git and teamwork

Git is a tool that records the history of your files, one saved snapshot (a commit) at a time. GitHub is a website that stores Git repositories and lets people review changes together.

1. What is the difference between git fetch and git pull?

Model answer

git fetch downloads new commits from the remote copy of the repository and updates your records of what is there, but it does not change the files you are working on. git pull is a fetch followed by a merge into your current branch, so your files change. I prefer fetch first when I want to look before I change anything.

2. Why does a team use a separate branch for each change?

Model answer

A branch is a movable label on a commit, so each change can be built and reviewed without touching the main line of work. It keeps the main branch in a state that can be deployed. The trade-off is that branches must be merged back, which can cause conflicts when two people edit the same lines.

3. What is the difference between a merge and a rebase?

Model answer

A merge joins two histories with a new commit, and it keeps the record of when the branches split. A rebase copies your commits onto a newer base, so the history reads as one straight line. Rebase rewrites commit IDs, so I never rebase a branch that other people already share.

4. What is a pull request, and what is a review for?

Model answer

A pull request is a proposal to merge one branch into another. It shows the exact changes, lets others leave comments, and runs the automated checks. A review catches bugs before they reach the main branch, and it spreads knowledge of the code across the team, which lowers the bus factor (the number of people who must be unavailable before the project stalls).

5. You accidentally committed a password. What do you do?

Model answer

I treat the password as compromised. First I revoke it and create a new one, because anyone who saw the commit may have copied it. Then I remove it from the repository history, since deleting the line in a new commit does not remove the old one. I also check whether the repository was public, and I add a rule so the file is ignored next time.

Linux and bash

Linux is an operating system. Bash is the shell, the program that reads the commands you type in the terminal (a text window for typing commands). A command is an instruction you type, such as ls, which lists files.

6. What do the letters r, w and x mean in file permissions?

Model answer

For a file, r means read the contents, w means change them, and x means run it as a program. For a directory, r lets you list what is inside, w lets you add or delete entries, and x lets you enter it with cd. The command chmod changes these permissions.

7. What is a process, and how do you stop one?

Model answer

A process is a running copy of a program. ps lists processes and top shows them live. kill followed by the process ID sends a polite stop signal. If the process ignores it, kill -9 forces it to stop, but it gives the program no chance to clean up.

8. What is an exit code, and why does it matter?

Model answer

An exit code is the number a program returns when it finishes. Zero means success, and anything else means failure. The shell stores the last one in $?. Cron, CI and scripts use the exit code to decide whether to continue, so a script that always exits with zero hides its failures.

9. What is a Python virtual environment for?

Model answer

A virtual environment is a folder with its own copy of Python and its own installed packages. It keeps one project's package versions from breaking another project. I create one with python -m venv, activate it, and then install packages with pip, which is Python's package installer.

10. What does set -euo pipefail do at the top of a script?

Model answer

-e stops the script when a command fails. -u treats an unset variable as an error rather than as an empty string. -o pipefail makes a pipeline (commands joined by |) fail if any command in it fails, not just the last one. Together they stop a script from carrying on after a silent error.

HTTP and APIs

HTTP (Hypertext Transfer Protocol) is the rule set browsers and programs use to ask for data from servers. A request is the question you send. A response is the answer you get back. An API (application programming interface) is a set of addresses that return data in a fixed shape.

11. What is the difference between GET and POST?

Model answer

GET asks the server for data and should not change anything on the server, so it is safe to repeat. POST sends data to the server to create something or trigger an action, so repeating it can create duplicates. I use GET for reading readings and POST only when I am sending data that the server must store.

12. What do the status codes 200, 401, 403, 404 and 500 mean?

Model answer

200 means success. 401 means the server does not know who you are, usually because the credentials are missing or wrong. 403 means the server knows you but will not allow this action. 404 means the address does not exist. 500 means the server failed while handling a valid request. A script should treat each differently, for example by retrying a 500 but not a 404.

13. What is JSON, and how do you pull one field out of it with jq?

Model answer

JSON (JavaScript Object Notation) is text that stores data as key-value pairs and lists. jq is a command-line tool that reads JSON. For example, curl -s URL | jq -r '.station' fetches the data and prints only the station field. The -r flag prints the raw text without quotation marks.

14. Why do you keep an API key in an environment variable rather than in code?

Model answer

Code is shared, committed and often published, so a key written into it leaks. An environment variable is set outside the code, on the machine that runs it, and the program reads it when it starts. The .env file that holds such values is listed in .gitignore, a file that tells Git which files never to save.

15. What does idempotent mean, and why does it matter for retries?

Model answer

An operation is idempotent when running it twice leaves the same result as running it once. Networks fail and timeouts happen, so a client often retries. If the operation is idempotent, the retry is safe. A plain insert is not idempotent, because it adds a second row. An upsert is.

Python and data

Python is the programming language the course uses. A variable is a name that stores a value. A function is a named, reusable block of code. A module is a single Python file, and a package is a folder of modules.

16. Why is looking up a key in a dictionary fast?

Model answer

A dictionary is a hash map. Python computes a number (a hash) from the key and uses it to jump straight to the stored value. On average, the time does not grow with the number of items, which is written O(1), or constant time. A list lookup, by contrast, may check every item.

17. Why store timestamps in UTC?

Model answer

UTC (Coordinated Universal Time) is one fixed clock with no daylight saving changes. If data is stored in local times, two readings can be ambiguous in the hour when clocks change, and a comparison between cities breaks. I store UTC and convert to local time only when I display the value.

18. Do Python type hints check types when the program runs?

Model answer

No. Type hints, such as def f(x: int) -> str, are annotations that describe what the code expects. Python ignores them at runtime. A separate tool such as mypy reads them and reports mismatches before the code runs. They help readers and tools, but they do not stop a wrong value from being passed in.

19. What is a DataFrame, and why avoid looping over its rows?

Model answer

A DataFrame is a table in pandas, the Python data library. It can apply one operation to a whole column at once, which is called vectorised work. That is faster than a Python loop and usually clearer. A loop is still right when each row needs a step that is hard to express as a column operation.

20. What is the difference between a module and a package?

Model answer

A module is one Python file, and importing it lets you use its functions. A package is a folder of modules that are imported together as one name. The folder usually contains an __init__.py file, which marks it as a package. I group related files into a package once they share a theme.

SQL

SQL (Structured Query Language) is the language for asking questions of a relational database, which stores data in tables with rows and columns. A query is one SQL question.

21. What is a primary key, and why does an upsert need one?

Model answer

A primary key is a column, or set of columns, whose value is unique for each row. An upsert inserts a row if no row has that key, and updates it if one does. Without a key the database cannot tell whether an incoming reading is new or a repeat, so the same reading would be added twice.

22. What is the difference between an inner join and a left join?

Model answer

A join combines rows from two tables that match on a condition. An inner join keeps only the rows that match in both tables. A left join keeps every row from the left table, and fills the missing right-hand columns with NULL, which means no value. I use a left join when losing a station with no readings would hide a problem.

23. What is the difference between WHERE and HAVING?

Model answer

WHERE filters individual rows before any grouping happens. HAVING filters groups after an aggregate function such as COUNT or AVG has been applied. So WHERE removes bad readings before the average is taken, and HAVING removes stations whose average is based on too few readings.

24. What is a window function?

Model answer

A window function calculates a value across a set of related rows without collapsing them into one row, as GROUP BY does. For example, ROW_NUMBER() OVER (PARTITION BY station ORDER BY reading_time) numbers the readings within each station. The OVER clause defines the window.

25. What is a CTE, and why would you use one?

Model answer

A CTE (common table expression) is a named temporary result defined with WITH. It lets you write a complex query as a sequence of named steps, rather than nested brackets. The trade-off is that a CTE is not stored, so if several queries need the same result, a view is the better choice.

Cloud

Cloud computing means renting computers, storage and services from a provider over the internet. AWS (Amazon Web Services) is one such provider. A region is a geographic area that holds AWS data centres.

26. What is IAM, and what does least privilege mean?

Model answer

IAM (Identity and Access Management) is the system that decides who can do what in the cloud account. Least privilege means giving each identity only the permissions it needs for its task and nothing more. If a key leaks, the damage is limited to what that key could do.

27. What is the difference between an IAM user and an IAM role?

Model answer

An IAM user is a long-term identity, usually for a person, with its own credentials. An IAM role has no permanent password or key. A user or a service assumes the role and receives temporary credentials for a short time. Roles are safer for services, such as a Lambda function, because no long-lived key has to be stored.

28. What is an S3 bucket, and why turn on the public access block?

Model answer

S3 (Simple Storage Service) stores files as objects inside buckets, which are named containers. The public access block stops the bucket or its objects from being made public, even by an accidental policy change. I keep it on by default because a public bucket with personal or sensitive data is a common cause of leaks.

29. Why does the choice of region matter?

Model answer

A region determines where the data physically sits. It affects latency (the delay before a response arrives), the price, which services are available, and where the law says the data may be stored. I pick the region closest to the users and check that it offers every service I need before I deploy.

30. Why set a budget alert, and what does a teardown script do?

Model answer

A budget alert emails you when spending passes a set amount, so a forgotten resource is noticed early. A teardown script deletes the resources the project created, in the right order, so that they stop costing money. I run the teardown at the end of each session and check the bill the next day.

Machine learning

Machine learning means building a model that learns patterns from data. A model is the learned rule. Training is the step where the model learns from the training data. Testing is the check on data the model has not seen.

31. What is data leakage?

Model answer

Data leakage is when information from outside the training data, or from the future, reaches the model during training. The score then looks better than the model really is. A common example is scaling the whole dataset before splitting it. The fix is to fit every preprocessing step on the training data only.

32. Why use a time-based split for time-series data?

Model answer

A time series is data recorded in order over time, such as hourly air-quality readings. A random split would let the model train on readings from after the test period, which is cheating. A time-based split trains on the earlier data and tests on the later data, which matches how the model would be used.

33. What is a baseline, and why compare against one?

Model answer

A baseline is a very simple prediction, such as always predicting the average value. It shows the least a model should beat. If my model is only slightly better than the baseline, the extra complexity may not be worth it. I always report the baseline next to the model's score.

34. When is accuracy a misleading metric?

Model answer

Accuracy is misleading when the classes are unbalanced. If 99 per cent of readings are normal, a model that always says normal scores 99 per cent accuracy and detects nothing. For rare events I report precision (of the alarms raised, how many were real) and recall (of the real events, how many were caught).

35. What does a pipeline do in scikit-learn?

Model answer

scikit-learn is the Python machine-learning library. A Pipeline chains preprocessing steps and the model into one object. When you call fit, each step learns only from the training data, and the same steps are applied to the test data. This prevents leakage and keeps the steps in the same order every time.

Shipping and operating software

Shipping means releasing a working version to users. Operating means keeping it running afterwards.

36. What is continuous integration?

Model answer

Continuous integration (CI) runs the build and the tests automatically on every change, in a clean environment. It catches errors early and gives the whole team a shared, repeatable result. In GitHub Actions, a workflow file describes the steps, and each run shows a green tick or a red cross.

37. What is the difference between a Docker image and a container?

Model answer

A Docker image is a read-only template that holds the program and everything it needs. A container is a running instance of an image. You can start many containers from one image, and stopping a container does not change the image. Docker is the tool that builds and runs both.

38. What is an SLI, and what is an SLO?

Model answer

An SLI (service-level indicator) is a measured quality, such as the share of requests answered within 300 milliseconds. An SLO (service-level objective) is the target for that measure, such as 99.5 per cent over 30 days. The gap between the target and 100 per cent is the error budget, the amount of failure you can accept before you must slow down changes.

39. What is a rollback, and why prepare one before a release?

Model answer

A rollback returns the system to the last version that worked. Preparing it before release means knowing the exact previous version and the command to restore it. Deciding in advance what counts as failure, such as a failed smoke test, stops the team from arguing about it during an incident.

40. What is a smoke test?

Model answer

A smoke test is a quick check after deployment that the most important paths work. For example, it calls the health endpoint and expects a 200 response, then loads the main page. It does not test every feature. Its job is to answer one question quickly: is the release alive?

Behavioural questions

These questions ask about your past behaviour. Answer each with the STAR pattern: Situation (the context), Task (what you had to achieve), Action (what you did, in the first person), and Result (what happened, with a number if you have one). Keep each answer to about 90 seconds.

The stories below are examples built on CityPulse-style work. They show the shape. Replace every detail with what actually happened to you. An examiner will ask follow-up questions, and a made-up story collapses under them.

Tell me about a bug that took a long time to find

Situation: The dashboard showed fewer stations than the API returned, and the team had no error message.

Task: I had to find out where rows were disappearing and fix the cause before the next demo.

Action: I ran the fetch script alone and counted the rows at each stage. The count dropped in the cleaning step. I printed the rows that were removed and found that a missing timestamp was being treated as an error, so the whole station was dropped. I changed the rule to keep the station and flag the row, and I added a test with a missing timestamp.

Result: The station count matched the API again. The test now fails if a row is dropped without a log message.

Tell me about a disagreement in your team

Situation: A partner wanted to store the data in a single large CSV file, and I wanted a database table.

Task: We had to agree on one approach before the load step could be built.

Action: I listed what each option made easy and hard, using the queries the dashboard needed. I asked my partner which query would be slowest with a CSV file, and we tested it together. We kept the database, and I wrote the first version of the load step so they could review it.

Result: We agreed on the approach in one session, and the review caught a bad column type before it reached the main branch.

Tell me about a mistake you made

Situation: I pushed a change that included a file with a test API key in it.

Task: I had to remove the key and prevent the same thing happening again.

Action: I told the team straight away, rotated the key so the old one could no longer be used, and removed the key from the history. Then I moved the key into an environment variable and added the file to .gitignore.

Result: No one used the old key, and the team added a check in the pipeline that scans for keys before merging.

Tell me about something you learned quickly

Situation: I had to write a script in bash for a lesson I had not studied, and the deadline was the same day.

Task: I needed the script to run on a schedule, reliably, without my supervision.

Action: I read the lesson notes on cron and set -euo pipefail, then wrote a short version of the script. I ran it by hand three times with a deliberately broken input to see whether the exit code was correct, and I added a log line at the start and the end.

Result: The script ran on schedule, and the log showed the failed run clearly when the input was broken.

Tell me about explaining something technical to someone who did not understand it

Situation: A non-technical team member asked why the dashboard showed yesterday's numbers.

Task: I had to explain the delay without using jargon, so they could decide whether it mattered.

Action: I compared the pipeline to a daily newspaper. The data is collected and checked overnight, and the dashboard shows the latest completed edition. I showed them the time of the last update on the screen.

Result: They decided the daily update was fine for their report, and they asked for the time stamp to stay visible.

Questions to ask them

At the end of an interview, you will be asked whether you have questions. Asking good ones is part of the score. Choose two or three from this list and listen to the answers.

  • What does a typical first month look like for someone in this role?
  • How does the team review code, and how long does a review usually take?
  • What does an incident look like here, and who is on call?
  • Which part of the system is the hardest to change, and why?
  • How do you decide what to build next?

Avoid questions that the company's website already answers, such as the number of employees or the year it was founded.
