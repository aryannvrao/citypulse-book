## What the quiz tests

The real Day Quiz has ten case-study multiple-choice questions, one for each topic below, in the same order. Each question gives a short scenario from a CityPulse team and asks what to do or what is true. The pass mark is 70%. The first attempt is what your skill score keeps, so a second attempt does not replace it. Take the first attempt slowly.

Use the same method for every question. Read the last line first, because it tells you what is being asked: the best command, the most likely cause, or the first thing to check. Then go back to the scenario and underline the facts that matter, such as the status code, the flag already used, or the name of a field. Next, eliminate options. Many wrong options are true in general, for example "-s hides the progress meter", but they do not fix the problem in the scenario. Finally, watch three words. "Most" asks you to rank causes. "First" asks what to do before anything else. "Best" asks you to choose between several answers that would work, and to pick the cleanest one.

### Plain GET requests with curl

**What it is.** A GET request asks a server for data. It is curl's default method, so `curl "$URL"` with no method flag sends a GET. curl then prints the reply body to stdout, which is your terminal unless you send it somewhere else.

```text
$ curl -s "https://api.example.org/v1/items"
{"items":[{"id":1,"name":"Pune"}]}
```

The output is the body exactly as the server sent it. curl has not created a file. Three flags are often confused here. `-s` hides the progress meter, and it changes only what you see. `-o FILE` saves the body to FILE. `-O` saves the body to a file named after the last part of the URL. A GET only reads data, so repeating it is safe.

**How it shows up in a case study.** The Y2 squad has a fetch step that runs `curl -s "$URL"` at the start of the day. The terminal shows a long JSON line, and the next step fails because `items.json` does not exist. The data is arriving, so the URL is right and the method is correct for reading. Nothing told curl where to put the body. Adding `-o items.json` writes the body to the file, and the next step finds it. Changing the method to POST would send a request the server does not expect.

:::trap Quiet does not mean saved
Adding `-s` does not save anything. It only hides the progress meter. Without `-o`, `-O` or a shell redirect, the body goes to the terminal and no file is written.
:::

```quiz
Q: Your script runs curl -s "https://api.example.org/v1/items", and the next line reads items.json, which does not exist. The server returns the right JSON. Which change makes the file appear?
- Add -X POST to the command
* Add -o items.json to the command
- Add -G to the command
- Replace -s with -v
WHY: -o items.json writes the body to the file. -X POST changes the method, which this read does not need. -G and -v do not save anything.

Q: A colleague says that because the command uses -s, curl runs quietly and saves the reply to a file called items. Which statement about curl -s "https://api.example.org/v1/items" is true?
- It saves the body to a file named items
- It sends a HEAD request and prints nothing
- It sends a POST request and saves the reply
* It sends a GET request and prints the body to the terminal
WHY: Plain curl sends GET and writes the body to stdout. -s removes only the progress meter. The tempting wrong answer is the saved file, which needs -o or -O.

Q: A monitoring script must keep the body of a GET for station data in station.json, with no progress bar. Which single command does this?
* curl -s -o station.json "https://api.example.org/v1/station"
- curl -s -d station.json "https://api.example.org/v1/station"
- curl -s "https://api.example.org/v1/station" -H station.json
- curl -s -X DELETE -o station.json "https://api.example.org/v1/station"
WHY: -o station.json saves the body and -s keeps the output clean. -d sends the text station.json as a POST body, -H sends it as a header, and -X DELETE asks the server to delete the station.
```

### Pulling a field from every array item

**What it is.** jq reads JSON from a pipe or a file and applies a filter. `.readings` selects the array. `[]` breaks the array into its elements, and each element passes on to the rest of the filter. `.value` then picks one field from each element.

```text
$ echo '{"readings":[{"value":42.1},{"value":18.7}]}' | jq '.readings[].value'
42.1
18.7
```

The output has one value per line, in array order. The field name comes after the element, not after the array. The filter `.readings.value` fails, because it asks an array for a key called value. jq reports `Cannot index array with string "value"`. The filter `.readings[]` on its own prints whole objects, not the values.

**How it shows up in a case study.** Ana receives a readings payload, and she wants a list of pollutant names for a report. She writes `jq '.readings.pollutant'` and gets an error that mentions indexing an array. The error tells her the field name is in the wrong place. The fix is to loop first and then select the field: `.readings[].pollutant`. Her list then holds one name per reading, in the same order as the payload.

:::trap Missing brackets
`.readings.value` looks as if it should loop over the readings. It does not. Without `[]`, jq asks the array for a key, and arrays do not have keys.
:::

```quiz
Q: A payload holds {"readings":[{"station":"ST1","value":10.0},{"station":"ST2","value":30.0}]}. Ravi needs the station name from each reading, one per line. Which filter does this?
- jq '.readings.station'
- jq '.readings[]'
* jq '.readings[].station'
- jq '.readings | keys'
WHY: [] loops the array and .station picks the field from each element. The tempting wrong answer is .readings[], which prints whole objects. keys prints index numbers for an array.

Q: Mei's payload is {"data":[{"pm2_5":12.5},{"pm2_5":null},{"pm2_5":30.1}]}. She needs all three values in order, including the null. Which filter does this?
* jq '.data[].pm2_5'
- jq '.data.pm2_5'
- jq '.pm2_5[]'
- jq '.data[] | select(.pm2_5)'
WHY: .data[].pm2_5 outputs every value in order, including null. The select version drops the null reading, which breaks the rule. .data.pm2_5 fails on an array.

Q: Tomas runs jq '.readings[].value' on the reply {"readings":[]}. Which output does he see?
- The number 0
- The text null
- An error saying the array is empty
* Nothing at all
WHY: An empty array has no elements, so the loop produces no output. Counting would need length, and an empty array is not an error for this filter.
```

### Sending a JSON body with POST

**What it is.** A POST request sends data to the server, usually to create or process something. In curl, `-X POST` sets the method, `-H "Content-Type: application/json"` tells the server that the body is JSON, and `-d` supplies the body. Using `-d` alone also sends a POST, but `-X POST` makes the intent clear.

```text
$ curl -s -X POST -H "Content-Type: application/json" -d '{"city":"Pune"}' "$URL"
```

The body travels inside the request, not in the URL. The `-G` flag is the trap. With `-G`, every `-d` value is appended to the URL as a query string, and the request stays a GET. The server then receives no body.

**How it shows up in a case study.** A squad registers a new station by sending JSON to the stations endpoint. Their script runs `curl -G -d '{"name":"MG Road"}' "$URL"`. The log shows the station name inside the URL, and no station is created. The request is a GET with the data in the query string. The fix is to remove `-G`, add `-X POST` and send the header, so the body travels in the request.

:::trap The -G flag
Adding `-G` because the command has data in it turns the data into a query string. A GET with a query string is still a GET, and the body is empty.
:::

```quiz
Q: A script must create a reading by sending a JSON object to an API as a POST, with the data in the request body and not in the URL. Which command does this?
- curl -G -d '{"station":7}' "$URL"
* curl -X POST -H "Content-Type: application/json" -d '{"station":7}' "$URL"
- curl -s -H "Accept: application/json" "$URL"
- curl -d "$URL" '{"station":7}'
WHY: -X POST sets the method, the Content-Type header describes the body and -d carries it. The tempting wrong answer is -G, which moves the data into the URL. The Accept header describes the reply, not the body.

Q: A teammate says that -d with JSON is enough and the other flags are decoration. Which statement is right for sending {"city":"Pune"} to a server that reads the body by its declared type?
- -X POST is decoration, because -d always sends a GET
- The Content-Type header is never needed for a POST
* -d sends a POST, but the Content-Type header tells the server how to read the body, so keep it
- -G is required whenever -d is used
WHY: -d implies POST, but without the header the server may not read the body as JSON. The tempting wrong answer is that -X POST is unnecessary. It is harmless and clear.

Q: Ana's script runs curl -G -d '{"name":"Koramangala"}' "$URL". Afterwards no station exists, and her log shows the name in the URL. What is the cause?
* -G turned the data into a query string on a GET request, so no body was sent
- The name is too long for a URL
- The server needs -X DELETE first
- -d cannot send JSON, so she needs -F
WHY: -G is the cause. The URL length is not the issue. The server receives a read request with no body, so nothing is created.
```

### Reading a 401 status

**What it is.** The first digit of a status code is a class. 2xx means success, 4xx means the client sent something the server rejects, and 5xx means the server failed. A 401 Unauthorized reply means the server does not accept the credentials: none were sent, or they are wrong or expired. Despite its name, 401 is about who you are. A 403 Forbidden means the server knows who you are and refuses this action. A 404 means no resource lives at that URL.

```term
$ curl -s -o /dev/null -w '%{http_code}\n' -H "X-API-Key: $OPENAQ_API_KEY" "$URL"
401
```

The output is one number. A 401 tells you to check the key, not the jq filter, because the filter has not run yet.

**How it shows up in a case study.** The squad's fetch script worked last week. Today the same URL returns 401, and nobody has changed the script. The request reaches the server, which rejects the credentials. The body and the jq filter come after the status check, so they are not the cause. The likely reasons are an expired key, a key that was rotated, or an empty value in the `.env` file that the script loads.

:::trap 401 is not a jq problem
A typo in a jq filter appears only after a 200 status, and a wrong path usually gives 404. A 401 always points to credentials.
:::

```quiz
Q: The fetch script printed HTTP 401 for a URL that returned 200 last week. The script has not changed. What is the most likely cause?
- The jq filter has a typo
- The URL needs a trailing slash
- The body is larger than before
* The key is missing, wrong or expired
WHY: 401 is about credentials. The tempting wrong answer is the jq filter, but jq never runs before the status check, so it cannot produce a 401.

Q: Ming's script gets 403 Forbidden from the readings endpoint, although the same key works on other endpoints. Which statement is right?
- The key is missing, so the status should be 401
* The server knows the key but does not allow this request, so check the permissions for that resource
- The URL does not match a resource, so check the path
- The server failed, so retry later
WHY: 403 means the identity is known and not allowed. The tempting wrong answer is 401, which is about a missing or rejected key.

Q: A cron job prints HTTP 401 for every station. The developer edits the jq filter and runs it again, and the message is still 401. What should the developer do next?
- Change the jq filter again
- Add -G to the curl command
* Check that the key variable is loaded and valid, for example with set -a and source, then retry
- Increase --max-time
WHY: The key is what the server rejected. --max-time handles slow replies, and -G changes where data goes.
```

### Sending keys in a header

**What it is.** Many APIs read a key from a request header, a line such as `X-API-Key: value`. In curl, `-H` adds one header. The header travels with the request, and it is not part of the address.

```bash
curl -s -H "X-API-Key: $OPENAQ_API_KEY" "https://api.openaq.org/v3/locations?limit=1"
```

The shell fills in the variable before curl runs, so the key value is sent in the header. Your shell history records the text you typed, which contains the variable name and not the value. Keys in the URL are different. A URL is written into server logs, proxy logs, browser history and shared links, so a key placed there can be read later. HTTPS protects the key while it travels between your computer and the server, but it does not protect a URL that is logged afterwards.

**How it shows up in a case study.** A developer copies an example that puts the key in the URL, as `?api_key=...`. The squad's shared log then contains the key in plain text. The reasoning has two parts. First, move the key to a header so that future requests keep it out of the address. Second, treat the logged key as exposed and rotate it with the provider, because the log has already spread it.

:::trap Literal keys in commands or scripts
Typing the key value into a command puts it in your history. Writing it into a script puts it into Git history at the next commit. Use the variable name in both places.
:::

```quiz
Q: Priya's script contains the line KEY=k_demo_123 and sends it with -H "X-API-Key: $KEY". She commits the file, then deletes the line in a new commit. Which statement is true?
* The key is still in the Git history, so it must be rotated with the provider
- The key is gone, because the newest commit has no key
- The key is safe, because -H hides the value
- The key is safe, because the file ends in .sh
WHY: git log shows every earlier change. Deleting a line does not remove it from history. The tempting wrong answer is that only the newest commit matters.

Q: Ben's command uses -H "X-API-Key: $OPENAQ_API_KEY". He asks why the value does not appear in his shell history. Which explanation fits?
- The header flag encrypts the key on your computer
- The shell never writes commands to history
* The history records the text typed, which holds the variable name, and the value is filled in only when the command runs
- bash -x hides the key
WHY: The shell expands the variable at run time, so the history holds the name. bash -x does the opposite and prints the expanded key, which is a separate trap.

Q: A URL with ?token= in it is written into a shared log. Which change keeps the credential out of the log without changing the data returned?
- Add -G to the curl command
* Send the token in a header, such as -H "Authorization: Bearer $TOKEN", if the API accepts that
- Replace -s with -v
- Add --max-time 5
WHY: A header keeps the credential out of the address. -v prints request headers too, so it makes the leak worse. --max-time limits time, not secrecy.
```

### Filtering with select

**What it is.** `select(condition)` passes its input through only when the condition is true, and drops it otherwise. Inside a filter, you usually loop first with `[]`, so that select tests one element at a time. You can combine tests with `and` and `or`, compare with `==`, `!=`, `>` and `<`, and then pipe the result to a field.

```text
$ echo '{"readings":[{"pollutant":"PM2.5","value":42.1},{"pollutant":"NO2","value":18.7}]}' | jq '.readings[] | select(.value > 40) | .pollutant'
"PM2.5"
```

The loop sends each reading into select. Only the PM2.5 reading passes, and `.pollutant` prints its name. The output keeps quotes because there is no `-r`. Inside a filter, a single `=` is assignment, not a comparison. The filter `select(.pollutant = "PM2.5")` assigns, and the result of an assignment is the updated object, which jq treats as true, so every reading is kept.

**How it shows up in a case study.** Bilal writes `jq '.readings | select(.value > 40) | .value'` and gets an error that mentions indexing an array. He has applied select to the whole array, not to each reading. Adding `[]` after `.readings` sends each reading into the test separately. He then uses `==` to compare pollutant names.

:::trap One equals sign
In jq, `=` assigns and does not compare. A select built with `=` keeps everything, and the output looks plausible until you count the rows.
:::

```quiz
Q: Nadia wants the value of every reading above 40 from a readings array. Which filter is correct?
- jq '.readings | select(.value > 40)'
- jq '.readings[] | .value > 40'
- jq '.readings[] | select(.value = 40)'
* jq '.readings[] | select(.value > 40) | .value'
WHY: The loop, the test and the field each have a place. The first option tests the whole array. The second prints true or false for each reading, and nothing is filtered.

Q: A reply holds PM2.5 and NO2 readings. Which filter prints only the NO2 values, one per line?
* jq '.readings[] | select(.pollutant == "NO2") | .value'
- jq '.readings[] | select(.pollutant = "NO2") | .value'
- jq '.readings[] | select(.pollutant != "PM2.5")'
- jq '.readings | select(.pollutant == "NO2")'
WHY: == compares. The second option assigns and keeps every reading. The third keeps NO2 but prints whole objects, and the fourth applies select to the array.

Q: The filter is jq '.readings[] | select(.pollutant == "PM2.5" and .value > 40 or .value > 100) | .value'. The readings are PM2.5 at 30 and NO2 at 150. Which values are printed?
- 30 and 150
- 30 only
- Nothing
* 150 only
WHY: and binds more tightly than or, so the test is (PM2.5 and above 40) or above 100. The PM2.5 at 30 fails both parts. The NO2 at 150 passes the second part. The tempting wrong answer is reading the filter from left to right.
```

### Viewing only the headers

**What it is.** Headers describe the reply: its type, its size and more. To see them without the body, use `-D -` to print the headers to stdout and `-o /dev/null` to throw the body away.

```bash
curl -s -D - -o /dev/null "$URL" | head -5
```

The output starts with a status line such as `HTTP/2 200`, followed by header lines such as `content-type`. The exact lines depend on the server. `-I` is a shorter option that sends a HEAD request, which asks for headers only. Some servers answer HEAD differently from GET, so `-D -` is the safer check when you need to match what a GET returns. `-w '%{http_code}'` prints only the status code, and it never prints headers.

**How it shows up in a case study.** Sana wants to check the content type before parsing a reply. She runs `curl -s -o /dev/null -w '%{http_code}\n' "$URL"` and sees only `200`. The command is working, but `-w` prints the status and nothing else. She changes the command to `-D -` so the headers appear.

:::trap Status is not headers
`-w '%{http_code}'` prints one number, the status code. Headers need `-D -`.
:::

```quiz
Q: Omar needs the Content-Type and length the server sends for the readings endpoint, without seeing the body. Which command does this?
- curl -s -o /dev/null -w '%{http_code}\n' "$URL"
- curl -s "$URL" | head -c 400
* curl -s -D - -o /dev/null "$URL"
- curl -s -X DELETE "$URL"
WHY: -D - prints the headers and -o /dev/null discards the body. The first option prints only the status code. The second shows the start of the body, and the fourth deletes data.

Q: A colleague says curl -s -I "$URL" always gives the same output as curl -s -D - -o /dev/null "$URL". What is the best reply?
- Yes, they are the same in every case
- No, -I deletes the data on the server
- No, -I prints the body and hides the headers
* Usually, but -I sends a HEAD request, and some servers answer HEAD differently, so check with a GET when it matters
WHY: The best answer is the careful one. -I is HEAD, and the other form is GET. The tempting wrong answer is that they always match.

Q: Sana's check prints 404 for a URL copied from the slides. Which action is the first thing to try?
- Add -D - to see the headers of the 404
* Check the path and the query string, because 404 means no resource lives at that address
- Increase --max-time, because 404 is a timeout
- Save the body to out.json
WHY: 404 means the address does not match a resource, so the path comes first. --max-time handles slow replies, and saving the body does not change the status.
```

### Counting with length

**What it is.** `length` counts the elements of an array, the keys of an object, or the characters of a string. `keys` gives the names, not the count. For an array, `keys` gives the index numbers 0, 1, 2 and so on.

```text
$ echo '{"readings":[{"v":1},{"v":2},{"v":3}]}' | jq '.readings | length'
3
```

The output is the count. If you replace `length` with `keys`, the output is a list of index numbers such as `[0, 1, 2]`. That list has three items, but it is not the count. `.readings[] | length` gives something else again: the number of keys inside each reading, one number per line.

**How it shows up in a case study.** Lina's log line should say how many readings a station returned. Her log reads `[0,1,2]`. She used `keys`, which prints index numbers. Changing the filter to `.readings | length` prints the count. Her reasoning is that the count must be one number, not a list.

:::trap Keys are not a count
`keys` on an array prints indices, so the output looks like a list of numbers that could be a count. Use `length` when you need the number.
:::

```quiz
Q: A log line must say how many readings a station returned. The readings array is not empty. Which filter prints the number?
* jq '.readings | length'
- jq '.readings | keys'
- jq '.readings[] | length'
- jq '.count'
WHY: length gives the element count. The tempting wrong answer is keys, which prints indices. The third option counts keys inside each reading, and the fourth reads a field that may not exist.

Q: A reply is {"station_id":7,"readings":[]}. Which output does jq '.readings | length' print?
- An error, because the array is empty
* 0
- null
- []
WHY: An empty array has length zero, and the output is the number 0. An empty array is not an error, and null is what a missing key gives.

Q: Which filter prints the number of keys in the object {"a":1,"b":2}?
- jq '.[]'
- jq 'keys'
- jq 'select(.a)'
* jq 'length'
WHY: length on an object counts its keys. keys prints the names, and .[] prints the values.
```

### Failing a script on HTTP errors with --fail

**What it is.** By default, curl treats any finished transfer as success, even when the server answers with an HTTP error. The exit code is 0. With `-f` or `--fail`, curl exits with code 22 when the status is 400 or above, and it does not print the error page as if it were data.

```term
$ curl -s -o /dev/null "https://api.example.org/v1/nope"; echo $?
0
$ curl -sf -o /dev/null "https://api.example.org/v1/nope"; echo $?
22
```

The first exit code is 0 because the transfer finished. The second is 22 because of `-f`. Under `set -e`, a non-zero exit stops the script. `-s` hides the progress meter and leaves the exit code alone.

**How it shows up in a case study.** Oscar's pull script runs `curl -s "$API"` and pipes the result to jq. The script uses `set -euo pipefail`. During an outage, the server returns HTTP 500 with an HTML page. The script does not stop at the HTTP step, and jq fails later with a parse error that does not name the cause. Oscar adds `-f`, so curl exits with 22 and the script stops at the right place.

:::trap Silent does not mean strict
`-s` only hides the progress output. A script with `-s` alone carries on after a 500, and that is the failure this trap describes.
:::

```quiz
Q: A script runs curl -sf "$URL" against a server that answers HTTP 500. Which exit code does curl return?
- 0
* 22
- 1
- 6
WHY: -f makes curl exit with 22 for HTTP errors of 400 and above. Plain curl would return 0 here. 6 means the host could not be resolved, and 1 means an unsupported protocol, so neither is the HTTP-error code.

Q: Dev's script runs curl -s -o "$TMP" "$URL" and must not treat a 404 response as data. Which change is right?
- Add -G
- Replace -s with -v
- Remove the -o flag
* Add -f so that curl exits non-zero on the 404
WHY: -f is the flag for HTTP errors. -G moves data into the URL. -v prints more detail and does not change the exit code. Removing -o prints the body, which is the wrong fix.

Q: Which statement about curl -s is correct?
- It makes curl exit non-zero on HTTP errors
- It makes curl retry failed requests
* It only hides the progress meter, so it does not change the exit code
- It makes curl skip the body
WHY: -s affects only the progress meter. The tempting wrong answer is that silence means failure handling, which needs -f.
```

### The anatomy of an HTTP exchange

**What it is.** An HTTP request has a request line, headers and an optional body. The request line holds the method, the path and the query string. Each header is a `Name: value` line. A reply has a status line, headers and an optional body. A blank line separates the headers from the body.

```text
GET /v1/items?city=Pune HTTP/1.1
Host: api.example.org
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{"items":[]}
```

The request tells the server what to fetch and which replies the client accepts. The reply tells the client whether the request worked and what the body is. HTTP/2 carries the same parts, and curl shows them with lowercase header names.

**How it shows up in a case study.** Ruth's script searches the JSON body for the word "error" to decide whether a request failed. One day the server returned a 500 status with a body that did not contain that word. The script treated the reply as good and wrote bad rows. The status line is the HTTP receipt, and the body is data. The script should check the status first, then check the fields it needs.

:::trap The status is not in the body
The status code lives in the status line. curl exposes it through `-w '%{http_code}'`. A body can contain any text, including words that look like errors.
:::

```quiz
Q: Which part of an HTTP request tells the server which reply formats the client accepts?
* The Accept header, written as Name: value
- The path, such as /v1/items
- The query string after the question mark
- The method, such as GET
WHY: Accept is a header. The path names the resource, the query string passes parameters, and the method is the verb. The tempting wrong answer is the query string, which only passes parameters.

Q: A reply starts with HTTP/1.1 200 OK, then headers, then the body {"error":"quota exceeded"}. Which statement is right?
- The request failed, because the body contains an error field
- The status code 200 is inside the body
- The Content-Type header is the status code
* The request worked at HTTP level, so the script must check the error field in the data
WHY: The status line says the HTTP exchange worked. The body can still carry an application problem, so the script must read that field. The tempting wrong answer treats the body word as the status.

Q: Which list gives the parts of an HTTP request in the right order?
- Status line, headers, body, method
* Request line with the method, path and query string, then headers, then an optional body
- Body, headers, request line
- Query string, method, status line, body
WHY: The request line comes first, then headers, then the optional body. The tempting wrong answer is the status line, which belongs to the reply.
```

### Quick self-test

The questions below mix the ten topics, one each, and are harder than the ones above.

```quiz
Q: A teammate runs curl -s -o out.json -X GET "$URL" and then curl -s "$URL" | jq '.items | length'. Both commands succeed. Which statement about the second command is true?
- It saves the items to a file named out.json
- It sends a POST and prints the count
- It sends a HEAD request, so no count is printed
* It sends a GET, passes the body through the pipe to jq, and writes no file
WHY: The file belongs to the first command only. The second sends a GET and prints the count from jq. The tempting wrong answer attaches the file to the second command.

Q: A reply has readings where one value is null. Lena wants the average of the non-null values using jq alone. Which filter does this?
* jq '[.readings[].value | select(. != null)] | add / length'
- jq '.readings[].value | add / length'
- jq '.readings | add / length'
```

### What each function needs

The three functions need a small set of Python ideas. Each one is taught below with a tiny example that has nothing to do with the lab's data. Do not put these examples together to build the lab's functions. Their purpose is to show each idea on its own.

**Parsing a JSON string.** `json.loads` takes a string and returns Python objects. A JSON object becomes a dictionary, a JSON array becomes a list and a JSON number becomes an int or a float.

```python
import json

shop = json.loads('{"aisles": [{"name": "dairy", "items": 4}]}')
print(shop["aisles"][0]["name"])   # dairy
print(type(shop["aisles"]))        # <class 'list'>
```

Expected output: `dairy`, then `<class 'list'>`.

**Reading a key that may be missing.** `dict.get(key, default)` returns the value when the key exists and the default when it does not. Plain `d[key]` raises a `KeyError` in that case.

```python
stock = {"apples": 3}
print(stock.get("apples", 0))   # 3
print(stock.get("pears", 0))    # 0
```

**Filtering a list with a comprehension.** A list comprehension builds a new list in one line. The `if` part keeps only the items that pass the test, and the order stays the same.

```python
numbers = [7, 2, 9, 4]
print([n for n in numbers if n % 2 == 0])   # [2, 4]
```

**Dividing and rounding.** `/` always gives a float in Python 3. `round(x, 2)` rounds to two decimal places. Python rounds a value that sits exactly halfway to the even neighbour, so `round(2.5)` gives 2 and `round(3.5)` gives 4.

```python
print(sum([2, 4, 9]) / len([2, 4, 9]))   # 5.0
print(round(1 / 3, 2))                   # 0.33
print(round(2.5), round(3.5))            # 2 4
```

**Checking for an empty collection.** `if not items:` is true for an empty list, an empty dictionary and `None`. Use it before dividing by `len`, because dividing by zero raises `ZeroDivisionError`.

```python
groups = []
if not groups:
    print("nothing to average")   # nothing to average
```

**Sorting with a key and a tie-break.** `sorted(items, key=...)` sorts by the value the key function returns. A tuple as the key sorts by its first part and then its second part. A minus sign flips a number to sort in descending order.

```python
scores = [("bo", 5), ("al", 9), ("cy", 5)]
print(sorted(scores, key=lambda t: (-t[1], t[0])))
# [('al', 9), ('bo', 5), ('cy', 5)]
```

The first part sorts by score from high to low. The second part breaks ties by the name, from A to Z.

**Testing types.** `isinstance(x, int)` checks the type. `bool` is a subclass of `int`, so `isinstance(True, int)` is `True`. To exclude booleans from a number check, test for `bool` first.

```python
print(isinstance(True, int))             # True
print(isinstance(True, bool))            # True
print(isinstance("3", (int, float)))     # False
```

**Slicing and negative indexes.** `text[1:3]` takes the characters from index 1 up to, but not including, index 3. A negative index counts from the end, so index -1 is the last item.

```python
word = "harbour"
print(word[1:4])     # arb
print(word[-1])      # r
```

**The median.** `statistics.median` returns the middle value of a sorted list. With an even number of values it returns the average of the two middle values, as a float.

```python
import statistics
print(statistics.median([5, 1, 3, 9]))   # 4.0
```

**Placeholders in SQL.** The `sqlite3` module lets you pass values to a query with `?` placeholders, which keeps the values separate from the SQL text. The values go in a tuple.

```python
import sqlite3
con = sqlite3.connect(":memory:")
print(con.execute("select ? + ?", (2, 5)).fetchone())   # (7,)
```

This lab does not need `sqlite3`, but the same placeholder rule protects you whenever a value comes from outside your program.

### Worked twin problem

The problem below is a different domain with the same skills. It is not the platform's problem. A parcel-tracking API returns a JSON string. Its top level is an object with a `parcels` list, and each parcel has a `code` (text), a `status` (text) and a `weight_kg` (a number).

Write three functions. Each takes one argument, the payload string.

- `delivered_codes(payload_json)` returns a list of the `code` values of the parcels whose `status` is `"delivered"`, in document order. It returns `[]` when there are no parcels.
- `mean_weight(payload_json)` returns the mean `weight_kg` of the delivered parcels only, rounded with `round(x, 2)`. It returns `0.0` when no parcel is delivered.
- `lightest_code(payload_json)` returns the `code` of the delivered parcel with the lowest `weight_kg`. Parcels that are not delivered are ignored. If two delivered parcels share the lowest weight, the smaller code in ascending order wins. It returns `None` when no parcel is delivered.

The solution below is complete. Read it after you have tried the problem yourself.

```python test
import json


def delivered_codes(payload_json):
    data = json.loads(payload_json)
    codes = []
    for parcel in data.get("parcels", []):
        if parcel.get("status") == "delivered":
            codes.append(parcel["code"])
    return codes


def mean_weight(payload_json):
    data = json.loads(payload_json)
    weights = [p["weight_kg"] for p in data.get("parcels", [])
               if p.get("status") == "delivered"]
    if not weights:
        return 0.0
    return round(sum(weights) / len(weights), 2)


def lightest_code(payload_json):
    data = json.loads(payload_json)
    best_code = None
    best_weight = None
    for parcel in data.get("parcels", []):
        if parcel.get("status") != "delivered":
            continue
        w = parcel["weight_kg"]
        code = parcel["code"]
        if best_weight is None or w < best_weight or (w == best_weight and code < best_code):
            best_weight = w
            best_code = code
    return best_code


PAYLOAD = '{"parcels": [{"code": "P-14", "status": "delivered", "weight_kg": 2.5}, {"code": "P-02", "status": "lost", "weight_kg": 4.0}, {"code": "P-09", "status": "delivered", "weight_kg": 4.0}, {"code": "P-05", "status": "delivered", "weight_kg": 1.0}, {"code": "P-30", "status": "lost", "weight_kg": 0.5}]}'
TIE_ORDER = '{"parcels": [{"code": "P-88", "status": "delivered", "weight_kg": 3.0}, {"code": "P-11", "status": "delivered", "weight_kg": 3.0}]}'
THIRDS = '{"parcels": [{"code": "P-1", "status": "delivered", "weight_kg": 1.0}, {"code": "P-2", "status": "delivered", "weight_kg": 2.0}, {"code": "P-3", "status": "delivered", "weight_kg": 2.0}]}'
EMPTY = '{"parcels": []}'
NO_KEY = '{}'
ONE = '{"parcels": [{"code": "P-7", "status": "lost", "weight_kg": 0.5}]}'

assert delivered_codes(PAYLOAD) == ["P-14", "P-09", "P-05"]
assert mean_weight(PAYLOAD) == 2.5
assert lightest_code(PAYLOAD) == "P-05"

assert lightest_code(TIE_ORDER) == "P-11"
assert delivered_codes(TIE_ORDER) == ["P-88", "P-11"]
assert mean_weight(THIRDS) == 1.67

assert delivered_codes(EMPTY) == []
assert mean_weight(EMPTY) == 0.0
assert isinstance(mean_weight(EMPTY), float)
assert lightest_code(EMPTY) is None

assert delivered_codes(NO_KEY) == []
assert lightest_code(NO_KEY) is None

assert delivered_codes(ONE) == []
assert mean_weight(ONE) == 0.0
assert lightest_code(ONE) is None
```

Line by line, the important parts are these.

- `import json` gives the program the JSON reader, and `json.loads(payload_json)` turns the string into a dictionary. Each function starts with that line.
- `data.get("parcels", [])` returns the list, or an empty list when the key is missing. That is why `NO_KEY` returns an empty result and does not crash.
- In `delivered_codes`, `parcel.get("status") == "delivered"` keeps only the delivered parcels. Because the loop runs in array order, the codes come out in document order.
- In `mean_weight`, the comprehension collects the weight of each delivered parcel only. The `if not weights` check comes before the division, so a payload with no delivered parcel returns `0.0` and never reaches `ZeroDivisionError`.
- `round(sum(weights) / len(weights), 2)` rounds once, at the end. For `PAYLOAD`, the delivered weights are 2.5, 4.0 and 1.0. They add up to 7.5, and 7.5 divided by 3 is 2.5. For `THIRDS`, 5.0 divided by 3 is 1.666..., which rounds to 1.67.
- In `lightest_code`, the `continue` skips any parcel that is not delivered, so a lighter lost parcel such as `P-30` can never win. The first condition, `best_weight is None`, accepts the first delivered parcel. The second, `w < best_weight`, replaces the best when a parcel is lighter. The third handles a tie: a parcel with the same weight replaces the best only when its code is smaller.
- The `or` order matters. When `best_weight` is `None`, Python stops at the first test and never compares `code` with `best_code`, which is also `None` at that point.
- `assert` lines are the checks. Each one prints nothing when it passes and stops the program with an error when it fails. The `is None` test is used for empty results because `None` is compared by identity.

The trace below steps through `lightest_code` on the tie payload, where the first parcel is `P-88` and the second is `P-11`. Both are delivered and weigh 3.0.

```python test
import json
```
