## What the quiz tests

The Day Quiz for today has ten case-study multiple-choice questions, one for each topic in this chapter, in the order the sub-sections below follow. Each question gives a short scenario about the CityPulse team and asks what to do, what to check or what is true. The pass mark is 70 per cent, which means seven correct answers out of ten. Only your first attempt counts towards your skill score, so treat the first try as the real one and read every question properly before you choose.

Use this method on every case-study question.

1. **Read the last line first.** It says what is asked, such as "what should the team do first" or "which setting proves the bucket is private". Knowing the question tells you which facts matter.
2. **Underline the facts in the scenario that matter.** These are usually a symptom, a constraint or a role, such as "the pipeline profile is scoped" or "the file is 12 GB".
3. **Eliminate options that are true in general but do not fix this scenario.** Many wrong answers are correct facts about S3 or boto3 that do not solve the problem in front of you.
4. **Watch for "most", "first" and "best".** "First" means the step that comes before the others. "Best" means the option that fits every constraint in the scenario, not just one of them.

The quiz tests whether you can match a symptom to the right behaviour and pick the fix that causes the least harm. Each sub-section teaches one topic from zero, then gives three practice questions. The final block is a harder mixed self-test.

### Uploading with boto3

**What it is.** boto3 is the official AWS SDK (Software Development Kit) for Python. An SDK is a library that gives you ready-made functions for one service, so you do not write the web requests yourself. You create a client with `boto3.client("s3")`. The client finds your credentials on its own through the credential chain, so the code holds no secret. An upload is one call to `put_object` with three named arguments. `Bucket` is the bucket name, `Key` is the object's full name, and `Body` is the content. `Body` is normally bytes, so the safe habit is to turn a Python string into bytes with `.encode("utf-8")` first. The example below needs AWS to run, so read it for its shape only.

```python
import boto3

s3 = boto3.client("s3")
body = "ts,value\n2026-12-17T06:00:00Z,41.2\n".encode("utf-8")
s3.put_object(Bucket="citypulse-x7k2q9", Key="clean/aqi/date=2026-12-17/sample.csv", Body=body)
```

`encode("utf-8")` turns the text into bytes, and `\n` is a new line inside the string. When the upload works, nothing is printed. When AWS refuses it, the call raises `ClientError`.

**How it shows up in a case study.** The ingest job runs at 06:00 and uploads the day's readings to `clean/aqi/`. The team finds that the job reports success, yet no file appears in the bucket. Their script wraps the upload in `except Exception: pass`, so every failure is hidden and the exit code is 0. The right reasoning is to narrow the handler to the one error the script expects, `ClientError`, print the message to standard error and return 1. Then the scheduler marks the run as failed, and someone sees it.

:::trap Trusting a quiet success
A broad `except` that prints nothing makes a refused upload look like a good one. Catch the expected error, report it and return a non-zero code.
:::

### The S3 object model

**What it is.** S3 (Simple Storage Service) keeps three kinds of thing. A **bucket** is a named container. Its name is unique across the whole of AWS and cannot be changed later. An **object** is one stored file, which means its bytes plus metadata such as size and content type. A **key** is the object's full name inside the bucket, and it is one single string. In `clean/aqi/date=2026-12-17/aq_clean.parquet` the slashes are part of the text. S3 has no real folders. The console shows folder-like views by grouping keys that share a prefix. Because of this, you cannot rename a folder in one step. You must copy each object to its new key and then delete the old one.

**How it shows up in a case study.** A data engineer wants to rename `raw/aqi-old/` to `raw/aqi-2026/` for the whole team. In a file system this is one command. The bucket holds about 40,000 keys under the old prefix. The team therefore plans a copy job that lists every key, copies each one to its new name, checks the copies and only then deletes the originals. The reasoning starts from the fact that the key is the whole name, so changing a prefix means changing every key under it.

:::trap Expecting a folder to be an object
The console shows a folder icon, but S3 holds no folder to rename. A single rename call does not exist.
:::

### Partitioning keys by date

**What it is.** Partitioning means splitting data into parts by a value that readers filter on, and writing that value into the key. CityPulse uses `date=YYYY-MM-DD`. A listing with the prefix `clean/aqi/date=2026-12-17/` then returns only the objects for that day, because S3 matches the start of each key. The format matters. ISO dates, which put the year first, then the month, then the day, with leading zeros, sort correctly as plain text.

```python
dates = ["2026-12-10", "2026-12-09", "2027-01-02"]
print(sorted(dates))
```

The output is `['2026-12-09', '2026-12-10', '2027-01-02']`, which is calendar order. The day-first form does not behave this way. The text `01-01-2027` sorts before `17-12-2026`, because `0` comes before `1`, even though 1 January 2027 is the later date.

**How it shows up in a case study.** The dashboard team notices that its weekly report lists dates in the wrong order. The first pipeline wrote keys such as `clean/aqi/17-12-2026/`, and the report sorts those names as text. The fix is to write new uploads with `date=YYYY-MM-DD`.

:::trap A date that looks right
`17-12-2026` looks like a date to a person, but as text it sorts wrongly across years. Use the ISO form every time.
:::

```quiz
Q: A reader lists the prefix clean/aqi/date=2026-12-17/ to load one day of AQI data. Which key does the listing return?
* clean/aqi/date=2026-12-17/aq_clean.parquet
- clean/aqi/date=2026-11-17/aq_clean.parquet
- clean/aqi/date=2026-12-18/aq_clean.parquet
- clean/aqi/aq_clean_2026-12-17.parquet
WHY: A prefix match needs the key to start with the whole prefix, including the slash at the end. The tempting wrong answer is the file whose name contains the date, but the date is not at the start of its key.

- The sort is correct for these dates, but breaks in leap years.

- The keys cannot be sorted, because they contain hyphens.

```

### Paginating long listings

**What it is.** A listing call returns one page of keys, not all of them. `list_objects_v2` returns at most 1,000 keys per call. When more keys exist, the response has `IsTruncated` set to `True`, and a `NextContinuationToken`, which is a bookmark for the next call. A **paginator** hides this loop. `s3.get_paginator("list_objects_v2")` gives you an object whose `paginate` method yields one response per page. Each page has `KeyCount`, the number of keys in that page. Also, when no key matches the prefix, the response has no `Contents` entry at all, so `resp["Contents"]` raises `KeyError`. The safe form is `resp.get("Contents", [])`. The loop below uses plain Python to show the idea. Each dictionary stands for one page.

```python
pages = [{"KeyCount": 2}, {"KeyCount": 1}]
total = 0
for page in pages:
    total += page["KeyCount"]
print(total)
```

The output is `3`. Each pass adds one page's count to the running total.

**How it shows up in a case study.** The audit job counts the objects under `raw/` and reports 1,000 every month, even though the number grows. The job calls `list_objects_v2` once and reads the first response. The reasoning is that `IsTruncated` tells the reader that more pages exist. A paginator, and a total that adds each page's `KeyCount`, fixes the report.

:::trap Reading only the first page
One call looks correct on a small test bucket and stops at 1,000 keys in production, without an error. Use the paginator.
:::

```quiz
Q: The audit job calls list_objects_v2 once for raw/ and counts the Contents list. The bucket holds 2,400 keys under raw/. What does the report show?
- 2,400, because one call returns every key under the prefix.
- 2,000, because the call returns two full pages automatically.
- 0, because the call fails when there are more than 1,000 keys.
* At most 1,000, because the call returns only the first page and IsTruncated is True.
WHY: list_objects_v2 returns at most 1,000 keys per call, and the rest are skipped without an error. The tempting wrong answer is 2,400, which assumes one call returns everything.

- An empty list, because S3 always includes Contents.
- Zero, because S3 sets Contents to 0 for empty prefixes.
- None, because S3 sets Contents to None when the prefix is empty.
WHY: With no match, the key is missing, so a plain lookup fails. The tempting wrong answer is an empty list, which is the right value only if the code uses resp.get("Contents", []).

Q: A team wants the number of objects that match a prefix, using a paginator. Which code is correct?

```

### Presigned URLs

**What it is.** A presigned URL is a web address that already carries a signature made with the signer's credentials. Anyone who holds the link can open it, even without an AWS account, until the link expires. You create one with `generate_presigned_url`. The first argument is the operation name, such as `"get_object"`. `Params` names the bucket and key. `ExpiresIn` is the lifetime in seconds, so 3600 means one hour. The link carries the rights of the account that signed it, and the signing identity must stay valid.

```python
import boto3

s3 = boto3.client("s3")
url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "citypulse-x7k2q9", "Key": "clean/aqi/date=2026-12-17/aq_clean.parquet"},
    ExpiresIn=3600,
)
```

The value of `url` is a long `https` address, and its query text includes an expiry such as `X-Amz-Expires=3600`.

**How it shows up in a case study.** A partner needs one clean file for a week of review, and the admin suggests making the bucket public for a day. The better answer is a presigned link to that one object. It covers one key, and its lifetime is set in seconds, so it stops working by itself. A public bucket exposes every object while it is open, and someone must remember to close it.

:::trap Confusing seconds with minutes
`ExpiresIn=60` gives one minute, not one hour. Work out the value in seconds before you run the code.
:::


### Lifecycle rules

**What it is.** A lifecycle configuration is a set of rules that S3 applies in the background, without any code running. A rule has a `Filter` that limits it to a prefix, such as `raw/`. A `Transitions` entry moves current objects to a cheaper storage class after a number of days, such as `STANDARD_IA`. The object stays in the bucket and can still be read, though reads from the cheaper class cost extra. A `NoncurrentVersionExpiration` entry deletes old versions a number of days after they stopped being the latest, and it applies only in a versioned bucket. An `Expiration` entry deletes current objects, so it removes data. S3 applies rules in the background, so an object may move or disappear some time after its day limit.

```json
{"Rules": [{"ID": "raw-cheaper", "Status": "Enabled", "Filter": {"Prefix": "raw/"}, "Transitions": [{"Days": 30, "StorageClass": "STANDARD_IA"}]}]}
```

**How it shows up in a case study.** Storage cost has grown since the bucket turned on versioning. Finance asks for the cheapest fix that still keeps every raw file. The reasoning is to move `raw/` objects to `STANDARD_IA` after 30 days, which keeps the data, and to expire noncurrent versions after 7 days, which removes only the old copies. The team does not add an expiration rule for current raw data, because that would delete the files they must keep.

:::trap Expiration is not transition
An expiration rule for current objects deletes them. A transition only changes the storage class, and the data stays.
:::

```quiz
Q: The team must keep raw/ data for the record, but wants it cheaper after 30 days. Which rule type does this?
- An Expiration rule with Days set to 30 on the raw/ prefix.
- A bucket policy that denies reads after 30 days.
* A Transition to STANDARD_IA after 30 days, limited by a Filter on raw/.
- A presigned URL that expires after 30 days.
WHY: A transition keeps the data and changes its storage class. The tempting wrong answer is an expiration, which deletes the objects.

Q: After the lifecycle rule runs, old versions of clean/ files still take up space. The rule has no noncurrent expiry. Which setting is missing?
- A Transition from STANDARD to STANDARD_IA.
* NoncurrentVersionExpiration with NoncurrentDays set to 7.
- A Filter that sets Prefix to the bucket name.
- A second bucket that holds the older versions.
WHY: Noncurrent expiry deletes old versions after the set number of days. The tempting wrong answer is a transition, which keeps the old data in a cheaper class.

Q: A lifecycle rule has an Expiration with Days set to 90 and a Filter prefix of clean/aqi/. Which result is correct?

- Only old versions are removed after 90 days.
- Nothing changes, because lifecycle rules ignore prefixes.
* Current objects under clean/aqi/ are deleted about 90 days after they were created.
WHY: An expiration on current objects deletes them, and the prefix limits which objects are affected. The tempting wrong answer is the transition, which keeps the data.
```

### Handling boto3 errors

**What it is.** When AWS refuses a call, boto3 raises `botocore.exceptions.ClientError`. An exception is an error that Python raises while the program runs, and `try` and `except` catch it. The error details are in the `response` dictionary of the exception object. The error code is at `e.response["Error"]["Code"]`, for example `AccessDenied`, `NoSuchKey` or `NoSuchBucket`. The message is at `e.response["Error"]["Message"]`. The example below builds a `ClientError` by hand, so it runs without AWS.

```python
from botocore.exceptions import ClientError

try:
    raise ClientError({"Error": {"Code": "AccessDenied", "Message": "Access Denied"}}, "PutObject")
except ClientError as e:
    print("code:", e.response["Error"]["Code"])
```

The output is `code: AccessDenied`. A good handler catches only the error type it expects, prints the message to standard error, and returns a non-zero exit code.

**How it shows up in a case study.** A nightly job logs "upload failed" for every run, but the team cannot see why. The job prints only a short message and returns 0 at the end, so the scheduler marks every run as successful. The reasoning is that the error code tells you the cause. `AccessDenied` points to permissions, and `NoSuchBucket` points to the bucket name in the configuration. The fix is to catch `ClientError` only, print the error and return 1.

:::trap Catching everything
A broad `except` that returns success hides every failure, including bugs in your own code. Catch the error you expect.
:::

```quiz
Q: A script catches ClientError and prints the error code for an upload. AWS refuses the request because the pipeline profile lacks permission. Which code does e.response show?
* AccessDenied
- NoSuchBucket
- NoSuchKey
- ValueError
WHY: AccessDenied means the identity is not allowed to act. The tempting wrong answer is NoSuchKey, which means the object is missing, not that permission is lacking.

Q: A script wraps the upload in except Exception: pass and returns 0 at the end. Each upload fails with AccessDenied, but the scheduler marks the job as green. Which change fixes the problem?

* Catch ClientError only, print the error to stderr and return 1.
- Remove the try block and let boto3 retry until it works.
WHY: Catching only ClientError, reporting it and returning 1 makes the failure visible to the scheduler. The tempting wrong answer is a bare except that prints the error but still returns 0.

Q: A reader downloads a file and receives the error code NoSuchKey. Which statement is correct?

* The key does not exist in the bucket, so the name or the date in the key is probably wrong.
- The permissions are wrong, so the admin must grant s3:GetObject.

```

### Encryption at rest

**What it is.** Encryption at rest means the data is encrypted while it is stored. Default encryption with SSE-S3 (server-side encryption with S3-managed keys) makes S3 encrypt every new object with AES-256, using keys that AWS manages. You set it once on the bucket, and your code needs no change. When a reader asks for an object, S3 decrypts it for any identity that is allowed to read it. Encryption at rest is therefore not access control. Access is controlled by bucket permissions and by Block Public Access. SSE-KMS uses a key from AWS Key Management Service, and each use of the key can be logged, but each reader also needs permission to use that key. Client-side encryption means your code encrypts the file before upload. Then S3 holds data that it cannot read.

**How it shows up in a case study.** The client's policy says that all stored data must be encrypted at rest by default, and the team does not want to manage keys. An auditor asks who can read the data when the bucket is encrypted. The reasoning is that SSE-S3 meets the policy, because AWS manages the keys with no work for the team. Who can read the data is decided by the permissions and by Block Public Access. The pipeline profile is scoped, so only that identity and the admin identities can read it.

:::trap Treating encryption as access control
An encrypted object is still readable by any identity that has read permission. Encryption protects the stored disks, not the people inside the account.
:::


### Versioning

**What it is.** Versioning keeps every version of an object. With versioning on, an overwrite creates a new version and keeps the old one. A delete adds a **delete marker** on top, so the older versions still exist. Each version has a **version ID**. You read an older version by passing `VersionId` to `get_object`. You restore it by copying that version back to the same key, which makes the copy the newest version. Old versions take storage and cost money, so a lifecycle rule should expire noncurrent versions after a set number of days. Versioning protects against overwrites and deletes inside one bucket. It is not a full backup, because it does not protect you from losing the whole bucket.

**How it shows up in a case study.** A bad pipeline run overwrites yesterday's good Parquet file with an empty file. The team needs the good file back under the same key. The reasoning is to list the versions, find the version ID of the good file and copy it back. The team should not rely on re-running the pipeline, because a rebuild may not reproduce the same bytes. The team should also check the expiry window, because a version that has expired cannot be copied back.

:::trap Versioning as a backup
Versioning protects objects inside the same bucket. It does not replace a copy stored somewhere else.
:::

```quiz
Q: An engineer deletes clean/aqi/date=2026-12-17/aq_clean.parquet with the normal delete command, and the bucket has versioning on. What is the state now?
- The file and all its history are gone for good.
* The current version is hidden behind a delete marker, and the older versions still exist.
- The file is moved into a folder called trash and can be read with the same key.
- The bucket becomes read-only until an admin restores it.
WHY: With versioning on, a delete adds a delete marker and keeps the versions. The tempting wrong answer is a permanent delete, which happens only when the versions themselves are removed.

* The old version may already be gone, so the restore can fail for that version.
- The restore works, because the rule removes only versions older than a year.
- The restore works, because noncurrent versions are copied to a backup bucket.
- The restore works, because the delete markers hold the old bytes.
```

### Multipart uploads

**What it is.** A single upload request, `PUT`, can carry at most 5 GB. A larger object must be uploaded in parts. A **multipart upload** starts, sends each part with a part number, and then completes by naming all of the parts. Each part except the last must be at least 5 MiB, and an upload can have up to 10,000 parts. The boto3 method `upload_file` does the splitting for you. It switches to multipart once the file passes its threshold, which defaults to 8 MB. An upload that never completes keeps its stored parts, and those parts cost money. A lifecycle rule can abort incomplete uploads after a set number of days.

```python
import boto3

s3 = boto3.client("s3")
s3.upload_file("big.parquet", "citypulse-x7k2q9", "clean/aqi/date=2026-12-17/big.parquet")
```

It chooses a single request or a multipart upload by itself.

**How it shows up in a case study.** A 12 GB hourly export fails with a size error from a script that was written around `put_object`. The reasoning is that a single request is limited to 5 GB, so the script must use `upload_file`, which splits large files. The team must also add a rule that aborts incomplete multipart uploads, because the failed runs left parts behind that still cost money.

:::trap Assuming put_object has no size limit
`put_object` takes one object up to 5 GB. Use `upload_file` or the multipart calls for anything larger.
:::

### What each function needs

Each function uses a few Python ideas. Learn each idea with the small example given. The examples use fruit, shop and school data, so you can see the idea without the lab's details. Try each example in a shell or a file before you rely on it.

**Strings and slicing (for `s3_uri`).** A string can be sliced with `text[start:end]`. Leaving out `start` begins at the first character, and `text[1:]` removes one character from the front.

```python
name = "#ticket-9"
print(name[1:])                        # ticket-9
print("ORDER-17".startswith("ORDER"))  # True
print(f"{'Pune'}-{3}")                 # Pune-3
```

`startswith` checks the beginning of a string and returns `True` or `False`. An f-string puts values into the text where the braces are, and the output is `Pune-3`.

**Copying a dictionary (for `put_object`).** `dict(d)` makes a new dictionary with the same pairs. Changing the copy does not change the original.

```python
prices = {"mango": 40}
copy = dict(prices)
copy["kiwi"] = 55
print(prices)  # {'mango': 40}
print(copy)    # {'mango': 40, 'kiwi': 55}
```

The copy is a **shallow** copy. The new dictionary holds the same list objects as the old one, so changing a list inside the copy changes it in the original too. Keep this in mind when a value is a list.

**Looking up a key that may be missing (for `get_object`).** `d[key]` raises `KeyError` when the key is missing. `d.get(key)` returns `None` instead, and `d.get(key, default)` returns the default you give.

```python
stock = {"tea": 3}
print(stock.get("tea"))     # 3
print(stock.get("coffee"))  # None
print(stock.get("coffee", 0))  # 0
print("coffee" in stock)    # False
```

`in` checks whether a key exists and returns `True` or `False`. Use `get` when a missing key is a normal answer, and use `in` when you need to know the difference between a stored value and a missing one.

**Filtering and sorting (for `list_prefix`).** A list comprehension builds a new list from a loop in one line. `sorted` returns a new sorted list and leaves the original alone. Text is compared character by character, using the character codes, so capital letters come before lower-case ones.

```python
words = ["pear", "fig", "banana"]
print([w for w in words if w.startswith("b")])  # ['banana']
print(sorted(words))                            # ['banana', 'fig', 'pear']
print(sorted(words, key=len))                   # ['fig', 'pear', 'banana']
print(sorted(["b", "a", "B"]))                  # ['B', 'a', 'b']
```

The `key` argument changes what is compared, so `key=len` sorts by length. Without a key, the order is the normal text order, and `B` comes before `a`. The statement asks for sorted keys, so you must not add a key that changes the order.

### Worked twin problem

The twin problem below is about a college coding club and its scores. It uses dictionaries, copies, `None`, sorting with a key and a boundary check, so you practise the same skills in a different domain.

**The task.** A college coding club keeps its scores in a dictionary. Each key is a student's name, and each value is a list of scores from 0 to 100. Write three module-level functions.

- `add_score(book, name, score)` returns a **new** dictionary, a copy of `book`, with `score` added to the end of the list for `name`. The name must be a non-empty string after spaces are removed from both ends. The score must be an `int` or a `float`, not a `bool`, and it must be from 0 to 100 inclusive. Any other input raises `ValueError`.
- `average(book, name)` returns the average of the student's scores, rounded to one decimal place. It returns `None` when the student is missing or has no scores.
- `ranking(book)` returns a list of names that have at least one score. The list is ordered by average, highest first. Names with equal averages are ordered from A to Z.

For example, `ranking({"B": [50], "A": [50]})` returns `["A", "B"]`, and `ranking({})` returns `[]`.

```python test
def add_score(book, name, score):
    if not isinstance(name, str) or name.strip() == "":
        raise ValueError("name must be a non-empty string")
    if isinstance(score, bool) or not isinstance(score, (int, float)):
        raise ValueError("score must be a number")
    if score < 0 or score > 100:
        raise ValueError("score must be from 0 to 100")
    new_book = dict(book)
    new_book[name] = list(book.get(name, [])) + [score]
    return new_book


def average(book, name):
    scores = book.get(name)
    if not scores:
        return None
    return round(sum(scores) / len(scores), 1)


def ranking(book):
    rated = []
    for name in book:
        avg = average(book, name)
        if avg is not None:
            rated.append((name, avg))
    rated.sort(key=lambda pair: (-pair[1], pair[0]))
    return [name for name, _ in rated]


def raises_value_error(fn):
    try:
        fn()
    except ValueError:
        return True
    return False
```

**Line-by-line explanation.**

- `add_score` checks the name first. `isinstance(name, str)` confirms the type, and `name.strip() == ""` catches a name that is empty or only spaces. Either case raises `ValueError`, which stops the function before anything is stored.
- The score check comes next. `isinstance(score, bool)` is checked before the number test, because `bool` is a subclass of `int`. Without that check, `True` would pass as the score `1`. The test `not isinstance(score, (int, float))` rejects strings such as `"80"`.
- The range check uses `score < 0 or score > 100`, so the values 0 and 100 are allowed and anything outside the range is refused.
- `new_book = dict(book)` makes a copy, so the caller's dictionary is not changed. `list(book.get(name, []))` copies the old list too, so the new list is separate. Then `+ [score]` adds the new score at the end.
- `average` returns `None` when `book.get(name)` gives `None` for a missing student, or an empty list. The test `not scores` is true for both.
- `round(sum(scores) / len(scores), 1)` divides the total by the count, and then rounds once at the end. Rounding at the end gives `70.7` for the scores 70, 71 and 71, where the exact average is 70.666...
- `ranking` builds a list of `(name, average)` pairs and skips students whose average is `None`.
- The `sort` call uses a key of `(-pair[1], pair[0])`. The minus sign makes higher averages sort first, and the name breaks any tie in A-to-Z order. The statement's tie rule is carried by the second part of the key.
- The last line returns only the names. `for name, _ in rated` unpacks each pair and throws away the average with `_`.

The club dictionary in the tests has a student called Dev with an empty list, so the ranking must leave Dev out. The three students with an average of 85.0 come first, in name order: Asha, Kiran, then Ravi.

```python test
def raises_value_error(fn):
    try:
        fn()
    except ValueError:
        return True
    return False


def reserve(plan, seat, passenger):
    if seat not in plan:
        raise ValueError("unknown seat")
    if not isinstance(passenger, str) or passenger.strip() == "":
        raise ValueError("passenger name required")
    if plan[seat] is not None:
        raise ValueError("seat already taken")
    new_plan = dict(plan)
    new_plan[seat] = passenger
    return new_plan


def free_seats(plan):
    return sorted(seat for seat, who in plan.items() if who is None)


def occupancy(plan):
    if not plan:
        return 0.0
    taken = sum(1 for who in plan.values() if who is not None)
    return round(100 * taken / len(plan), 1)
```
