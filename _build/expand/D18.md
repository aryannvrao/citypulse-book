### Grouping rows with groupby

**What it is.** `groupby` splits a table into groups. You name one or more columns, pandas puts the rows that share a value into one group, and then you apply an aggregate such as `mean`, `sum`, `count` or `size` to each group. Think of a teacher who sorts exam papers into piles by class, then adds up the marks in each pile.

```python
import pandas as pd
readings = pd.DataFrame({
    "station": ["S1", "S2", "S1", "S2", "S1"],
    "pm25": [40.0, 55.0, 60.0, 50.0, 50.0],
})
print(readings.groupby("station")["pm25"].mean())
```

The output is:

```text
station
S1    50.0
S2    52.5
Name: pm25, dtype: float64
```

The column name `["pm25"]` comes before `mean`, so only that column is averaged. The result has one value per station. The station names have become the index, not an ordinary column. The mean for S1 is (40 + 60 + 50) divided by 3, which is 50.0. The mean for S2 is (55 + 50) divided by 2, which is 52.5.

Two aggregates count rows, and they differ on blanks. `size()` counts every row in the group, including rows whose value is missing. `count()` counts only the non-missing values in each column. `mean()` skips missing values as well, so a group with many blanks is averaged over fewer readings than its row count suggests.

**How it shows up in a case study.** A CityPulse team has a table of hourly readings with columns for station, hour and PM2.5. The lead asks which station had the highest average PM2.5 over the week. The right move is to group by station, take the mean of the PM2.5 column, and sort the result. A tempting shortcut is to average the whole column first. That gives one number for the whole city, and it cannot say which station is worst. Another mistake is to group by the PM2.5 values themselves, which makes one group for each distinct reading and never compares stations. The question names a category, so the category is the group key.

:::trap Grouping by the value instead of the category
`df.groupby("pm25")` makes a group for every distinct reading. The station averages are never computed, so the answer looks like data but answers nothing.
:::

### Parsing timestamps with to_datetime

**What it is.** A timestamp stored as text, such as `2026-04-18T05:30:00+05:30`, is only a string to pandas until you convert it. `pd.to_datetime` turns a column into real datetime values, so you can take the hour, compare two moments, and group by time. A UTC offset such as +05:30 is read as a fixed point in time. Adding `utc=True` converts every value to UTC so that all rows share one clock.

```python
import pandas as pd
raw = pd.Series(["2026-04-18T05:30:00+05:30", "2026-04-18T00:00:00+00:00"])
ts = pd.to_datetime(raw, utc=True)
print(ts.dt.hour.tolist())
```

The output is `[0, 0]`. The first text says 05:30 in India, which is midnight UTC. The second text is already midnight UTC. Both rows are the same moment, so both hours are 0.

The `errors` argument decides what happens to a cell that cannot be read. The default, `"raise"`, stops the program at the first bad cell. `"coerce"` stores that cell as `NaT`, which is pandas' missing timestamp. A column that looks like dates but is still text fails with an error when you call `.dt`, because `.dt` works only on real datetime values.

**How it shows up in a case study.** A CityPulse ingest job receives a batch of sensor files. Most timestamps carry a +05:30 offset, one station sends UTC times ending in Z, and one cell holds the text n/a. The team must finish the batch and still report how many rows were unusable. The right first step is `pd.to_datetime` with `utc=True` and `errors="coerce"`, then a count of the `NaT` rows. The bad rows are reported rather than hidden. A tempting alternative is to keep the timestamps as text and sort them, which is wrong when the offsets differ, because the text 05:30 looks later than 00:30 even when it is earlier in real time.

:::trap Comparing text timestamps
As text, "2026-04-18T05:30:00+05:30" sorts after "2026-04-18T00:30:00+00:00". As moments, the first one is 00:00 UTC and the second is 00:30 UTC, so the first is earlier. Convert before you compare.
:::

### Drawing a histogram

**What it is.** A histogram counts values that fall into ranges of equal width. Each range is a bin. The horizontal axis holds the values, and the height of each bar is the number of values in its bin. Because the bins are continuous and touch each other, a histogram shows the shape of the spread: whether the values cluster, have a long tail, or sit in two separate groups.

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
values = [42, 45, 48, 55, 61]
counts, edges, patches = plt.hist(values, bins=2)
```

With two bins, the range runs from 42 to 61, so each bin is 9.5 wide. The edges are 42.0, 51.5 and 61.0. Three values fall in the first bin and two in the second, so the counts are 3 and 2. The function `plt.hist` returns the counts, the edges and the drawn patches, so you can check the numbers as well as look at the picture.

The number of bins is a choice. Too few bins hide the shape, and too many bins turn the chart into noise, with bars that are almost empty. A histogram is the right chart when the question is about how values are spread. A line chart shows change over time and hides the spread.

**How it shows up in a case study.** A CityPulse analyst wants to know whether PM2.5 is mostly moderate with a few high spikes, or whether it is spread evenly across the month. A line chart of readings over time shows the ups and downs but not how common each level is. A histogram of the 720 hourly PM2.5 values answers the question directly. If the tallest bar sits in the moderate range and a thin tail reaches high values, most readings are moderate and the tail needs its own check. A bar chart of mean PM2.5 per station is the wrong tool here, because it compares stations and hides the spread inside each one.

:::trap A bar chart of categories
A bar chart has gaps between bars, because each bar is a separate category. A histogram has no gaps, because its bins are equal ranges of one continuous value.
:::

### Finding and handling missing values

**What it is.** A missing reading is stored as `NaN`, which stands for Not a Number. `NaN` is not zero. It means that no value was recorded. `isna()` returns `True` for each missing cell, `isna().sum()` counts them in each column, and `isna().mean()` gives the share of cells that are missing. Most pandas statistics, including `mean`, skip `NaN` silently.

```python
import numpy as np
import pandas as pd
pm = pd.Series([40.0, np.nan, 60.0, np.nan])
print(pm.isna().sum())
print(pm.mean())
print(pm.fillna(0).mean())
```

The output is `2`, then `50.0`, then `25.0`. The count of missing cells is 2. The mean of the two real readings, 40 and 60, is 50.0, because the blanks are skipped. Filling the blanks with zero gives the list 40, 0, 60, 0, whose mean is 25.0. The zeros have changed the answer, and they claim the sensor measured clean air at those times.

The two common responses are `dropna`, which removes the rows that are missing, and `fillna`, which replaces them. Either choice has to be recorded. A report should say how many rows were removed or filled, so that every figure has a count behind it.

**How it shows up in a case study.** A station's PM2.5 sensor goes offline for six hours on a Tuesday. In the readings file those hours have blank cells. An analyst computes the weekly mean and gets a figure lower than the team expects. The mean skipped the blank cells, so it rests on fewer readings than the 168 rows the week should have. The right response is to record the number of blanks and the number of readings used, and to state the gap in the report. The tempting fix is `fillna(0)`, which makes the failed sensor look like clean air and pulls the mean down. The honest figure is the mean of the real readings, with the count beside it.

:::trap Filling gaps with zero
A missing reading is not a zero reading. Zero means the air was clean. Count the blanks, report them, and leave them out of the mean, unless the method you publish says otherwise.
:::

### Resampling a time series

**What it is.** To resample is to regroup a time-ordered series into fixed intervals, such as one hour or one day, and then apply an aggregate to each interval. `resample` needs a time index, so first set one with `set_index("ts")` or use a series whose index is already datetime. The string `"h"` means hour, and `"D"` means day. In pandas 2.2 and later, `"h"` is the spelling for hours, and older versions used `"H"`.

```python
import pandas as pd
idx = pd.to_datetime(["2026-04-01 00:10", "2026-04-01 00:40", "2026-04-01 02:20"])
s = pd.Series([50.0, 54.0, 60.0], index=idx)
print(s.resample("h").mean())
```

The output shows three rows, one per hour, from 00:00 to 02:00. The 00:00 row holds 52.0, the mean of 50 and 54. The 01:00 row shows `NaN`, because no reading fell in that hour. The 02:00 row holds 60.0. `resample` creates a row for every interval in the range, even when the interval is empty. That is why a gap shows up as `NaN` rather than being dropped.

The time zone of the index controls where the intervals start. A UTC index gives UTC days, which end at 05:30 IST. If you want IST days, call `tz_convert("Asia/Kolkata")` before you resample.

**How it shows up in a case study.** A team has ten-minute readings from one station and wants an hourly mean for the morning rush in IST. Two problems appear. Some hours have no rows, because the logger paused, and the timestamps are in UTC. The right method converts the index to IST first, then resamples to hours. The empty hours show `NaN`, which is honest, and the team reports the count of empty hours rather than dropping them silently. Converting after resampling would not help, because the hour and day edges would already be fixed at UTC.

:::trap Resampling in UTC by accident
A daily resample on a UTC index starts each day at UTC midnight, which is 05:30 IST. An evening reading at 01:00 IST on 19 April falls into the 18 April bin. Convert with `tz_convert` before you resample.
:::

### Drawing a time-series chart

**What it is.** A time-series chart puts time on the horizontal axis and the measured value on the vertical axis, usually as a line. With matplotlib you pass the time index as `x` and the values as `y` to `ax.plot`. The axes object then lets you add a reference line, labels and a title. The axis label is only text, so it must match the clock that the points actually use.

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import pandas as pd
idx = pd.date_range("2026-04-01", periods=3, freq="D", tz="UTC")
s = pd.Series([40.0, 70.0, 55.0], index=idx).tz_convert("Asia/Kolkata")
fig, ax = plt.subplots()
ax.plot(s.index, s.values)
ax.set(xlabel="Date (IST)", ylabel="PM2.5 (µg/m³)")
```

The `tz_convert` line changes the displayed clock of each point to IST without moving the points in time. Each of the three daily points now sits at 05:30 IST, so the axis label and the points agree. If the call were missing, each point would sit at UTC midnight, and the axis would show UTC clock times under an IST label.

**How it shows up in a case study.** A ward officer asks whether PM2.5 rose after a new road opened on 10 April. The analyst plots daily means against date. The x-axis must be in IST, the chart needs the 60 µg/m³ reference line, and the title should state the finding with a number. The analyst checks the title against the data, not from memory, because the same chart will be drawn again when the next month arrives.

:::trap An IST label on UTC times
If the points are not converted, the axis shows UTC clock times under an IST label. Every reading then appears five and a half hours earlier than it happened.
:::

### Building a grid with pivot_table

**What it is.** `pivot_table` builds a grid. The values of one column become the rows, the values of another column become the columns, and each cell holds a summary of a third column. The `aggfunc` argument chooses the summary. Its default is `"mean"`. Use `pivot_table` when several rows share the same row and column pair, because it combines those rows instead of refusing them.

```python
import pandas as pd
df = pd.DataFrame({
    "day": ["Mon", "Mon", "Tue", "Tue"],
    "hour": [9, 9, 9, 10],
    "pm25": [40.0, 60.0, 50.0, 70.0],
})
grid = df.pivot_table(index="day", columns="hour", values="pm25", aggfunc="mean")
print(grid)
```

The output is a two-by-two grid. The Monday row at hour 9 holds 50.0, which is the mean of the two Monday readings at that hour, 40 and 60. Monday at hour 10 has no rows, so the cell is `NaN`. Tuesday holds 50.0 at hour 9 and 70.0 at hour 10. Each row of the grid is a day, and each column is an hour.

The same grid can be built with `pivot`, but `pivot` raises a `ValueError` when a row and column pair appears twice. That is why `pivot_table` is the usual choice when many stations report the same hour.

**How it shows up in a case study.** A team wants a grid of mean PM2.5 with weekday down the side and hour across the top, so they can see when the city is worst. Five stations report every hour, which means each weekday and hour pair appears several times in the table. The right tool is `pivot_table` with `aggfunc="mean"`, which averages the repeats. A `pivot` call on the same table would stop with a duplicates error. A `groupby` with a single key gives one dimension only, so it cannot produce a weekday by hour grid.

:::trap Using pivot on repeated readings
`df.pivot(index=..., columns=..., values=...)` raises a `ValueError` about duplicate entries when five stations report the same hour. Use `pivot_table` and state the summary you chose.
:::

### Flagging outliers with the IQR rule

**What it is.** An outlier is a value far from the rest of the data. The interquartile range, or IQR, is the width of the middle half of the data: Q3 minus Q1. Q1 is the 25th percentile, the value below which a quarter of the data falls, and Q3 is the 75th percentile. The common rule marks a value as an outlier when it is below Q1 minus 1.5 times the IQR, or above Q3 plus 1.5 times the IQR. Those two limits are called the fences.

```python
import pandas as pd
values = pd.Series([10, 12, 13, 14, 15, 16, 40])
q1 = values.quantile(0.25)
q3 = values.quantile(0.75)
iqr = q3 - q1
upper = q3 + 1.5 * iqr
print(q1, q3, upper)
print(values[values > upper].tolist())
```

The output is `12.5 15.5 20.0`, then `[40]`. The first quartile is 12.5 and the third is 15.5, so the IQR is 3.0. The upper fence is 15.5 plus 4.5, which is 20.0. Only the value 40 is above the fence. The rule uses strict inequalities, so a value exactly on a fence is not flagged. The rule flags values for checking. It does not prove they are errors, and it does not justify deleting them.

**How it shows up in a case study.** A team reviews daily PM2.5 means for one station. The first quartile is 43.5 and the third quartile is 57.7, so the IQR is 14.2 and the upper fence is 79.0. A day at 92 is flagged. The rule says to look at that day, not to delete it. The analyst checks the station logs and the neighbouring days before deciding whether the reading is a fault or a real event. The tempting shortcut is to delete the flagged day so that the chart looks tidy. That hides a possible real event and changes the monthly mean without evidence.

:::trap Treating a flag as a verdict
A flagged value needs checking. Deleting it because of the rule alone removes data that may be real, and the rule cannot tell a fault from an event.
:::

### Measuring correlation

**What it is.** Correlation measures how strongly two columns move together in a straight-line way. The value runs from -1 to 1. A value near 1 means that when one column rises, the other tends to rise in step. A value near -1 means one rises as the other falls. A value near 0 means no straight-line pattern. Pandas uses the Pearson method by default, and `method="spearman"` ranks the values first, which suits steady curved links.

```python
import pandas as pd
df = pd.DataFrame({"pm25": [40, 50, 60, 70], "pm10": [70, 85, 100, 118]})
print(round(df["pm25"].corr(df["pm10"]), 2))
```

The two columns rise together almost in a straight line, so the correlation is close to 1. Working it through gives about 0.9989, which prints as 1.0 at two decimal places. That number describes the straight-line pattern in these four rows. It does not say that PM2.5 causes PM10, and it does not say that one is a percentage of the other. Pandas skips missing values pair by pair, so a blank in one column does not stop the calculation.

**How it shows up in a case study.** A team sees that PM2.5 and PM10 readings correlate strongly at one station, with a value of 0.92. A report that says PM10 causes PM2.5 goes too far, because the two could both be driven by dust, traffic or weather. The right statement is that the two rise and fall together, with a shared source as one possible reason. The analyst also names what the number does not measure. A tempting claim is that PM10 is 92 per cent of PM2.5, which the correlation does not show.

:::trap Reading a correlation as a percentage
A correlation of 0.92 is not "92 per cent of the other column". It is a number between -1 and 1 that describes straight-line association only.
:::

### Placing charts side by side with subplots

**What it is.** `plt.subplots(rows, columns)` creates one figure and a grid of axes, one axes for each panel. With one row and two columns, the call returns two axes, and you unpack them with `fig, (ax1, ax2) = plt.subplots(1, 2)`. With more than one row and column, the second value is a two-dimensional array, and you index one panel with `axes[row, column]`. The option `sharex=True` makes the panels share a horizontal scale, so the times line up.

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
fig, (ax1, ax2) = plt.subplots(1, 2, sharex=True, figsize=(8, 3))
ax1.plot([1, 2, 3], [10, 20, 15])
ax1.set(title="PM2.5")
ax2.plot([1, 2, 3], [30, 25, 40])
ax2.set(title="PM10")
fig.savefig("pair.png", dpi=100)
```

Each panel has its own axes object, so each line is drawn on the panel you name. `ax1.plot` draws on the left panel and `ax2.plot` on the right. The two titles name the panels. The file `pair.png` holds both panels, and because the panels share the x-axis, a value at the same position on each panel refers to the same time.

**How it shows up in a case study.** A ward officer wants PM2.5 and PM10 for the same week shown side by side, so the times line up and the two scales can be compared. The analyst draws two panels that share the horizontal axis. Drawing both series on one axes would put them on one vertical scale, which hides the difference in size between the two pollutants unless the scales are normalised. The right setup is `plt.subplots` with `sharex=True`, then one drawing call on each axes.

:::trap Calling plot on the whole array
With two or more panels, `plt.subplots` returns an array of axes, and an array has no `plot` method. Index one panel first, such as `axes[0, 0].plot(...)`.
:::

### The task in plain words

**The scenario.** CityPulse engineers open every new sensor feed by looking at its distribution before they trust it. You are asked to write three small functions that summarise air-quality readings. - `summary(values)`
- `per_station_average(readings)`

Here are the rules from the statement, in plain English:

- **`summary(values)`** takes a list of numbers. It returns a dictionary with exactly five keys: `count`, `min`, `max`, `mean` and `median`.

- The values for `min`, `max`, `mean` and `median` are rounded to 2 decimal places.

### What each function needs

This section teaches the Python ideas you will need. Every example uses different data from the lab, so that you practise the idea and not the answer. Do not put these examples together into your functions.

**Built-in list helpers.** `min`, `max`, `sum` and `len` work on any list of numbers.

```python
ages = [3, 9, 4, 12]
print(min(ages), max(ages), sum(ages), len(ages))
```

The output is `3 12 28 4`. The count is the length of the list, and the mean is the sum divided by the count.

**Sorting a copy.** `sorted` returns a new list and leaves the original alone. `list.sort()` changes the list it is called on, which may be the caller's list.

```python
prices = [30, 10, 20]
ordered = sorted(prices)
print(ordered)
print(prices)
```

The output is `[10, 20, 30]`, then `[30, 10, 20]`. The original list is unchanged. You can also sort with a key. This sorts words by length, and it keeps the original order for ties:

```python
words = ["pear", "fig", "banana"]
print(sorted(words, key=len))
```

The output is `['fig', 'pear', 'banana']`.

**The median.** The `statistics` module has a ready-made median, and it is useful for checking your own code. The median of an odd count is the middle value. The median of an even count is the average of the two middle values.

```python
import statistics
print(statistics.median([3, 9, 4]))
print(statistics.median([3, 9, 4, 10]))
```

The output is `4`, then `6.5`. The second list sorts to 3, 4, 9, 10, and the two middle values 4 and 9 average to 6.5. In your own code you should write the median steps yourself, using the integer division `n // 2`, which gives the middle index. Integer division drops the remainder: `7 // 2` is 3, so the middle of seven items is at index 3.

**Rounding.** `round(x, 2)` rounds to two decimal places. Round only once, at the point where you return the value.

```python
print(round(12.3456, 2))
print(round(7, 2))
```

The output is `12.35` and then `7`. Because `7` is an integer, `round(7, 2)` returns an integer, not `7.0`. A float stays a float, so a value that must be a float should be built from a division or a float literal.

**Dictionaries and `dict.get`.** `dict.get(key, default)` returns the value for a key, or the default if the key is missing. It lets you count without a special case for a new key.

```python
words = ["cat", "dog", "cat"]
counts = {}
for w in words:
    counts[w] = counts.get(w, 0) + 1
print(counts)
```

The output is `{'cat': 2, 'dog': 1}`. A dictionary built with a loop keeps the order in which the keys were first added. To insert keys in sorted order, loop over `sorted(...)` of the keys and add them one at a time.

**Dictionary comprehension.** A dictionary comprehension builds a dictionary in one expression, and it is a clean way to divide each total by its count.

```python
totals = {"x": 9, "y": 4}
counts = {"x": 3, "y": 2}
print({k: totals[k] / counts[k] for k in totals})
```

The output is `{'x': 3.0, 'y': 2.0}`.

**Integer conversion with `int`.** `int(x)` drops the decimal part of a number. It rounds towards zero, not to the nearest whole number.

```python
print(int(2.9), int(-2.9))
```

The output is `2 -2`. A value of 2.9 becomes 2, so `int` is a way of putting a number into a bin, as long as you remember that it drops the fraction.

**Lists of a fixed length.** `[0] * 4` makes a list of four zeros. You can change one position with `counts[2] += 1`.

```python
counts = [0] * 4
counts[2] += 1
print(counts)
```

The output is `[0, 0, 1, 0]`.

**Checking types with `isinstance`.** `isinstance(value, int)` checks whether a value is an integer. A boolean is a subclass of `int` in Python, so a check for `int` also accepts `True` and `False`.

```python
print(isinstance(True, int))
print(isinstance("5", int))
```

The output is `True`, then `False`. If a rule ever says that booleans are not numbers, you must check for them before the `int` test. The statement of this lab does not mention booleans, so use this only if a rule you can see requires it.

**Guarding against division by zero.** Check the condition before you divide. In a range of values, the width is zero when every value is the same, so you need a separate branch for that case.

```python
temps = [21, 21, 21]
spread = max(temps) - min(temps)
if spread == 0:
    print("all readings are the same")
else:
    print(spread)
```

The output is `all readings are the same`. The check prevents a division by zero later in the code.

### A method that works for every graded lab

Follow these steps in order. They take a little longer at the start, and they save time at the end, when you would otherwise be guessing why a hidden test failed.

1. Read the starter file from top to bottom. Note the three function names, their parameters and any code that already runs when the file is loaded.
2. Write the examples from the statement as `assert` lines before you write any function body. For this lab, that means the `summary` example, the `per_station_average` example and the `histogram_bins` example. Work out each expected value by hand before you trust it.
3. Add your own `assert` lines for every row of the rules table. Each row becomes at least one check, and each check has a value you worked out yourself.
4. Implement one function at a time. After each one, run the asserts that belong to that function. Do not start the next function until the current one passes.
5. Check the types and the rounding last. Confirm that `count` is an integer, that the four summary values have two decimals, and that the keys are in sorted order.
6. Run the visible tests once. Read the result, and fix any failure before you go further.
7. Submit once, when every assert you wrote passes and the visible tests pass.

Keep the asserts in a separate file, or in a block at the bottom of your file that you can remove before you submit. Do not change an assert to match a wrong answer. If an assert fails, the function is wrong, not the assert, unless you find that you worked out the expected value incorrectly.

### Worked twin problem

This is a different problem with a different domain, and it needs the same skills: sorting, grouping, counting into ranges and handling edge cases. Read the statement and try it yourself before you read the solution.

**The task.** A library records loans as dictionaries with the keys `branch`, `book_id` and `days`. Implement three functions:

- `median_days(days)` takes a list of whole numbers of days. It returns the median, as a number, without rounding. An empty list returns `None`.
- `distinct_books_per_branch(loans)` takes a list of loan dictionaries. It returns a dictionary from each branch name to the number of different `book_id` values that branch lent. A book lent twice counts once. The dictionary must list the branches with the most distinct books first, and branches with the same count appear in alphabetical order. An empty list returns `{}`.
- `band_counts(days, edges)` takes a list of loan lengths and a list of band edges. The bands run from one edge to the next, and the lower edge is included while the upper edge is not. It returns one count for each band. A loan at or beyond the last edge is not counted. If `edges` has fewer than two values, or the edges do not strictly increase, the function raises `ValueError`.

**The tested solution.** The block below is the complete solution, with the asserts that check it. Read it after you have tried the task.

```python test
def median_days(days):
    if not days:
        return None
    ordered = sorted(days)
    n = len(ordered)
    mid = n // 2
    if n % 2 == 1:
        return ordered[mid]
    return (ordered[mid - 1] + ordered[mid]) / 2


def distinct_books_per_branch(loans):
    books_by_branch = {}
    for loan in loans:
        books_by_branch.setdefault(loan["branch"], set()).add(loan["book_id"])
    counts = {branch: len(books) for branch, books in books_by_branch.items()}
    ordered = sorted(counts.items(), key=lambda item: (-item[1], item[0]))
    return dict(ordered)


def band_counts(days, edges):
    if len(edges) < 2:
        raise ValueError("need at least two edges")
    for low, high in zip(edges, edges[1:]):
        if not low < high:
            raise ValueError("edges must strictly increase")
    counts = [0] * (len(edges) - 1)
    for d in days:
        for i in range(len(edges) - 1):
            if edges[i] <= d < edges[i + 1]:
                counts[i] += 1
                break
    return counts


def raises_value_error(func, *args):
    try:
        func(*args)
    except ValueError:
        return True
    return False


assert median_days([]) is None
assert median_days([5]) == 5
assert median_days([9, 1, 4]) == 4
assert median_days([1, 2, 3, 10]) == 2.5
assert median_days([3, 3]) == 3.0

loans = [
    {"branch": "North", "book_id": "B1", "days": 5},
    {"branch": "South", "book_id": "B2", "days": 9},
    {"branch": "North", "book_id": "B1", "days": 7},
    {"branch": "North", "book_id": "B3", "days": 2},
    {"branch": "South", "book_id": "B4", "days": 1},
    {"branch": "East", "book_id": "B5", "days": 3},
]
assert list(distinct_books_per_branch(loans).items()) == [("North", 2), ("South", 2), ("East", 1)]
assert distinct_books_per_branch([]) == {}

days = [0, 6, 7, 13, 14, 29, 30, 45]
assert band_counts(days, [0, 7, 14, 30]) == [2, 2, 2]
assert band_counts([], [0, 7]) == [0]
assert band_counts([-1, 0, 6.5], [0, 7]) == [2]
assert raises_value_error(band_counts, [1], [5])
assert raises_value_error(band_counts, [1], [0, 7, 7])
```

**Line by line.**

- `median_days` returns `None` for an empty list, because there is no middle value to report.
- `sorted(days)` makes a new ordered list, so the caller's list is not changed.
- `mid = n // 2` finds the middle index. For an odd count, the middle value is the median. For an even count, the two middle values are averaged, and the division by 2 gives a float such as 2.5.
- `setdefault(loan["branch"], set())` returns the set for that branch, and creates an empty set the first time the branch appears. `.add(loan["book_id"])` then adds the book. A set keeps only one copy of each value, so a book lent twice counts once.
- The dictionary comprehension turns each set into its size with `len(books)`.
- `sorted(counts.items(), key=...)` sorts the (branch, count) pairs. The key `(-item[1], item[0])` sorts by the count from high to low, using the negative sign, and then by the branch name from A to Z for ties. `dict(ordered)` keeps that order, because a dictionary keeps the order of its insertion.
- `band_counts` checks the edges first. The `zip(edges, edges[1:])` pairs each edge with the next one, so that each pair can be tested for strict increase.
- The inner loop tests each band in turn. The test `edges[i] <= d < edges[i + 1]` includes the lower edge and excludes the upper edge. The `break` stops the search as soon as a band is found, so a loan is counted only once.
- A loan of 30 days is not in any band here, because 30 is not below the last edge. This is the boundary rule at work.
- The asserts check the normal case, a single value, a tie in the middle of a list, an empty list, the lower-edge rule, the excluded upper edge, negative values, and the two error cases.

### Your turn

The problem below is new. Read it, write your own solution, and make the asserts pass before you open the solution box.

Bike-share trips are recorded as dictionaries with the keys `start` and `fare`. The `fare` is a number, or `None` when the fare was not recorded. Implement two functions:

- `top_starts(trips, k)` returns a list of the `k` station names with the most trips, the busiest first. Stations with the same count appear in alphabetical order. If `k` is zero or negative, it returns an empty list.
- `mean_fare(trips)` returns the mean of the fares that are not `None`, rounded to 2 decimal places. If no fare is available, it returns `None`.

The asserts that your code must pass are:

```python
trips = [
    {"start": "Indiranagar", "fare": 40.0},
    {"start": "Koramangala", "fare": None},
    {"start": "Indiranagar", "fare": 30.0},
    {"start": "Jayanagar", "fare": 25.5},
]
assert top_starts(trips, 2) == ["Indiranagar", "Jayanagar"]
assert top_starts(trips, 10) == ["Indiranagar", "Jayanagar", "Koramangala"]
assert top_starts(trips, 0) == []
assert top_starts([], 3) == []
assert mean_fare(trips) == 31.83
assert mean_fare([{"start": "A", "fare": None}]) is None
```

:::answer Show a solution
```python test
def top_starts(trips, k):
    if k <= 0:
        return []
    counts = {}
    for trip in trips:
        start = trip["start"]
        counts[start] = counts.get(start, 0) + 1
    ranked = sorted(counts, key=lambda s: (-counts[s], s))
    return ranked[:k]


def mean_fare(trips):
    fares = [t["fare"] for t in trips if t["fare"] is not None]
    if not fares:
        return None
    return round(sum(fares) / len(fares), 2)


trips = [
    {"start": "Indiranagar", "fare": 40.0},
    {"start": "Koramangala", "fare": None},
    {"start": "Indiranagar", "fare": 30.0},
    {"start": "Jayanagar", "fare": 25.5},
]
assert top_starts(trips, 2) == ["Indiranagar", "Jayanagar"]
assert top_starts(trips, 10) == ["Indiranagar", "Jayanagar", "Koramangala"]
assert top_starts(trips, 0) == []
assert top_starts([], 3) == []
assert mean_fare(trips) == 31.83
assert mean_fare([{"start": "A", "fare": None}]) is None
```
:::

**Why this solution works.** `counts.get(start, 0) + 1` counts each station, and the sort key `(-counts[s], s)` places the busiest stations first and breaks ties alphabetically. `ranked[:k]` takes the first `k` names, and slicing returns fewer names when there are fewer stations than `k`. `mean_fare` keeps only the fares that are not `None`, which is a list comprehension with a condition. It rounds once, at the end, and it returns `None` when the list of fares is empty.
