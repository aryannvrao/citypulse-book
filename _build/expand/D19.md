### Showing text and headings

**What it is.** Streamlit draws text with a few calls. Each call adds one element to the page, in the order the script runs. `st.title` draws the largest heading. `st.header` and `st.subheader` draw smaller headings, in that order. `st.markdown` renders text that uses Markdown symbols, such as `**bold**` for bold text and a leading dash for a list item. `st.caption` draws small grey text for a note. `st.text` shows its text exactly as typed, in a plain monospaced font, so symbols such as `**` are not turned into bold.

Here is a small example:

```python
import streamlit as st

st.title("CityPulse Air Quality")
st.caption("Readings refresh every ten minutes.")
st.markdown("**Warning:** PM2.5 is above 60 at CP-003.")
```

On the page, from top to bottom, you see a large heading, then a line of small grey text, then a line with the word Warning in bold. The three calls do not depend on each other. Changing the order of the lines changes the order on the page.

**How it shows up in a case study.** A city team has a dashboard page for one station. The operations lead wants the page name as the main heading, a small grey line under it saying when the data was last loaded, and a short bold warning for the officer. The officer reads the heading first, so only the page name should use the largest size. The loaded-at line is a note, not a section, so `st.caption` fits it. The warning is short formatted text, so `st.markdown` fits it. A developer who uses `st.title` for every line would make every line look like a page name.

:::trap Using st.title for a note
The title is the largest element on the page. Using it for a small note makes the note look like a second page name, which confuses the reader and breaks the layout the team asked for.
:::

### Drop-down lists with selectbox

**What it is.** `st.selectbox(label, options)` draws a drop-down list and returns the option the user chose. It returns the option value itself, such as the text `"CP-002"`. It does not return the position of that option, and it does not return the label. The first option is chosen when the page loads. Pass `index=` to choose a different default position. Each choice reruns the script, so the code after the call always sees the current value.

```python
import streamlit as st

colour = st.selectbox("Pick a colour", ["red", "green", "blue"], index=1)
st.write("You picked", colour)
```

On first load the drop-down shows green, and the page says "You picked green". If the user picks blue, the script reruns and the page says "You picked blue". The number 1 in the code is only the default position. It never appears on the page.

**How it shows up in a case study.** Officers choose one of four stations from a sidebar drop-down. The code takes the value and filters the readings for that station id. The developer should filter on the value itself, because the widget already returns the station that was picked. A developer who expects a position would first look the station up in the list, which adds a step and a source of errors. Reason from what the widget returns, then use it directly. Pass `index` as well, so that the page loads with a sensible default.

:::trap Expecting a position or a label
The variable does not hold 0, and it does not hold the label "Station". It holds the chosen value. Filtering against a number matches no rows and gives an empty chart, and no error warns you.
:::

### Interactive tables with dataframe

**What it is.** `st.dataframe(df)` draws a table that the user can scroll, sort and resize by clicking column headings. It is meant for exploring data. `st.table(df)` draws a static table with no sorting. By default a DataFrame shows its index, the row numbers, as the first column. Pass `hide_index=True` to hide that column.

```python
import pandas as pd
import streamlit as st

readings = pd.DataFrame({"station": ["CP-001", "CP-002"], "pm25": [45.7, 61.2]})
st.dataframe(readings, hide_index=True)
```

On the page you see a grid with two columns, station and pm25, and two rows. There are no row numbers on the left. Clicking the pm25 heading sorts the rows by that column. For a single number, such as a mean, use `st.metric` instead, because a table is the wrong shape for one value.

**How it shows up in a case study.** An officer must scan about 1,400 daily rows and find the worst days by sorting on PM2.5. A developer proposes `st.table` because it looks simpler. Reason from the job: the officer needs to sort and scroll, so the table must be interactive, which means `st.dataframe`. `st.table` would show every row with no way to sort it, and it suits a fixed printout in a report. The row numbers mean nothing to the officer, so hide them.

:::trap Choosing st.table for an explorer
st.table looks tidy, but its output cannot be sorted. A team that picks it for an exploration page has to rebuild the sorting by hand. Use st.dataframe when the user explores, and st.table when the output is fixed.
:::

```quiz
WHY: st.dataframe draws an interactive grid, and clicking a heading sorts it. st.table is static, so sorting is not available. st.metric takes a single value, not a table, and st.caption draws small text.
```

### Headline numbers with metric

**What it is.** `st.metric(label, value, delta=None, delta_color="normal")` draws a headline number with a label above it. The `delta` is the change, and Streamlit prints it with an arrow. The `delta_color` option sets the colour rule. With `"normal"`, a positive change is green and a negative change is red. With `"inverse"`, a positive change is red and a negative change is green. With `"off"`, the change is grey and has no colour.

```python
import streamlit as st

st.metric("Mean PM2.5 (µg/m³)", 36.5, 6.5, delta_color="inverse")
```

On the page you see the value 36.5 in large text, with an upward arrow and the change +6.5 in red. Because the rule is inverse, the rise is shown as bad. The option `label_visibility="hidden"` removes the label, and it does not change the colour.

**How it shows up in a case study.** An officer compares this week's mean PM2.5 with last week's, which was 30.0. This week it is 36.5. The card should show the value and the change, and the change must be red, because a rise in pollution is bad news. The developer passes the difference as `delta` and sets `delta_color="inverse"`. The reasoning is about direction: decide which way is bad for the reader, then choose the colour rule that matches. A table or a chart would not give the headline number the officer needs.

:::trap Leaving the colour rule at normal
The default colours a rise green, which tells the officer that pollution improved. Pollution metrics need `"inverse"`, so that a higher value is shown as bad.
:::

```quiz
Q: The team shows the number of days over the air-quality limit. Last week there were 2 such days and this week there are 5. The card should show the rise in red. Which call does this?
* st.metric("Days over limit", 5, 3, delta_color="inverse")
- st.metric("Days over limit", 5, 3, delta_color="normal")
- st.metric("Days over limit", 5, 3, delta_color="off")
- st.metric("Days over limit", 3, 5, delta_color="inverse")
WHY: The value is 5 and the change is 5 minus 2, which is 3, shown in red because of inverse. normal shows the rise in green, off shows it in grey, and the last option swaps the value and the change.

Q: A card shows the worst-day PM2.5 at 42.0, with a change of -4.0 from the previous period. A fall is good news, and the team wants the fall shown in green. Which option does this?
- delta_color="normal"
- delta_color="off"
* delta_color="inverse"
- label_visibility="hidden"
WHY: With inverse, a negative change is green, which fits a pollutant where a fall is good. With normal, a fall is red. off gives grey. label_visibility hides the label and has no effect on the colour.

Q: A card's label is already written as a heading just above it, so the label should not be drawn again inside the card. The value and the arrow must stay. Which option does this?
- delta=None
- delta_color="off"
- st.caption(label)
* label_visibility="hidden"
WHY: label_visibility="hidden" removes the label and keeps the value and the change. Leaving out delta removes the change, and delta_color="off" removes only the colour. st.caption draws another line of text and does not touch the card.
```

### Caching with cache_data

**What it is.** `st.cache_data` stores what a function returns. Later calls with the same arguments return the stored copy and skip the body of the function. Pass `ttl=` to set a time to live in seconds. After that time the stored value expires, and the function runs again. Without `ttl`, the stored value stays until the server restarts or the code changes. Use `st.cache_resource` for objects that must not be copied, such as a database connection.

```python
import time
import streamlit as st

@st.cache_data(ttl=60)
def slow_square(n):
    time.sleep(2)
    return n * n

st.write(slow_square(4))
```

The first time the page runs, it waits about two seconds and shows 16. For the next sixty seconds, every rerun with the argument 4 shows 16 at once, because the body of `slow_square` does not run. After sixty seconds the stored value expires, and the next run waits two seconds again.

**How it shows up in a case study.** An officer reports that the dashboard never shows new daily files, even an hour after they arrive. The loader is decorated with `@st.cache_data`, but with no `ttl`. The stored copy never expires, so the page keeps showing the file from the first load. The fix keeps the cache, because the speed matters, and adds a time limit that matches the team's freshness target, such as `ttl=600` for ten minutes. Reason from the freshness target first, then choose the time limit.

:::trap Caching forever, or reading outside the cache
A cache with no time limit never refreshes. A read placed outside any cached function runs on every rerun, so the cache does not help at all.
:::

```quiz
Q: A loader reads a file from storage. Officers say new files never appear, even a day later. The decorator is @st.cache_data with no arguments, and the team still wants the page to load quickly. Which change fixes this?
- Remove the decorator entirely
* Add ttl=600 to the decorator
- Add st.stop() at the top of the loader
- Replace it with @st.cache_resource and no arguments
WHY: ttl=600 lets the stored copy expire after ten minutes, so new files appear, and clicks still reuse the copy. Removing the decorator makes every rerun read the file, which is slow. st.stop ends a run, and cache_resource with no arguments keeps its value forever too.

Q: A function opens a database connection. The team wants that connection shared across reruns, and the object cannot be copied. Which decorator fits?

- @st.cache_data(ttl=600)

* @st.cache_resource
WHY: st.cache_resource is meant for objects such as connections that should not be copied. st.cache_data returns a copy of its stored value, which is built for data that can be copied. st.session_state is not a decorator at all.

Q: A script reads a large file at the top, outside any function, so the read runs on every click and the page takes four seconds to respond. The data itself must stay the same. Which change makes clicks faster?

```

### The rerun model and stop

**What it is.** Streamlit runs the whole script from the first line to the last on every interaction, such as a widget change. Each run creates its variables afresh, so a value set at the top starts again each time. `st.stop()` ends the current run immediately and without an error. Lines below it are not run. Lines above it still appear on the page.

```python
import streamlit as st

st.write("Top of the page")
if st.checkbox("Stop here"):
    st.stop()
st.write("Bottom of the page")
```

When the box is not ticked, the page shows both lines. When the officer ticks the box, the script reruns, reaches `st.stop`, and ends. The page shows only the top line, and no error appears. The bottom line is not drawn, because its code never ran.

**How it shows up in a case study.** The dashboard needs a station before it can draw a chart. When no station is chosen, the page must show a warning and skip the chart without a traceback. The developer writes the warning and then calls `st.stop()`. Reason from the rule: the run ends at the stop, so nothing below it runs, and no error appears. A developer who expects a counter to remember its value would also get a wrong result, because each run starts again from the top.

:::trap Expecting a value to survive a rerun
A line such as `visits = 0` followed by `visits = visits + 1` shows 1 on every run. The value is not kept between reruns. Store it in st.session_state when it must survive.
:::

```quiz
Q: A team writes visits = 0 near the top of the script and visits = visits + 1 below it, then shows visits on the page. The officer clicks a widget five times. What does the page show after the fifth click?
- 5
- 6
* 1
- 0
WHY: Each run starts from the top, so visits is set to 0 and then to 1 again. The tempting answer is 5, which assumes the value keeps counting. 0 is wrong because the increment still runs on each run.

Q: A page must show a warning and no charts while no station is chosen. The developer adds the warning, and then the rest of the run must end without an error or a traceback. Which call does this?
* st.stop()
- st.rerun()
- st.session_state.clear()
- st.cache_data()
WHY: st.stop ends the current run cleanly, so lines below it are not run. st.rerun starts a new run, which is the opposite of what is needed. Clearing session state removes stored values, and st.cache_data is a decorator, not a way to end a run.

Q: A developer creates seen = [] at the top of the script and adds the current station to seen once per run. After five clicks, how long is seen?
- 5
* 1
- 0
- The script raises an error
WHY: The list is made again on every run, so each run holds one item. The tempting answer is 5, which assumes the list survives between runs. 0 is wrong because the append runs on every run, and no error is raised.
```

### Per-user memory with session state

**What it is.** `st.session_state` is a dictionary-like store that belongs to one browser session. Its values survive reruns for that user, which normal variables do not. Write the first value only when the key is missing, using `if "visits" not in st.session_state:`, and update it afterwards. Each open browser tab has its own session state, so two officers never share a value.

```python
import streamlit as st

if "visits" not in st.session_state:
    st.session_state["visits"] = 0
if st.button("Add one"):
    st.session_state["visits"] += 1
st.write(st.session_state["visits"])
```

The first time the page loads, the value is 0. After each press of Add one, the value goes up by one, and the page shows the new number. Reloading the browser tab starts a new session, so the count starts again at 0 in that tab.

**How it shows up in a case study.** Each officer wants the station she last viewed to be remembered during her visit, without changing what other officers see. A developer stores it in a top-level variable, which resets on every run. Another proposes a cached function, which is shared by all users. The right place is session state, because the value belongs to one browser session. Reason from who should see the value: one officer, one session.

:::trap Global variables and cache for per-user data
A top-level variable is reset on every rerun. A value inside st.cache_data is shared by every user. Neither keeps data for one officer, so use st.session_state.
:::

```quiz

- A top-level variable last_station = "CP-001"
- @st.cache_data on a function that returns the station
- An environment variable STATION set once when the server starts
* st.session_state with the key last_station
WHY: st.session_state holds a value for one browser session across reruns. A top-level variable is reset on each run, a cached value is shared by all users, and an environment variable is shared by the whole server.

Q: A developer stores a click count inside a function decorated with @st.cache_data(ttl=600) and returns it. Two officers click on their own pages, and both see the same number. Why?

* st.cache_data stores one value that all users of the app share
- A ttl of 600 is too short for a count
- Streamlit cannot store numbers in a cache
WHY: The cache holds one stored value for the whole app, so every user gets it. The first option blames the browser, but the browser stores nothing for this function. A ttl of 600 limits how long the copy lasts, not who shares it, and numbers can be cached.

Q: A developer writes if "clicks" not in st.session_state: st.session_state["clicks"] = 0 at the top, and inside if st.button("Add one"): adds one with st.session_state["clicks"] += 1. The officer presses the button three times. What is the value afterwards?
- 0
- 1
* 3
```

### Sidebar and columns

**What it is.** `st.sidebar` is the narrow column on the left of the page. Any element written with `st.sidebar.` is drawn there, wherever it appears in the script. `st.columns(3)` returns three areas that sit side by side in the main part of the page, and each area takes ordinary calls such as `.metric`.

```python
import streamlit as st

st.sidebar.selectbox("Station", ["CP-001", "CP-002"])
left, right = st.columns(2)
left.metric("Readings", 1392)
right.metric("Stations", 4)
```

The sidebar shows the station drop-down on the left. The main area shows two cards side by side, with Readings on the left and Stations on the right. Moving the sidebar line to the bottom of the script does not move the drop-down into the main area.

**How it shows up in a case study.** The officer wants a date filter in a left column and three KPI cards in a row at the top of the main area. The sidebar suits the filter, because a filter is a control the officer changes and it can stay out of the way. The cards need width to read, so they belong in columns. A developer who puts the cards in the sidebar gives them a narrow strip, and the row the officer expects is lost. Reason from the place each element should appear.

:::trap Cards in the sidebar
st.sidebar is narrow, so cards placed there stack on top of each other instead of sitting in a row. Put KPI cards in st.columns, and put filters in the sidebar.
:::

### Matplotlib figures with pyplot

**What it is.** Matplotlib is a Python library for drawing charts. You create a figure, add lines or bars to it, and then pass the figure to `st.pyplot(fig)`, which draws it on the page. Plotly is another charting library. A Plotly figure goes to `st.plotly_chart(fig, use_container_width=True)` instead. Each call accepts only its own kind of figure.

```python
import matplotlib.pyplot as plt
import streamlit as st

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [4, 9, 16])
ax.set_title("Squares")
st.pyplot(fig)
```

The page shows one chart titled Squares. The line rises from 4 at x equal to 1, to 9 at x equal to 2, and to 16 at x equal to 3. `plt.subplots()` creates a figure and one set of axes, and the names `fig` and `ax` hold them.

**How it shows up in a case study.** A team has a histogram of PM2.5 drawn with Matplotlib in an older notebook, and a Plotly chart from the shared charts module. Both must appear on the same dashboard page. The reasoning is about the library behind each figure. The histogram goes to `st.pyplot`, and the Plotly chart goes to `st.plotly_chart`. Neither call can draw the other's figure, so the team must check which library made each figure before choosing a call.

:::trap Passing a figure to the wrong call
A Matplotlib figure passed to st.plotly_chart, or a Plotly figure passed to st.pyplot, fails, because each call accepts only its own kind of figure.
:::

```quiz
Q: A team has a Plotly figure returned by the shared charts module and wants it on the page. Which call draws it?
- st.pyplot(fig)
* st.plotly_chart(fig, use_container_width=True)
- print(fig)
- st.table(fig)
WHY: st.plotly_chart draws Plotly figures. st.pyplot expects a Matplotlib figure, so it is the wrong call here. print writes text to the terminal and draws nothing on the page, and st.table draws a table.

Q: A developer draws a histogram with Matplotlib into hist_fig and writes st.plotly_chart(hist_fig) in the app. The page shows an error. Which call should replace it?
- st.line_chart(hist_fig)
- st.dataframe(hist_fig)
- st.metric("Histogram", hist_fig)
* st.pyplot(hist_fig)
WHY: hist_fig is a Matplotlib figure, so st.pyplot is the matching call. st.line_chart, st.dataframe and st.metric do not draw Matplotlib figures, and st.metric would show the figure as a value, which it cannot be.

Q: A developer creates a Matplotlib line chart in fig and then forgets to pass it to Streamlit. The officer reloads the page. What does she see for this chart?
* Nothing, because the figure is created but never drawn on the page
- An automatic chart drawn from the variable name
```

### Batching filters in a form

**What it is.** `st.form(key)` groups widgets so that the script does not rerun when one of them changes. The run happens only when the user presses the button created with `st.form_submit_button(label)`. All the values are then sent together, in one run. Each form has a key, which is a unique text name.

```python
import streamlit as st

with st.form("filters"):
    station = st.selectbox("Station", ["CP-001", "CP-002"])
    pollutant = st.selectbox("Pollutant", ["pm25", "no2"])
    submitted = st.form_submit_button("Apply")

if submitted:
    st.write(station, pollutant)
```

Changing either drop-down does nothing yet. When the officer presses Apply, the script runs once, and the page shows the two chosen values. The variable `submitted` is True only in that run. The indented lines under `with st.form("filters"):` are the widgets that belong to the form.

**How it shows up in a case study.** The dashboard has a station, a pollutant and a date range, and the query behind them is slow. Each change reruns the page, so the officer waits after every click and sees the page flicker. The team wants the three values applied together, when the officer is ready. Reason from the wait: a form holds back the reruns until one submit, so the query runs once. The form needs a submit button, or no change is ever applied.

:::trap Forgetting the submit button
A form with no st.form_submit_button is an error: Streamlit shows a "Missing Submit Button" message, because the form's values can never be sent. A plain st.button inside a form is an error too. Also, st.stop is not a way to wait for a button to be pressed.
:::

## The graded lab

### The task in plain words

The lab is a small data layer for the CityPulse dashboard. The dashboard has a drop-down for a station and a date picker for a day. When the officer changes either one, the page calls one function and shows the numbers it returns. You write that function. The page code is not part of the lab, and you do not need Streamlit to pass it.

Here is the statement in plain English.

- **The function.** You implement `station_day_kpis(readings, station_id, date)`. It takes a list of readings, a station id as text, and a date as text. It returns one dictionary.
- **The shape of a reading.** Each reading is a dictionary with four keys: `station_id`, `ts`, `pollutant` and `value`.
- **The timestamps.** `ts` is text such as `"2026-11-03T08:00"`. `date` is text such as `"2026-11-03"`.
- **Which readings count.** Keep a reading only if its `station_id` equals the `station_id` argument and its `ts` starts with the `date` text. Both conditions must be true.
- **`count`.** The number of matching readings, as a whole number.
- **`avg_value`, `max_value` and `min_value`.** Taken over the `value` of the matching readings. Each is rounded to 2 decimal places.
- **`pollutants`.** A sorted list of the distinct pollutant names among the matching readings. Each name appears once.
- **No match.** If nothing matches, return exactly `{"count": 0, "avg_value": 0.0, "max_value": None, "min_value": None, "pollutants": []}`.
- **The example.** The statement shows a call with station "A" and the date "2026-11-03". Its result has count 3, average 37.0, maximum 51.0 and minimum 18.0, and the pollutants NO2 and PM25, in that order.

Each run may take up to 30 seconds and use up to 128 MB of memory. A plain, correct solution uses a tiny fraction of either. The limits matter only if you do something very wasteful, such as repeating the whole list many times over.

The platform scores the lab in two parts. The scoring table is below.

| Test | Points |
|---|---|
| KPIs for station A on the selected day | 25 |
| single-reading station | 15 |
| different day filters correctly | 15 |

The four visible tests are a sample. The platform also runs two hidden tests. You cannot see them, and they are worth 30 points together. ### What each function needs

The function uses a handful of Python ideas. Each one is shown below on different data, so you can learn it without being given the lab's answer. Copy each example, run it, and compare the output with the comment. Build your own function from these ideas only after you can explain each one in your own words.

**1. Reading a key safely with `get`.**

```python
pet = {"name": "Milo", "legs": 4}
print(pet.get("colour", "unknown"))
print(pet.get("legs", 0))
```

Expected output: `unknown`, then `4`. `pet["colour"]` would raise a `KeyError`, because the key is missing. `get` returns the default instead, so the program keeps going.

**2. A list comprehension with two conditions.**

```python
trees = [{"kind": "oak", "age": 40}, {"kind": "pine", "age": 12}, {"kind": "oak", "age": 9}]
old_oaks = [t for t in trees if t["kind"] == "oak" and t["age"] > 10]
print(old_oaks)
```

Expected output: `[{'kind': 'oak', 'age': 40}]`. The `and` keeps an item only when both tests are true. The kept items stay in their original order, and the list being read is not changed.

**3. Checking the start of a text.**

```python
name = "invoice-2024-07-19.pdf"
print(name.startswith("invoice-2024"))
print(name.startswith("2024"))
print("2024" in name)
```

Expected output: `True`, `False`, then `True`. `startswith` checks only the beginning of the text. `in` finds the text anywhere, including the middle, so it can match where you did not intend. When the statement says "starts with", use `startswith`.

**4. Removing duplicates and sorting.**

```python
colours = ["red", "blue", "red", "amber"]
unique = set(colours)
print(sorted(unique))
print(len(colours), len(unique))
```

Expected output: `['amber', 'blue', 'red']`, then `4 3`. A `set` keeps each item once, but a set has no order you can rely on. `sorted` returns a new list in alphabetical order, and the original list is left as it was.

**5. Sums, averages, and the empty case.**

```python
heights = [1.5, 2.0, 1.0]
print(sum(heights) / len(heights))
print(max(heights), min(heights))
print(max([], default=None))
```

Expected output: `1.5`, then `2.0 1.0`, then `None`. `max([])` without a `default` raises a `ValueError`, so check for an empty list first, or give a default. Dividing by `len` of an empty list is also an error. Decide what an empty input returns before you do any arithmetic on it.

**6. Rounding once, at the end.**

```python
print(round(10 / 3, 2))
print(round(2.675, 2))
print(round(2.5))
```

Expected output: `3.33`, then `2.67`, then `2`. `round` picks the nearest value, and for an exact half it picks the even neighbour, so `round(2.5)` is 2. The number 2.675 is stored as slightly less than 2.675, so it rounds down. Round the final result, not the parts that feed it. Rounding a sum first and then dividing can give a different last digit.

**7. Booleans are numbers, and 0 is not the same type as 0.0.**

```python
print(isinstance(True, int))
print(type(True) is int)
print(isinstance(2.0, int))
print(0 == 0.0)
print(type(0.0).__name__)
```

Expected output: `True`, `False`, `False`, `True`, then `float`. `bool` is a subclass of `int`, so `isinstance(True, int)` is True. The check `type(x) is int` is stricter, because it accepts only `int` itself. `0 == 0.0` is True, so an equality test cannot tell the two apart. `type` can.

**8. Changing a list in place.**

```python
scores = [3, 1, 2]
ordered = sorted(scores)
print(scores, ordered)
scores.sort()
print(scores)
```

Expected output: `[3, 1, 2] [1, 2, 3]`, then `[1, 2, 3]`. `sorted` returns a new list and leaves `scores` alone. `scores.sort()` changes `scores` itself. If that list belongs to the caller, the caller's data has changed, and nobody asked for that.

### The rules people miss

Each row below comes from a rule in the statement, or from a Python behaviour that could break one. Treat the last column as a check you run yourself. The statement gives you no range for the date, so no boundary is inclusive or exclusive in the usual sense. The day boundary comes entirely from the text match on `ts`.

| Rule in the statement | What a careless solution does | How to check yours |
|---|---|---|
| Keep readings whose `station_id` equals the argument | Ignores the station, or keeps every reading for the day | Add a reading for another station on the same day, and check that it is excluded |
| `ts` starts with `date` | Uses `date in ts`, which also matches text in the middle, or `ts == date`, which never matches a timestamp with a time in it | Make one reading at 23:59 on the date and one at 00:00 the next day. Only the first counts |
| `station_id` must equal the argument | Uses `in` or `startswith` on the id, so "A" also matches "AB" | Add a reading for station "AB" on the same day and ask for "A". It must not count |
| Both conditions must be true | Uses `or` where `and` is needed | Add one row that matches only the station and one that matches only the date. Neither may count |
| `count` is a number of matching readings, an integer | Counts distinct stations, or returns a float such as 3.0 | `type(result["count"]) is int` must be True |
| `avg_value` is taken over the matching values, rounded to 2 decimals | Averages every reading, or rounds each value before averaging | Work out the average by hand from the matching values only, then compare it with the two-decimal result |
| `max_value` and `min_value` are taken over the matching values | Takes the maximum or minimum over the whole list | Print the matching values, then check the maximum and minimum against them |
| Rounding to 2 decimals | Rounds the sum, then the average, and gets a different last digit | Compare the unrounded average printed in full with the rounded value, and check the rounding by hand |
| `pollutants` is a sorted list of distinct names | Returns duplicates, returns a set, or returns the names in whatever order they appear | `isinstance(result["pollutants"], list)` must be True, and the list must equal the sorted unique names |
| No match gives the exact zero dictionary | Returns `None`, raises a `ValueError` from `max([])`, or returns `0` where the statement shows `0.0` | Call with `[]` and with an unknown station. Compare the whole dictionary with `==`, and check the type of `avg_value` |
| Each `value` is a number | Adds a string such as `"45.7"` to a float, which raises a `TypeError`, or treats `True` as the number 1 | Print the type of one reading's `value` in your own test. Convert only if a test shows text values |
| The input list is not changed | Calls `.sort()` or `.pop()` on the readings, so the caller's list changes | Copy the list before the call, then compare the copy with the list after the call using `==` |

The statement has no tie-break rule, because the function returns no single record that could be picked from a tie. Equal values do not change the maximum, the minimum or the average, and repeated pollutant names are removed by the distinct rule. Do not invent a tie-break rule that the statement does not give.

### Worked twin problem

The twin problem is about gym class bookings, not CityPulse. It needs the same skills: two conditions in one filter, a month matched as the start of a text, a count of booleans, a rounded ratio, a sum rounded once at the end, a value taken from the earliest item by a key, and a fixed result for no match.

**Scenario:** A gym records each class booking for each member. The app shows a monthly summary for one member.

## Your task

Implement `member_month_summary(bookings, member, month)`. Each booking is a dictionary with the keys `member`, `class_name`, `start`, `fee` and `attended`. `start` looks like `"2027-03-04T18:00"`. `month` looks like `"2027-03"`. `fee` is a number, and `attended` is True or False.

Keep the bookings where `member` equals the argument and `start` starts with `month`. Return a dictionary with these keys:

- `booked`: the number of matching bookings, as an integer.
- `attended`: the number of matching bookings whose `attended` is True, as an integer.
- `attendance_rate`: `attended` divided by `booked`, rounded to 2 decimal places. It is 0.0 when there are no matches.
- `fees`: the sum of the matching fees, rounded to 2 decimal places.
- `first_class`: the `class_name` of the matching booking with the earliest `start`. If two share the earliest `start`, take the one that comes first in the list.

If nothing matches, return `{"booked": 0, "attended": 0, "attendance_rate": 0.0, "fees": 0.0, "first_class": None}`.

For the bookings in the solution below, `member_month_summary(bookings, "M1", "2027-03")` returns three bookings, two attended, a rate of 0.67, fees of 21.0, and the first class "Yoga".

```python test
bookings = [
    {"member": "M1", "class_name": "Yoga", "start": "2027-03-04T18:00", "fee": 6.5, "attended": True},
    {"member": "M1", "class_name": "Spin", "start": "2027-03-09T07:30", "fee": 8.0, "attended": False},
    {"member": "M1", "class_name": "Yoga", "start": "2027-03-11T18:00", "fee": 6.5, "attended": True},
    {"member": "M2", "class_name": "Pilates", "start": "2027-03-05T10:00", "fee": 7.25, "attended": True},
    {"member": "M1", "class_name": "Yoga", "start": "2027-04-01T18:00", "fee": 6.5, "attended": True},
]
extra = [
    {"member": "M3", "class_name": "Pilates", "start": "2027-03-02T09:00", "fee": 0.1, "attended": False},
    {"member": "M3", "class_name": "Spin", "start": "2027-03-02T09:00", "fee": 0.2, "attended": False},
]
third = [
    {"member": "M4", "class_name": "Spin", "start": "2027-03-02T09:00", "fee": 5.0, "attended": True},
    {"member": "M4", "class_name": "Spin", "start": "2027-03-03T09:00", "fee": 5.0, "attended": False},
    {"member": "M4", "class_name": "Spin", "start": "2027-03-04T09:00", "fee": 5.0, "attended": False},
]
empty = {"booked": 0, "attended": 0, "attendance_rate": 0.0, "fees": 0.0, "first_class": None}

def member_month_summary(bookings, member, month):
    matches = [b for b in bookings if b["member"] == member and b["start"].startswith(month)]
    if not matches:
        return {"booked": 0, "attended": 0, "attendance_rate": 0.0, "fees": 0.0, "first_class": None}
    booked = len(matches)
    attended = sum(1 for b in matches if b["attended"] is True)
    earliest = min(matches, key=lambda b: b["start"])
    return {
        "booked": booked,
        "attended": attended,
        "attendance_rate": round(attended / booked, 2),
        "fees": round(sum(b["fee"] for b in matches), 2),
        "first_class": earliest["class_name"],
    }

before = list(bookings)
assert member_month_summary(bookings, "M1", "2027-03") == {"booked": 3, "attended": 2, "attendance_rate": 0.67, "fees": 21.0, "first_class": "Yoga"}
assert member_month_summary([], "M1", "2027-03") == empty
assert member_month_summary(bookings, "M9", "2027-03") == empty
assert member_month_summary(bookings, "M1", "2027-04") == {"booked": 1, "attended": 1, "attendance_rate": 1.0, "fees": 6.5, "first_class": "Yoga"}
assert member_month_summary(extra, "M3", "2027-03") == {"booked": 2, "attended": 0, "attendance_rate": 0.0, "fees": 0.3, "first_class": "Pilates"}
assert member_month_summary(third, "M4", "2027-03")["attendance_rate"] == 0.33

```

**Line by line.** The first lines build test data. Each booking is a dictionary, and the lists `extra` and `third` test the rounding of fees, a tie on the start time, and the rounding of a rate. `empty` is the exact result for no match.

`def member_month_summary(bookings, member, month):` defines the function with its three inputs.

`matches = [...]` is a list comprehension with two conditions. `b["member"] == member` checks the member, and `b["start"].startswith(month)` checks that the start text begins with the month. The `and` requires both to be true. The result is a new list, and `bookings` is not changed.

`if not matches:` is true when the list is empty. The function then returns the fixed result at once. This is the guard that stops `min` from failing later on an empty list.

`booked = len(matches)` counts the matches. The count is an integer, so it can be used as a divisor.

`attended = sum(1 for b in matches if b["attended"] is True)` adds one for each booking whose `attended` value is the bool `True`. The `is True` test is used on purpose. A plain `if b["attended"]` would work for this data, but `is True` states exactly which value is being counted.

`earliest = min(matches, key=lambda b: b["start"])` returns the booking with the smallest `start`. The `key` says what to compare. Because the timestamps have a fixed format, comparing them as text gives the earliest one. When two bookings tie, `min` returns the first of them in the list.

The return dictionary builds each value. `round(attended / booked, 2)` divides once and rounds once. `round(sum(...), 2)` adds the fees and rounds the total once, which is why 0.1 plus 0.2 gives 0.3 rather than a long decimal. `earliest["class_name"]` reads one field from the chosen booking.

The asserts test the normal case, the empty list, a wrong member, a month with one booking, the rounding of fees, the tie on the start time, and the rounding of one third to 0.33. The last assert checks that the input list is unchanged. A silent run means every check passed.
