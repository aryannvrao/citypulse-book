### The ticket in plain words

A hiring manager often has about 30 seconds for each candidate. Many open one link, glance at it and decide whether to read on. This ticket asks you to build that link: a live web page, your **portfolio**, that answers four questions at once. Who are you? What have you built? Does it work? How can someone contact you?

The page lives at `https://<username>.github.io`. At the top sits a short introduction, called the **hero**. Below it come two or three **case studies**, each describing one project with a short demo. Skills appear as a list, and every skill links to proof. Your contact details appear near the top too.

Your LinkedIn profile must match it.

Your trainer checks the result four ways: the page loads over a secure connection on a desktop and a phone, the demo plays on a phone, a student from another squad understands the page in 30 seconds, and every link opens. The portfolio freezes on 29 April as Y2-D08, so fix peer feedback before then.

### How your trainer checks it

#### TC1: the address answers with HTTP 200

The step is `curl -sI https://<username>.github.io | head -1`. The expected result is `HTTP/2 200`.

- `curl` fetches the address.
- `-s` (silent) hides the progress meter.
- `-I` asks for the headers only. The server still sends its status line.
- `|` sends the output to the next command.
- `head -1` keeps only the first line, which is the status line.

Passing looks like this:

```term
$ curl -sI https://<username>.github.io | head -1
HTTP/2 200
```

`HTTP/2` names the protocol version. `200` means the page loaded, so this is a pass.

Failing looks like one of these. `HTTP/2 404`: Pages is not enabled or is still building, the repository name is wrong, or there is no `index.html` in the root of the `main` branch. Nothing printed: curl could not connect, so check your internet connection. `curl: (6) Could not resolve host`: the username is mistyped.

```flow
TITLE: What TC1 checks
NODES: Your laptop | GitHub Pages | Your repository
STEPS:
1>2 :: request the page :: curl asks for https://<username>.github.io over HTTPS.
2>3 :: read main :: Pages finds the files on the main branch.
3>2 :: send the files :: The repository hands its files to Pages.
2>1 :: HTTP/2 200 :: The page is served, and curl prints the status line.
```

#### TC2: the demo plays on a phone, with no sideways scroll

The trainer opens the page on a phone in a private window and scrolls to the first project. The demo must play, and the page must not slide sideways. A GIF plays by itself. An MP4 needs its play button to work.

The HTML for an MP4 that plays on a phone looks like this. You will place it in your own page in Y2-T61.4.

```html
<video src="assets/citypulse-demo.mp4" controls muted playsinline></video>
```

- `<video>` is the video player tag.
- `src` names the file. Its spelling and capital letters must match the file exactly.
- `controls` shows the play button. `muted` removes sound, which phones require if a video is ever set to autoplay. `playsinline` stops iPhones forcing the video to full screen.

Failing looks like a blank box, usually a wrong `src`. Or the page slides sideways, usually because one picture is wider than the screen. The fix is a style rule, `img, video { max-width: 100%; height: auto; }`, which keeps pictures and videos inside the screen width. Your page also needs this line inside `<head>`, or phones draw it at desktop width: `<meta name="viewport" content="width=device-width, initial-scale=1">`. A complete page needs `<!doctype html>`, `<html>`, `<head>` (with that meta line and a `<title>`) and `<body>`; put your hero and case studies inside `<body>`.

#### TC3: the peer scores the 30-second card 4 or 5

A peer from another squad opens the page, looks for 30 seconds and scores the card out of 5. Afterwards they must correctly state who you are, what you built, where to see it working and how to contact you. You need 4 or 5. You cannot score your own page. Use the trainer's card for its exact items.

Failing means a score of 3 or lower. The usual cause is something the peer could not find or got wrong, such as the demo or the contact details. Fix the top issue and ask your trainer whether another run is allowed.

#### TC4: every link opens

The trainer clicks each link or runs a link checker. You can run the same check with this loop, in the site folder on your laptop. Save it as `check-links.sh` there (keep it out of your pull request if the squad prefers).

```bash
for url in $(grep -oE 'https://[^" ]+' index.html | sort -u); do
  code=$(curl -s -o /dev/null -w "%{http_code}" -L "$url")
  echo "$code $url"
done
```

- `grep -oE 'https://[^" ]+'` finds every `https://` address in `index.html`. `-o` prints only the match.
- `sort -u` removes duplicates.
- `for ... do ... done` runs the lines between them once for each link, with the link in the variable `url`.
- `code=$(...)` stores the status code. `-o /dev/null` discards the page body, and `-w "%{http_code}"` prints only the code.
- `-L` follows redirects, so the final address is checked.

Passing output has `200` at the start of every line:

```term
$ bash check-links.sh
200 https://github.com/your-username/citypulse-squad
200 https://github.com/your-username/industry-squad
```

A `404` means the link points at nothing. A private repository often shows `404` to a visitor who is not signed in. A `403` can mean the site refuses automated requests, so open that link in a browser. LinkedIn often answers automated requests with `999`, so open your LinkedIn link in a browser instead. `000` means the link could not be reached. The loop only checks `https://` links, so your local `assets/` files are checked by eye on the phone.

### Do it, step by step

Do one stage, test it, then move on. Build each file in stages; do not paste a finished page.

#### Y2-T61.1: create the repository and confirm the URL loads

**Goal.** A repository named exactly `<username>.github.io` with a page that loads.

**Stage 1: create the repository.** Run this on your laptop.

```bash
GH_USER=$(gh api user --jq .login)
gh repo create "$GH_USER.github.io" --public --clone && cd "$GH_USER.github.io"
```

- `GH_USER=$(...)` stores your username in a variable, a named box for a value.
- `gh api user --jq .login` asks GitHub for your details and keeps the `login` field.
- `gh repo create` makes the repository. `--public` is needed for a free Pages site, and `--clone` copies it to your laptop.

Expected output: the new repository's URL. Then `git branch --show-current` should print `main`.

**Stage 2: add a placeholder page.**

```bash
echo "<h1>Placeholder</h1>" > index.html
```

`echo` prints text. The `>` writes it into `index.html`, replacing the file's contents.

**Stage 3: commit, push and turn on Pages.**

```bash
git add index.html
git commit -m "Portfolio: create Pages repo and confirm the URL loads"
git push -u origin main
```

`git add` stages the file, `git commit -m` saves it with a message, and `git push -u origin main` sends it to GitHub. In the repository on GitHub, open **Settings**, then **Pages**, and check the source is "Deploy from a branch", `main`, folder `/ (root)`, and that **Enforce HTTPS** is ticked. Wait about a minute.

**Stage 4: test.** Run TC1 with `curl -sI "https://$GH_USER.github.io" | head -1`. Expect `HTTP/2 200`. If nothing prints, wait and try again.

#### Y2-T61.2: write the hero and add contact links

**Goal.** A top section with your name, target role, one proof line and contact links.

HTML is made of tags. Here is a small example about a bakery:

```html
<h1>Bakery owner</h1>
<p>Doubled weekend orders in four months, tracked from my order book.</p>
<a href="mailto:owner@example.com">Email</a>
```

- `<h1>` is the main heading.
- `<p>` is a paragraph.
- `<a href="...">` is a link. The words between the tags are what the reader clicks.
- `mailto:` opens the reader's email program with the address filled in.

Replace the example with your own role and your own number. The number must come from a file or record you can point to. Add one link each for email, LinkedIn and GitHub, each starting with `https://`.

Preview it with `python -m http.server 8000` in the repository folder, then open `http://localhost:8000`. Press `Ctrl+C` to stop the server. Test by clicking every link. Commit and push.

#### Y2-T61.3: write two or three case studies

**Goal.** One section per project, each answering five questions: problem, your role, stack, one result number and the links.

Find your own commits before you write. Run this inside the project's repository:

```bash
git log --author="$(git config user.name)" --oneline
```

`git config user.name` prints your Git name. `--author` keeps only your commits, and `--oneline` prints each on one line. Use these commits and the numbers in them as evidence.

Write the first case study and test it before the next one. Each needs the problem in one or two sentences, your role in the first person, the tools used, one number with its unit and the file or record it comes from, and links to the repository, pull request or demo.

Use an anchor to link a section on the page. A section with `id="case-1"` can be reached from `<a href="#case-1">`. Click it to check the jump works. Do not copy another student's case study. The viva will ask about every number you write.

Commit with `Portfolio: add case study for my part of CityPulse`.

#### Y2-T61.4: record the demo and embed it

**Goal.** One demo under 5 MB that plays on a phone, with alt text.

**Stage 1: record.** Use any screen recorder and capture 15 to 60 seconds of your project running. This guide assumes `~/Videos/citypulse-demo.mov`. Replace it with your file.

**Stage 2: make a small MP4.** Create the folder with `mkdir -p assets`, then run:

```bash
ffmpeg -i ~/Videos/citypulse-demo.mov -t 45 -vf "scale=720:-2" -c:v libx264 -pix_fmt yuv420p -crf 28 -an -movflags +faststart assets/citypulse-demo.mp4
```

- `-i` is the input file. `-t 45` keeps the first 45 seconds.
- `-vf "scale=720:-2"` makes the picture 720 pixels wide and keeps the height even.
- `-c:v libx264` is the H.264 codec, which plays on almost every phone.
- `-pix_fmt yuv420p` picks the colour format every phone can decode.
- `-crf 28` sets quality. A higher number makes a smaller file.
- `-an` removes sound. `-movflags +faststart` helps the video start on a slow connection.

Expected output: a long ffmpeg log. Then `ls -lh assets/citypulse-demo.mp4` must show under 5 MB. If it is larger, shorten `-t` or raise `-crf` to 30.

**Stage 3: embed it with alt text.** Put this in the first project's section. The alt text describes a different project, so write your own description.

```html
<video src="assets/citypulse-demo.mp4" controls muted playsinline></video>
<img src="assets/citypulse-demo.gif" alt="Screen recording of a form being filled in and submitted">
```

Use the MP4 or a GIF, not necessarily both. The spec allows either. To make a GIF instead, run `ffmpeg -i ~/Videos/citypulse-demo.mov -t 15 -vf "fps=10,scale=480:-1" assets/citypulse-demo.gif`, and check it is still under 5 MB. Delete whichever embed line you do not use, or the page shows a broken box. A `<video>` tag has no `alt`, so put a sentence describing the demo in the paragraph just above it.

`alt` is read aloud by screen readers, so it must say what happens in the demo. The `<video>` attributes are explained under TC2.

**Stage 4: check on a phone.** Push, wait a minute, and check the page on your phone in a private window. Commit with `Portfolio: add demo MP4 with alt text`.

### Defend it in the viva

1. **Why does the portfolio need HTTPS, and why does TC1 check it?**

:::answer Model answer
HTTPS encrypts the connection, so the page cannot be altered in transit and the browser shows a padlock. A hiring manager who sees a warning may leave. TC1 uses `curl -sI` and expects `HTTP/2 200`, which proves the server returned a page rather than an error.
:::

2. **What is the trade-off between a GIF and an MP4 for the demo?**

:::answer Model answer
A GIF plays by itself and loops, which suits a short silent clip, but it is larger for the same length and looks worse at detail. An MP4 is smaller for the same length and can carry sound, but it needs a play button on some phones. A good answer names the file size and length the choice produced.
:::

3. **What did you personally do in this ticket?**

:::answer Model answer
Point to your own commits, not the squad's. Name the case study you wrote, the demo you recorded and compressed, and the pull request that merged it. Show the commits with `git log --author`, and tie each number in the case study to the file it came from.
:::

4. **How does the page layout answer the 30-second test?**

:::answer Model answer
The test asks who, what, where it works and how to contact, in that order. The hero comes first, so the name and target role appear immediately. Case studies follow, with the demo near the top. Contact links and proof links sit where a reader can reach them in one click.
:::

5. **What does your link checker prove, and what does it miss?**

:::answer Model answer
It proves each link in `index.html` returned `200` when I ran it, after following redirects with `-L`. It misses links added by JavaScript, and it cannot judge whether the target is the right content. A `200` on an empty repository still passes the link check, so I also click through each link by eye.
:::

### Check yourself

```quiz
Q: What does the -I flag do in curl -sI https://example.com?
- It prints the whole page body.
* It fetches the headers only, so you see the status line.
- It follows redirects to the final address.
- It hides the progress meter and nothing else.
WHY: -I asks for the headers only. -s hides the progress meter. -L is the flag that follows redirects, and it is easy to confuse with -I.

Q: Which HTML attribute gives a screen reader a description of a picture?
- src
- href
- title
* alt
WHY: alt is the alt text that screen readers read aloud. src names the file, href names a link target, and title shows a tooltip, which is not the description a screen reader needs.

Q: Which ffmpeg option removes the sound track from the output?
* -an
- -t 45
- -crf 28
- -vf "scale=720:-2"
WHY: -an removes audio. -t sets the length, -crf sets quality and -vf sets picture filters, so none of the other three removes sound.
```
