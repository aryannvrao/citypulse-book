### The ticket in plain words

This is the last ticket of the course. It is a simulated campus hiring day, the kind of day a company runs to choose interns. You sit three rounds in one day.

Round 1 is a timed, watched test of aptitude and coding. Round 2 is a technical interview: a short CityPulse talk, questions on SQL and Python, and one data structures and algorithms (DSA) problem solved while you explain your thinking. Round 3 has two parts. The first is a human resources (HR) interview about how you work with other people. The second is a group discussion (GD) of about eight students on one question: should a city publish real-time air-quality predictions when they are sometimes wrong?

CityPulse needs this because internship partners want to match interns to jobs on evidence, not on one exam. The trainer collects your scores, computes your final readiness score (the CRI), and checks it with a second trainer. The CRI workbook holds the components and weights, so this guide does not repeat them. The trainer also checks two earlier deliverables, Y2-D08 (the frozen portfolio) and Y2-D09 (its status on the LMS, the online learning system). Finally the trainer issues a feedback letter. It lists your CRI, three strengths, three gaps and a 30-day plan for the weeks before you join. You read it and acknowledge it. Then the results go to the Atria programme office and to the internship partners in the agreed private format.

Your job is to arrive prepared, perform as yourself, and check that the records about you are right.

### How your trainer checks it

Your trainer checks the ticket against five acceptance criteria and four test cases. Each acceptance criterion says what must be true. Each test case is a command or a manual step that proves it. Read this section before the day, so nothing surprises you.

The five acceptance criteria cover scores for every round, a verified final CRI, D08 and D09 confirmed, the feedback letter, and the results file sent privately. The four test cases below prove the ones you can check yourself.

#### TC1: four scores per student

Trainer's steps: export the Round 1 platform results, and open the Round 2 and Round 3 rubric sheets. Expected result: four non-empty scores per student.

You can check your own row. Create a small fictional file in a scratch folder so you can practise the command safely. The names and numbers are made up.

```bash
printf 'roll,r1,r2,r3_hr,r3_gd\nDEMO01,71,64,80,77\nDEMO02,58,,70,66\n' > sample_scores.csv
```

`printf` prints the text, and `>` writes it into the new file `sample_scores.csv`. The `\n` marks the end of each line. Line 1 is the header. Line 2 is a student with four scores. Line 3 has a blank third score.

Now the check. This is the command the trainer's check is modelled on. It runs on the file you just made, which has one blank score.

```bash
awk -F, 'NR>1 && ($2=="" || $3=="" || $4=="" || $5=="") {print "missing:", $1; bad=1} END {if (!bad) print "TC1 PASS: all rows have 4 scores"}' sample_scores.csv
```

Each part does one job. `awk` runs a small program on each line. `-F,` sets the comma as the field separator. `NR>1` skips the header, where `NR` is the line number. `$2==""` means "field 2 is empty", and fields 2 to 5 hold the scores. `||` means "or". `print "missing:", $1` prints the roll of a student with a blank score. `bad=1` remembers that a problem was found. `END {...}` runs after the last line and prints a pass message only if nothing was marked bad.

Expected output on the sample file, which has a blank score:

```
missing: DEMO02
```

There is no pass line, so the test fails for that student. The usual cause is one score that was never entered, or a round that was exported with a different column order. Check the header line first with `head -n 1`. Field numbers depend on the header, so change `$2` to `$3` and so on if the trainer's export has its columns in another order.

On a fully filled file, the output is a single pass line. This is what passing looks like:

```term
$ printf 'roll,r1,r2,r3_hr,r3_gd\nDEMO01,71,64,80,77\n' > fixed_scores.csv
$ awk -F, 'NR>1 && ($2=="" || $3=="" || $4=="" || $5=="") {print "missing:", $1; bad=1} END {if (!bad) print "TC1 PASS: all rows have 4 scores"}' fixed_scores.csv
TC1 PASS: all rows have 4 scores
```

#### TC2: the second trainer recomputes the CRI

Trainer's steps: pick five students at random and recompute each final CRI from the components. Expected result: the values match the workbook.

Every number must be rebuildable from its parts. The idea is a weighted total. The weights below are fictional, so do not use them for your own CRI; the real weights are in the workbook.

This trace shows the steps for one student with two components.

```trace
TITLE: Rebuilding one weighted total step by step
CODE:
components = {"a": 80, "b": 60}
weights = {"a": 0.5, "b": 0.5}
total = 0
for k in weights:
    total = total + components[k] * weights[k]
result = total / sum(weights.values())
STEPS:
1 :: components={"a": 80, "b": 60} :: Line 1 stores the component scores for one student.
2 :: weights={"a": 0.5, "b": 0.5}; components={"a": 80, "b": 60} :: Line 2 stores the weights.
3 :: total=0; weights={"a": 0.5, "b": 0.5} :: The running total starts at zero.
4 :: k="a"; total=0 :: The loop takes the first component name.
5 :: k="a"; total=40.0 :: 80 times 0.5 is 40.0, and it is added to the total.
4 :: k="b"; total=40.0 :: The loop comes round again for the second component.
5 :: k="b"; total=70.0 :: 60 times 0.5 is 30.0, and it is added to the total.
6 :: result=70.0 :: The weights add up to 1.0, so dividing gives 70.0.
```

A tested version of the same idea is below. It uses a tolerance, which is the small allowed difference for rounding. The trainer's tolerance is not in this guide, so ask for it.

```python test
def weighted_total(components, weights):
    """Weighted average of component scores. The weights are fictional here."""
    total_weight = sum(weights.values())
    return sum(components[k] * weights[k] for k in weights) / total_weight

def matches_workbook(recomputed, workbook_value, tolerance=0.05):
    return abs(recomputed - workbook_value) <= tolerance

assert round(weighted_total({"a": 80, "b": 60}, {"a": 0.5, "b": 0.5}), 2) == 70.0
assert matches_workbook(70.02, 70.0)
assert not matches_workbook(71.0, 70.0)
assert weighted_total({"a": 100}, {"a": 2}) == 100.0
```

Run it with `python` in the folder where you saved it. No output means every assert passed. An assert that fails stops the program with an error that names the line.

Expected output for a passing run: nothing is printed, and the prompt returns. A failing run shows `AssertionError` and the line number. The usual causes are a weight that was typed wrong, a component taken from the wrong round, or a rounding step applied too early.

### Defend it in the viva

Each model answer explains the reasoning. Do not memorise it. Use your own words and evidence.

**Q1 (why): Why does the CRI use a weighted total rather than a plain average?**

:::answer Model answer
A plain average treats every component as equally important. A weighted total lets the workbook favour the components that best show internship readiness. The weights are a judgement, so they must be written down, so anyone can rebuild the number from the same inputs.
:::

**Q2 (trade-off): Why is the CRI checked by a second trainer?**

:::answer Model answer
A second check catches formula errors and mistyped scores before the number is issued. The trade-off is time, because the result waits until 15:00. For a record that partners use to make hiring decisions, that delay is worth it, since an error is harder to fix after the letter is out.
:::

**Q3 (what you did): Which part of this ticket did you prepare, and how can someone check it?**

:::answer Model answer
Name one subtask, the commits on your branch that show the preparation, and the check you ran on your own record. The commits show the work and the outputs show the checks.
:::

**Q4 (why): Why does TC3 use `grep -F` with the roll?**

:::answer Model answer
The roll is treated as plain text, so a full stop or other character cannot change what is matched. The output shows the line number, so the trainer can see the exact match. The trade-off is that grep matches substrings, so a longer roll can match too, and the output must be read with care.
:::

**Q5 (understanding): What does the freeze SHA prove?**

:::answer Model answer
The SHA names one exact commit. If it matches the current commit of the same repository that the freeze row names, the portfolio has not changed since it was frozen. A match in a different repository proves nothing. If it does not match, raise it with the trainer and record a dated exception, rather than editing the freeze to match.
:::

### Check yourself

```quiz
Q: In the command grep -n -F "DEMO01" freeze_audit.csv, what does -F do?
- It deletes every line that contains the roll.
* It treats the roll as plain text, not as a pattern.
- It forces grep to follow links to other files.
- It prints only the first line of the file.
WHY: -F makes grep match the text literally. Without it, characters such as a full stop could change the meaning of the search. It does not delete lines or follow links, and it does not limit output to one line.

Q: TC1 expects four non-empty scores per student. A row has one blank score. What is the result?
- The test passes, because the other three scores are present.
- The row is ignored, and the trainer fills in the blank automatically.
* The test fails for that student, so the missing score must be fixed or recorded.
- The test passes, because blank scores count as zero.
WHY: The expected result is four non-empty scores. A blank field is not a score, so the row fails. Counting a blank as zero would hide the missing entry.

Q: Why does the trainer recompute the final CRI from its components?
- So the CRI can be made larger for strong students.
- So the letter can be printed without a signature.
- So the freeze SHA can be changed to match the commit.
* So a second person can confirm that every total matches its components and the workbook.
WHY: The recomputation checks the record. It does not change scores, sign letters or edit the freeze. Its purpose is to show that the final number can be rebuilt from its parts.
```
