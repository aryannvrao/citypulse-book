### The ticket in plain words

The ward health team at the client wants a forecast of next-hour PM2.5. PM2.5 is very fine dust in the air, and wards use it to decide when to close windows or warn patients with breathing problems. Your squad has already shown in the EDA notebook (exploratory data analysis, the notebook where you look at data before modelling) that a model is possible.

The story in the description is the gap between "it worked on my laptop" and "we can trust it". A notebook that runs on one machine, with steps nobody wrote down, cannot be audited or improved. Nobody can tell whether a better score came from a better model or from a different copy of the data.

This ticket builds a locked baseline. A baseline is the simplest honest model, and every later model is judged against it. Anyone who clones the repository, creates a fresh environment and runs one command must get the same error score. You also score naive persistence, which predicts that the next hour equals the current hour. If your model cannot beat that, you must say so in the log.

Finally, the preprocessing moves into one scikit-learn Pipeline. The API will receive raw rows later, so it must apply exactly the steps that training used.

### How your trainer checks it

The trainer checks six acceptance criteria and runs four test cases (TC1 to TC4).

- **Clean clone.** The printed MAE must be within ±1% of `mae` in the committed `metrics.json`, from a fresh clone with no edits. This is TC1.
- **No absolute paths.** `C:/`, `/Users/` and `/home/` appear nowhere in the code, and all parameters come from `config.yaml`.
- **Time split.** Test rows have `ts` on or after `split.test_start`, and training rows come before it.
- **metrics.json.** The file holds the required keys, and `mae` is below `naive_mae` or the gap is explained in the log. This is TC2.
- **Feature tests.** `pytest -q` passes at least one feature test, and every student has a test commit. This is TC3.
- **Feature branch.** On `feat/pipeline`, `build_pipeline(cfg)` returns one Pipeline, and a draft pull request exists.

#### TC1: the clean-clone run

The trainer runs this in an empty folder:

```bash
git clone https://github.com/citypulse-y2/citypulse-<squad> && cd citypulse-<squad> && git checkout v0.6-p6
python -m venv .v && . .v/bin/activate && pip install -r requirements.txt
python train.py --config config.yaml; echo $?
```

`git clone` copies the repository and `git checkout` switches to the tagged commit. `python -m venv .v` creates a private package folder, and `. .v/bin/activate` switches to it (on Git Bash, use `. .v/Scripts/activate`). `pip install -r requirements.txt` installs the listed packages. `echo $?` prints the exit code, where 0 means success.

Passing: exit code 0, a model file appears under `output_dir`, and the printed MAE is within 1% of `metrics.json`. Failing: `ModuleNotFoundError: No module named 'sklearn'` means the venv is not active or a package is missing. `FileNotFoundError` on the parquet path means the data is not committed or the path is wrong. `KeyError` means a key in code does not match `config.yaml`. An MAE outside 1% means the snapshot, the package versions or the seed differ.

#### TC2: the metrics.json keys

```bash
python -c "import json;m=json.load(open('metrics.json'));print(m['mae'],m['naive_mae'],m['seed'],m['git_sha'])"
```

`python -c` runs one line of code, `json.load` reads the file into a dictionary `m`, and each `m['name']` looks up one key. Passing prints four values with no `KeyError`, and the `seed` matches `config.yaml`. Use Git Bash, because PowerShell handles the nested quotes differently.

#### TC3: the feature tests

```term
$ pytest -q tests/test_features.py
..                                                                 [100%]
2 passed in 0.12s
```

`pytest` runs functions named `test_*`, `-q` keeps the output quiet, and each dot is one passing test. A failure prints `F` and an `AssertionError`. `No module named 'src'` is fixed in Y2-T33.5.

#### TC4: the seed is deterministic

The trainer sets a new seed in `config.yaml` and runs training twice. Both MAE values must match.

```bash
grep -n seed config.yaml
python train.py --config config.yaml && cp metrics.json run1.json
python train.py --config config.yaml && cp metrics.json run2.json
diff run1.json run2.json && echo same
```

`grep -n seed` prints the seed line with its number. `cp` saves each run's result so the second run cannot overwrite the first. `diff` compares the two files and prints nothing when they match, so `&& echo same` prints `same` only on success. If `diff` prints lines, the usual causes are unseeded randomness, rows in a different order, or a timestamp written into `metrics.json`. Afterwards, `git checkout -- config.yaml` restores the file if you have no other changes to it.

#### Y2-T33.2 Feature functions in src/features.py

**Goal.** Write two pure functions: they take a table, return a new one, and read no files and print nothing.

**Technique: groupby and shift.** Shifting inside each group stops values crossing from one group into another. Here is a fictional example with two shops:

```python
import pandas as pd

shops = pd.DataFrame({"shop": ["Bakery", "Bakery", "Florist", "Florist"], "sales": [10, 14, 3, 5]})
shops["next_sales"] = shops.groupby("shop")["sales"].shift(-1)
print(shops)
```

`groupby("shop")` makes one group per shop. `shift(-1)` moves each value up one row inside its group, so the last row of each group gets `NaN`, a marker for a missing value. Expect `next_sales` to be 14, NaN, 5 and NaN. Without `groupby`, the first Bakery row would receive a Florist value. The trace shows the same idea step by step.

```trace
TITLE: Taking the next value only inside the same shop
CODE:
shop = ["Bakery", "Bakery", "Florist", "Florist"]
sales = [10, 14, 3, 5]
next_sales = [None, None, None, None]
for i in range(len(sales)):
    if i + 1 < len(sales) and shop[i + 1] == shop[i]:
        next_sales[i] = sales[i + 1]
STEPS:
3 :: next_sales=[None, None, None, None] :: Start with one empty answer per row.
4 :: i=0 :: The loop visits row 0 first.
5 :: i=0 :: Row 1 is also a Bakery, so the check passes.
6 :: i=0; next_sales=[14, None, None, None] :: The next sales figure, 14, is stored for row 0.
4 :: i=1 :: Row 2 is a different shop.
5 :: i=1 :: Florist is not Bakery, so nothing is stored.
4 :: i=2 :: Row 2 is a Florist and looks at row 3.
5 :: i=2 :: Row 3 is also a Florist, so the check passes.
6 :: i=2; next_sales=[14, None, 5, None] :: The next sales figure, 5, is stored for row 2.
```

**Stage 1: sort first.** The shift takes the next row, not the next hour, so sort by station and time first. Inside `add_target`, return a sorted copy with `df.sort_values(["station", "ts"])`.

**Stage 2: write add_target.** Create `src/features.py` with `add_target(df)`. Copy the table with `df.copy()`, sort it, then add a `target` column the way the shop example does, using `pm25` and `station`. Decide whether rows with no target are kept, and record that choice in the log. The test in Y2-T33.5 assumes `add_target` keeps them, so adjust its second assert if you drop them.

**Stage 3: write add_time_parts.** Stored timestamps are usually UTC, so convert before reading the hour:

```python
import pandas as pd

ts = pd.Series(pd.to_datetime(["2026-11-17 18:30"], utc=True))
local = ts.dt.tz_convert("Asia/Kolkata")
print(local.dt.hour[0], local.dt.weekday[0])
```

`utc=True` reads the strings as UTC. `tz_convert` changes the zone, so the clock changes too. `dt.weekday` gives Monday as 0. 18:30 UTC is 00:00 the next day in India, and that day, 18 November 2026, is a Wednesday (Monday is 0, so Wednesday is 2), so the output is `0 2`. Write `add_time_parts(df)` to add `hour` and `weekday` the same way.

#### Y2-T33.3 config.yaml and train.py

**Goal.** Put every setting in `config.yaml`, then write `train.py` to read it and run the stages in order.

**Technique: YAML and safe loading.** A YAML file uses `key: value` lines, with indentation for groups and `- ` for list items. You fill in the values, such as your column names:

```yaml
seed: 0
data:
  path:
target:
split:
  test_start:
features:
  numeric:
  categorical:
model:
  name:
  params:
output_dir:
```

Read it in Python with `yaml.safe_load`, which is the safe choice for a file you did not write. Install the library with `pip install pyyaml` and add it to `requirements.txt`:

```python
import yaml

with open("config.yaml", encoding="utf-8") as f:
    cfg = yaml.safe_load(f)
print(cfg["seed"])
```

`with open` closes the file when the block ends. `safe_load` returns a dictionary, and `cfg["seed"]` looks up one value.

**Technique: a time split.** Earlier rows go to training and later rows to testing, with no shuffling:

```python
import pandas as pd

hours = pd.DataFrame({"ts": pd.to_datetime(["2026-01-01 09:00", "2026-01-01 10:00", "2026-01-01 11:00"])})
cut = pd.Timestamp("2026-01-01 10:00")
train = hours[hours["ts"] < cut]
test = hours[hours["ts"] >= cut]
print(len(train), len(test))
```

`hours["ts"] < cut` gives a true or false answer per row, and square brackets keep the true rows. The output is `1 2`. Your real `time_split` must convert `split.test_start` to the same timezone as `ts`, because comparing a timezone-aware column with a timezone-naive value raises an error, and a cut placed in the wrong zone selects the wrong rows. Also write `test_start` in quotes in `config.yaml` (for example `"2026-01-01 10:00"`). Without quotes, YAML turns a date into a Python date or datetime object instead of text, and `pd.Timestamp(...)` is the safer way to read it either way.

**Stage 1: argument and config functions.** Use `argparse` with `parser.add_argument("--config", required=True)` to read the option, then return the loaded config from a function called `load_config`.

#### Y2-T33.8 build_pipeline on feat/pipeline

**Goal.** Build one Pipeline holding the preprocessing and the model, and open a draft pull request. The chapter [Day 21 — scikit-learn pipelines, features and tuning](D21.html) explains the pieces in depth.

**Stage 1: branch.** `git checkout main`, `git pull`, then `git checkout -b feat/pipeline`.

**Technique: ColumnTransformer on a toy table.** Here is a fictional example:

```python
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.pipeline import make_pipeline

toy = pd.DataFrame({"temp": [20.0, None, 24.0], "district": ["North", "South", "North"]})
pre = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), ["temp"]),
    ("cat", OneHotEncoder(handle_unknown="ignore"), ["district"]),
])
print(pre.fit_transform(toy).shape)
```

`temp` gets a median fill and scaling. `district` gets one-hot encoding. `handle_unknown="ignore"` turns an unseen district into zeros instead of an error. The output is `(3, 3)`: one numeric column and two district columns.

Put three steps in order: a `FunctionTransformer` from `sklearn.preprocessing` that wraps `add_time_parts`, so raw rows with `ts` work, then your ColumnTransformer, then the model built from `cfg["model"]`. Name the steps `time`, `pre` and `model`. Return one `Pipeline`.

### What goes wrong

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'src'` in pytest | Pytest does not add the repository root to its path. | Add an empty `conftest.py` in the root. |
| `Missing optional dependency 'pyarrow'` | Parquet needs `pyarrow`, which is missing from `requirements.txt`. | Add it and reinstall. |
| `FileNotFoundError` for the parquet file on the clean clone | The data was not committed, or the path is relative to another folder. | Commit the snapshot or its rebuild script, and run from the root. |
| `Object of type int64 is not JSON serializable` | A numpy number went into `metrics.json`. | Wrap it in `int(...)` or `float(...)`. |
| TC4 gives different MAE values | Unseeded randomness, rows in a different order, or a timestamp in `metrics.json`. | Pass the seed everywhere, sort rows, drop timestamps. |
| Clean-clone MAE is more than 1% away | Different snapshot, unpinned packages, or a `metrics.json` from another run. | Compare SHA-256 values, pin versions, rerun on the tag. |
| Leakage test shows a target from another station | The shift was not inside `groupby`, or rows were not sorted. | Use `groupby("station")["pm25"].shift(-1)` after sorting. |

### Defend it in the viva

Answer each question in your own words first, then compare with the model answer.

1. Why does the baseline use a time split and not a random shuffle?

:::answer Model answer
PM2.5 is a time series, so each hour depends on earlier hours. A random shuffle puts future rows into training, so the model learns from information it would not have when forecasting. A time split matches real use, so the score is honest.
:::

2. What is the trade-off between committing the snapshot and using a fetch script?

:::answer Model answer
Committing the file makes a clean clone work offline with identical data, but the repository grows. A fetch script keeps the repository small, but it depends on the source staying available and unchanged. A good answer names both costs, the squad's choice and the fingerprint that proves the copy.
:::

3. Walk me through the leakage test you wrote. What does it prove?

:::answer Model answer
A strong answer names the test and its toy data. It says the first row must get the next value in the same group, and the last row of a group must have no target. Removing the grouping would give the other group's value, so the test would fail.
:::

4. Why is naive persistence a fair baseline, and what does an MAE of a given size mean?

:::answer Model answer
Naive persistence uses only the current value, so any model must beat it to be worth using. MAE is the average error in PM2.5 units. A lower MAE on the same rows means the model adds something. If it does not, the ticket requires the gap to be explained.
:::

5. Why do you record the seed, git_sha and config_hash in metrics.json?

:::answer Model answer
The seed says which random choices were made, git_sha says which code produced the result, and config_hash says which settings were used. Together they let anyone rerun the experiment and get the same MAE, which is what makes the baseline trustworthy.
:::

Q: You want the next hour's PM2.5 for each station, and the shift must stay inside its own station. Which expression does this?
- df["pm25"].shift(-1)
- df.shift(-1)["pm25"]

WHY: groupby splits the rows by station before shift runs, so no value crosses into another station. A plain shift moves values across station boundaries, which is leakage.
