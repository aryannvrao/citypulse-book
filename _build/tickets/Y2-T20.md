### The ticket in plain words

CityPulse is the city-data platform your squad is building. Its sensor feed sometimes sends the same reading twice, and ops wants every duplicate flagged across 10 million rows.

The obvious way to find a duplicate is to compare each row with every row before it. For 10 million rows that is about 50 trillion comparisons, which will not finish in any sensible time. A **set** fixes this. A set remembers what it has already seen and answers "have I seen this?" almost at once. One pass over the file is then enough, and the work grows in step with the number of rows.

This ticket is a practice interview. You work alone. You solve six small problems, state the speed and memory cost of each, run a script on real sensor data, and may explain one solution on a whiteboard. The point is to show that you choose the right data structure under pressure, and can say why.

The sheet gives each problem a **signature**. Copy the name, parameters and order exactly. The trainer's hidden runner calls the function by that signature, so `def count_pairs(nums, target)` and `def count_pairs(target, nums)` are different functions as far as the runner is concerned.

Two techniques cover most of these problems. Learn them on small examples first.

**Technique 1: a set remembers what you have seen.** The example below is a teaching twin, not one of your six. It returns the first word that appears twice.

```python test
def first_repeat(words):
    seen = set()
    for word in words:
        if word in seen:
            return word
        seen.add(word)
    return None

assert first_repeat(["a", "b", "a", "c"]) == "a"
assert first_repeat(["a", "b", "c"]) is None
assert first_repeat([]) is None
assert first_repeat(["x", "x"]) == "x"
```

Line by line:

- `seen = set()` creates an empty set. This is the memory of the loop.
- `for word in words:` visits each word once, in order.
- `if word in seen:` checks membership. On a set this is O(1) on average. On a list it would scan every item.
- `return word` stops at the first repeat, so the function does not read the rest of the list.
- `seen.add(word)` remembers the word for later checks.
- `return None` runs only when no repeat exists.

The four `assert` lines test a normal case, a case with no repeat, an empty list and two equal words in a row. If all four pass, Python prints nothing. A failed assert stops with `AssertionError`.

**Technique 2: a Counter counts how often each item appears.** `Counter(items)` adds one to a count for each item in one pass, and `most_common(k)` ranks the top k. Use it when a problem asks "how many of each?".

**Stage 2. Count duplicates with a set.** Replace the last two lines with a function that tracks keys. Add this below the `import` lines:

```python
def count_dups(path, key_cols):
    seen = set()
    dups = 0
    with open(path, newline="") as f:
        for row in csv.DictReader(f):
            key = tuple(row[c] for c in key_cols)
            if key in seen:
                dups += 1
            else:
                seen.add(key)
    return dups
```

`key_cols` is a list of column names. `tuple(...)` builds the key from them, because a list is not hashable and cannot go in a set. The `if` checks the set, and the `else` adds new keys. The function returns the count of repeats. Its cost is O(n) time and O(d) space, where d is the number of distinct keys.

**Q1. Why does a set make the duplicate check O(n), where a list makes it O(n²)?**

:::answer Model answer
A set uses a hash to jump straight to the slot for a key, so each membership check takes O(1) on average. Over n rows the total is O(n). A list membership test scans every earlier item, so the total is about n times n divided by two, which is O(n²). The change from list to set is one line of code, but it changes the whole cost. Say "on average", because a bad set of hash collisions can be slower.
:::

**Q2. What is the memory cost of your set, and when would you not use it?**

:::answer Model answer
The set stores one entry for each distinct key, so the extra memory is O(n) in the worst case. With 10 million distinct tuples that can be gigabytes, so memory is a real limit. I would not use a set when memory is tight. Sorting the rows costs O(n log n) time, and sorting in place needs little extra space, although the rows must still be loaded first. A sliding window that keeps only recent keys is another choice when duplicates are close together in time. The right answer depends on which resource the system cannot spare.
:::

**Q5. Why do the pure-Python and pandas timings differ, and which would you use in production?**

:::answer Model answer
Pandas loads the whole file into a table and runs its duplicate check in optimised code, so it is often faster but needs more memory. Pure Python streams the file row by row, using little memory but running slower. Timings also depend on what each includes, such as the file read. I would choose by the limit that matters, and say so in the README.
:::

Q: Your key is station_id, timestamp and pollutant. Why must the key be a tuple before it goes in the set?
- Tuples are faster to print than lists
- Tuples are sorted automatically by Python

WHY: A set can store only hashable items. A tuple of strings is hashable, while a list of the same strings is not. The printing speed, the sorting and the memory of tuples have nothing to do with this rule.
