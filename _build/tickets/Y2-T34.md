### The ticket in plain words

CityPulse is a Bengaluru city-data platform. One job it does is forecast PM2.5 for the next hour. PM2.5 is fine dust in the air, measured in micrograms per cubic metre. The Project 6 baseline model sees only current readings and simple time parts, such as the hour.

Bengaluru air depends on what happened in the last few hours, on rush-hour traffic and on events such as Diwali. So you will add five new features. A feature is an input column the model reads. Examples are the reading from one hour ago, or a festival flag that is 1 on a festival day and 0 otherwise.

The analyst wants evidence, not guesses. For each feature you remove it, retrain on the same data and measure how much the error grows. That check is an ablation. A feature that does not move the error beyond random noise has not earned its place.

The second rule is about where the work happens. The API receives raw rows straight from the data file. If features are built in a notebook and rebuilt by hand in the API, the two copies drift apart and predictions degrade with no error message. This is called training/serving skew. So every feature must live inside one Pipeline, a chain of named steps that is fitted once and then runs the same way on new rows.

#### Y2-T34.2 Make every station a full hourly grid

**Goal.** Each station has one row per hour, sorted by station and then time. Only then does `shift(n)` mean "n hours earlier".

**Stage 1: measure the gaps.** `shift` counts rows, not hours, so a missing hour silently shifts the wrong value into a lag.

```python
import pandas as pd
df = pd.read_parquet("PATH_FROM_CONFIG")
df = df.sort_values(["station", "ts"])
steps = df.groupby("station")["ts"].diff().dropna()
print((steps != pd.Timedelta("1h")).sum(), "steps that are not one hour")
```

`sort_values` puts each station in time order, and `diff` gives the time since the previous row of the same station. Expected output for clean data: `0 steps that are not one hour`.

**Stage 2: make the Pipeline refuse bad input.** Your acceptance criteria forbid pandas preprocessing outside the Pipeline, so do not fill gaps in `train.py`. Add this check to `src/features.py`, and call it from `TimeFeatures.fit` in the next subtask:

```python
def check_hourly(X):
    steps = X.groupby("station")["ts"].diff().dropna()
    bad = (steps != pd.Timedelta("1h")).sum()
    if bad:
        raise ValueError(f"{bad} steps are not one hour: sort or fill the grid first")
```

It raises an error for gaps and for unsorted rows, because unsorted rows give negative steps.

**Stage 3: real gaps.** Agree with your trainer how gaps are filled, because filling changes the raw rows.

**Test.** Take a three-row table for one station, drop the middle row, and call `check_hourly`. It must raise `ValueError`.

#### Y2-T34.3 Add TimeFeatures inside the Pipeline

**Goal.** A class `TimeFeatures` that adds your columns and is the first step of the Pipeline, named `time_features`.

**Stage 1: an empty step.** The base classes from scikit-learn make your class act as a step.

```python
from sklearn.base import BaseEstimator, TransformerMixin

class TimeFeatures(BaseEstimator, TransformerMixin):
    def fit(self, X, y=None):
        return self

    def transform(self, X):
        X = X.copy()
        return X
```

`fit` learns nothing, so it returns `self`. `transform` copies the table so the caller's table is never changed. Test it on a one-row table, and check the output is unchanged.

**Stage 2: lags inside each station.**

```python
g = X.groupby("station")["pm25"]
X["pm25_lag1"] = g.shift(1)
X["pm25_lag24"] = g.shift(24)
```

`groupby` makes one group per station, and `shift` moves values down inside each group. Without `groupby`, the first row of one station would receive the last value of the station above, which your test in T34.5 catches.

**Stage 3: a rolling mean that does not see the answer.** The P6 pattern `s.rolling(3).mean()` includes the current row, which holds the answer. Shift first:

```python
X["pm25_roll3_mean"] = g.transform(lambda s: s.shift(1).rolling(3).mean())
```

Inside the function, `shift(1)` moves the series down one row, so the window holds only earlier hours.

:::trap Rolling over the current row
Without `shift(1)`, the window includes the current hour. The model then learns from the answer, and the ablation shows a gain that will not hold on new data.
:::

**Stage 4: hour features in Indian time.**

```python
import numpy as np
hour = pd.to_datetime(X["ts"]).dt.tz_convert("Asia/Kolkata").dt.hour
X["hour_sin"] = np.sin(2 * np.pi * hour / 24)
X["hour_cos"] = np.cos(2 * np.pi * hour / 24)
```

`tz_convert` changes the time zone first, then `.dt.hour` reads the hour. The sine and cosine place each hour on a circle.
**Stage 5: insert the step.** Put the step first in the Pipeline list, before the ColumnTransformer:

```python
Pipeline([("time_features", TimeFeatures()), ("pre", pre), ("model", model)])
```

Add your new names to the feature lists in `config.yaml`, matching the keys that `src/pipeline.py` reads. Check that the OneHotEncoder has `handle_unknown="ignore"`.

Lags and the rolling mean are NaN for the first rows of each station. Some models (for example `LinearRegression`) raise an error on NaN, while others (for example `HistGradientBoostingRegressor`) accept it. If your model rejects NaN, add a `SimpleImputer` to the numeric branch inside the ColumnTransformer, not as pandas code outside the Pipeline.

```flow
TITLE: What happens to one raw row inside the Pipeline
NODES: Raw row | TimeFeatures | ColumnTransformer | Model
STEPS:
1>2 :: raw row in :: The row comes straight from the data file, unchanged.
2>3 :: columns added :: Lags, rolling mean and hour features are computed inside each station.
3>4 :: scaled and encoded :: Numbers are scaled and station names are one-hot encoded.
4>4 :: prediction :: The model answers with the same steps it learned during fit.
```

#### Y2-T34.6 Write ablation.py

**Goal.** A script that trains the full model, trains five variants that each drop one feature, measures the noise floor and writes the table. Every run uses the same split and seed.

**Stage 1: split as train.py does.** Copy the split from `train.py` so the two scripts agree:

```python
test_start = pd.Timestamp(cfg["split"]["test_start"], tz="Asia/Kolkata")
train = df[df["ts"] < test_start]
test = df[df["ts"] >= test_start]
```

Decide with your trainer how the test rows get lag history from before `test_start`.

**Stage 2: one function for one run.**

```python
from sklearn.metrics import mean_absolute_error

def fit_score(cfg, seed):
    pipe = build_pipeline(cfg)           # apply `seed` the way train.py does (for example the model's random_state); otherwise the argument is unused
    pipe.fit(train, train[cfg["target"]])
    return mean_absolute_error(test[cfg["target"]], pipe.predict(test))
```

**Stage 3: drop one feature.**

```python
import copy

def without(cfg, feature):
    out = copy.deepcopy(cfg)
    out["features"]["numeric"].remove(feature)   # use the list that holds the feature
    return out
```

If your squad counts `hour_sin` and `hour_cos` as one feature, that leave-one-out row must remove both columns together. `deepcopy` keeps the config in memory separate from the original, and the file on disk is never changed. The TimeFeatures step still computes the dropped column, but the ColumnTransformer ignores it, which is what the ablation measures.

**Stage 4: deltas and noise floor.** Define the delta as MAE without the feature minus full MAE. A positive delta means the error grew when the feature was removed, so the feature helps.

```python
import numpy as np

full = fit_score(cfg, seed=SEED)
rows = []
for f in FIVE_FEATURES:
    mae_without = fit_score(without(cfg, f), seed=SEED)
    rows.append((f, mae_without, mae_without - full))
floor = np.std([fit_score(cfg, seed=s) for s in [1, 2, 3, 4, 5]], ddof=1)
```

`ddof=1` gives the sample standard deviation over five seeds. Write which one you used. A delta with an absolute value below `floor` is marked "no evidence".

**Stage 5: write without stacking.** Format each number with `f"{x:.3f}"`. Put the table between two marker lines and replace that block on each run, so reruns do not add a second table. Keep the table and the noise-floor line within the last twelve lines of the file.

### Defend it in the viva

**1. Why must the lag features live inside the Pipeline rather than in pandas before the split?**

:::answer Model answer
If lags are built in a notebook, the API must rebuild them by hand, and the copies can drift apart silently. Inside the Pipeline there is one set of steps, and the step checks the row order it depends on, so mistakes fail loudly.
:::

**2. What is the trade-off of estimating the noise floor from five seeds?**

:::answer Model answer
Five seeds give a rough spread, and the estimate itself moves when the seeds change. Too few seeds can make the floor too small, so a weak feature looks like a win, or too large, so a real feature looks like no evidence. More seeds cost more training time. State the seed count and the std type in the table, so a reviewer can judge the verdicts.
:::

**3. What did you personally do in this ticket, and how would the trainer see it in Git?**

:::answer Model answer
Name the feature you owned, the commit that added it, the test that covers it, and the row in the ablation table that shows its delta. Then explain one decision you made and why. Write your own version with your own commit and numbers.
:::

**4. Why convert to Asia/Kolkata before taking the hour?**

:::answer Model answer
02:30 UTC is 08:00 in India. Reading the UTC hour shifts the daily cycle by five and a half hours.
:::

**5. Why does the rolling mean need `shift(1)` first?**

:::answer Model answer
The feature may use only values known before the hour being predicted. Without the shift, the window contains the current PM2.5, which is the target, so the ablation shows a gain that disappears on new data.
:::

### Check yourself

```quiz
Q: A feature uses rolling(3).mean() on pm25 with no shift. What is wrong?
- Nothing, the window always covers the three hours before the current one.
- The first row of each station is NaN, so the feature cannot be used.
* The window includes the current hour's pm25, which is the target, so the feature leaks the answer.
- pandas refuses to compute a rolling mean on floating-point numbers.
WHY: rolling(3) includes the current row, so shift by one first. The NaN rows are normal, which makes that option the tempting wrong answer.

Q: A 10:00 row is missing for one station and the grid was not filled. What does shift(1) on the 11:00 row hold?
- The 10:00 value, which pandas has lost, so it raises an error.
* The 09:00 value, two hours earlier, so the lag is wrong.
- NaN, because shift always fails on a gap.
- The 11:00 value, because shift skips missing hours.
WHY: shift counts rows, not hours. With 10:00 missing, the row above 11:00 is 09:00. Filling the grid makes one row equal one hour again.

Q: A reading is stamped 02:30 UTC. Which hour should the time feature use?
* 08:00, because you convert to Asia/Kolkata first, which is five and a half hours ahead.
- 02:00, because the stored hour is used as it is.
- 02:30, because minutes are kept in the feature.
- 20:30 of the previous day, because India is behind UTC.
WHY: 02:30 UTC plus five and a half hours is 08:00 in India. The stored hour gives 2, which is the trap.
```
