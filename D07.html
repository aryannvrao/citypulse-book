The idea in one minute

Today you learn to take a raw sensor file, check it, and turn it into a few numbers you can trust, using only tools that come with Python. Think of a clerk who receives a pile of handwritten forms from air-quality sensors. Before adding anything up, the clerk checks which column is which, writes each value in the right box, and counts only the forms that answer the question being asked. A Python script does the same job. It reads each line of a CSV file (a plain text table), turns the text into numbers, filters the rows, and prints a summary.

By the end of the day you will be able to write small functions that take values in and return values out, read a CSV without crashing on bad rows, group and summarise readings, print a neat report, and prove the result with a test.

Starting from zero

You do not need any prior programming. Each term below appears in this chapter, so read them once.

Terminal. A text window where you type instructions to the computer and read its replies. On Windows you can use PowerShell or Git Bash. On macOS and Linux it is called Terminal.

Command. One line you type in the terminal, followed by Enter. The computer runs it. For example, python --version asks Python to print its version number.

File and folder. A file holds data or instructions, such as readings.csv. A folder (sometimes called a directory) holds files. The terminal always works inside one folder, which is called the current folder or working directory.

Changing folder. cd means "change directory". cd Desktop\citypulse moves the terminal into a folder called citypulse on the Desktop. Use dir on Windows or ls on Git Bash, macOS and Linux to list the files in the current folder.

Script. A text file of Python instructions, saved with the ending .py. You run it with python summarise.py. The word "script" just means a program that is short enough to live in one file.

Python and the interpreter. Python is a programming language. The program that reads your .py file and carries out its instructions is called the interpreter. The slides ask for Python 3.11 or later. Check your version with python --version.

Variable. A name that holds a value, so you can use the value later. In total = 5, the name total now holds the number 5.

Type. The kind of value something is. int is a whole number such as 7. float is a number with a decimal point such as 36.6. str is text such as "S1". bool is True or False. None means "no value".

List. An ordered collection written in square brackets, such as [36.6, 52.1]. Items are numbered from 0, so the first item is values[0].

Dictionary (dict). A collection of key-value pairs written in curly braces, such as {"S1": 36.6}. The key "S1" finds the value 36.6.

Function. A named block of code. You define it with def, give it inputs called parameters, and send back a result with return. Calling average([1, 2, 3]) runs the block and gives you 2.0.

Standard library. The collection of modules that ships with Python. A module is a single .py file that gives you ready-made code, and you load it with import. For example, import csv loads the module that reads CSV files.

CSV. Comma-Separated Values. A plain text table in which each line is a row and commas separate the columns. The first line is usually a header that gives the column names. The file readings.csv in this chapter looks like this:

station_id,ts,pollutant,value
S1,2026-03-01T00:00:00,pm25,36.6
S1,2026-03-01T00:00:00,no2,22.9

API. Application Programming Interface. A defined way for one program to ask another for data. The slides use one of these to fetch weather and air-quality data.

Server. A computer, or a program on a computer, that answers requests from other programs over a network. The API in the slides is provided by a server run by someone else.

Error (exception). A problem that stops the normal flow of a program, such as a missing file. Python reports it with a name such as FileNotFoundError. You can catch an error and decide what to do with it.

The tools

The csv module and DictReader

What it is. csv is a standard library module that reads and writes CSV files. You could split each line on commas yourself with line.split(","), but that breaks when a quoted field contains a comma. The csv module handles quotes correctly, so you should use it.

Why CityPulse uses it. The sensor dumps are CSV files, and the module needs no extra installation. The course's later lesson moves to pandas, but pandas is not needed to read a file this small.

How it works. csv.DictReader reads the header line once, then gives you one dictionary per data row. The keys are the header names, and the values are the text from that row. Every value is a string, even "36.6".

The slide code, explained. The Technology in Action workbook uses this function:

import csv

def load(path):
    rows = list(csv.DictReader(open(path)))
    for r in rows:
        r["value"] = float(r["value"])
    return rows

if __name__ == "__main__":
    rows = load("readings.csv")
    print(f"loaded {len(rows)} rows")
    print("first:", rows[0])
    print("value is", type(rows[0]["value"]).__name__)

Line by line:

  • import csv loads the CSV module so you can write csv. before its functions.
  • def load(path): defines a function called load that takes one parameter, path, the file name as text.
  • rows = list(csv.DictReader(open(path))) opens the file, reads every row as a dictionary, and stores all of them in a list called rows. list(...) forces the reading to happen now.
  • for r in rows: takes each dictionary in turn and calls it r.
  • r["value"] = float(r["value"]) replaces the text in the value key with a float. float("36.6") returns the number 36.6.
  • return rows gives the list back to whoever called the function.
  • if __name__ == "__main__": is true only when you run this file directly, not when another file imports it. The lines below it run only in that case.
  • The three print lines show the row count, the first row, and the type of its value.

Expected output when readings.csv has 1,440 data rows:

loaded 1440 rows
first: {'station_id': 'S1', 'ts': '2026-03-01T00:00:00', 'pollutant': 'pm25', 'value': 36.6}
value is float

Trap: Comparing text with numbers

A value read from CSV is text, so row["value"] > 50 either fails or compares the wrong things. Python 3 raises TypeError when you compare text with a number. Always convert with float() once, at the point where you read the file.

Trap: Forgetting newline="" on the file

The Python documentation asks you to open CSV files with newline="". Without it, a quoted field that contains a line break can be read wrongly on Windows. The lab uses open(path, newline="", encoding="utf-8") for this reason.

Comprehensions and f-strings

What they are. A list comprehension builds a new list from an old one in a single line. An f-string is a piece of text that starts with f" and puts variables inside curly braces.

Why CityPulse uses them. A comprehension reads like the question you are asking, such as "the pm25 values". An f-string formats numbers for people to read, such as 38.7 rather than 38.700000000000003.

How it works. [expression for item in list if condition] loops over the list, keeps the items where the condition is true, and applies the expression to each one. An f-string with :.1f formats a number with one digit after the decimal point.

The slide code, explained.

vals = [float(r["value"]) for r in rows if r["pollutant"] == "pm25"]
print(f"pm25 avg: {mean(vals):.1f}")

Line by line:

  • vals = stores the result in a variable called vals.
  • [float(r["value"]) ...] is the expression. It is applied to every row that passes the filter.
  • for r in rows loops over the rows, and if r["pollutant"] == "pm25" keeps only the rows whose pollutant is pm25. The double equals sign checks equality. A single equals sign would store a value, and Python would reject it in this position.
  • In the print line, mean(vals) calls the mean function you import from statistics.
  • :.1f inside the braces means "format as a float with one decimal place". The value 38.66 prints as 38.7.
Tip: Use the question as the guide

When you write a comprehension, read it aloud as a sentence. "Each float value, for each row, where the pollutant is pm25." If the sentence does not match the question you were asked, the code is wrong.

Trap: Rounding is only for display

:.1f changes how the number looks, not the number you keep. Calculate with the full value and round only in the printed text.

statistics and collections

What they are. statistics is a standard library module with functions such as mean, median and stdev. collections is a module with extra container types, such as defaultdict, which is a dictionary that creates a missing entry for you.

Why CityPulse uses them. A city-wide average hides hotspots, so the course groups readings by station. defaultdict(list) lets you append to a group without first checking whether the group exists.

The slide code, explained.

from collections import defaultdict
from statistics import mean

groups = defaultdict(list)
for r in rows:
    if r["pollutant"] == "pm25":
        groups[r["station_id"]].append(r["value"])
avgs = {s: mean(v) for s, v in groups.items()}

Line by line:

  • The two from ... import lines load one named item from each module, so you can write mean(...) rather than statistics.mean(...).
  • groups = defaultdict(list) creates a dictionary where any new key starts with an empty list.
  • The loop keeps pm25 rows only.
  • groups[r["station_id"]].append(r["value"]) finds the list for that station, creating it if needed, and adds the value to it.
  • avgs = {s: mean(v) for s, v in groups.items()} is a dictionary comprehension. For each station s and its list of values v, it stores the mean of v.
Trap: mean of an empty list

statistics.mean([]) raises StatisticsError. Check that a list is not empty before you call mean, and decide what the empty case should return.

Modules and packages

What they are. A module is one .py file. A package is a folder of modules that contains a file named __init__.py. A package that has a pyproject.toml file can be installed, so that any script can import it from any folder.

Why CityPulse uses them. The course splits code into config.py, fetch.py and later modules, so several students can work on different files at once. Installing the package means python -m citypulse.fetch works from anywhere.

How it works. python -m name runs a module as a program. pip install -e . installs the folder you are in, in editable mode, so your code edits take effect at once.

The slide commands, explained.

mkdir -p src/citypulse
cat > pyproject.toml <<'EOF'
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"
[project]
name = "citypulse"
version = "0.3.0"
requires-python = ">=3.11"
dependencies = ["requests==2.32.3", "python-dotenv==1.0.1"]
EOF
echo '__version__ = "0.3.0"' > src/citypulse/__init__.py
python -m pip install -e . && python -c 'import citypulse; print(citypulse.__version__)'

Line by line:

  • mkdir -p src/citypulse creates the folder src/citypulse. -p creates the parent folder src too, and does not complain if the folder already exists.
  • cat > pyproject.toml <<'EOF' writes everything up to the next EOF line into a file called pyproject.toml. The quotes around 'EOF' stop the shell changing the text.
  • The lines between are the package description. name and version identify the package, and requires-python says which Python versions it supports. dependencies lists the other packages to install, with exact versions.
  • echo '...' > src/citypulse/__init__.py writes one line into the __init__.py file. echo prints text, and > sends it to a file instead of the screen.
  • python -m pip install -e . runs pip, the package installer, as a module. -e . means "install the package in the current folder in editable mode".
  • && runs the next command only if the previous one succeeded.
  • The final command imports the package and prints its version, 0.3.0.
Trap: Installing outside the virtual environment

If you run pip install -e . without activating your virtual environment (.venv), the package goes into the global Python, and the next project may not find it. Activate the environment first.

Trap: Naming a file after a library

A file called logging.py or statistics.py in your folder hides the real library, because Python looks in the current folder first. Choose project names such as readings_report.py.

logging

What it is. logging is the standard library module for messages that have a level, a time and a destination. The levels are DEBUG, INFO, WARNING and ERROR.

Why CityPulse uses it. print has no levels and no timestamps, and it mixes messages in with your data output. A logged ERROR line tells you why a scheduled run failed. The course also has a gate that requires zero print( calls in src/.

How it works. Each module creates its own logger with logging.getLogger(__name__). The main function sets the format and level once, and every logger uses that setup.

The slide code, explained.

import logging
import requests

log = logging.getLogger(__name__)

class FetchError(Exception):
    """Raised when the source API cannot be read."""

def fetch_json(url: str, timeout: float = 20.0) -> dict:
    """GET url and return the decoded JSON body, or raise FetchError."""
    try:
        resp = requests.get(url, timeout=timeout)
        resp.raise_for_status()
    except requests.RequestException as exc:
        log.error("fetch failed for %s: %s", url, exc)
        raise FetchError(str(exc)) from exc
    return resp.json()

Line by line:

  • import requests loads a third-party library (one you installed with pip) that makes web requests.
  • log = logging.getLogger(__name__) creates a logger named after the module. __name__ is the module's name, such as citypulse.fetch.
  • class FetchError(Exception): defines a new kind of error. The docstring (the text in triple quotes) describes it.
  • def fetch_json(url: str, timeout: float = 20.0) -> dict: defines the function. timeout has a default of 20 seconds. The -> dict part says what the function returns.
  • requests.get(url, timeout=timeout) sends a GET request, which asks the server for data. If the server does not answer within 20 seconds, the request fails.
  • resp.raise_for_status() turns an HTTP error such as 404 or 500 into an exception.
  • except requests.RequestException as exc: catches only request problems. exc holds the error so you can log it.
  • log.error("fetch failed for %s: %s", url, exc) writes an ERROR message. The values are passed as separate arguments, not joined with an f-string.
  • raise FetchError(str(exc)) from exc raises your own error and keeps the original as its cause.
  • return resp.json() converts the response body from JSON text to a Python dictionary.

When the URL is wrong, the log line contains ERROR, the words fetch failed for, and the URL. The exact layout depends on how main() configures the format.

Trap: A bare except hides bugs

except: or except Exception: pass catches everything, including typing mistakes in your own code, and then discards them. Catch the specific error you expect and log it.

Trap: Calling basicConfig in every module

Configure logging once, in main(). If each module configures it, messages can be duplicated or formatted in different ways.

Type hints

What they are. Annotations that say what a function takes and returns, such as name: str and -> Row. Python does not enforce them when the code runs.

Why CityPulse uses them. Five students each write a different function, and the hints make the agreement between them explicit. Editors and the checker mypy use the hints to find mistakes early.

How it works. A TypedDict describes the keys and value types of a dictionary once, so every function that builds or reads a row uses the same names.

The slide code, explained.

from typing import Any, TypedDict

class Row(TypedDict):
    timestamp: str
    location: str
    pm2_5: float | None
    pm10: float | None

def parse(payload: dict[str, Any], location: str) -> Row:
    """Pure: turn the 'current' block of an Open-Meteo response into one row."""
    cur = payload["current"]
    return Row(timestamp=to_utc_iso(cur["time"], payload.get("timezone", "UTC")),
               location=location, pm2_5=cur.get("pm2_5"), pm10=cur.get("pm10"))

Line by line:

  • from typing import Any, TypedDict loads the names used for hints. Any means "any type".
  • class Row(TypedDict): defines the shape of a row. Each line after it names a key and its type.
  • float | None means "a float or None". The | symbol combines types. This form needs Python 3.10 or later.
  • def parse(payload: dict[str, Any], location: str) -> Row: takes the response dictionary and a location name, and promises to return a Row.
  • The docstring says parse is pure. A pure function reads only its inputs, does no file or network work, and gives the same result for the same input.
  • cur = payload["current"] takes the current block of the response. A missing key here raises KeyError.
  • payload.get("timezone", "UTC") reads the timezone, or uses "UTC" if it is missing.
  • Row(...) builds the row from named values, and cur.get("pm2_5") returns None when the key is absent.
Trap: Hints are not checks

Python does not check hints at runtime. parse will happily return a row with wrong data. Check the fields and units yourself, as the check_units function does below.

Trap: Plain dict everywhere

Annotating every value as dict tells the reader nothing about the keys. Use TypedDict for a shape you know.

UTC datetimes and data dictionaries

What they are. UTC (Coordinated Universal Time) is the shared clock that does not change with the seasons or with local time zones. A data dictionary is a document that lists every column, with its type, unit, source and an example.

Why CityPulse uses them. Open-Meteo returns local times, and the bash fetcher used Asia/Kolkata times. Parity between the two fetchers requires the same UTC strings. A data dictionary means that nobody can change the unit of a column without anyone noticing.

How it works. zoneinfo attaches a named time zone to a naive time, which is a time with no zone attached. astimezone converts it to UTC, and strftime formats it as text.

The slide code, explained.

from datetime import datetime, timezone
from zoneinfo import ZoneInfo

def to_utc_iso(local_time: str, tz_name: str = "UTC") -> str:
    """'2026-12-01T18:30' in Asia/Kolkata -> '2026-12-01T13:00:00Z'."""
    aware = datetime.fromisoformat(local_time).replace(tzinfo=ZoneInfo(tz_name))
    return aware.astimezone(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")

EXPECTED_UNITS = {"pm2_5": "μg/m³", "pm10": "μg/m³"}

def check_units(units: dict[str, str]) -> None:
    """Raise ValueError if current_units differ from docs/data-dictionary.md."""
    for col, unit in EXPECTED_UNITS.items():
        if units.get(col) != unit:
            raise ValueError(f"{col}: expected {unit!r}, got {units.get(col)!r}")

Line by line:

  • datetime.fromisoformat(local_time) reads text such as 2026-12-01T18:30 and returns a datetime object, a value that holds a date and a time.
  • .replace(tzinfo=ZoneInfo(tz_name)) attaches the zone Asia/Kolkata to it. Now the value is "aware", meaning it knows its zone.
  • .astimezone(timezone.utc) converts it to UTC. 18:30 in India is 13:00 UTC, because India is five and a half hours ahead.
  • strftime("%Y-%m-%dT%H:%M:%SZ") formats the result as text. %Y is the year, %m the month, %d the day, %H:%M:%S the time, and the final Z marks UTC.
  • EXPECTED_UNITS maps each column to the unit it must have. μ and ³ are the Greek mu and the superscript three, which together spell µg/m³.
  • check_units loops over the expected columns. units.get(col) returns the unit from the response, or None if it is missing.
  • raise ValueError(...) stops the program with a clear message when a unit differs. !r shows the text in quotes so that invisible differences are visible.

Expected result: to_utc_iso("2026-12-01T18:30", "Asia/Kolkata") returns '2026-12-01T13:00:00Z'.

Trap: Appending Z without converting

Writing Z onto an IST time gives a value that is five hours and thirty minutes wrong. Convert to UTC first, then add the Z.

Trap: datetime.utcnow

datetime.utcnow() returns a naive value and is deprecated. Use datetime.now(timezone.utc), which returns an aware value.

The worked example

Goal. Read readings.csv, which has 1,440 rows (6 stations, 3 pollutants, 80 timestamps), and print a headline: how many rows there are, how many are pm25, and the pm25 average. The course's answer is pm25 avg: 38.7.

Code. The Technology in Action version is summarise.py. The indentation was lost in the extraction, so it is restored here.

import csv
from statistics import mean

rows = list(csv.DictReader(open("readings.csv")))  # list[dict]
vals = [float(r["value"]) for r in rows if r["pollutant"] == "pm25"]  # filtered
print(f"rows: {len(rows)}")       # total samples
print(f"pm25 n: {len(vals)}")     # filtered count
print(f"pm25 avg: {mean(vals):.1f}")  # simple aggregate

Explanation, line by line.

  • Line 1 loads the CSV module and line 2 loads mean.
  • Line 4 reads the whole file into a list of dictionaries. The # list[dict] comment describes the result.
  • Line 5 keeps the pm25 rows and converts each value to a float in one step.
  • Line 6 prints the total number of rows, using len, which counts the items in a list.
  • Line 7 prints the number of pm25 values.
  • Line 8 prints the mean to one decimal place.

Note that open("readings.csv") is never closed in this version. For a script that runs and exits, this is harmless, but in the lab you will use with open(...) as f: so the file is closed for certain.

Step 2: Model a reading with a dataclass

What you do. Create a file called readings_report.py in the same folder. A dataclass is a class that stores a fixed set of named fields. A class is a blueprint for a kind of object. The @dataclass line above the class tells Python to write the setup code for you.

Line by line: line 1 loads dataclass from the standard library. Line 3 is a decorator, a line starting with @ that changes the class below it. class Reading: defines a new type. The four lines below it are the fields, each with a name and a type.

Step 3: Parse the CSV safely

What you do. Add these functions below the class. parse_row converts one dictionary into a Reading. load_readings reads the whole file and skips any row that cannot be converted, counting how many it skipped.

import csv

def parse_row(row: dict) -> Reading:
    return Reading(
        station_id=row["station_id"],
        ts=row["ts"],
        pollutant=row["pollutant"],
        value=float(row["value"]),
    )

def load_readings(path: str) -> tuple[list[Reading], int]:
    readings = []
    skipped = 0
    with open(path, newline="", encoding="utf-8") as f:
        for row in csv.DictReader(f):
            try:
                readings.append(parse_row(row))
            except (KeyError, TypeError, ValueError):
                skipped += 1
    return readings, skipped

Line by line:

  • parse_row(row: dict) -> Reading takes one row and returns a Reading. float(row["value"]) is the only conversion, and it happens in one place.
  • load_readings returns two things at once, a list and a count, written as tuple[...].
  • with open(path, newline="", encoding="utf-8") as f: opens the file. The with block closes the file automatically, even if an error happens inside it. encoding="utf-8" says how to read the characters.
  • for row in csv.DictReader(f): reads one row at a time from the open file.
  • try: starts a block that may fail. If parse_row fails, Python jumps to the except line.
  • except (KeyError, TypeError, ValueError): catches three specific problems: a missing column (KeyError), a missing value that becomes None (TypeError), and text that is not a number such as "abc" (ValueError).
  • skipped += 1 adds one to the count, which is short for skipped = skipped + 1.

Converting types with int, float and str

What it is. Python tracks the type of every value. int is a whole number, float is a decimal number and str is text. A value read from a CSV file is always text, even when it looks like a number. Three built-in functions change the type. int() gives a whole number, float() gives a decimal number and str() gives text. Each one accepts only the text it can read. float("36.6") works, but int("36.6") raises ValueError.

raw = "36.6"
print(type(raw).__name__)
print(float(raw) > 50)
print(int(float(raw)))

Output:

str
False
36

The first line shows that raw is text. The second line converts it to a float and compares it with 50. The third line converts to a float and then to an int. int() cuts off the decimal part without rounding, so 36.6 becomes 36, not 37.

How it shows up in a case study. A CityPulse loader sends the value column straight into a check for readings above 50. The job fails with TypeError on the first row, although the file is fine. The check compares text with a number. The right decision is to convert the value once, with float(), at the point where each row is read. The rest of the program then works with numbers. The team does not need a different file format or a higher threshold.

Trap: Calling int on a decimal

The tempting wrong answer is that int("52.1") gives 52, so the check still works. In fact it raises ValueError, and the row is never read. Use float() for sensor values.

Lists, dictionaries, sets and tuples

What it is. A collection holds several values in one variable. A list is ordered, can hold repeats and is written in square brackets. A dictionary holds key-value pairs in curly braces and finds a value by its key. A set holds unique items with no fixed order. A tuple is ordered and cannot be changed after it is made. Reading a dictionary with d[key] raises KeyError when the key is missing, while d.get(key, default) returns the default instead.

readings = ["S1", "S2", "S1"]
print(len(readings), readings.count("S1"))
print(sorted({"S1", "S2", "S1"}))
limits = {"pm25": 50, "no2": 200}
print(limits["pm25"], limits.get("o3", "none"))

Output:

3 2
['S1', 'S2']
50 none

len counts all three items, and count counts the S1 items. The set literal keeps each id once, and sorted returns a list in order. The square-bracket read finds the value for pm25. The get call looks for o3, which is not a key, so it returns the default text none.

How it shows up in a case study. A dashboard keeps the latest reading for each station in a dictionary. A station that has not reported yet has no key. The page reads latest["S9"], crashes, and takes the rest of the page down with it. The right decision is to read with get, and to show a missing station as "no data yet", not as zero. A list would not help, because it has no keys. A set would not store the values at all.

Trap: Expecting a dictionary to create missing keys on read

The tempting wrong answer is that reading latest["S9"] creates the key. A normal dictionary raises KeyError. Only a defaultdict creates a missing key on read, and you must choose it on purpose.

Closing files with with open

What it is. A context manager is an object that prepares something before an indented block and cleans it up afterwards. You use one with the with keyword. The most common example is a file. with open(path) as f: opens the file and names it f. When the block ends, Python closes the file, even when an error happened inside the block. Your code does not need to remember a close() call.

with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("pm25 ok\n")
print(f.closed)

Output:

True

The first line opens notes.txt for writing, which creates it if it is missing. The second line writes one line into it. When the indented block ends, Python closes the file. The last line prints True, which shows that f is closed. The name f still exists after the block, but the file it points to is closed.

How it shows up in a case study. A scheduled job reads a large readings file and writes a summary. Row 300 is malformed and raises an error. The team's version opens the file with a plain open call and closes it at the bottom. The bottom line is never reached, so the file stays open and the summary is left half written. The right decision is to use with for every file the job opens. A longer timeout or a sleep does not close the file.

Trap: Using the file after the block

The tempting wrong answer is that f can still be read after the block. The file is closed, so f.read() raises ValueError: I/O operation on closed file. Read and write only inside the block.

Defining functions with def, parameters and return

What it is. A function is a named block of code. def starts the definition, the names in brackets are parameters, and the indented body does the work. return sends a value back to the caller. A function with no return line gives back None, which means no value. print shows text on the screen, but it does not give the value to the caller.

def show_average(values):
    print(sum(values) / len(values))

def average(values):
    return sum(values) / len(values)

result = show_average([30, 60])
print(result)
print(average([30, 60]))

Output:

45.0
None
45.0

show_average computes the mean and prints it, but it has no return line. The assignment stores None in result, so the second line prints None. average returns 45.0, and the last line prints it. Both functions do the same arithmetic. Only the one with return gives the caller a value to use.

How it shows up in a case study. A CityPulse analyst writes a function that works out the average pm25 value and prints it for the morning standup. Later, the weekly report calls the same function, stores the result and multiplies it by a factor. The job crashes with TypeError. The function works on screen, but it never sends the average back. The right decision is to return the number and let the caller decide how to display it.

Trap: Printing instead of returning

The tempting wrong answer is that a printed result is a returned result. The caller receives None, so every later step that uses the number fails.

Handling errors with try, except, else and finally

What it is. Some code can fail, for example when text is not a number or a file is missing. The try block holds that code. An except block runs only when the named error happens inside the try block, so you name the error type you expect. An else block runs only when nothing went wrong. A finally block runs in every case, including when the function reaches a return. An error you do not catch stops the program and shows a traceback.

def to_float(text):
    try:
        value = float(text)
    except ValueError:
        print("not a number:", text)
        return None
    else:
        print("converted")
        return value
    finally:
        print("checked")

print(to_float("36.6"))
print(to_float("n/a"))

Output:

converted
checked
36.6
not a number: n/a
checked
None

The first call succeeds, so except is skipped and else prints converted and returns the value. finally runs before the function hands the value back, so checked prints next. The second call raises ValueError inside float. The except block prints the message and returns None, and finally still runs.

How it shows up in a case study. A CityPulse fetch step calls a web service while the network is down. A developer wrote except: with pass so that the scheduled job does not crash. The job ends with an empty report and no error in the log. The right decision is to catch only the error the call can raise, log the reason, and raise a clear error that stops the run. The problem is not that errors happen, but that they disappear.

Trap: A silent except

The tempting wrong answer is that a silent handler is safer. The empty report then looks like valid data. A bare except: also catches KeyboardInterrupt, which stops the user from cancelling the program.

Producing values lazily with yield

What it is. A generator is a function that uses yield instead of return to hand back values one at a time. Calling the function does not run its body. It returns a generator object, and each value is produced only when the caller asks for the next one. A generator can be used only once, because it is empty after it has produced everything. Generators save memory on large data, because the whole list is never built.

def high_values(values, limit):
    for v in values:
        if v > limit:
            yield v

gen = high_values([40, 55, 61], 50)
print(sum(gen))
print(list(gen))

Output:

116
[]

The function yields each value above the limit, one at a time. gen holds the generator, and its body has not run yet. sum(gen) pulls 55 and 61 from it and gives 116. After that the generator is empty, so list(gen) returns []. To use the values again, you must call high_values again.

How it shows up in a case study. A team reads a year of readings from a very large file. The first step builds a list of every row in memory, and the shared server runs out of memory. A second step computes the total with sum and the count with len(list(...)) from the same generator, and the count is zero. The right decision has two parts. Use a generator so each row is handled as it arrives. When two results need the same data, build one list once, or call the generator function again.

Trap: Reusing a generator

The tempting wrong answer is that list(gen) after sum(gen) still gives the values. It gives [] with no error, so the mistake is easy to miss.

Writing small record classes with @dataclass

What it is. A class is a blueprint for a kind of object. A dataclass is a class in which you list the fields with type hints, and the @dataclass line above the class writes the usual set-up code for you. That code includes __init__, which stores the fields when you create an object, __repr__, which prints the object clearly, and __eq__, which compares two objects field by field.

from dataclasses import dataclass

@dataclass
class Reading:
    station_id: str
    value: float

a = Reading("S1", 36.6)
b = Reading("S1", 36.6)
print(a)
print(a == b)

Output:

Reading(station_id='S1', value=36.6)
True

@dataclass changes the class below it. The two fields are the only code you wrote. Reading("S1", 36.6) creates an object, matching the values to the fields in order. print(a) shows the generated text form. a == b is True, because every field is equal, even though a and b are two separate objects.

How it shows up in a case study. A team stores each parsed sensor row as a plain dictionary. A typo such as "stn_id" silently creates a new key, and the report counts the wrong station. The right decision is a dataclass with fixed field names. A misspelled attribute such as reading.stn_id fails at once with AttributeError, instead of quietly producing a wrong count. The dataclass is not a database, and it is not faster, so those answers are wrong here.

Trap: Mutable default lists

The tempting wrong answer is that items: list = [] gives each object its own list. Python raises ValueError when the class is defined, so the module does not even import.

Default arguments that are lists or dicts

What it is. A default argument is a value used when the caller does not pass one, written as def f(x=5). Python evaluates the default once, when def runs, not on each call. If the default is a list or a dictionary, every call that uses it shares the same object. Changes made in one call are visible in the next. The usual fix is a None default, with a new list created inside the function.

def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

print(add_tag("pm25"))
print(add_tag("no2"))

Output:

['pm25']
['pm25', 'no2']

The fixed version is this:

def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags

With the fixed version, both calls print a one-item list: ['pm25'] and then ['no2']. The default tags=[] creates one list when the function is defined, so the first call adds pm25 to it, and the second call finds it still holding pm25. In the fixed version, None is the default, so if tags is None creates a new list for each call that does not pass one.

How it shows up in a case study. A CityPulse alert function keeps a history of alerts for the dashboard. Tests run one after another in the same process, and the second test sees alerts left over from the first. The team's first idea is to clear the history at the end of each run, but that breaks callers who pass their own list. The better decision is to change the default to None and create the list inside the function. No caller has to remember to clean up.

Trap: Thinking defaults reset on each call

The tempting wrong answer is that Python rebuilds [] for every call. It does not. The same list object is reused, so check what a second call sees.

Importing modules and the name check

What it is. A module is one .py file. import name loads the whole module, and you use its names with a dot, such as statistics.mean. from name import thing loads one name, so you can write mean alone. Python searches the folder of the running script first, then the standard library and installed packages. The check if __name__ == "__main__": is true only when the file is run directly. When another file imports it, __name__ holds the module name, so the code under the check does not run.

## helpers.py
def double(x):
    return x * 2

if __name__ == "__main__":
    print("running helpers directly")

## main.py
from helpers import double
print(double(4))

Running python main.py prints 8. Running python helpers.py prints running helpers directly.

main.py loads only double. Importing runs the top of helpers.py, which defines double, but it skips the body of the check, because __name__ is helpers during the import. Running helpers.py directly sets __name__ to "__main__", so the body runs. The output of main.py is 8, because 4 times 2 is 8.

How it shows up in a case study. A student names a helper file statistics.py, so the average code sits "near the statistics". The lab script imports mean from statistics, and the import fails with an error that names mean. The local file is found first, because it sits in the same folder and that folder is searched first. The right decision is to rename the file to something that describes the project, such as readings_stats.py. Python itself does not need changing.

Trap: Naming a file after a library

The tempting wrong answer is that Python falls back to the real library when a local file exists. It does not. A file named logging.py, statistics.py or csv.py hides the real module for every script in that folder.

Caching results with functools.lru_cache

What it is. functools.lru_cache is a decorator, a line beginning with @ that wraps a function. The wrapper keeps a table from arguments to results. When the function is called again with the same arguments, the stored result is returned at once, and the body does not run. The table lives in memory for one run of the program. Every argument must be hashable, which means Python can compute a stable key from it. Numbers, text and tuples are hashable. Lists and dictionaries are not, so calling a cached function with them raises TypeError.

from functools import lru_cache

@lru_cache(maxsize=None)
def square(n):
    print("computing", n)
    return n * n

print(square(3))
print(square(3))

Output:

computing 3
9
9

The first call with 3 finds no stored result, so the body runs, prints computing 3 and returns 9. The second call finds the stored 9 and returns it without printing. maxsize=None means the table has no size limit.

How it shows up in a case study. A CityPulse function station_total(path) reads a CSV file and sums its values. A developer adds lru_cache to speed up a dashboard. At 09:00 the total is correct. At 10:00 the file has new rows, but the dashboard still shows the 09:00 total. The function reads the file, which is not one of its arguments, so the cache cannot see the change. The right decision is to remove the cache from any function that reads files, the clock or other changing data. A bigger cache size does not help.

Trap: Caching a function that reads a file or the clock

The tempting wrong answer is that a bigger cache fixes stale results. The cache returns the old result for the same argument, even when the file has changed. Cache only pure functions, whose result depends only on their inputs.

  • Filtering then dividing. Build the filtered list first, then divide. Check that the list is not empty before you divide, because dividing by zero raises ZeroDivisionError:
items = []
print(sum(items) / len(items) if items else 0.0)

Output: 0.0.

  • Rounding at the end. round(x, 2) keeps two decimal places, and it should be applied only to the final result:
values = [1, 2, 2]
print(sum(values) / len(values))
print(round(sum(values) / len(values), 2))

Output: 1.6666666666666667, then 1.67.

  • Round half to even. Python's round sends a halfway value to the nearest even digit:
print(round(2.5), round(3.5))

Output: 2 4.

  • Floats and whole numbers. / always gives a float, while // gives a whole number:
print(7 / 2, 7 // 2)

Output: 3.5 3.

  • Text is not a number. Plus joins text, and it adds numbers:
print("4" + "2", 4 + 2)

Output: 42 6.

For busiest_station.

  • Finding the largest with a key. max and min accept a key function. max returns the first maximal item it meets when several items are equal:
words = ["pear", "fig", "apple"]
print(min(words, key=len))

Output: fig.

  • Text order. Strings compare character by character, so "item10" comes before "item9":
print("item10" < "item9")

Output: True.

  • Making a stable choice on a tie. A tuple such as (-count, name) compares the count first and the name only when counts are equal.

For all three functions.

  • Not changing the input. sorted returns a new list, while list.sort() changes the list it is called on:
original = [3, 1, 2]
ordered = sorted(original)
print(original, ordered)

Output: [3, 1, 2] [1, 2, 3].

  • Booleans are integers. bool is a subclass of int, so isinstance(True, int) is true. Keep this in mind when a check for numbers might accept True:
print(isinstance(True, int), isinstance(True, bool))

Output: True True.

  • Statistics. statistics.mean gives the average of a list, and it raises StatisticsError on an empty list:

Output: 2.0.

Worked twin problem

This problem has a different domain and different rules from the lab, but it needs the same skills. Read it as a lab task.

A library records each loan as a dictionary with three keys: member (text), genre (text) and days (a whole number of days the book was kept). Write three functions.

  • loans_per_genre(loans) returns a list of (genre, count) tuples, sorted by count from highest to lowest. Genres with the same count are sorted by name, A to Z. An empty list gives [].
  • average_days(loans, genre) returns the average days of the loans for that genre, rounded to one decimal place. It returns None if no loan has that genre.
  • top_member(loans) returns the member with the most loans. On a tie, it returns the member who appears first in the list. It returns None for an empty list.

The solution and its tests are below. The block runs when the book is built.

def loans_per_genre(loans):
    counts = {}
    for loan in loans:
        genre = loan["genre"]
        counts[genre] = counts.get(genre, 0) + 1
    return sorted(counts.items(), key=lambda pair: (-pair[1], pair[0]))


def average_days(loans, genre):
    days = [loan["days"] for loan in loans if loan["genre"] == genre]
    if not days:
        return None
    return round(sum(days) / len(days), 1)


def top_member(loans):
    counts = {}
    for loan in loans:
        member = loan["member"]
        counts[member] = counts.get(member, 0) + 1
    if not counts:
        return None
    return max(counts, key=counts.get)


loans = [
    {"member": "Ana", "genre": "science", "days": 14},
    {"member": "Ben", "genre": "fiction", "days": 7},
    {"member": "Ana", "genre": "fiction", "days": 10},
    {"member": "Ben", "genre": "science", "days": 21},
]

assert loans_per_genre(loans) == [("fiction", 2), ("science", 2)]
assert loans_per_genre([]) == []
assert loans_per_genre([
    {"member": "x", "genre": "b", "days": 1},
    {"member": "x", "genre": "a", "days": 1},
    {"member": "x", "genre": "b", "days": 1},
]) == [("b", 2), ("a", 1)]
assert average_days(loans, "science") == 17.5
assert average_days(loans, "fiction") == 8.5
assert average_days(loans, "poetry") is None
assert average_days([], "science") is None
thirds = [{"member": "x", "genre": "g", "days": d} for d in (1, 2, 2)]
assert average_days(thirds, "g") == 1.7
assert top_member(loans) == "Ana"
assert top_member([]) is None
assert top_member([
    {"member": "Zed", "genre": "g", "days": 1},
    {"member": "Amy", "genre": "g", "days": 1},
]) == "Zed"
assert top_member(loans + [{"member": "Ben", "genre": "g", "days": 1}]) == "Ben"
print("all checks passed")

Line by line, starting with loans_per_genre:

  • counts = {} starts an empty dictionary for the counts.
  • The loop reads the genre of each loan and stores the count plus one, using get with a default of 0, so a new genre starts at 1.
  • sorted(counts.items(), key=...) turns the dictionary into (genre, count) tuples and sorts them. The key (-pair[1], pair[0]) sorts the count from highest to lowest, because the minus sign reverses it, and the genre name from A to Z for equal counts.
  • An empty list never enters the loop, so counts stays empty and sorted returns [].

For average_days, the list comprehension keeps the days for one genre. An empty list returns None before any division. Otherwise the sum divided by the length is rounded to one decimal place. The third assert, thirds, gives 5 divided by 3, which is 1.6666, and that rounds to 1.7.

For top_member, the counting is the same. max(counts, key=counts.get) returns the member with the largest count. Python's max returns the first maximal item it meets, and dictionaries keep the order in which keys were first added. So on a tie, the member who appeared first in the list wins. The top_member(loans) assert (Ana and Ben tied, Ana first) and the Zed and Amy assert test that rule, and the final assert checks that Ben wins when he has the most loans.

Say it out loud

Why do you convert the value to a float at the start?

Model answer

CSV fields are always text, so "36.6" > 50 is either an error or a wrong comparison. I convert the value once, where the row is read, so the rest of the code works with numbers. That also means a bad value fails in one known place, where I can skip the row and count it. Every later function can then assume the type is correct.

Why use with open(...) instead of a plain open?

Model answer

The with statement guarantees that the file is closed when the block ends, even if an exception happens in the middle. A plain open depends on the code reaching a close call, and a crash skips it. In a scheduled job that runs unattended, an unclosed file can leave data unwritten or lock it on some systems. The with form costs nothing extra and removes that risk.

Why is a bare except: dangerous?

Model answer

A bare except: catches every error, including bugs in my own code, such as a misspelled variable name. If I then do nothing, the error disappears and the report shows wrong or empty results with no sign of a problem. I catch only the errors I expect, such as ValueError for bad numbers, and I log the reason. Unexpected errors then stop the program, and I can see and fix them.

What is a pure function, and why does it help testing?

Model answer

A pure function returns a result that depends only on its inputs, and it does no file, network or clock work. Because of that, I can test it with an assert on a small hand-made input, and the test will always give the same result. The fetching and saving stay in separate functions, so that the parsing can be tested without a network connection. This is why parse in the slides takes the JSON as an input.

What is the difference between a module and a package?

Model answer

A module is a single .py file that other code can import. A package is a folder of modules with an __init__.py file, and it can be installed with a pyproject.toml file. The installed package can be imported from any folder, so scripts, tests and the scheduled job all use the same code. The editable install with pip install -e . links the package to my source folder, so my edits take effect immediately.
